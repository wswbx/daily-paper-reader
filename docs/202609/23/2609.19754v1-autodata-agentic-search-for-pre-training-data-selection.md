## 摘要
LLM 智能体近来在通过执行反馈编辑模型与训练代码来自动化机器学习工程方面展现出前景。然而，数据在很大程度上仍处于这种智能体优化循环之外。我们将预训练数据选择视为对逐文档特征的启发式工程，即词法统计、类别标签和困惑度。我们提出 AutoData，一个直接在可执行选择算法上进行搜索的智能体。与先前在固定领域集合上优化权重的数据混合方法不同，AutoData 搜索更丰富的程序空间，包括评分、分层和随机选择规则，并通过代理模型的验证反馈迭代改进算法，从而自动发现特征交互。在一次通宵搜索中，AutoData 发现了一种选择算法，其性能优于现有的人工设计数据筛选流水线。尽管仅在这个小型代理模型上进行搜索，所发现的方案仍能迁移到更大规模，并提升下游指标 CORE。这些结果表明，数据工程可被视为一个智能体机器学习问题，将自主研究从模型和训练代码优化扩展到数据。

## Abstract
LLM agents have recently shown promise in automating machine learning engineering by editing model and training code under execution feedback. Data, however, remains largely outside this agentic optimisation loop. We frame pre-training data selection as heuristic engineering over per-document features, i.e., lexical statistics, categorical labels, and perplexity. We introduce AutoData, an agent that searches directly over executable selection algorithms. Unlike prior data mixture methods that optimise weights over a fixed set of domains, AutoData searches a richer program space of scoring, stratification, and stochastic selection rules, discovering feature interactions automatically by iteratively refining algorithms with validation feedback from a proxy model. Within an overnight search, AutoData discovers a selection algorithm that outperforms existing human-designed curation pipelines. Despite being searched only on this small proxy, the discovered recipe transfers to larger scales and improves the downstream metric CORE. These results suggest that data engineering can be treated as an agentic machine learning problem, extending autonomous research from model and training-code optimization to the data.

- **核心命题**：把预训练数据选择重新表述为**对逐文档特征的启发式工程**，并让智能体直接在**可执行的选择算法**上做搜索——即把数据工程变成"智能体机器学习问题"，将自主研究从模型/训练代码扩展到数据侧。

## 2. 方法论

### 核心思想
- 每个文档由一组特征刻画（词法统计、类别标签、困惑度、LLM 标注质量信号）；选择算法本身是一段**可执行程序**，智能体借助代理模型的验证反馈迭代精炼该程序。
- 与 RegMix / DoReMi 等在**固定领域集合上优化权重**的做法不同，AutoData 搜索的是更丰富的程序空间：**评分规则、分层规则、随机选择规则**及其特征交互。

### 问题形式化
- 给定文档池 $D=\{d_i\}_{i=1}^N$、文档级特征 $\{x_i\}$、固定预算 $B$，选择算法为
  $f: (D, \{x_i\}_{i=1}^N, B) \to S$，其中 $S \subset D,\ |S| = B$。
- 令 $A_\theta(S)$ 为固定超参 $\theta$ 下在 $S$ 上预训练得到的模型，$J(\cdot)$ 为评测函数（val-bpb 或 CORE 准确率），搜索目标为
  $f^* = \arg\max_{f \in \mathcal{F}} J\big(A_\theta\big(f(D,\{x_i\},B)\big)\big)$。

### 特征库（四条互补轴）
- **词法特征**：token 长度（nanochat tokenizer）、$n \in \{1,\dots,5\}$ 的 distinct $n$-gram 比率（捕捉重复/模板化文本）。
- **类别特征**：用 WebOrganizer 分类器给出 topic 与 format 标签，联合得到 $24 \times 24 = 576$ 个类别单元。
- **困惑度特征**：以 Qwen2.5-0.5B-Base 计算逐文档 bits-per-byte，刻画相对参考分布的难度。
- **LLM 标注特征**：Gemini-3-Flash 对部分候选池抽取三类计数——错误事实声明数 `n_factual`、显式推理步数 `n_rsteps`、无效推理步数 `n_rerrors`。

### 自演化循环（基于 AIDE 脚手架）
每次迭代：(i) 智能体在**此前候选及其得分摘要**的条件下提出新的选择函数 $f$；(ii) 执行 $f$ 从文档池构建训练子集 $S$；(iii) 用固定超参训练代理语言模型；(iv) 在留出验证集上以 $J(\cdot)$ 评测，得分连同历史轨迹摘要回传给智能体，指导下一轮提案。

### 发现的两类代表性配方（算法流程，文字说明）
- **Recipe #1（优化 val-bpb）**：预算的 1/3 作为均匀采样的随机 backbone 保证覆盖；其余候选计算复合分数——词法多样性（$n$-gram）经 tanh 变换、**困惑度项被多样性"门控"**（仅当 $n$-gram 多样性也高时，低困惑度才加权，避免偏好重复样板）、长度与 char/token 密度作为**中心化项**惩罚双向离群；随后在 (topic, format) 单元内做**收缩式中心化**（$\mu_c$ 按 $n_c/(n_c+\tilde n)$ 收缩）抑制高频单元过度入选；最后分成大小为 3 的 slate，加 Gumbel 噪声做**锦标赛 argmax**（等价 softmax 采样）。
- **Recipe #2（优化 CORE）**：50% 预算作为随机 backbone；其余按长度、char/token 比、$n$-gram 多样性、困惑度计算复合分数，各特征用**三角核（triangular kernel）** 映射到池自适应分数（长度/多样性偏好中高值、困惑度偏好低值、比率偏好正常密度）；再按源顺序切块，赋予每篇文档其所在块的标准化均值作为**源邻域先验**；最终分数 = 组合分 + 先验 + Gumbel 噪声，取 Top-$B_{\text{rep}}$ 与 backbone 合并并去重到恰好 $B$ 篇。

## 3. 实验设计

- **数据池**：NVIDIA ClimbMix 全量 400B-token 英文预训练语料，6,542 个训练 shard，$N = 553{,}155{,}584$ 篇文档；留出一个 shard 作为验证集并从所有选择池中排除。
- **选择预算**：$B = 14{,}374{,}266$ 篇（约语料 2.6%），与标准 NanoChat 任务的数据规模一致，所有方法共享同一全局选择预算。
- **代理模型**：深度 8 的 GPT-2，`target-param-data-ratio = 10`（约 0.42B 训练 token）；因全量训练代价高，每次评估在所选池中均匀抽 880,000 篇文档的子样本上训练；单次约 10 分钟（1×H100）。
- **子样本协议**：同一子样本上用 4 个不同训练种子并行训练 4 个代理模型（4×H100），固定子样本、只变训练种子，以隔离训练噪声、降低方差。
- **Benchmark / 评测信号**：
  - **val-bpb**：留出 ClimbMix shard 上的验证 bits-per-byte（越低越好）；
  - **CORE**：22 个标准任务（常识推理、阅读理解、世界知识）的 centered accuracy 无加权平均（越高越好）。
  - 分别以两种信号各跑一次独立搜索，并同时报告两个指标（优化指标 + 未优化指标以检验泛化）。
- **对比基线**：
  1. **Random sampling**（ClimbMix 默认策管效果）；
  2. **DCLM-Baseline 分类器**（保留正例，负例换成 ClimbMix 采样文档以适配目标语料）；
  3. **Perplexity filter**（Qwen2.5-0.5B 打分，因 ClimbMix 已高度过滤，按建议取**中段困惑度带**）；
  4. **RegMix**（以 $K=24$ 个 WebOrganizer topic 为域，采样 $N=128$ 组 Dirichlet 混合，训练 depth-8 代理并用 LightGBM 回归预测 val-bpb，取最优混合）。
- **跨规模验证**：在 depth = 8 / 12 / 16 / 20 / 24 五档模型（125M → 1.3B 参数）上比较，小模型从同一 $B$ 文档子集中按各自训练预算均匀子采样。

## 6. 主要结论与发现

- **智能体搜索有效**：约 200 步搜索后，AutoData 发现的配方在 val-bpb 与 CORE 两个目标上均超过 DCLM、困惑度过滤、RegMix 与默认 ClimbMix 排序。
- **跨规模可迁移**：在 val-bpb 上，depth 8–20 均显著优于全部四个基线；depth 24 时与默认 ClimbMix 相当，说明跨规模迁移存在上限。CORE 上除 depth 16 外各尺度均优于基线，但**差异不具统计显著性**。
- **人工策管在"已策管池"上会失效**：DCLM-Baseline 与 PPL 过滤在各尺度上 val-bpb 均回退；RegMix 仅在 depth-12 的 CORE 上较好，整体不稳定——说明策管方法对源数据池高度敏感，换池后可能需重新设计。
- **发现的配方超越单特征排序与阈值过滤**：倾向"复合评分 + 保多样性选择机制"，在偏向高质量文档的同时保持数据分布的广泛覆盖。
- **不同 LLM 的"数据观"差异明显**：三者都用长度、$n$-gram、困惑度；但在类别特征上分歧巨大（GPT-5.5 与 Opus-4.7 约 90% 配方使用，Gemini-3-Pro 仅 1–2%）。评分聚合上 GPT-5.5 偏好乘法复合（86.5%），Gemini/Opus 偏好线性复合（96.0%/85.5%）；选择规则上 GPT-5.5 偏好锦标赛（91.0%），另两者偏好分层配额（各 87.5%）。**没有任何智能体使用单特征评分或纯阈值/全局 Top-$B$**，表明它们普遍避免硬过滤、倾向保多样性。
- **特征消融**：LLM 标注特征取得最好 val-bpb（0.95021，+2.1σ），提示语义级信号仍有空间；但廉价特征单独使用也能达到 +1.8~1.9σ，两个词法特征即与全 8 特征相当，单困惑度特征略优于全集——说明**小而精的特征集**更有利。

## 7. 优点

- **问题定位新颖且有说服力**：把数据选择从"固定预处理流水线"重构为"可执行配方的优化问题"，填补了智能体自动研究在数据侧的空白，并用 ClimbMix 替换 FineWeb-Edu 的 27% 加速作为动机支撑。
- **搜索空间设计更丰富**：不是优化固定域上的混合权重，而是搜索评分/分层/随机选择三类规则的组合程序，能自动发现特征交互（如"困惑度被多样性门控"这类非平凡结构）。
- **实验控制严谨**：固定子样本 + 4 种子并行隔离训练噪声；固定源池与全局选择预算；配对 $t$ 检验；同时报告优化指标与未优化指标以检验泛化；跨 5 个模型尺度验证迁移。
- **可解释性分析扎实**：给出两轴操作分类框架（评分聚合 × 选择规则）并量化不同 LLM 的偏好分布，还提供了四个完整配方代码（附录），便于复现与理解。
- **工程可行**：单次评估 10 分钟、单卡 H100 即可，通宵搜索即可产出优于人工流水线的配方，实用门槛低。

- **下游对齐/微调阶段未涉及**：评测止于预训练代理模型的 val-bpb 与 CORE，未考察所选数据分布对后续 SFT/RLHF、指令跟随、长文本与多语能力的影响，而"预训练数据选择"的最终价值需在这些环节体现。

## 9. 总体评价

AutoData 把"数据选择"从一个静态预处理工程问题，重新表述为一个可由智能体在**可执行程序空间**中搜索的优化问题，并用跨 5 个模型尺度、双目标信号、多种子配对检验的实验框架验证了其有效性。其最有价值的贡献或许不只是某个具体配方，而是三条可迁移的观察：（i）在**已高度策管**的语料池上，DCLM、PPL 过滤、RegMix 等经典人工流水线会失效甚至回退，说明数据策管方法具有强池依赖性；（ii）智能体自发收敛到"复合评分 + 保多样性选择（锦标赛/分层配额）"的结构，而几乎从不采用单特征排序或全局硬阈值过滤；（iii）不同 LLM 在特征偏好上高度一致（长度、$n$-gram、困惑度）却在类别特征与聚合方式上严重分歧，暗示"数据观"本身是一个尚未被充分约束的归纳偏置来源。

同时，论文的结论强度受限于单一语料、中等模型规模、CORE 指标不显著、以及算力与标注成本披露不足。它更适合被定位为**可行性证明与方法论开篇**，而非可直接部署的数据策管方案。后续工作的自然方向包括：将特征库与选择机制一并纳入搜索空间、在真实规模（数十亿参数、多语/多域语料）上验证迁移性、把搜索目标从代理指标换成更贴近下游能力的信号，以及把 LLM 标注的边际收益与其成本做显式的权衡建模。
