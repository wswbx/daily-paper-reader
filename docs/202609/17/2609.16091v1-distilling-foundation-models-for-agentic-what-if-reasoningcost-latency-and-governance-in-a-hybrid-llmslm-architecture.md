## 摘要
表格基础模型通过上下文学习提供强大的零训练预测性能，但其高推理延迟使其难以作为交互式智能体循环中的热路径决策后端。我们在UCI Adult和五个OpenML基准上的商业决策模拟中，将TabPFN教师模型蒸馏为一个紧凑的前馈学生模型：分类头将53.2M参数压缩至8,546（6,220倍）；部署的双头贷款流水线将111.4M参数压缩至17,059（6,532倍）。学生模型保持了95.4–100.5%的准确率和96.8–100.0%的AUC，其中在credit-g上的准确率保持率最低，为95.4%；一个alpha = 0的硬标签对照表明，教师模型的软目标带来了2.1–7.0个AUC点的提升。

## Abstract
Tabular foundation models deliver strong zero-training predictive performance via in-context learning, but their high inference latency makes them impractical as hot-path decision backends in interactive agentic loops. We distill a TabPFN teacher into a compact feed-forward student across a business-decision simulation on UCI Adult and five OpenML benchmarks: the classification head compresses 53.2M parameters to 8,546 (6,220x); the deployed two-head loan pipeline compresses 111.4M parameters to 17,059 (6,532x). The student retains 95.4-100.5% accuracy and 96.8-100.0% AUC, with the lowest accuracy retention on credit-g at 95.4%; an alpha = 0 hard-label control shows that the teacher's soft targets provide a 2.1-7.0 AUC point gain.

# 论文总结：为智能体式 What-If 推理蒸馏基础模型——混合 LLM+SLM 架构中的成本、延迟与治理

## 1. 核心问题与整体含义

- **背景**：表格基础模型（如 TabPFN）通过上下文学习（in-context learning）实现零训练、少样本的强预测性能，但其推理时需要将整个训练集作为上下文输入，单次预测延迟高达 CPU 12.6s / GPU 0.84s，无法作为交互式多步智能体循环中的"热路径"决策后端。
- **部署痛点**：主流方案把工具编排与最终响应生成都交给云端 LLM（如 gpt-4o-mini），导致每次决策反复向外部 API 传输敏感属性（年龄、收入、婚姻状况等），既增加 token 延迟，又带来 GDPR 数据治理风险。
- **核心研究问题**：将表格预测器知识蒸馏为紧凑学生模型，并采用"非对称混合编排"（云 LLM 仅负责工具选择与 schema 解析，预测与响应生成留在本地），能否在保持任务质量的同时，降低端到端延迟、运营成本与敏感数据暴露？
- **整体含义**：论文给出了一条兼顾精度、效率与合规的部署路径，并首次在智能体 what-if 推理场景下系统量化了"延迟收益来自哪里"——延迟下降几乎全部来自移除 TabPFN，而成本下降才来自减少云调用。

## 2. 方法论

### 2.1 核心思想

- 以 TabPFN 为教师，蒸馏出与教师架构无关的紧凑前馈 MLP 学生；教师提供软目标（soft targets）作为额外监督信号。
- 在智能体层面采用非对称分工：云 LLM（gpt-4o-mini）单次调用完成工具选择 + 结构化场景解析（OpenAI function calling schema 约束）；蒸馏学生 MLP 本地执行数值预测；本地 Qwen2.5-3B-Instruct SLM 本地完成最终自然语言答案格式化。

### 2.2 蒸馏损失（分类）

- 软化温度 $T>0$，软硬混合权重 $\alpha\in[0,1]$，学生/教师 logits 为 $z_S, z_T$，硬标签 $y$：
  - $L_{soft}=T^2\cdot D_{KL}\big(\mathrm{softmax}(z_T/T)\,\|\,\mathrm{softmax}(z_S/T)\big)$
  - $L_{hard}=\mathrm{CrossEntropy}(z_S, y)$
  - $L_{cls}=\alpha L_{soft}+(1-\alpha)L_{hard}$
- 主实验配置：$T=2.0$，$\alpha=0.7$，10 epochs，Adam，batch 64，seed 42，无 hint/embedding loss。$T^2$ 乘子用于补偿温度缩放导致的梯度幅值变化。

### 2.3 蒸馏损失（回归）

- 无 softmax 可软化，改为对教师点预测 $\hat y_T$ 与真值 $y$ 的 MSE 混合：
  - $L_{reg}=\alpha\cdot \mathrm{MSE}(\hat y_S,\hat y_T)+(1-\alpha)\cdot \mathrm{MSE}(\hat y_S, y)$
- 主回归 $\alpha=0.7$，$T=1.0$，10 epochs；OpenML 回归扩展 $\alpha=0.9$，$T=1.0$，200 epochs。

### 2.4 学生架构

- 3 层 MLP：$W_1\in\mathbb{R}^{64\times d_{in}}$，$W_2\in\mathbb{R}^{32\times 64}$，$W_3\in\mathbb{R}^{C\times 32}$，Dropout 0.2，ReLU 隐层，分类头 sigmoid / 回归头线性。
- 唯一随数据集变化的是输入宽度 $d_{in}$（one-hot 编码后维度），因此参数量为 $64d_{in}+2210$（二分类）。

### 2.5 混合智能体架构

- **全 LLM 基线**：同一云模型接收系统提示、用户查询与工具 schema，决定工具调用、抽取参数、由 TabPFN 教师执行预测、再由同一云模型消费原始工具输出生成最终答案（每查询最多 3 次云调用）。
- **混合架构**：云模型仅一次 schema 约束的 function calling（工具选择 + 场景解析），蒸馏学生 MLP 执行预测，本地 Qwen2.5-3B 格式化答案，全程在本地信任边界内。
- 两条管道在工具 schema、系统提示意图、评估查询集上完全一致，仅操纵两个变量：(a) 预测模型（教师 vs 学生），(b) 响应生成模型（云 LLM 多轮 vs 本地 SLM 单次）。
- 用 LangSmith 对两条管道做全链路追踪（含 token 用量、预测延迟、生成延迟），离线评估指标通过 `Client.create_feedback` 回写到生产 trace。
