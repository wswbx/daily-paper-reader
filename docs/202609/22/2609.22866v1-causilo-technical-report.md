## 摘要
我们提出 Causilo，一种表格基础模型（TFM），它将前沿的预测性能与极快的推理速度相结合。在 TabArena 上，Causilo 达到 1785.4 Elo，推理时间中位数为每 1K 个测试样本 0.10 秒。它比 TabPFN-3.5-Fast 少用 31.6% 的推理时间，处于性能-效率帕累托前沿。Causilo 遵循 TabICL 的先列后行架构，但在行压缩之前引入了一个额外的行细化模块。该模块在列编码之后，在每一行内的单元格表示之间交换信息。细化后的单元格随后通过一个额外的列阶段再次访问上下文集，然后被压缩为行嵌入。为了提升推理效率，两个行阶段都通过固定数量的摘要 token 使用交叉注意力，使其注意力成本与特征数量保持线性。Causilo 在约 3600 万个合成表格上预训练，在 TabArena、BeyondArena 和 ScoringBench 上取得了强劲的基准测试结果，以显著更快的推理实现了前沿级性能。

## Abstract
We introduce Causilo, a tabular foundation model (TFM) that combines frontier predictive performance with exceptionally fast inference. On TabArena, Causilo achieves 1785.4 Elo, at a median inference time of 0.10 seconds per 1K test samples. It outperforms TabPFN-3.5-Fast with 31.6% less inference time, placing it on the performance--efficiency Pareto frontier. Causilo follows TabICL's column-then-row architecture but introduces another row-refinement module before row compression. This module exchanges information among cell representations within each row after column encoding. The refined cells then visit the context set again through an additional column stage before being compressed into row embeddings. For inference efficiency, both row stages use cross-attention through a fixed number of summary tokens, keeping their attention cost linear in the number of features. Pretrained on approximately 36M synthetic tables, Causilo delivers strong benchmark results across TabArena, BeyondArena, and ScoringBench, achieving frontier-level performance with substantially faster inference.

## 1. 核心问题与整体含义

- **研究动机**：表格基础模型（TFM）已形成“预训练 + 上下文学习”的范式，但现有模型在**预测性能与推理效率**之间存在明显权衡。
- **背景矛盾**：
  - 一类模型保留单元格表示，在特征轴和样本轴上交替注意力，性能强，但注意力成本随特征数和样本数二次增长。
  - 另一类采用 TabICL 式“先列后行”架构：先做列编码，再把每行压缩成固定宽度行嵌入，再由 ICL Transformer 预测。该设计推理更快，但压缩后无法继续更新单个单元格表示。
- **核心问题**：能否在保留更丰富单元格表示的同时，维持行嵌入式上下文学习的高效率？
- **整体含义**：Causilo 试图回答这一问题，目标是在表格预测中同时达到前沿性能和极快推理，并位于 TabArena 等基准的**性能–效率帕累托前沿**。

## 2. 方法论

### 2.1 核心思想

- **Refine First, Compress Later**：在将单元格压缩为行嵌入之前，先进行额外精炼，让单元格在行内交互，并再次访问上下文集。
- 整体流程：  
  **列编码 → 行精炼 → 列精炼 → 行压缩 → 上下文预测**。
- 与 TabICL 相比，Causilo 在行压缩前加入“行精炼 + 第二次列阶段”，使每个单元格在融合行内特征信息后，仍能重新利用上下文样本信息。

### 2.2 关键技术细节

- **输入表示**：
  - 将相邻特征每 3 个分为一组，最后一组不足则零填充。
  - 标量值用 16 个学习频率的正弦/余弦特征编码，再经共享线性投影到 128 维。
  - 缺失值使用学习嵌入。
  - 组内 3 个单元格表示求和并缩放，形成一个 cell token；上下文行的每个 cell token 加入目标嵌入。
- **列编码**：
  - 使用 Set Transformer 的 inducing-token 注意力模式。
  - 每列中，固定数量诱导 token 先从上下文 cell token 中 gather 信息，再向上下文和查询行 broadcast。
  - 查询 cell token 不参与共享摘要生成。
- **行精炼**：
  - 对每一行，使用 K=4 个临时 summary token。
  - 交替执行：summary 向 cell token broadcast，更新后的 cell token 再 gather 回 summary。
  - summary 跨层携带行内信息，最终丢弃，保留精炼后的 cell token。
- **列精炼**：
  - 用独立参数再次执行“仅上下文 gather + 全行 broadcast”。
  - 此时 cell token 已含行内信息，因此跨行更新可结合跨特征证据。

  - 使用另一组 K=4 个学习 summary token。
