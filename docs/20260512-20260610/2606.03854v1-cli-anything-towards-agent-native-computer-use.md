## 摘要
随着大型语言模型在推理和工具使用能力上的进步，研究人员越来越多地寻求将其用于能够与现有软件交互的计算机使用智能体。当前主流方法是开发通过视觉界面控制应用程序的GUI智能体：解释屏幕截图、定位UI元素、执行鼠标点击以模拟人类交互。这种以GUI为中心的模式从根本上与智能体能力不匹配。目前的GUI智能体在面对脆弱的像素级交互、时序依赖以及因界面变化而失效的基于坐标的操作时表现不佳。它们迫使智能体模拟人类的感知限制，而不是利用其在结构化数据处理和程序化控制方面的计算优势。CLI-Anything主张智能体原生的计算机使用设计。我们不强迫智能体导航视觉布局，而是创建与智能体自然操作方式一致的接口：通过结构化命令、显式状态表示和确定性反馈。我们将现有应用程序转换为命令行工具，保留功能的同时暴露针对AI原生交互优化的机器可读协议。这消除了困扰GUI智能体的有损视觉到计算转换。与其构建复杂的屏幕阅读器和点击模拟器，我们应该围绕智能体的优势重新设计交互范式：精确的程序化控制和确定性执行。我们探讨了这种智能体原生计算机使用转换的方法论、架构、证据和未来方向。我们构建了CLI-Hub作为一个综合性平台，将这一智能体原生计算机使用愿景付诸实践。该平台为计算机使用的这一根本性转变提供了方法论、架构和基础设施。

## Abstract
As large language models advance in reasoning and tool use capabilities, researchers increasingly seek to leverage them for computer use agents that can interact with existing software. The dominant approach develops GUI agents that control applications through visual interfaces: interpreting screenshots, locating UI elements, and executing mouse clicks to mimic human interaction. This GUI-centric paradigm fundamentally misaligns with agent capabilities. Current GUI agents struggle with brittle pixel-level interactions, timing dependencies, and coordinate-based actions that break with interface changes. They force agents to emulate human perceptual limitations rather than leverage their computational strengths in structured data processing and programmatic control. CLI-Anything argues for agent-native computer use design. Instead of forcing agents to navigate visual layouts, we create interfaces aligned with how agents naturally operate: through structured commands, explicit state representations, and deterministic feedback. We transform existing applications into command-line harnesses that preserve functionality while exposing machine-readable protocols optimized for AI-native interaction. This eliminates the lossy visual-to-computational translation that plagues GUI agents. Rather than building sophisticated screen readers and click simulators, we should redesign interaction paradigms around agent strengths: precise programmatic control and deterministic execution. We examine the methodology, architecture, evidence, and future directions for this agent-native transformation of computer use. We have built CLI-Hub as a comprehensive platform that operationalizes this agent-native computer use vision. The platform provides methodology, architecture, and infrastructure for this fundamental transformation of computer use.

    - **认知错位**：强迫智能体模拟人类的感知局限（如视觉搜索），而未能发挥其在结构化数据处理和程序化控制方面的计算优势。

## 2. 论文提出的方法论：核心思想、关键技术细节

该方法论的核心是**工具提升方法（Harness Lift Methodology）**，旨在为现有专业软件打造一个智能体原生的控制界面。

- **核心思想**：
    - 智能体应该通过结构化命令、显式状态和确定性反馈来操作软件。
    - 利用软件已有的后端接口（如命令行接口、脚本API、内部数据模型），而非模仿人类操作。
    - 验证对称性：既然最终的工件（如图片、文档）可以被程序化验证，那么其创建过程也应能被程序化控制。

- **关键技术细节**：
    1.  **工具提升流程（Harness Lift Pipeline）**：一个系统化的7阶段流程：
        - **定位（Locate）**：进行接口考古，识别软件的后端引擎、API、命令系统、内部数据模型（如Blender的bpy API）。
        - **建模（Model）**：定义领域的核心名词（如场景、对象、材质）和操作（映射为命令）。
        - **设计（Design）**：设计双模CLI（同时支持交互式REPL和非交互式子命令），定义命令语法、JSON响应格式和可恢复的错误。
        - **实现（Implement）**：基于真实的软件后端实现状态管理、提交流程和撤销/重做功能。
        - **渲染（Render）**：调用真实的软件后端进行渲染和导出，确保输出工件的真实性（避免使用替代渲染器）。
        - **验证（Verify）**：进行单元测试和端到端（E2E）测试，验证真实输出的文件、像素、时长等。
        - **发布（Publish）**：生成机器可读的技能描述（SKILL.md），注册元数据到CLI-Hub平台。

    2.  **智能体最低软件契约**：一个形式化契约 `H = (S, C, I, R, V, D)`，定义了软件需为智能体提供的基本要素：
        - `S`：持久化状态空间（项目文件、会话文件等）。
        - `C`：命令词汇表（领域特定的操作和查询）。
        - `I`：检测表面（提供JSON状态、历史记录等廉价检查）。
        - `R`：渲染/导出关系（必须委托给真实软件后端）。
        - `V`：验证层（单元测试、E2E测试、格式检查等）。
        - `D`：发现层（技能描述、注册表元数据、安装路径）。

    3.  **预览协议（Preview as Display Protocol）**：一种不依赖于实时GUI流式传输的可视化反馈机制。
        - **预览包（Preview Bundle）**：一个包含 `manifest.json`、`summary.json` 和渲染后工件（如图片）的磁盘包。
        - **生产者/消费者分离**：软件工具在生产预览状态，CLI-Hub作为通用消费者读取和展示预览，保证了后端真实性。

    4.  **CLI-Hub平台**：一个集成的生态平台，负责：
        - **工具发现与分发**：提供注册表，让智能体或人类能找到、安装并调用各种命令行工具。
        - **技能管理**：生成并存储机器可读的技能描述，方便智能体理解工具用法。
        - **预览查看**：作为预览协议的消费者，提供统一的预览界面。

    - 实验主要关注“构建工具本身”的成功，而非“智能体用该工具完成任务”的成功率。例如，没有测试智能体使用Blender CLI完成一个复杂建模任务的最终效果和效率。
4.  **人类体验的缺失**：该范式完全牺牲了为人类设计的交互体验。虽然论文声明GUI将保留作为人类显示界面，但CLI对于非技术人员来说门槛太高。这强化了“AI优先”而非“人机协作”的倾向。
5.  **智能体的设计依赖**：该范式的成功假定智能体能够完美地解析结构化命令和JSON回包，并能规划复杂的命令序列。如果智能体自身能力不足，该范式同样会面临失败。
