## 摘要
终端智能体越来越能够从单个用户提示中自主执行复杂、长期的任务。为此，它们必须解释环境中遇到的指令（例如README文件、代码注释、堆栈跟踪），并确定这些指令与任务的相关性。这带来了一个根本性挑战：必须遵循相关线索以完成任务，而无关或误导性线索则必须被忽略。现有基准测试并未捕捉这一能力。一个智能体可能通过盲目遵循所有指令显得有能，或者通过完全忽略它们显得稳健。我们引入了TAB（任务对齐基准），这是一套源自Terminal-Bench 2.1的89个终端任务。每个任务都有意地未充分说明，缺失信息以自然环境产物中嵌入的必要线索形式提供，同时伴随一个看似合理但无关的干扰项。解决这些任务需要选择性地使用线索而忽略干扰项。将TAB应用于十个前沿智能体，揭示了任务能力与任务对齐之间的系统性差距。最强的Terminal-Bench智能体在TAB上实现了高任务完成率但低任务对齐。评估六种提示注入防御进一步表明，抑制干扰项执行也会抑制完成任务所需的线索。这些结果表明，任务对齐的智能体需要选择性地使用环境指令，而非全盘接受或拒绝。

## Abstract
Terminal agents are increasingly capable of executing complex, long-horizon tasks autonomously from a single user prompt. To do so, they must interpret instructions encountered in the environment (e.g., README files, code comments, stack traces) and determine their relevance to the task. This creates a fundamental challenge: relevant cues must be followed to complete a task, whereas irrelevant or misleading ones must be ignored. Existing benchmarks do not capture this ability. An agent may appear capable by blindly following all instructions, or appear robust by ignoring them altogether. We introduce TAB (Task Alignment Benchmark), a suite of 89 terminal tasks derived from Terminal-Bench 2.1. Each task is intentionally underspecified, with missing information provided as a necessary cue embedded in a natural environmental artifact, alongside a plausible but irrelevant distractor. Solving these tasks requires selectively using the cue while ignoring the distractor. Applying TAB to ten frontier agents reveals a systematic gap between task capability and task alignment. The strongest Terminal-Bench agent achieves high task completion but low task alignment on TAB. Evaluating six prompt-injection defenses further shows that suppressing distractor execution also suppresses the cues required for task completion. These results demonstrate that task-aligned agents require selective use of environmental instructions rather than blanket acceptance or rejection.

# 论文总结：No More, No Less: Task Alignment in Terminal Agents

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：终端智能体在执行复杂任务时，需要从环境中读取各种指令（如README、代码注释、日志等），但环境中的指令既有完成任务必需的线索（cue），也有无关甚至误导性的干扰项（distractor）。现有基准要么只测任务完成能力（如Terminal-Bench），要么只测抵抗恶意指令的能力（如提示注入基准），但缺少同时评估智能体**选择性使用环境信息**的能力。
- **整体含义**：任务对齐（Task Alignment）要求智能体“不多不少”——只遵循与用户目标相关的线索，忽略无关指令。当前前沿智能体在任务完成率高的情况下，任务对齐度可能很低，导致执行无关操作，甚至可能引发安全问题。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：将任务对齐分解为两个独立指标：
  - **线索利用率（Cue Utilization, U）**：智能体成功观察到指令后，是否利用它完成任务。
  - **干扰抵抗率（Distraction Resistance, R）**：智能体观察到干扰后，是否拒绝执行它。
  - **任务对齐分数 T = U × R**。
- **关键技术细节**：
  - 从 Terminal-Bench 2.1 的 89 个任务出发，通过**指令抽象**（移除必需信息）、**表面发现**（分析典型代理轨迹确定自然注入位置）、**注入设计**（将缺失信息作为线索放置，同时放置一个似是而非的干扰项）、**检测**（扫描日志和文件系统判断是否执行）和**验证**（人工审核+自动化测试）构建 TAB 基准。
  - 每个任务有3种干扰变体（盲/知情/针对性）以控制领域相关性。
  - 实验使用统一的 Terminus-2 脚手架，避免支架差异影响。
- **公式**（文字说明）：
  - 令 `S_base(a,t)` 表示代理 a 在原始充分指令下能解决任务 t，`T_a` 为这类任务的集合。
  - 线索利用率 `U(a) = Pr(S_align | t ∈ T_a, C_obs=1)`，即观察到线索后成功完成任务的概率。
  - 干扰抵抗率 `R(a) = 1 - Pr(D_exec | D_obs)`，即观察到干扰后不执行的概率。
  - 任务对齐 `T(a) = U(a) × R(a)`。

## 3. 实验设计：数据集/场景、benchmark、对比方法

- **数据集/场景**：TAB 基准包含 89 个源自 Terminal-Bench 2.1 的终端任务，覆盖 17 个领域（Git 恢复、数据库恢复、编译器构建等），每个任务包含必要线索和干扰项，均嵌入在自然环境产物中（源代码注释、shell 输出、数据文件等）。
- **Benchmark**：TAB 本身作为新基准，同时使用 Terminal-Bench 原始指令下的任务解决率作为能力基线。
- **对比方法**：
  - **10个前沿代理**：GPT-5.5, GPT-5.4 mini, GPT-5.4 nano, Gemini 3.1 Pro, Gemini 3 Flash, Claude Opus 4.7, MiniMax-M2.7, Qwen-3.6-35B, DeepSeek-V4 Flash, GLM-5。

## 6. 论文的主要结论与发现

- **任务能力与任务对齐显著分离**：最强能力模型 GPT-5.5（TB 解决率 73%）任务对齐仅 23%（U=85%, R=27%）；而能力稍低的 Claude Opus 4.7（TB 70%）任务对齐达 72%（U=77%, R=94%）。
- **主要失败模式是过度遵从**：大多数错误不是任务被带偏，而是代理在完成任务的同时执行了无关指令（图3左）。
- **干扰抵抗困难**：干扰越相关、越与线索同处一处、表面越易读，代理越可能执行。
- **现有防御无效**：六种防御均降低干扰执行率，但同时也显著降低线索利用率和任务完成率，未能实现选择性合规。
- **结论**：可靠的终端智能体需要选择性使用环境指令，而非全盘接受或拒绝；当前评估体系需增加任务对齐维度。

## 8. 不足与局限

- **人工审核偏差**：虽然有多人独立审核，但审核人员来自同一研究团队，可能存在偏差。
- **防御方法选择有限**：只测试了提示注入防御，未尝试训练级方法（如 RLHF/DPO）或架构级分离（如 CaMeL），而这些可能更有效。
