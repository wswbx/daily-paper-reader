## 摘要
尽管现代表格学习器在捕捉统计模式方面表现出色，但它们常常在语义真空中运行，将文本特征视为离散符号，忽略了特征名称或单元格条目中固有的丰富语义。我们提出了CASE（上下文感知语义嵌入），一种新颖的框架，弥合了大型语言模型（LLM）的语义理解与表格学习器统计能力之间的差距。与现有方法孤立地嵌入行不同，CASE采用了一种上下文化策略：我们使用具有代表性的行样本预先填充基于Gemma 3自定义训练的表格语言模型的KV缓存，以建立数据集语义的持久锚点。这确保了生成的行嵌入是动态上下文化的，解决了语义歧义，并将表示锚定在特定领域的上下文中。我们在多个基准测试（CARTE、TextTab和TabArena）上的实验表明，CASE在语义丰富的数据集上显著提高了表格学习器的性能，尤其是在低数据场景下。

## Abstract
While modern tabular learners excel at capturing statistical patterns, they frequently operate in a semantic vacuum, treating textual features as discrete symbols, ignoring the rich semantics inherent in feature names or cell entries. We propose CASE (Context-Aware Semantic Embeddings), a novel framework that bridges the gap between the semantic understanding of Large Language Models (LLMs) and the statistical capabilities of tabular learners. Unlike existing methods that embed rows in isolation, CASE utilizes a contextualization strategy: we pre-fill the KV cache of a custom-trained Gemma 3-based Tabular Language Model with a representative sample of rows to establish a persistent anchor of the dataset's semantics. This ensures that generated row embeddings are dynamically contextualized, resolving semantic ambiguities and anchoring representations in domain-specific context. Our experiments across several benchmarks (CARTE, TextTab, and TabArena) demonstrate that CASE substantially improves the performance of tabular learners on semantically rich datasets, particularly in low-data regimes.

## 2. 方法论

- **核心思想**：使用基于 Gemma 3 的表格语言模型（TLM）生成上下文感知的行嵌入，而非孤立嵌入；通过 KV 缓存预填充建立数据集语义锚点，再将嵌入压缩后注入任意下游表格学习器。
- **TLM 预训练**：
  - 模型：Gemma 3 decoder-only 系列（270M、1B、4B、12B 参数），非指令微调版本。
  - 序列化：表头 + 行序列，行内特征用 EOC 分隔，目标列用 BOT 标记，行尾用 EOR。
  - 训练目标：仅对目标 token 计算掩码负对数似然损失，迫使模型基于上下文预测目标。
  - 训练数据：T4 大型真实表格语料库，随机抽取表格、256 行、选一列作目标，训练 8500 步，batch size 128。
- **上下文感知嵌入提取**：
  - 从训练集随机采样代表性子集（默认 k=128 行，最大 32k tokens）作为上下文。
  - 将上下文序列化后传入 TLM，保留 KV 缓存作为永久前缀。
  - 对每个查询行，复用该 KV 缓存进行前向传播，提取最终 BOT 位置的隐藏状态作为行嵌入。
  - 采用 PCA 将嵌入降维（默认 d′ = 32），与原始特征拼接，供任意表格学习器使用。

## 6. 主要结论与发现

- CASE 在语义丰富基准上大幅提升表格学习器性能：分类提升 2.9%~6.8%，回归 R² 提升 3.8%~19.1%。

- 低数据场景优势显著：语义先验补偿统计信号不足，性能下降幅度小于传统预测器。
- 模型规模越大，嵌入质量越高；上下文从 0 到 1k tokens 有“上下文跳跃”，证明语义锚点的重要性。
- 对上下文随机选择、列顺序扰动表现稳健（统计上无显著差异）。
- 语义损坏测试确认性能增益来自真实语义推理，而非记忆或统计伪影。
- 在数值密集型 TabArena 上性能略有下降，但绝对差异较小，表明 CASE 应作为可选的语义增强模块。

## 7. 优点

- **创新性**：通过 KV 缓存预填充实现全局上下文感知的行嵌入，而非孤立嵌入，解决了语义歧义问题。
- **通用性**：模块化设计，可与任意下游表格学习器结合，且不要求修改原有模型。
- **高效性**：KV 缓存复用 + 单次前向传播 + PCA 降维，压缩了推理成本，且固定特征维度避免 TF-IDF 的特征膨胀。
- **严谨性**：大量消融和统计检验，主动分析数据污染、列顺序、随机采样等潜在问题。
- **实践价值**：开源推理代码，易复现；在低数据场景下实用价值高。

## 8. 不足与局限

- **排列不变性缺失**：CASE 对列/行顺序非排列不变，虽实验显示影响不显著，但架构上存在局限。
- **数值归纳偏置有限**：基于 token 的 LM 对连续数值的处理能力弱于专用表格模型。
- **随机上下文采样**：可能遗漏关键锚点行；尽管实验表明方差小，但仍非最优策略。
- **PCA 降维可能次优**：线性降维可能丢失非线性语义信息，未来可探索流形学习。
- **计算开销**：特征提取阶段仍依赖 12B 级 LLM，相比简单特征工程更重；且训练算力信息不透明。
- **领域适用范围**：在纯数值型数据（如 TabArena）上可能产生轻微负面效果，需要选择性使用。
- **数据污染风险**：虽经分析，但 Gemma 3 预训练数据专有，无法完全排除泄露可能。
