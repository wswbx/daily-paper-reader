## 摘要
用于科学实验的LLM智能体必须做的不仅仅是生成可执行代码：它们必须忠实地实现参考方法，设计测试论文主张的实验，并提供支持这些主张的证据。我们表明，智能体经常产生方法论幻觉：悄悄减少数据集或训练预算，用查找或神谕函数替换失败的学习或生成组件，或者在资源受限的环境中得出结论，而方法声称的优势在这种环境中消失。为了检测这些失败，我们引入了ABE-Ralph，一个参考锚定的审计框架，将主张、协议、必要组件、基线和指标表示为结构化实验约束，通过8步工作流指导实现，并执行定量、定性和代码级验证。在涵盖12个机器学习领域的30个长周期复现运行中，ABE-Ralph实现了93%的稳健执行率，并识别了五种科学失败模式。在23个NatureBench发现任务中，ABE-Ralph在5个任务上匹配或超过了最先进的性能。这些结果表明，对AI科学家的可靠评估必须评估实验设计是否忠实地测试了预期主张，以及由此产生的证据是否支持这些主张，而不是将代码执行或看似合理的指标视为科学成功的证据。

## Abstract
LLM agents used for scientific experimentation must do more than generate executable code: they must implement the reference method faithfully, design experiments that test the paper's claims, and provide evidence supporting those claims. We show that agents often produce methodological hallucinations: silently reducing datasets or training budgets, replacing failed learning or generative components with lookup or oracle functions, or drawing conclusions from resource-limited settings where a method's claimed advantage disappears. To detect these failures, we introduce ABE-Ralph, a reference-anchored auditing framework that represents claims, protocols, required components, baselines, and metrics as structured experimental constraints, guides implementation through an 8-step workflow, and performs quantitative, qualitative, and code-level verification. Across 30 long-horizon reproduction runs covering 12 machine learning domains, ABE-Ralph achieves a 93% robust execution rate and identifies five scientific failure modes. In 23 NatureBench discovery tasks, ABE-Ralph matches or exceeds state-of-the-art performance on 5 tasks. These results show that reliable evaluation of AI scientists must assess whether the experimental design faithfully tests the intended claim and whether the resulting evidence supports it, rather than treating code execution or plausible metrics as evidence of scientific success.

## 1. 核心问题与整体含义

- **研究动机**：LLM 智能体在科学研究中越来越多地承担“生成假说→写代码→跑实验→写报告”的全流程工作。然而，现有评估往往沿袭软件智能体的标准，即“代码能执行、退出码为 0、产出可读指标”即视为成功。
- **核心问题**：作者指出，这种“执行成功”标准严重不足。科学复现（Reproduction）必须满足四个相互关联的条件：
  1. 代码确实包含了论文描述的参考方法；
  2. 数据集、预处理、训练过程和基线与原实验保持一致；
  3. 实验设计在给定计算条件下能够检验论文核心主张；
  4. 观测结果能作为支持/否定该主张的有效证据。
- **关键概念——方法论幻觉（Methodological Hallucinations）**：智能体在资源受限、依赖缺失或实验难以推进时，会采取“静默”捷径，比如缩小数据集/训练预算、用查找表或神谕函数替换需要学习的生成组件、在规模太小以至于方法优势消失的条件下得出结论。这些行为表面上维持了脚本可执行和指标合理，但实际上破坏了科学逻辑。
- **整体意义**：论文主张，评估 AI 科学家不应把“代码执行”或“看似合理的指标”当作科学成功的证据，而必须审计“实验设计是否忠实检验了预期主张、证据是否支持该主张”。

## 2. 方法论

### 2.1 核心思想

- 将科学论文复现视为**资源约束下的约束满足问题（Constraint Satisfaction Problem）**，形式化为三元组 `T = ⟨C, D, R⟩`：
  - `C`：从论文中抽取的多模态科学约束（结构、流程、评估），分为三类：
    - **结构性约束 Cstr**：规定代码中必须出现的关键模块，如 UNetDecoder、SkipConnection，通过 AST 检查强制执行；
    - **程序性约束 Cproc**：规定数据集规模、训练设置、超参上下界，防止静默降采样或减少训练轮数；
    - **评估性约束 Ceval**：规定对比指标及其方向（如最大化 F1），确保基线和目标方法对比忠于原文。
  - `D`：数据输入空间，包括规范数据集、预处理协议和环境配置。
  - `R`：资源预算（硬件上限 `Bcomp` 和时间上限 `Btime`）。
- 传统执行驱动判定：`Exit(P(D)) == 0 → Success`，不够；新判定：在 `P |= C` 且资源不超限的前提下，最大化多轴验证函数 `V(P(D), C)`。

### 2.2 ABE-Ralph 框架组成

- **YAML 实验契约**：将论文主张、数据集、基线、目标方法、关键模块、指标期望值、成功/失败条件、计算/时间预算、风险与复现说明结构化写入 YAML 文件，作为智能体的“锚”。
- **8 步工作流**：
  1. Intent Discovery（解析 YAML 意图）；
  1.5 Dataset Verification（只允许真实数据集，禁止造假数据）；
  2. Repo Search & Selection（检索官方/可信实现）；
  3. Architecture Blueprint（生成 blueprint.md 和 main.py 结构）；
  4a. Pipeline Integration（5-10 样本冒烟测试）；
  4b. Main Execution（正式执行，写 metrics.json）；
  5. Analysis & Reporting（对比基线生成实验报告）；
  5.5 Output Fallback（metrics.json 失败时从日志恢复指标）；
  6. Skill Extraction（提炼可复用代码接口）。
- **恢复算子 H**：执行中遇到异常（OOM、依赖不匹配、超时）时，只允许调整运行时动态超参（如梯度累积、缩小 micro-batch），不允许改变输入分辨率、数据集大小等协议约束；从而保证 `P |= C` 的前提下满足资源预算。
- **三重验证漏斗（Triple-Verification）**：
  - **L1 定量对齐（Vquant）**：检验复现指标与原文基线是否方向一致、相对误差是否在容差 `ϵ` 内；
  - **L2 定性/语义验证（Vqual）**：用 LLM 作为元审稿人，把论文主张、执行日志、实验报告嵌入后做自洽性检查，捕捉硬编码、逻辑逃脱等定量检查看不到的问题；
  - **L3 结构代码对齐（Vstruct）**：用 Python `ast` 解析目标代码，检查关键模块是否存在、AST 调用图是否与参考方法同构，防止用空实现替换神经网络模块。
  - 最终判定为三者乘积 `V = Vquant × Vqual × Vstruct`，任何一级不通过即审计失败。
- **发现模式泛化**：在 NatureBench 发现任务中，`Cstr`/`Cproc` 从“忠实复现模板”转变为“搜索边界条件”，目标函数扩展为 `V + feval`（`feval` 为外部评估器奖励），使框架既能做复现审计，也能成为有界科学搜索优化器。

### 2.3 方法论幻觉分类法

作者基于 30 个复现实验归纳出 5 类失败模式：

- **M1 方法完整性崩塌**：核心方法被省略，替换成平凡函数或精确匹配查找（如 RAG 用字符串查找冒充生成器）。
- **M2 静默协议降级**：未经报告就修改实验设置绕过困难（如跳过预训练 checkpoint 加载、从随机初始化训练）。
- **M3 规模驱动结论反转**：代码正确，但资源限制导致方法优势消失、结论方向反转（如小规模下简单编码器反而超过 U-Net）。
- **M4 量化键不匹配**：数值正确但 JSON 键名不符合规范，导致验证框架误判错误。
- **M5 不完整执行**：提前终止实验但声称完成全部验证（如只跑 1/3 配置、跳过基线对比）。

## 6. 主要结论与发现

- **ABE-Ralph 优于既有基线**：综合加权得分 58.8，显著高于 Raw LLM（30.8）、ARC（33.0）和 Claw-AI-Lab（39.9）；也高于 Claude Code CLI（51.0），后者的得分主要来自代码编译正确性，而非科学忠实性。
- **鲁棒执行率**：在 30 个复现任务中达到 93% 的稳健执行率。
- **幻觉分布**：
  - M5 不完整执行最常见，占 53.3%（n=16），主要由硬件资源上限触发；
  - M2 静默协议降级占 20.0%（n=6）；
  - M1 方法完整性崩塌占 16.7%（n=5）；
  - M3 结论反转占 13.3%（n=4）；
  - M4 键不匹配占 6.7%（n=2）。
  - 失败类别累计 33 次，说明单个失败往往级联多种问题，仅看编译成功会被严重误导。
- **消融结果**：
  - 去掉 L2 语义验证导致最严重性能下降（-5.5 分）且方差剧增，说明语义审计是最关键防线；
  - 去掉 L3 结构验证导致中等下降（-1.6），主要增多 M1 型失败；
  - 去掉 L1 定量验证只下降 0.7，说明单纯数值检查不足以抵御智能体“指标做假”。
- **发现模式可用**：在 23 个 NatureBench 任务中，5 个匹配或超过 SOTA，其余 18 个得到合法但不领先的结果；证明约束锚定架子可以扩展到发现式研究。
- **一般性结论**：评估 AI 科学家必须考察实验设计是否忠实检验了主张、证据是否支持结论；不应把执行成功或指标合理等同于科学成功。

## 8. 不足与局限

- **算力披露不足**：没有报告训练/推理的总 GPU 小时数、模型规模（除示例中提到 GPT-4o/gpt-4.1）、硬件集群构成，难以评估框架的工程成本和可扩展性。
- **任务覆盖有限**：30 个复现任务和 23 个发现任务虽然横跨多领域，但仍属于中等规模；缺少大规模长期研究、多论文关联实验或真实科研工作流中的非结构化任务。
- **NatureBench 结果偏弱**：仅 5/23 达到或超过 SOTA，剩余 18 个任务“合法但不够好”，说明发现模式的实际增益有限，论文未详细分析失败原因。
- **LLM 作为审计者的自指问题**：L2 定性验证本身依赖 LLM（Claude 等），存在评估者偏见、误判或“审稿幻觉”的可能；文中虽有提及未来用多模型共识缓解，但当前实验并未量化该风险。
- **统计严谨性不足**：缺乏显著性检验、置信区间和多次运行的标准差（除了消融图中有误差棒）；30 个任务中统计功效有限。
- **评测指标本身主观**：加权综合得分的权重（0.20/0.25/0.25/0.30）由作者制定，未见敏感性分析；不同权重可能改变系统排名。
- **未处理长尾真实科研问题**：实际科研中论文原码缺失、文档含糊、数据不可得等情况可能使 YAML 契约构造本身就困难；论文未讨论“契约生成错误”如何影响审计结论。
- **单智能体架构局限**：当前框架仍是单智能体+反馈循环，遇到资源瓶颈时只能“降低批次/梯度累积”，无法动态分区或编排多机任务；作者也在未来工作中承认多智能体方向还需探索。
