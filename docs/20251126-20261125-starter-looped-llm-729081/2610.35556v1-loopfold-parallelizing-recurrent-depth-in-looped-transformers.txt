Abstract
Looped Transformers increase computation per token by repeatedly applying a shared
backbone, offering a way to improve language modeling and downstream task performance at a fixed
backbone parameter count. However, each loop depends on the preceding loop, so increasing recurrent
depth also increases decoding latency. Existing approaches include Parallel Loop Transformers, which
reduce latency by overlapping loop computation across token positions, but yield rapidly diminishing
marginal accuracy gains at larger depths. To address this challenge, we introduce LoopFold, which folds
computation at multiple recurrent depths into parallel batches for the same token prefix. A lightweight
predictor estimates inputs to later loops so they can start before earlier loops finish. A corrector then
refines the outputs of these later loops using newly available results from earlier loops. All components
are trained jointly using only the final next-token prediction loss. In experiments with 1.4B models,
deeper LoopFold configurations achieve progressively higher average zero-shot accuracy across eight
tasks, rising from 53.41% to 56.38%. Vanilla looped models and PLT show limited gains over the
same depth range. Compared with a nine-loop vanilla model, LoopFold uses five sequential stages and
additional parallel computation to reduce decoding latency by 46%.
1. Introduction
Looped Transformers increase computation per token by repeatedly applying a shared backbone
(Dehghani et al., 2019; Geiping et al., 2025a). This recurrent depth can improve language modeling
and downstream task performance at a fixed backbone parameter count (Saunshi et al., 2025).
However, each loop depends on the preceding loop’s output, so greater depth requires more sequential
backbone stages and increases the wall-clock time needed to generate each token.
Existing approaches reduce decoding latency by overlapping recurrent computation across token
positions. Parallel Loop Transformers (PLT) shift hidden states by one token between loops, allowing
different loop depths to run concurrently using states from neighboring tokens (Wu et al., 2025).
Adding loops initially improves accuracy, but the positional mismatch persists at every loop and
the marginal gains quickly diminish at larger depths (Yang et al., 2026). Recurrent-depth parallel
samplers refine several token drafts in parallel, but reducing the number of recurrent refinement steps
between draft updates trades accuracy for faster decoding (Geiping et al., 2025b). The challenge is to
start later loops before their inputs are available while still incorporating the results of earlier loops.
We introduce LoopFold to fold recurrent depth into parallel computation by batching hidden
states from different depths of the same token prefix. Specifically, a lightweight predictor estimates
the inputs to later loops, allowing them to start before the preceding loops finish. After each batched
evaluation, a corrector uses the newly available earlier-loop results to refine outputs computed from

and higher mean zero-shot accuracy than vanilla looped models. LoopFold thus improves the use
of recurrent computation in two complementary ways: it can yield better quality at a fixed total
backbone budget, and it can exploit available parallelism to perform additional recurrent computation
without proportionally increasing decoding latency.
2. Related Work
Scaling latent computation. Recurrent-depth language models increase computation by repeatedly
applying a shared transition, as in Universal Transformers (Dehghani et al., 2019). Such looping can
approach the accuracy of deeper models with untied layers on arithmetic and question-answering
tasks (Saunshi et al., 2025). PonderLM changes the input passed between loops, feeding a probability-
weighted average of token embeddings into the next loop (Zeng et al., 2026). Geiping et al. (2025a)
sample recurrent depths during training to support variable test-time computation. Ouro instead
learns an input-dependent exit gate for adaptive recurrent depth (Zhu et al., 2025). Hidden Decoding
takes a different route, expanding each token into multiple embedding streams that the backbone
processes together, while retaining their intermediate KV states as context (Liu et al., 2026).
Parallel recurrent computation. To shorten the sequential path between loops, PLT and recurrent-
depth parallel samplers overlap computation across token positions. PLT pipelines loop depths using
states shifted across token positions (Wu et al., 2025). Recurrent-depth parallel samplers accelerate
decoding from pretrained checkpoints by refining several token drafts concurrently, relying on per-loop
input injection and decodable intermediate states (Geiping et al., 2025b). LoopFold uses predicted
inputs and output correction to run several backbone loops in parallel for the same token prefix.
Parallel correction methods. Classical Parareal uses a fine propagator for accurate parallel local
solves and a cheaper coarse propagator for sequential correction, iterating toward the fine propagator’s
sequential solution (Lions et al., 2001). Neural variants replace or parameterize the coarse component
with learned networks (Lee et al., 2021). Related methods parallelize network evaluation through
fixed-point or Newton iterations (Song et al., 2021; Lim et al., 2024), with SNLP using structured
Jacobian approximations for Transformer layers (Han et al., 2026). LoopFold adapts parallel evaluation
and correction to a shared recurrent backbone. Its predictor initializes later-loop inputs once, allowing
several loops to run together, while its corrector incorporates newly available earlier-loop states
into the parallel outputs. Unlike classical Parareal, which iteratively seeks to recover the sequential
fine solution, LoopFold learns a fixed-stage parallel computation optimized directly for next-token
prediction. Its objective is therefore not to match the sequential recurrent trajectory, but to produce
predictive states under a constrained number of sequential stages.

4. Experiments
We evaluate LoopFold under three complementary comparison regimes. Matched-training-compute
comparisons test whether LoopFold can improve model quality at the same total backbone budget.
Comparable-latency comparisons test whether additional backbone evaluations can be shifted onto
the parallel dimension to improve quality without increasing the number of sequential stages. Finally,
matched-target-depth comparisons characterize quality when LoopFold reaches the same target
depth index with fewer sequential stages. Because these regimes hold different quantities fixed, we
report them separately rather than interpreting them interchangeably.
4.1. Experimental Setup
Models and training. We train 1.4B models from scratch on the Pile (Gao et al., 2020) using a
LLaMA-style backbone (Touvron et al., 2023), a global batch size of 256, and a common 30B-token
budget. Each schedule is trained separately with the same tokenizer, data order, and training recipe.
The learning rate warms up to 2×10−4 over the first 1% of steps, then follows cosine decay to 2×10−5.
The ablations use 410M models trained on 25B tokens.
Baselines. A vanilla looped model applies the shared backbone sequentially 𝐷times. Our PLT-𝐷
baselines use cross-loop pipelining without KV sharing (Wu et al., 2025). Hidden Decoding uses 5,
7, or 9 embedding streams per token (Liu et al., 2026). We omit recurrent-depth parallel samplers
because they require per-loop input injection that our backbone does not use (Geiping et al., 2025b).
Quality metrics. We report Pile validation perplexity (PPL) and zero-shot accuracy on LAMBADA-
OpenAI (LAMBADA-OAI) (Paperno et al., 2016; Radford et al., 2019), ARC-Easy and ARC-Challenge
(Clark et al., 2018), WinoGrande (Sakaguchi et al., 2020), PIQA (Bisk et al., 2020), HellaSwag (Zellers
et al., 2019), SciQ (Welbl et al., 2017), and RACE (Lai et al., 2017).
Training computation. We report total training backbone computation in ZFLOPs. For the 1.4B
models, one backbone evaluation per original token corresponds to 0.24 ZFLOPs over the training
run. The evaluation count per token is 1 + 𝑛(𝑆−1) for LoopFold, 𝐷for vanilla looped models and
PLT, and the stream count for Hidden Decoding. This counts computation across all sequential stages,
parallel lanes, and expanded token representations; the learned-map cost is given in Section 3.3.
Decoding latency. We measure wall-clock milliseconds per generated token with a 1,024-token
prompt and a 1,024-token greedy continuation. The main comparisons use a decoding batch size of
1. Section 4.5 reports aggregate throughput for batches up to 16. All decoding benchmarks run on
the same GPU in BF16 with tensor parallelism disabled, and timings cover the complete decoding
schedule.
4.2. Parallel Width at Fixed Stage Count
Parallel width controls how many recurrent states the backbone evaluates in each batched evaluation.
Figure 2 varies width while holding the number of sequential stages fixed at 𝑆= 3, 4, 5, testing
whether additional parallel computation improves PPL within the same sequential-stage budget.
Increasing parallel width at a fixed stage count consistently improves PPL, showing that additional
recurrent computation can improve model quality without extending the sequential path. However,
the gain per added parallel lane decreases as width grows, indicating progressively lower returns
from additional parallel computation.

4.3. Quality versus Training Compute and Decoding Latency
At matched training backbone compute, we fix LoopFold’s width at 2 and increase its stage count to
compare models across the same training budgets (Figure 3a and Table 2). The vanilla looped model
leads at 1.20 ZFLOPs, whereas LoopFold achieves lower PPL and higher mean zero-shot accuracy at
1.68 and 2.16 ZFLOPs. Thus, the parallel schedule can improve prediction quality within the same
training backbone budget while using fewer sequential stages. LoopFold also exceeds PLT and Hidden
Decoding in mean accuracy across all three budgets.
At comparable decoding latency, LoopFold at target depth indices 𝐷= 5, 7, 9 is compared with
vanilla looped models using 3, 4, and 5 loops, respectively (Figure 3b and Table 3). Each pair uses the
same number of sequential stages, allowing LoopFold to perform additional recurrent computation in
parallel within a similar time per token. This yields lower PPL and higher mean accuracy in all three
pairs, with gains on all eight tasks for the two deeper schedules. PLT and Hidden Decoding decode
faster but attain lower mean accuracy.

5. Conclusion
We introduced LoopFold to fold recurrent computation into parallel stages using a jointly trained
backbone, predictor, and corrector. Experiments show that this design can improve language modeling
and zero-shot downstream performance with fewer sequential backbone stages, while the component
analyses highlight the importance of correction. These results suggest that recurrent depth and
sequential decoding depth need not coincide: additional recurrent computation can be shifted onto
the parallel dimension when provisional states are subsequently corrected.
LoopFold reduces sequential depth at the cost of additional backbone computation and thus higher
FLOPs. It also increases KV-cache requirements; although KV sharing mitigates this overhead, our
experiments show a modest trade-off in quality and/or latency. Reducing these computational and
memory costs while preserving the benefits of parallel recurrent evaluation remains an important
direction for future work.
