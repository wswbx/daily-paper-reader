## 摘要
循环 Transformer 通过迭代共享层块来增加计算量而不增加参数，从而提供更强的性能和测试时扩展能力。然而，迄今为止，这种能力需要从头训练，并且对 LLM 仅带来有限增益。将现有模型微调为循环结构成本低得多，但相比 SFT 也仅带来边际增益。我们提出 LoopRes，一种有效、可扩展且简单的方法，将循环转化为预训练 LLM 显著且一致的增益。基于 Attention Residuals，LoopRes 让每个循环层直接关注先前循环的输出。由于这些输出是相同层的迭代结果且越来越难以区分，我们为每个输出赋予一个可训练的、循环感知的键，以编码其结构身份。关注所有先前循环也会让层跳过中间循环，因此我们将每层限制在最新 W 个循环的残差窗口内，迫使每个循环在最近循环的基础上增量构建。在来自 3 个模型家族的 6 个预训练 LLM 和 9 个基准上，LoopRes 带来显著且一致的增益：在 2 倍计算量下，它将 Qwen3-1.7B-Base 相比 SFT 提升 29.1%，超过最先进基线增益的两倍。这些增益在最大至 30B 的更大模型以及所有三个模型家族上均保持。更重要的是，从 1.7B 到 8B，随着计算量增长，LoopRes 的扩展比 SFT 更陡峭，达到更高上限，同时在长输出上需要更少计算。这些结果确立了 LoopRes 作为一种有效的循环方法，同时带来更好的性能和更好的测试时扩展能力。

## Abstract
Looped Transformers iterate a shared block of layers to increase computation without adding parameters, offering stronger performance and test-time scaling. However, this power has so far required training from scratch and yielded only modest gains for LLMs. Finetuning existing models into loops is far cheaper, yet also brings only marginal gains over SFT. We propose LoopRes, an effective, scalable, and simple approach that turns loops into significant and consistent gains for pretrained LLMs. Building on Attention Residuals, LoopRes lets each looped layer attend directly to the outputs of earlier loops. Since these outputs are iterates of the same layers and become harder to tell apart, we give each a trainable loop-aware key that encodes its structural identity. Attending to all earlier loops also lets layers skip intermediate ones, so we restrict each layer to a residual window of the latest W loops, forcing every loop to build incrementally on recent ones. Across 6 pretrained LLMs from 3 model families and 9 benchmarks, LoopRes delivers significant and consistent gains: at 2x compute, it improves Qwen3-1.7B-Base by 29.1% over SFT, more than doubling the gain of the state-of-the-art baseline. The gains hold on larger models up to 30B and across all three families. More importantly, from 1.7B to 8B, LoopRes scales more steeply than SFT as compute grows, reaching a higher ceiling while needing less compute on long outputs. These results establish LoopRes as an effective looping approach, delivering both better performance and better test-time scaling.

# LoopRes 论文结构化总结

## 1. 核心问题与研究动机

- **背景**：Looped Transformer 通过在一次前向中反复执行共享层块来增加“深度计算”，不增加参数，理论上可同时提升性能与测试时扩展（test-time scaling）。
- **现状矛盾**：
  - 从零预训练循环模型代价高昂，且在同计算量下收益有限甚至为负。
  - 把已有预训练 LLM 微调成循环结构便宜得多，但相比普通 SFT 仅带来边际增益。
- **根因诊断**：现有循环设计（layer loop、stack loop、输入注入、跨循环聚合等）都把前若干次循环的输出**压缩进一条狭窄通路**（单状态或少数状态），后续循环无法直接利用早期循环的丰富信息。
- **自然的补救**：Attention Residuals（AttnRes）让每层直接关注所有先前层输出。但 AttnRes 是为标准 Transformer 设计的，默认“源内容彼此不同、数量固定”，而循环打破这两个假设，导致三个问题：
  - **迭代相似**：同一层不同循环的输出高度相似（余弦相似度高），内容键难以区分。
  - **早期收敛**：查询范数在微调前 1/3 就接近终值，连接模式被过早锁定。
  - **源不断增长**：层可直接“跳读”到早期循环，跳过中间循环；三循环时全路径权重 33.7%，七循环时降到 0.05%，深层循环形同虚设。
- **整体含义**：论文主张把“循环深度”变成 LLM 的一条低成本扩展轴——用微调而非预训练兑现循环的潜力。

## 2. 方法论：LoopRes

### 2.1 基础架构
- 采用 Huginn 式循环架构：把 LLM 层切成 **prelude / core / coda**（约 1/4、1/2、1/4）。prelude 与 coda 各跑一次，core 跑 L 次（每次称为一个 loop），coda 在最后一次循环输出上预测下一 token，用交叉熵微调。
- 计算量以“每 token 经过的层数相对骨干”衡量：core 跑 L=3、L=7 分别对应 2×、4× 计算量。
- 仅对 **core** 应用 AttnRes：core 内层分为 B=2 个 block，记第 t 次循环第 i 个 block 输出为 b_i^(t)，块内部分和为 u_i^(t)。

### 2.2 AttnRes 的基本形式
- 每个子层不再读固定残差流，而是对源集合 S 做 softmax 加权：
  - x = Σ_{s∈S} α_s v_s，α_s = exp(qᵀk_s) / Σ_{s'} exp(qᵀk_{s'})，其中 k_s = RMSNorm(v_s) 为**内容键**，q 为子层可学习查询（初始化为 0）。
- 循环模型的源集合为：S_i^(t) = { prelude 输出 p，先前所有循环的 block 输出，当前循环已完成的 block 输出，当前 block 的部分和 u_i^(t) }。

### 2.3 LoopRes 的两处关键改动
- **循环感知键（loop-aware key）**：
  - 每个源额外配一个可训练向量 k^loop_s（每个 block、每个 loop 一个，初始化为 N(0, I)），编码“第几层、第几次循环”的结构身份。
  - 打分改为 α_s = softmax( q^loopᵀ k^loop_s + qᵀ k_s )，两个查询均初始化为 0，使训练起点为均匀权重。
  - 作用：(i) 用坐标区分同层的不同迭代；(ii) 该键被直接优化，不必只靠隐状态间接学习连接模式，从而绕开“早期收敛”。
- **残差窗口（residual window）**：
  - 每层只关注最近 W 个循环（默认 W=1）的源，源数量上界为 (W+1)B+1。
  - 作用：(i) 禁止跳读、强制逐循环增量构建；(ii) 防止 softmax 随源增多而稀释当前循环权重；(iii) 计算/显存/通信开销不随循环深度增长。
- **工程效率**：按 FlashAttention 思路把“加载查询键 + 加权求和”融进单个 Triton kernel，每个源只从 HBM 读一次、只写回结果，显著降低 IO 与峰值显存。

## 3. 实验设计

- **骨干模型（6 个、3 个家族）**：Qwen3-1.7B / 4B / 8B / 30B-A3B-Base、Qwen3.5-2B-Base、Llama-3.2-1B（默认 Qwen3-1.7B-Base）。

  - <4B：MATH500、OlympiadBench、AMC23、AIME25、AIME26（数学）+ HumanEval+、MBPP+（代码）。

  - 另报告 1,493 条留出对话上的验证损失。

  - 中间半层循环（与 LoopRes 同分割）：Huginn、Hyperloop、WMRE。
  - 全部在同一骨干、同一数据、同一超参下**自行重实现**，按各自原目标训练。

- **评测配置**：thinking 模式，temperature 0.6、top-p 0.95、top-k 20，最多 32K 新 token，每基准约 1,000 样本，报告 pass@1。

## 6. 主要结论与发现

- **主结果（Qwen3-1.7B-Base，7 基准平均）**：
  - SFT 43.2；2× 计算下 LoopRes 55.8（**+29.1%**，最好基线 BRT 49.2 / +13.9%）；4× 下 57.8（**+33.7%**，最好基线 Huginn 51.8 / +19.8%）。
  - 在每个基准、两个预算上均取得最佳；越难的基准（AIME 类）相对增益越大。
  - 验证损失相对 SFT 降低 6.3%（2×）与 6.8%（4×）。
- **循环越深收益越大**：多数基线加深后停滞甚至回退，LoopRes 从已较高的分数继续上升，L=5 后趋于饱和，L=3 是性价比最佳点。
- **可扩展性与泛化**：4B +9.2、8B +8.6、30B-A3B +5.5、Llama-3.2-1B +5.4、Qwen3.5-2B +12.0（均为 2× 计算）；**4B 的 LoopRes 平均分超过 8B 的 SFT**，说明循环可弥合规模差距。
- **测试时扩展更优**：随 decode FLOPs 增长，LoopRes 曲线斜率更陡、上限更高，且在长输出上以更少算力达到 SFT 同等分数。
- **机制发现**：
  - 学到“迭代式更新”：第一块主要更新自己上一轮输出，第二块主要依赖当前循环的第一块。
  - **loop-aware key 主导源选择**（约 76%~87% 的 Shapley 份额），内容键份额较小。
  - 内容键提供**逐 token 自适应深度**：功能词（"But"、"Wait"）偏向浅层输出，数字与数学符号偏向深层输出。
  - 相比 AttnRes：相邻循环可区分度显著提升、权重集中于最近循环、内容分数中“随 token 变化”的比例从约 2%~7% 升到约 22%~25%。

## 7. 局限性与可讨论之处

- **场景边界较窄**：全部实验都在“已有 LLM + SFT 微调”的设定下完成，未涉及从零预训练循环模型。论文的核心主张是“循环深度可作为低成本扩展轴”，但这一主张目前只在数学/代码 SFT 数据上被验证；能否在预训练阶段、通用语料、长上下文或 agentic 任务上复现同样的增益，仍是开放问题。
- **能力评估偏科**：9 个基准集中在数学竞赛与代码生成，缺少通用知识（MMLU 类）、指令跟随、多语言、长文理解、工具调用等维度。论文用验证损失作为补充，但验证集同样来自同分布 SFT 数据，难以排除“收益主要来自领域内模式”的可能。
- **深度收益饱和**：L=5 之后增益趋平，L=3 为性价比最优点。这意味着“循环深度”并非无限可扩展的轴，其上限可能受 core 层容量与 W=1 窗口的信息带宽限制；论文未进一步分析饱和是数据、容量还是窗口约束所致。
- **默认配置偏保守**：主实验统一用 W=1，消融虽覆盖不同 W，但未系统探索“W 随循环深度增长”或“分层设置 W”的策略，残差窗口的容量-开销权衡可能未被充分挖掘。
- **改动范围有限**：AttnRes 只施加于 core，prelude/coda 仍用标准残差；全层 AttnRes 变体仅作为附录实验出现，未与主配置在同等规模下正面对比。
- **大模型证据较弱**：4B 及以上只跑 2× 计算，且 30B-A3B 的增益（+5.5）明显小于 1.7B（+29.1）与 4B（+9.2）。这既可能是大模型本身能力更强导致天花板效应，也可能是 MoE 架构与循环结构的交互问题，论文未给出解释性分析。
- **机制分析为半定量**：Shapley 份额、逐 token 深度偏好等结论基于 128 个样本的可视化与统计，缺少跨骨干、跨数据集的稳定性检验；"功能词偏浅、数学符号偏深"这一观察目前更像有趣的定性现象，而非可操作的设计原则。
- **缺少与推理时方法的对照**：论文强调"测试时扩展更优"，但比较对象是自身的 SFT 基线随 decode FLOPs 的曲线，未与 self-consistency、best-of-n、多轮自我修正、显式 CoT 加长等主流推理时扩展手段在同算力下对比。循环带来的"隐式深度"与"显式长思维链"是互补还是替代，尚无答案。
- **工程门槛未充分披露**：融合 Triton kernel 是可行性的关键（去掉后耗时 +54.9%、显存 +47.5%），但论文未给出 kernel 实现细节、在不同 GPU 架构上的可移植性，以及反向传播（尤其梯度检查点）下的开销表现，复现门槛可能高于表面描述。
- **部署与生态影响未讨论**：循环推理改变了每 token 的实际计算量，对延迟、吞吐、批处理效率、KV cache 管理的影响，以及与现有推理框架（vLLM、SGLang 等）的兼容性均未涉及；作为"扩展轴"的实用价值最终取决于这些工程因素。
- **基线的"重实现折扣"**：如第 5 节所述，多个基线为适配微调场景做了简化改动。虽然统一重实现提升了内部公平性，但也意味着结论更应表述为"在这一微调协议下 LoopRes 优于这些适配版本"，而非对原方法的全面否定。

## 8. 方法与实验设计上的可借鉴点

- **把结构先验显式参数化**：loop-aware key 把"这是第几层、第几次循环"从隐状态中剥离为独立可训练向量，既解决了迭代间内容不可分的问题，又绕开了查询过早收敛。这一"结构身份与内容身份解耦"的思路可迁移到其他源集合动态增长的场景（如多轮对话记忆、递归工具调用、长程检索增强）。
- **用窗口约束信息通路而非靠正则**：残差窗口通过硬性限制可见源，同时实现三重目的——强制增量构建、防止 softmax 稀释、保持开销恒定。相比加惩罚项或 dropout，这种"结构性约束"更可靠且易于推理。
- **先诊断、再设计**：论文先用余弦相似度、查询范数演化、全路径权重占比三组测量定位 AttnRes 失效的具体机制，再针对性地提出两项改动。这种"机制诊断 → 定向修补 → 消融验证"的闭环，比直接堆叠模块更有说服力。
- **同算力对齐的评测协议**：以"每 token 经过的层数"为统一尺度，为全层循环与半层循环分别设定 L，使不同架构在相同计算预算下可比。这一做法值得在其他"计算量可变"的架构比较中推广。
- **自实现基线 + 数据翻倍对照**：统一骨干、数据、超参重实现 8 个基线，并额外做"SFT 数据翻倍"实验排除"多训练即多得"的解释，是提升经验性论文可信度的有效手段。
- **把 IO 优化作为一等公民**：将查询键加载与加权求和融合进单个 kernel，使每源只读写一次 HBM，把理论上的额外开销压到 +4.8% 时间、+0.7% 显存。这说明注意力式残差从"论文技巧"走向"可用方法"的关键往往在系统层而非算法层。

## 9. 总体评价

- **贡献定位**：论文的核心贡献不是提出全新的循环架构，而是识别出"把 AttnRes 直接搬到循环模型上会失效"这一具体而关键的问题，并给出两处轻量、可解释、开销可忽略的修补。它把"循环深度"从一种需要昂贵预训练才能兑现的潜力，转化为一条可在微调阶段低成本启用的扩展轴，具有明确的实用导向。
- **证据强度**：在 1.7B 骨干上，方法覆盖 9 种基线 × 2 个预算 × 7 个基准，且在每一格均取得最佳，配合深度扫描、跨骨干、跨家族、消融与机制分析，证据链较为完整；同算力对齐与自实现基线进一步增强了内部效度。相对薄弱处在于大模型仅覆盖 2× 预算、任务域集中于数学与代码、机制结论基于小样本。
- **可信度评估**：方法改动小、消融清晰、开销数据透明，复现的相对成本明确；主要不确定性来自绝对算力预算缺失、基线适配改动可能带来的折扣，以及融合 kernel 的实现门槛。
- **适用边界**：最适合"已有强骨干、希望在固定参数下用额外计算换取推理能力提升、且任务有可验证答案（数学/代码）"的场景；对通用对话、长上下文、需要低延迟的在线服务，收益与成本尚待验证。
- **一句话总结**：LoopRes 用"循环感知键 + 残差窗口"两处小改动，修好了 AttnRes 在循环模型上的三处水土不服，使微调阶段的循环深度成为一种即插即用、开销近乎为零的能力扩展手段，但其普适性与部署价值仍需更广的任务域和更大的计算预算来检验。
