## 摘要
循环语言模型可以通过共享权重的重复计算来增强推理能力，在不增加独立参数的情况下提高执行深度。然而，每一次额外的传递都会增加训练浮点运算量（FLOPs），使得这些收益的获取成本更高。为应对这一成本，我们提出 UpLoop，一种利用升级复用（upcycling）来训练循环 Transformer 的预训练方案，同时在最终参数数量、总训练 token 数和训练 FLOPs 上与标准稠密基线完全一致。具体而言，UpLoop 从浅层 Transformer 开始，通过复制已学习的层逐步增加深度，并利用早期节省的计算来支持训练后期对共享中间块的重复执行。跨模型规模的实验显示，语言建模和下游性能均有提升；在 1.3B 参数规模下，22 个下游任务的平均得分从 22.99 提高到 27.52。这些提升在监督微调后也延伸到了数学推理任务上。

## Abstract
Looped language models can strengthen reasoning through repeated computation with shared weights, increasing execution depth without adding independent parameters. However, each additional pass increases training floating-point operations (FLOPs), making these gains more expensive to obtain. To address this cost, we propose UpLoop, a pretraining schedule that uses upcycling to train looped Transformers while exactly matching a standard dense baseline in final parameter count, total training tokens, and training FLOPs. Specifically, UpLoop begins with a shallow Transformer, progressively grows its depth by copying learned layers, and uses the computation saved early to support repeated execution of a shared middle block later in training. Experiments across model scales show improvements in language modeling and downstream performance, with the average score across 22 downstream tasks increasing from 22.99 to 27.52 at 1.3B parameters. These gains also extend to mathematical reasoning after supervised fine-tuning.

## 1. 核心问题与研究动机

- **背景**：循环语言模型（Looped LM）通过共享权重的重复执行来增加"执行深度"，在不增加独立参数的前提下增强推理能力（如 Universal Transformer 一脉的工作）。
- **核心矛盾**：循环带来收益的代价是**训练 FLOPs 上升**——每多一次前向传递就多一份计算，因此在相同 token 预算下，循环模型比同规模稠密模型更贵。
- **核心问题**：能否在**最终参数量、总训练 token 数、总训练 FLOPs 三者都与标准稠密基线完全对齐**的条件下，训练出一个性能更优的循环语言模型？
- **整体含义**：论文将"计算预算的跨阶段再分配"作为答案，主张循环模型的额外计算可以由早期浅层训练节省的算力来"支付"，从而把循环收益变成零额外预训练成本。

## 2. 方法论（UpLoop）

### 核心思想
采用**四阶段预训练调度**，把"渐进式深度增长（upcycling/层复制）"与"中间块共享权重循环"结合：早期用浅层模型省算力，后期用省下的算力做重复执行。

### 关键技术细节
- **执行深度调度**：`L/4 → L/2 → L → L + (r−1)m`，其中 L 为稠密基线深度，m 为共享中间块深度，r 为重复次数。
- **渐进深度增长**：
  - 第一次增长：将 L/4 层**整体堆叠两次**得到 L/2 层，复制时同时继承**层权重与 Adam 优化器状态**，之后各层独立优化。
  - 第二次增长：把 L/2 层分为头/中/尾三块（深度 L/8, L/4, L/8），将中间块复制 3 份，得到 `(Θ_H, Θ_B^[1], Θ_B^[2], Θ_B^[3], Θ_T)`，同样复制权重与 Adam 状态。
- **中间块循环**：在全深度阶段之后，选取 m 个连续中间层作为共享块 B_φ，其余为头 F_H 与尾 F_T，前向变为 `h_out = F_T(B_φ^r(F_H(h_in)))`；头尾各执行一次，共享块执行 r 次。该转换**不改变参数量与优化器状态**，仅提升执行深度。
- **算力匹配公式**：训练 FLOPs 对深度仿射，即 `f(d) = κd + β`；在 `ΣD_j = D0` 约束下，等 FLOPs 要求
  `3L/4·D1 + L/2·D2 = (r−1)m·D4`
  即**浅层阶段节省的算力恰好抵消后期循环开销**。实验取 L=16, m=4, r=2，得 `12D1 + 8D2 = 4D4`。
- **调度细节**：三个转换点分别在约 **9.7%、23.0%、44.3%** 的累计 token 处；数据流连续，学习率按累计 token 走余弦衰减，**阶段切换不重启 LR**；各规模阶段更新步数均为整数且精确满足预算等式。

## 3. 实验设计

## 6. 主要结论与发现

- **语言建模**：三个规模 NLL 均下降（370M 2.777→2.743；760M 2.577→2.538；1.3B 2.433→2.398），在严格等预算下稳定优于 Vanilla。
- **零样本常识**：平均准确率 48.43→49.78（370M）、51.96→53.52（760M）、54.91→56.47（1.3B）。
- **22 任务综合**：平均分 18.95→20.90、21.38→24.82、22.99→27.52（1.3B）；推理原语提升最大（1.3B 上 VarAssign-math 58.10→91.10，VarAssign-code 66.60→91.20），数学应用题平均 5.35→7.55。
- **微调后数学推理**：GSM8K 精确匹配 8.72→12.05（zero-shot）、5.46→8.11（5-shot）。
- **与替代策略对比**：同等 NLL 下 UpLoop 所需 FLOPs 与 token 最少；Loop from scratch 需 1.20× FLOPs、Dense-20 (Iso-Tokens) 需 1.20× FLOPs 且参数更多（438M vs 371M），LIDAS 需 1.20× token。
- **机理发现**：
  - 共享层两次调用的梯度余弦相似度更高（0.586 vs 0.510/0.374）；
  - 状态扰动传播更稳定（2 次调用后距离比 0.867 vs 0.933/0.923；8 次调用时放大最少）；
  - 复制层既保留共同计算基底（同源层替换代价低：0.0288/0.0545）又发展出差异（权重余弦 0.383）；
  - 第二遍读取对答案形成至关重要（阻断目标信息读取导致 760M/1.3B 分别下降 8.6/14.5 个百分点，而第一遍阻断为 0）。

## 7. 优点

- **问题定位清晰、约束严格**：把"零额外预训练成本"形式化为参数/token/FLOPs 三重等式约束，并给出可解析核算的预算公式，实验与主张高度一致。
- **方法简洁可落地**：仅用层复制 + 中间块共享，不引入额外参数或复杂模块；复制时继承 Adam 状态、阶段切换不重启 LR 等工程细节考虑周到。

## 8. 不足与局限

- **推理成本未对齐**：UpLoop 训练成本与稠密基线相同，但**推理 FLOPs/token 约为 1.20–1.22×**（表 A3），部署成本更高，论文未讨论推理侧代价与收益权衡。

- **统计稳健性不足**：主实验单种子，缺少方差/置信区间；GSM8K 微调亦仅单种子。
- **微调算力未匹配**：SFT 阶段明确"算力不匹配"，因此微调后的增益不能完全归因于等预算优势。
