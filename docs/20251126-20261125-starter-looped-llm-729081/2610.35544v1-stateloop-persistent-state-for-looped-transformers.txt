Abstract Looped Transformers offer a parameter-efficient approach to language modeling by repeatedly
applying a shared backbone. Vanilla looped Transformers use each backbone output directly as the input
to the next iteration. These outputs may contain information useful several iterations later, but retaining
it across the loop depends entirely on the single hidden state. We introduce StateLoop, which maintains
one additional persistent state per token to retain information across iterations. At each iteration, a
learned gate controls how much of the previous state is retained and how much information from the
backbone output is incorporated. The updated state is projected back and added to the backbone output
for subsequent iterations and final prediction. This design reduces Pile perplexity and improves average
accuracy across eight zero-shot tasks over Vanilla Looped. Its perplexity advantage over Vanilla Looped
grows with trained loop depth, consistent with persistent state becoming increasingly useful as recurrent
computation deepens.
1. Introduction
Looped Transformers increase computation by repeatedly applying a shared backbone (Dehghani et al.,
2019). Saunshi et al. (2025) show that looped models improve language modeling over non-looped
models with the same number of parameters. Ouro demonstrates this approach at larger scale, with
1.4B and 2.6B looped models achieving performance comparable to larger standard Transformers
across downstream benchmarks (Zhu et al., 2025).
The design of connections between iterations is a central architectural consideration in looped
Transformers. Vanilla looped Transformers use each backbone output directly as the input to the
next iteration. As Pagliardini et al. (2024) show, DenseFormer achieves lower perplexity when later
layers can access much earlier outputs than when access is restricted to recent outputs. This finding
motivates the hypothesis that information produced in one iteration may likewise remain useful several
iterations later. In vanilla looped Transformers, retaining such information across iterations relies
entirely on the same hidden state that also supplies the input for subsequent backbone computation.
We therefore propose StateLoop, which maintains an additional persistent state for each token.
The state is carried across iterations and updated by combining its previous value with a projection of
the backbone output. A gate determined by the same output controls how much of the previous state
is retained and how much new information is written. An optional state mixer uses causal attention
or Mamba-2 to exchange information across token positions before readout. The updated state is
projected back and added to the backbone output, making the retained information available to later
iterations and final prediction.
We evaluate StateLoop at 410M and 1.4B scales to assess both its performance and the contribution
of the persistent state. Compared with Vanilla Looped, StateLoop reduces Pile perplexity by 0.18 and

2. Related Work
Looped Transformers and recurrent depth. The Universal Transformer introduced recurrent com-
putation across depth by repeatedly applying a shared block (Dehghani et al., 2019). Subsequent
work shows that looped Transformers can learn iterative algorithms for in-context learning (Yang
et al., 2024). Ouro extends this approach to large-scale language-model pretraining with learned
depth allocation (Zhu et al., 2025).
Connections between iterations. Recent looped language models differ in how they carry information
across iterations and construct the next backbone input. Parcae stabilizes the recurrent hidden state
by constraining the spectral norm of its state-transition matrix (Prairie et al., 2026). PonderLM feeds
back a weighted sum of token embeddings, with weights given by the predicted token probabilities
(Zeng et al., 2026). Hyperloop carries multiple residual streams across iterations and uses loop-specific
hyper-connections to read the backbone input from these streams and write the output back (Zeitoun
et al., 2026). These methods modify or enrich the recurrent stream itself, whereas StateLoop retains
the direct backbone stream and introduces a separate persistent state.
Persistent state and memory. LSTMs, GRUs, and selective state-space models update recurrent state
along a sequence (Hochreiter and Schmidhuber, 1997; Cho et al., 2014; Gu and Dao, 2024), while
Recurrent Memory Transformers carry memory tokens between sequence segments (Bulatov et al.,
2022). In looped architectures, Adaptive Loops and Memory augments repeated computation with
gated access to static learned memory banks (Frey et al., 2026), while Universal Transformers Need
Memory studies dynamically updated memory tokens as a computational scratchpad for recursive
reasoning (Sapunov, 2026). MeSH externalizes recurrent state management into a multi-slot buffer
with iteration-specific read and write routers (Yu et al., 2026). StateLoop explores a simpler design
point: it maintains a single continuously updated state per token, retains the main recurrent hidden
stream as a direct path, and shares all state-update and feedback parameters at every iteration.
3. Method
StateLoop adds a persistent state to each token. At each iteration, a gated update incorporates the
backbone output into the state, which is then read to form the next backbone input or the final
prediction. Figure 1 shows this computation.

4. Experiments
We evaluate language modeling and downstream accuracy, examine performance across trained loop
depths, and measure autoregressive decoding efficiency. Section 5 examines the design and behavior
of the persistent state.
4.1. Experimental Setup
Training configuration. All models are trained from scratch on the Pile (Gao et al., 2020) with a
LLaMA-style backbone (Touvron et al., 2023). All 1.4B comparisons use the same GPT-NeoX tokenizer,
data pipeline, 30B-token training budget, batch size 256, sequence length 2,048, and cosine-decay
schedule with peak learning rate 2 × 10−4. The shared Transformer backbone contains 24 layers, with
hidden width 𝑑= 2048, SwiGLU intermediate width 5504, and 32 attention heads of dimension 64.
StateLoop uses persistent-state width 𝑑𝑠= 2048, and the full-backbone recurrent models use 𝐾= 4
iterations of the shared backbone. The 410M studies use 25B training tokens and a peak learning rate
of 3 × 10−4, with the same batch size, sequence length, and cosine-decay schedule. Training budgets
count original language-model tokens.
State-branch configuration. Both token-axis mixers consist of a single residual module whose
parameters are shared across iterations. In the 1.4B model, the attention mixer uses pre-normalized
causal self-attention with rotary position embeddings (RoPE), 32 heads of dimension 64, and no
FFN. The Mamba-2 mixer uses an expansion factor of 2, an internal SSM state dimension of 128,
a convolution width of 4, a head dimension of 64, and 8 groups, without additional positional
embeddings.
Comparison models. All baselines are implemented in the same codebase. Vanilla Looped (Dehghani
et al., 2019) and PonderLM (Zeng et al., 2026) apply the full backbone for four iterations. Vanilla
Looped + FFN increases the SwiGLU intermediate width from 5,504 to 5,818, yielding approximately
the same parameter count as StateLoop + Mamba-2 Mixer. Our Hyperloop (Zeitoun et al., 2026),
MeSH (Yu et al., 2026), and Parcae (Prairie et al., 2026) baselines retain the partial-loop structures
used in their original studies. Hyperloop follows its original begin–middle–end structure, with only
the middle block applied recurrently. For MeSH and Parcae, we use eight layers each for the prelude,
recurrent core, and coda, with ten core repetitions, matching the 96 layer applications of four
StateLoop iterations, each with 24 layers. Pause Token inserts three pause tokens after each input
token to provide additional computation before predicting the next token (Goyal et al., 2024).
Evaluation metrics. We report perplexity (PPL) on Pile validation data, LAMBADA-OpenAI
(LAMBADA-OAI), and WikiText-2. PPL is the exponential of mean negative log-likelihood (NLL).
Pile and LAMBADA-OAI use token PPL, while WikiText-2 uses word PPL (Paperno et al., 2016;
Radford et al., 2019; Merity et al., 2017). Downstream evaluation covers LAMBADA-OAI, ARC-Easy,
ARC-Challenge, WinoGrande, PIQA, HellaSwag, SciQ, and RACE-high (RACE in the tables) under
both zero-shot and five-shot settings (Clark et al., 2018; Sakaguchi et al., 2020; Bisk et al., 2020;

4.3. Loop Depth
We next test whether the benefit of the additional state grows with the number of iterations, holding
state width fixed. With 𝑑= 𝑑𝑠= 1024, we train paired 410M Vanilla Looped and StateLoop models
using 𝐾= 3, . . . , 7 iterations. Each model uses 25B training tokens and is evaluated at the depth used
during training. With identity mixing, StateLoop has 411.10M parameters at every tested loop depth.
Both models benefit from more iterations, with larger gains for StateLoop (Figure 2). Its PPL
advantage over Vanilla Looped grows from approximately 0.14 at 𝐾= 3 to 0.30 at 𝐾= 7, consistent
with persistent state becoming increasingly useful as recurrent depth increases.

6. Conclusion
StateLoop equips each token with one additional persistent state to retain information across iterations.
It reduces perplexity and improves average downstream accuracy over Vanilla Looped, with optional
state mixers based on causal attention or Mamba-2 providing further downstream gains. The gains
obtained with both selective-SSM and GRU updates support the persistent-state design. Its growing
perplexity advantage over Vanilla Looped at greater trained depths further highlights the value of
persistent state for deeper recurrent computation. State interventions show that earlier states remain
partially usable at later boundaries, while continued state updates are important for prediction. These
findings support explicit persistent state as a promising design choice for looped Transformers.
Our experiments cover models up to the 1.4B scale, with the controlled loop-depth analysis
conducted at 410M. Extending this analysis to larger models can further characterize how persistent
state interacts with recurrent depth.
