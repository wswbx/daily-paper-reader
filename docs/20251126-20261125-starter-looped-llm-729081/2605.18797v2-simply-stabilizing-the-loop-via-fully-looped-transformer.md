## 摘要
扩展模型性能通常需要增加模型规模。Looped Transformer 通过迭代复用相同的 Transformer 块，提供了一种有吸引力的替代方案：在不增加参数数量或上下文长度的情况下，以额外计算换取性能提升。由于循环迭代次数可在推理时调整，它也为平衡性能与测试时计算提供了一种自然机制。然而，当循环迭代次数增加时，Looped Transformer 仍会遭受训练不稳定的问题。我们的分析揭示，这种不稳定性源于两个来源：梯度振荡和残差爆炸。为解决这两个问题，我们提出 Fully Looped Transformer，它引入两个无参数修改：（1）全循环架构（Fully Looped Architecture），将循环间信号分布到所有层以缓解残差爆炸；（2）注意力注入（Attention Injection），复用现有注意力块以抑制梯度振荡。这些修改稳定了训练动态，使 Fully Looped Transformer 能够稳定训练至 12 次循环迭代，而其他基线循环模型在此情形下会崩溃。在 Looped Transformer 不会崩溃的较温和设置中，Fully Looped Transformer 仍将下游任务的平均性能提升至多 13.2%。总体而言，我们的实验表明，Fully Looped Transformer 提高了训练稳定性，增强了下游性能，并通过在推理时改变循环迭代次数，在不同测试时计算预算下提供了初步的适应性。

## Abstract
Scaling model performance typically requires increasing model size. Looped Transformer offers a compelling alternative by iteratively reusing the same Transformer blocks, trading additional computation for improved performance without increasing parameter count or context length. Because the number of loop iterations can be adjusted at inference, it also provides a natural mechanism for balancing performance and test-time compute. However, Looped Transformer still suffers from training instability when the number of loop iterations increases. Our analysis reveals that this instability stems from two sources: gradient oscillation and residual explosion. To address these two problems, we propose the Fully Looped Transformer, which introduces two parameter-free modifications: (1) Fully Looped Architecture, which distributes inter-loop signals across all layers to mitigate residual explosion; (2) Attention Injection, which reuses the existing attention block to suppress gradient oscillation. These modifications stabilize training dynamics, enabling the Fully Looped Transformer to be trained stably up to 12 loop iterations, whereas other baseline looped models collapse in this regime. In milder settings where Looped Transformer does not collapse, Fully Looped Transformer still improves average downstream-task performance by up to 13.2\%. Overall, our experiments demonstrate that Fully Looped Transformer improves training stability, enhances downstream performance, and provides preliminary adaptability under different test-time compute budgets by varying loop iterations at inference.

# 《Simply Stabilizing the Loop via Fully Looped Transformer》论文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景约束**：LLM 的性能扩展传统上依赖增加模型参数与训练数据，但高质量公开文本数据的增长（约 10%/年）远慢于实际训练数据需求的增长（约 2.4×/年）。Chinchilla 缩放律要求参数与数据成比例扩展，单纯增大模型而不增加数据会导致次优训练结果。
- **替代范式**：Looped Transformer（LT）通过迭代复用同一批 Transformer 块，在不增加参数数量、不扩展上下文长度的前提下，用额外计算换取性能提升；且循环次数可在推理时调整，天然具备测试时计算（test-time compute）调节能力，并与推理任务、参数高效性等优势相关。
- **核心问题**：当循环次数增大时，LT 训练会失稳甚至崩溃。作者通过诊断实验（前 2000 优化步）识别出两个失稳来源：
  - **梯度振荡（gradient oscillation）**：循环结构类似 BPTT 训练的 RNN，梯度沿共享块累积，导致早期优化敏感、易进入不稳定区域。
  - **残差爆炸（residual explosion）**：循环增加有效循环深度，残差状态范数随循环次数快速放大，成为高循环次数下的主要优化瓶颈。
- **整体含义**：论文旨在不引入任何额外可学习参数的前提下，从架构层面稳定 LT 的训练动态，使其在更深循环下可训练，并保留测试时计算调节能力。

## 2. 方法论

### 核心思想
- 提出 **Fully Looped Transformer（FLT）**，作为对 LT 的“无参数”改进，包含两项互补修改：
  1. **Fully Looped Architecture（FLA）**：把上一次循环的输出分发到当前循环的**每一层**，缓解残差爆炸。
  2. **Attention Injection（AI）**：复用现有 Self-Attention 模块作为 Cross-Attention，以受控方式注入循环信号，抑制梯度振荡。

### 关键技术细节
- **FLA 的递归连接**：设第 t 次循环第 l 层的更新为
  - `h_l^(t) = f_θ^(l)(h_{l-1}^(t), h_L^(t-1))`，l = 1,…,L
  - 其中 `h_L^(t-1)` 是上一次循环的输出。相比原 LT 只把上轮输出送入第一层，FLA 让所有层都能直接访问循环状态，相当于在“循环维度”上提供 shortcut，降低有效循环深度带来的优化难度。
- **AI 的注意力注入**：
  - 第 1 次循环（t=1）使用标准 Self-Attention。
  - 后续循环（t>1）改为 Cross-Attention：以上一轮隐藏状态 `h_L^(t-1)` 作为 Query，当前层表示 `z_l^(t)` 同时作为 Key 和 Value：
    - `a_l^(t) = Attention(Q = W_Q h_L^(t-1), K = W_K z_l^(t), V = W_V z_l^(t))`
  - 由于 Softmax 归一化，注入信号是当前 value 向量的归一化混合，而非直接复制上一轮残差，从而限制信号幅度、控制梯度传播。
  - 第一层中 AI 直接使用输入嵌入 `x` 作为 `z_l^(t)`，起到类似 Input Injection 的作用。
  - 复用已有的 `W_Q, W_K, W_V` 投影矩阵，**不引入任何新参数**；将循环信号注入到 Q 而非 K/V，以保持与 KV-cache 复用机制的兼容性。
- **实现细节**：使用 Qwen3 分词器；采用 µP 进行深度相关学习率调整；Muon + AdamW 双优化器；按 Chinchilla 缩放律以 20 tokens/参数 设定训练 token 数；标准下一 token 预测损失，仅监督最后一步。

## 3. 实验设计

### 数据集与场景
- **预训练与验证**：FineWeb-Edu（约 200B 高质量 token，已去重精炼）。
- **语言建模评估**：WikiText-2 困惑度（PPL）、验证集 Bits-per-Byte（BPB）。
- **综合基准**：CORE Metric（DCLM 提出，聚合 21 项评测）。
- **下游任务**：LAMBADA OpenAI（0-shot）、OpenBookQA（0-shot）、PIQA（10-shot）、HellaSwag（10-shot）、ARC-Easy（10-shot）、ARC-Challenge（10-shot），报告准确率。

### 对比方法
- **LT**：原始 Looped Transformer。
- **LTi**：带 Input Injection 的 LT。
- **LTai**：仅第一层使用 Attention Injection 的 LT。
- **FLT**：本文方法（FLA + AI）。
- **FLTres**：消融变体，FLA 采用直接残差相加而非 AI。

### 实验设置
- **模型规模**：Small（127M 参数，6 层）与 Base（318M 参数，12 层）。
- **循环次数**：主实验 3/6/9 次；稳定性验证扩展到 12 次。
- **消融实验**：对比 FLA 单独、AI 单独、AI 仅第一层、FLTres；并测试 AI 在 FA、SWA、MLA、GQA 四种注意力机制下的兼容性。
- **测试时适应实验**：对以 3/6/9/12 次循环预训练的模型，分别在 1/3/6/9/12 次推理循环下评估。

## 6. 主要结论与发现

- **稳定性**：FLT 可稳定训练至 12 次循环；LT、LTi、LTai 在 12 循环下均崩溃。LT 在 9 循环时也已出现明显 loss 差距，Base 规模 9 循环直接崩溃。
- **性能提升**：
  - Base 规模下，FLT 是唯一随循环数增加而下游平均性能持续提升的变体：3→9 循环从 39.90 提升到 41.72；Wiki2 PPL 从 40.47 降至 38.44，Core Metric 从 15.37 升至 16.16，验证 BPB 从 0.898 改善至 0.892。
  - 6 循环时 FLT 相比原始 LT 下游平均提升 4.82 绝对点，相对提升约 **13.2%**。
  - Small 规模下 LTi 在 6 循环取得最佳平均（33.35），FLT 表现稳定但非最优；FLT 的优势在更大模型上更明显。
- **消融结论**：
  - FLA 能显著减小残差范数，但单独使用仍会出现梯度振荡与崩溃，不足以单独保证稳定。
  - AI 可承担类似 Input Injection 的作用；仅第一层 AI 在高循环下仍不稳定。
  - FLA + AI 组合效果最佳。
  - AI 与 FA/SWA/MLA/GQA 均兼容，12 循环下四种注意力机制均稳定完成训练且性能相近。
- **测试时适应**：在预训练循环数范围内，更多推理循环通常带来更好性能；超出训练循环数后性能波动、变得不可预测，说明需要显式训练可变循环数才能实现稳健的测试时计算适应。

## 7. 优点

- **问题诊断清晰**：先通过诊断实验定位“梯度振荡 + 残差爆炸”两个失稳机制，再针对性设计两项修改，形成“诊断—设计—验证”的闭环。
- **无参数、易集成**：两项修改均不引入新的可学习参数，AI 复用现有 Q/K/V 投影，可直接嵌入标准 Transformer 架构。
- **工程友好**：将循环信号注入 Q 而非 K/V，保持 KV-cache 复用兼容性；与多种注意力机制兼容，具备实际部署潜力。
- **实验设计较系统**：涵盖循环缩放、消融、注意力变体、测试时适应多个维度，并与 Input Injection 等已有稳定化技术做了对照。
- **兼顾稳定性与性能**：不仅解决了崩溃问题，还在温和设置下带来最高 13.2% 的下游性能提升，并展示了推理期计算调节的初步可行性。

## 8. 不足与局限

- **规模有限**：仅验证到 318M 参数、12 层、12 循环，未验证更深 backbone、更大模型或更长循环；作者本人将此列为首要局限。
- **单次运行、无误差棒**：每个配置仅训练一次，无法评估随机种子方差，结论的统计稳健性有限。
- **测试时适应不稳健**：推理循环数超过训练循环数后性能不可预测，说明当前方案尚不支持真正灵活的测试时计算外推。
- **数据覆盖单一**：仅使用 FineWeb-Edu 一个预训练语料，未涉及多语言、代码、数学等多样领域。
- **FLA 单独不足**：FLTres 在多种循环设置下崩溃，说明方法对 AI 组件存在依赖，两项修改的耦合关系仍需更细粒度分析。
- **算力成本未量化**：未报告总 GPU 小时或能耗，难以评估方法的实际训练成本与可复现性。
- **应用限制**：更多推理循环会增加计算与能耗；模型仍可能继承预训练数据的偏差与有害关联，作者在 Broader Impacts 中建议后续进行安全评估。
