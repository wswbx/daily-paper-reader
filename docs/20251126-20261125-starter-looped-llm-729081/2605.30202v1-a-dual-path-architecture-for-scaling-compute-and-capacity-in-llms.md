## 摘要
循环式Transformer通过多次应用共享模块，已成为在语言模型中扩展计算量的一种参数高效路径。然而，在固定FLOPs下，循环模型的容量严格小于基线Transformer。我们提出一种新颖的双路径模块，可灵活扩展计算量（即对隐藏状态施加的序列操作次数）和容量（即单步可用的参数）。为此，我们在单层内将这两个轴作为并行路径暴露出来：一个共享参数并重复应用K次的深层子层，以及一个仅应用一次且具有扩大前馈网络的宽子层。独立的逐token门控结合了这两个轴，并支持详细的逐token路由分析。我们表明，在两个FLOP预算下，我们的双路径模型在语言建模和下游评估上均优于等FLOP匹配模型，同时在匹配FLOPs时使用的参数少于基线。学习到的门控具有直接可解释性，并显示出系统性的逐token分配：功能词和词汇内容倾向于宽路径，而标点、符号和算术token倾向于深路径。

## Abstract
Looped transformers apply a shared block multiple times and have emerged as a parameter-efficient route to scaling compute in language models. However, at fixed FLOPs a looped model has strictly less capacity than a baseline transformer. We propose a novel dual-path block that can flexibly scale compute, the number of sequential operations applied to a hidden state, and capacity, the parameters available at a single step. For this we expose both axes as parallel pathways within a single layer: a deep sublayer re-applied K times with shared parameters, and a wide sublayer with an enlarged feed-forward network applied once. Independent per-token gates combine both axes and allow detailed per-token routing analyses. We show that across two FLOP budgets, our dual-path model surpasses iso-FLOP matched models on language modeling and downstream evaluations, while using fewer parameters than the baseline at matched FLOPs. The learned gates are directly interpretable and show systematic per-token allocation with function words and lexical content trend wide, while punctuation, symbols, and arithmetic tokens trend deep.

# 论文总结：A Dual-Path Architecture for Scaling Compute and Capacity in LLMs

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：循环式（looped / recursive）Transformer 通过多次重复应用共享参数块来扩展序列计算，是一种参数高效的扩展路线（Universal Transformers、looped decoders 等）。其吸引力在于：L 层循环 K 次可达到 KL 层非共享层的有效深度，而参数仅为 1/K。
- **核心矛盾**：在固定 FLOPs 下，循环模型的**容量（capacity，单步可用参数）严格小于**同等计算量的非共享堆叠，这一差距在依赖存储知识的任务上尤为明显。
- **概念区分**：循环与宽度缩放位于两个性质不同的轴上——循环用计算增加对隐藏状态的**序列操作次数（compute）**；宽度缩放增加**单步可用参数（capacity）**。标准架构将两者混为一谈，每个 token 在两条轴上都支付相同代价。
- **现有工作的局限**：MoE、Mixture-of-Depths、Mixture-of-Recursions、自适应停止等机制每次只放松**单一轴**（选哪些专家、循环几次、是否应用某层），无法让需要更多序列精炼的 token 只获得计算而不为不需要的容量付费，反之亦然。
- **论文主张**：在单层内将两个轴显式暴露为并行路径，由逐 token 门控动态组合，从而同时、灵活地扩展计算与容量。

## 2. 方法论

### 2.1 核心思想
- 每个 **dual-path block** 包含两个并行子层，共享同一输入 x：
  - **深层路径（compute）**：共享参数、重复应用 K 次的子层；
  - **宽层路径（capacity）**：FFN 隐藏维扩大、仅应用一次的子层。
- 两条路径均由**逐 token 的独立 sigmoid 门控**加权组合，且**两路对每个 token 都密集评估**（不跳过计算，而是重新分配计算）。

### 2.2 关键技术细节
- **深层路径**：Φ_deep 使用 FFN 隐藏维 d_deep，迭代 K 次共享参数；每步增益 s⁽ᵏ⁾_d = softplus(α⁽ᵏ⁾)，α⁽ᵏ⁾ 初始化为 −7（s≈9×10⁻⁴），使递归初始接近恒等，模型学习逐步偏离 x。
- **中间状态加权聚合**：不直接返回 h⁽ᴷ⁾，而是用小 router（对当前状态 h⁽ᵏ⁾ 与归一化步索引 k/(K−1) 做线性投影）产生每步权重 q_k∈[0,1]，令 π_k=∏_{j<k}(1−q_j)，则 h_deep = Σ_{k=1}^{K−1} π_k q_k h⁽ᵏ⁾ + π_K h⁽ᴷ⁾，实现逐 token 对后期迭代降权。
- **宽层路径**：Φ_wide 与深层路径共享 attention 配置，但 FFN 隐藏维 d_wide > d_deep，仅应用一次；增益 s_w = softplus(β)，β 初始化为 −7。
- **逐 token 门控**：线性投影 W_g∈R^{d×2}、b_g∈R²，得 logits (ℓ_d, ℓ_w)=xW_g+b_g，两个独立 sigmoid 门 g_d=σ(ℓ_d)、g_w=σ(ℓ_w)∈[0,1]；组合更新 y = g_d⊙h_deep + g_w⊙h_wide。W_g、b_g 初始化为 0，训练开始时 g_d=g_w=0.5。
- **单轴基线**：禁用一路即退化为 PURELOOP（y=h_deep，K 次递归标准 FFN）或 PUREWIDE（y=h_wide，一次扩大 FFN）。
- **路由读出指标**：
  - **Deep share**：ρ_d = g_d‖Δ_d‖ / (g_d‖Δ_d‖ + g_w‖Δ_w‖) ∈[0,1]，其中 Δ_d=h_deep−x、Δ_w=h_wide−x，衡量残差更新中来自深层路径的比例（仅看原始门值会忽略更新幅度）。
  - **路径对齐**：cos(Δ_d, Δ_w)，接近 +1 表示两路同向冗余，接近 0 表示正交、信息不重叠。

### 2.3 算法流程（文字说明）
1. 输入 x 分别送入深层子层（循环 K 次，逐步 softplus 增益，router 加权聚合中间态）与宽层子层（一次前向）。
2. 由 x 经线性层 + sigmoid 得到两路门控。
3. 按门控加权求和得到块输出，进入下一层。
4. 训练中同时记录门值与两路更新向量，用于事后路由分析。

## 3. 实验设计

- **骨干模型**：GPT2 风格 decoder-only，L=16 层、d=768、12 个 attention head；RoPE、QK-norm、Pre-RMSNorm、SwiGLU；所有配置（含基线）共享骨干，仅改变 FFN 宽度与递归深度。
- **FLOP 预算**：两个 iso-FLOP 预算，FM=80M 与 FM=160M（每层每 token 的 FFN FLOPs），对应约 1.28G 与 2.56G 总 FLOPs/token。
- **配置扫描**：每个预算下扫描 dual-path 的 FFN 分配比例 α∈{25, 50, 75}（深层路径所占 FFN FLOPs 份额）与递归深度 K∈{2,3,4}；参数总量约 240M–1.4B。
- **训练数据**：Nemotron-CC 去重子集，38B tokens，GPT-2 tokenizer，序列长度 4096；AdamW（峰值学习率 5×10⁻⁴，184 步线性 warmup，余弦衰减至 5×10⁻⁵）。
- **对比方法**：
  - **PUREWIDE**：全部预算用于容量（无递归、最宽 FFN，参数量最大）；
  - **PURELOOP**（K=2,3,4）：全部预算用于共享参数递归（参数量最小）；
  - 各 dual-path 配置（α×K 网格）。
- **评测基准**：
  - 语言建模：Paloma C4、WikiText-103 的 BPB；
  - 常识：ARC-c、ARC-e、HellaSwag、PIQA、SIQA、WinoGrande 的平均准确率与 BPB；
  - 数学：GSM8k 准确率 + OLMo3 base-easy math 七个子任务 BPB 平均；
  - 阅读/QA：LAMBADA、QASPER；
  - 使用 OLMES 评估框架。
- **FLOP 匹配协议**（附录 B）：按 SwiGLU 有效隐藏宽度公式反解最大合法 d_ffn，使各配置每层 FFN FLOPs 与预算一致（误差 <0.5%，残差 <2%）；dual-path 额外计入一次 attention 与 router（4d FLOPs）开销。PUREWIDE 采用向上取整以保持基线"诚实"（严格略多 FLOPs）。
