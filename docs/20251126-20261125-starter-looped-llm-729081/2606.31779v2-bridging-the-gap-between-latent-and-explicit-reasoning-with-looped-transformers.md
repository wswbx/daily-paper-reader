## 摘要
语言模型通常通过显式思维链（CoT）进行推理，逐 token 生成中间步骤。潜在 CoT 提供了一种替代方案：它在模型的隐藏状态中执行多步推理，用连续表示替代解码出的 token，从而获得更高效率。然而，现有潜在 CoT 方法在参数量超过 10 亿时表现不及显式 CoT，且差距随模型规模扩大而增大。循环式（或循环深度）Transformer 复用权重来增加计算深度而不增加参数，天然适合潜在推理。因此，我们追问循环 Transformer 能否弥合这一差距。我们以一套简单方案给出肯定回答：一种循环式填充 Transformer，它在 R 次迭代中并行处理 K 个潜在块，并对每个潜在位置对应的标准 CoT 步骤 token 施加交叉熵损失，类似于显式 CoT 监督。我们将其实例化为 LOTUS（Looped Transformers with parallel supervision on latents）。据我们所知，LOTUS 是首个在 30 亿参数规模上弥合与显式 CoT 差距的潜在 CoT 方法，同时在从紧凑数学表达式到自然语言的各类任务上，将思考阶段延迟缩短 2.5 倍至 6.9 倍。将 LOTUS 循环后的潜在表示通过基础语言模型头部进行投影，可以恢复标准推理步骤，甚至显现出其他有效的中间步骤，这表明其潜在空间具有可解释性并与 CoT 对齐。消融实验证实，循环骨干和对标准 CoT token 的并行监督二者都不可或缺。代码见 https://github.com/yingfan-bot/lotus。

## Abstract
Language models typically reason via explicit chain-of-thought (CoT), generating intermediate steps token-by-token. Latent CoT offers an alternative: it performs multi-step reasoning in the model's hidden states, replacing decoded tokens with continuous representations for greater efficiency. However, existing latent CoT methods underperform explicit CoT beyond 1B parameters, and the gap widens with scale. Looped, or recurrent-depth, Transformers, which reuse their weights to increase computation depth without adding parameters, are a natural fit for latent reasoning. We therefore ask whether looped Transformers can bridge this gap. We answer affirmatively with a simple recipe: a looped padded Transformer that processes K latent blocks in parallel for R iterations, with a cross-entropy loss on each latent position's gold CoT-step token, similar to explicit CoT supervision. We instantiate it as LOTUS (Looped Transformers with parallel supervision on latents). LOTUS is, to our knowledge, the first latent-CoT method to bridge the gap to explicit CoT at the 3B scale, while cutting thought-phase latency by 2.5x-6.9x from compact math expressions to natural language. Projecting LOTUS's post-loop latents through the base LM head recovers the gold reasoning steps and even surfaces alternative valid intermediate steps, evidence that its latent space is interpretable and CoT-aligned. Ablations confirm that both the looped backbone and the parallel supervision on gold CoT tokens are essential. Code is available at https://github.com/yingfan-bot/lotus.

## 1. 核心问题与研究动机

- **背景**：提升模型能力的主要手段已从“增大模型”转向“增加推理时计算”，即让模型先“思考”再作答。显式思维链（Explicit CoT）通过逐 token 生成中间推理步骤实现这一点，但由于必须顺序解码，长度为 N 的 CoT 需要 N 次串行前向，推理延迟高。
- **潜在推理（Latent CoT）的承诺与困境**：把中间计算放在连续隐藏状态中，用少量模型评估压缩多步推理。在 GPT-2 等小骨干上，Coconut / CODI / SIM-CoT 等方法已能追平 CoT 精度；但**超过 1B 参数后，没有任何潜在方法能在数学推理上匹配显式 CoT，且差距随规模扩大**（如 CODI+SIM-CoT 在 GPT-2 上 42.6 vs 42.7，到 3B 落后 9.2 分；KaVa 从落后 1.9 分扩大到 5.8 分）。
- **作者归因于两个问题**：
  - **P1 顺序生成**：Coconut、CODI、SIM-CoT 以纯自回归方式产生潜在 thought，串行前向次数仍随潜在 token 数线性增长，既保留了 CoT 的串行瓶颈，又丢失了显式 CoT 的可读中间步骤。
  - **P2 缺乏 CoT 接地（grounding）**：显式 CoT 每个推理步骤都有位置对齐的 token 监督目标；而 PCCoT、KaVa 虽用 Jacobi 迭代并行化，却只能通过教师隐状态蒸馏或压缩教师 KV-cache 等间接信号监督，导致潜在轨迹可能漂移、大规模训练不稳定。
- **为什么选循环 Transformer**：Looped / recurrent-depth Transformer 复用同一套权重做多次迭代，在不增加参数的情况下加深计算；理论上可在对数级迭代内解决图可达性等问题，比串行潜在方法有指数级改进。由此提出核心问题：**循环 Transformer 能否在更少串行步数下弥合与显式 CoT 的差距？**
- **整体含义**：论文给出肯定回答，并主张“循环填充骨干 + 对金标准 CoT token 的并行交叉熵监督”这一极简配方即可在 3B 规模上首次弥合差距，同时把思考阶段延迟降低 2.5–6.9 倍。

## 2. 方法论：LOTUS

### 2.1 核心思想
将标准 LM 改造为潜在推理器，由两个部件组成：(i) 由循环填充 Transformer（LPT）处理的**填充式潜在前缀**；(ii) 对**精确金标准 CoT token 的并行交叉熵监督**。实例化为 LOTUS（监督直接经基础 LM head 读出）与 LOTUS-aux（监督经辅助解码器）。

### 2.2 填充式潜在前缀
- 输入构造为：`x = [Q, <BoT>, (c 个可学习 <lat> token) × K 块, <EoT>, A]`。
- `<lat>` 在所有位置共享；`<BoT>/<EoT>` 为可学习定界符。
- 块预算 K 与块宽 c 为固定超参；块 i 意图编码第 i 个 CoT 步骤 T_i 的潜在表示。K 取覆盖数据中步骤数的值（GSM8K 99% 样例 ≤6 步，故 K=6），K ≥ S 时一块对齐一步。

### 2.3 循环潜在计算
- 先对 `[Q, <BoT>]` 做一次前向得到 KV cache `C_pre`，训练与推理全程复用，不重算。
- 对潜在嵌入 E 做 R 次迭代（输入注入式有限展开递归，梯度穿过全部 R 次）：
  - `h^(0) = f_θ(E | C_pre)`
  - `h^(t) = f_θ(E + h^(t-1) | C_pre), t = 1..R`
- 尾部 `<EoT>` 与答案 A 不进入循环。

### 2.4 直接步骤对齐监督（目标函数）
- **步骤损失**：把第 i 块第 j 个潜在位置经 LM head 读出，与第 i 步 CoT 的第 j 个 token 做批量交叉熵（padding 忽略）：
  `L_step = (1/N_step) Σ_i Σ_j CE(f_head(h^(R)_{i,j}), T_{i,j})`
- **答案损失**：单独一次最终前向，把循环后潜在状态 `h^(R)` 插入潜在行，条件于 `[C_pre, h^(R)]` 对答案后缀做标准下一 token 交叉熵：
  `L_ans = (1/|A|) Σ_m CE(f_head(z_m), A_{m+1})`
- **总目标**：`L = L_ans + λ_step · L_step`（实验中 λ_step=0.05）。
- **三个关键性质**：直接（与生成答案共用同一 LM head）、并行（K 块同时监督）、后循环（只读 h^(R) 而非每次迭代都读）。

### 2.5 为什么并行独立监督仍能产生全局连贯答案（理论视角）
- `L_step` 诱导的是**并行链似然（PCL）**：`p_PCL(T|Q) = Π_i Π_j p_θ(T_{i,j}|Q)`，即按位置条件独立分解；但潜在状态本身由循环 Transformer 在共享工作区上联合计算，被分解丢弃的依赖由**共享潜在计算**承载。
- **支撑集包含关系**：`supp(q(T|Q)) ⊆ Π_i Π_j supp(q(T_{i,j}|Q))`，因此 `L_step` 起“支撑覆盖”作用——让每个位置把概率质量放到正确的金标准 token 上，而无需复现联合分布（LOTUS 从不对该联合分布采样）。
- `L_ans` 提供 PCL 缺失的**全局选择压力**：答案在条件于整个潜在配置下训练，梯度偏好真正能支撑正确答案的联合隐状态。二者互补：覆盖来自 `L_step`，联合选择来自 `L_ans`。

### 2.6 LOTUS-aux 变体
- 复用同一循环骨干与前向流程，仅把循环内的监督改由一个**全尺寸辅助解码器 g_φ**（从基础模型权重初始化、共同训练）承担。
- 在第 t 次迭代读取第 t 块的 c 个潜在状态作为前缀，对金标准步骤 T_t 做教师强制下的下一 token 交叉熵（逐迭代读出）；监督仍是并行的（教师强制下一次前向打全部分数），自回归分解只影响损失、不影响计算。
- 代价：CoT 监督不再直接流经生成答案的 LM head，且教师强制引入训练/推理不一致；辅助解码器**仅在训练时使用**，推理与 LOTUS 完全相同。

### 2.7 推理流程
- 计算 Q 的 KV cache → 循环 R 次得到 h^(R) → 条件于潜在表示自回归解码答案。
- **潜在推理步骤在答案生成时从不被读出**（LM head 投影只用于训练对齐）；唯一串行解码的是很短的答案后缀，这正是延迟收益来源。
