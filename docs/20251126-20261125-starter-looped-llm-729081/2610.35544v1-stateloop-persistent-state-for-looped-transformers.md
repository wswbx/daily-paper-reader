## 摘要
循环 Transformer 通过重复应用共享主干，为语言建模提供了一种参数高效的方法。原始循环 Transformer 直接将每次主干输出作为下一次迭代的输入。这些输出可能包含在若干次迭代后仍有用的信息，但能否在循环中保留这些信息完全取决于单一隐藏状态。我们提出 StateLoop，它为每个 token 维护一个额外的持久状态，以在迭代之间保留信息。在每次迭代中，一个学习到的门控控制保留多少先前状态以及从主干输出中纳入多少信息。更新后的状态会被投影回并加到主干输出上，用于后续迭代和最终预测。该设计降低了 Pile 困惑度，并在八个零样本任务上相比原始循环 Transformer 提升了平均准确率。其相对于原始循环 Transformer 的困惑度优势随训练循环深度增加而增大，这与持久状态随着循环计算加深而变得更有用相一致。

## Abstract
Looped Transformers offer a parameter-efficient approach to language modeling by repeatedly applying a shared backbone. Vanilla looped Transformers use each backbone output directly as the input to the next iteration. These outputs may contain information useful several iterations later, but retaining it across the loop depends entirely on the single hidden state. We introduce StateLoop, which maintains one additional persistent state per token to retain information across iterations. At each iteration, a learned gate controls how much of the previous state is retained and how much information from the backbone output is incorporated. The updated state is projected back and added to the backbone output for subsequent iterations and final prediction. This design reduces Pile perplexity and improves average accuracy across eight zero-shot tasks over Vanilla Looped. Its perplexity advantage over Vanilla Looped grows with trained loop depth, consistent with persistent state becoming increasingly useful as recurrent computation deepens.

## 1. 核心问题与研究动机

- **背景**：循环 Transformer（Looped Transformer）通过反复复用同一个共享主干（shared backbone）来增加计算量，是一种参数高效的语言建模方案。已有工作（Universal Transformer、Saunshi et al. 2025、Ouro 的 1.4B/2.6B 模型）表明，在参数量相同时，循环模型可优于非循环模型。
- **核心问题**：循环架构中“迭代之间的连接方式”是关键设计点。Vanilla Looped 直接把第 k 次主干输出当作第 k+1 次输入，因此**跨迭代的信息保留完全依赖同一个隐藏状态**——它既要为下一次主干计算提供输入，又要承担记忆职责。
- **动机证据**：DenseFormer（Pagliardini et al., 2024）发现，当后续层能访问更早层的输出时，困惑度更低。作者据此假设：某次迭代产生的信息在若干次迭代之后仍可能有用，因此值得为之提供**独立于主干的显式记忆通道**。
- **整体含义**：论文提出 StateLoop，为每个 token 额外维护一个持久状态（persistent state），用门控方式跨迭代读写，从而把“计算流”和“记忆流”解耦。

## 2. 方法论

### 2.1 核心思想
- 保留 Vanilla Looped 的**直接主干反馈通路**（H^k 直接进入下一次迭代），同时**并联**一条独立的持久状态分支；状态经投影后“加回”主干输入与最终预测，而不是取代主干流。

### 2.2 关键流程（记号：主干宽度 d，状态宽度 d_s，总迭代 K 次，k = 0…K−1）
- **初始化**：E = √d · Embed(x)，S⁰ = 0，H⁰ = T(E)。
- **状态更新（沿“循环轴”逐 token 独立进行）**：
  - 归一化主干输出：U^k = RMSNorm_h(H^k)；
  - 选择性 SSM 更新：P^k = U^k·W_uᵀ（写到状态宽度）；
  - 输入相关步长：Δ^k = softplus(U^k·W_Δᵀ + b_Δ)，λ = exp(A_log)（逐通道可学习正速率）；
  - 更新式：**eS^{k+1} = exp(−λ⊙Δ^k)⊙S^k + (1 − exp(−λ⊙Δ^k))⊙P^k**；
  - 即**保留门 g = exp(−λ⊙Δ^k)**、**写入门 η = 1 − g**，二者均由主干输出决定，可随 token 与迭代变化。
- **初始化技巧**：W_Δ = 0、b_Δ = log(e^0.3 − 1) 使初始 Δ = 0.3；λ 在通道间按对数从 0.01 到 4 初始化，从而给出可控的初始写入率 η_c = 1 − exp(−0.3λ_c)。
- **可选 token 轴混合 X_ψ**（形状保持 n×d_s，只依赖前缀以保证因果性）：
  - 恒等映射（默认）：S^{k+1} = eS^{k+1}；
  - 因果注意力混合：S^{k+1} = eS^{k+1} + CausalAttention(RMSNorm_m(eS^{k+1}))（pre-norm + 残差 + RoPE）；
  - Mamba-2 混合：S^{k+1} = Mamba2Block_ψ(eS^{k+1})。
- **读回主干（k = 0…K−2）**：N^{k+1} = RMSNorm_s(S^{k+1})，**Z^{k+1} = H^k + N^{k+1}·W_{s→z}ᵀ**，H^{k+1} = T(Z^{k+1})。
- **最终预测**：**Y = H^{K−1} + N^K·W_{s→out}ᵀ**，再由 LM Head 得到词表 logits。
- **训练**：端到端最小化标准自回归负对数似然；主干、状态更新、反馈投影、可选混合器的参数**在所有迭代间共享**。

## 6. 主要结论与发现

- **主结果（1.4B, 30B token）**：StateLoop 以 +1.18% 参数将 Pile PPL 从 7.79 降到 7.61（−0.18），LAMBADA-OAI 6.94→6.71、WikiText-2 16.50→15.96；zero-shot Avg-8 从 53.31 升至 54.28（+0.97pp），five-shot 55.12→56.60。

- **循环深度（410M，K = 3…7，成对训练）**：在每一个训练深度上，StateLoop 的 Pile 验证 PPL 均低于同深度的 Vanilla Looped，说明增益并非某一特定 K 的偶然结果；随 K 增大，Vanilla Looped 的收益较早进入饱和甚至回退，而 StateLoop 的曲线更平缓，表明显式状态通道在一定程度上缓解了“单纯堆叠迭代次数”带来的边际收益递减。作者据此把 StateLoop 定位为“让额外迭代更划算”的机制，而非仅靠增加循环次数换性能。
- **解码效率**：由于每次迭代多了状态更新与读回投影，StateLoop（恒等混合）在 K=4 时的单 token 延迟高于 Vanilla Looped K=4，但仍明显低于 Vanilla Looped K=5——即“4 次迭代 + 状态”在效果上对标“更多次迭代”，而墙钟成本更接近 4 次迭代。三种变体中，恒等混合最快；因果注意力混合带来额外开销；Mamba-2 混合在参数对齐（与 Vanilla Looped + FFN 等参）条件下取得较好的效果—效率折中，是作者推荐的“等参可比”配置。
- **消融结论**：
  - **状态宽度**：d_s 从 128 增至 1024 时性能单调改善，但在较大宽度后增益趋缓，说明状态容量的收益存在饱和点，d_s = d 并非唯一合理选择；
  - **反馈设计**：仅用状态替代主干反馈（state-only）明显劣于 StateLoop 的“主干直连 + 状态并联”，验证了 2.1 节的核心设计主张——状态应作为**补充记忆**而非**替代计算流**；
  - **状态持久性**：若在每次更新前将状态清零（退化为无跨迭代记忆），性能下降，直接证明“跨迭代保留”本身是增益来源，而非仅仅多了一组可训练参数；
  - **更新规则**：选择性 SSM 更新优于 GRU 式更新，作者归因于输入相关的步长 Δ 与逐通道衰减 λ 提供了更细粒度的写入门控，使不同通道可以按不同时间尺度保留信息。
- **状态读取的贡献分布（Shapley）**：对 7 次状态读取的 128 种掩码组合计算精确 Shapley 值后发现，各次读取的贡献并不均匀：中间至后期迭代的读取贡献普遍高于最早期的读取，但**没有任何一次读取的贡献为零**，说明状态在多轮迭代中被持续、累积地使用，而不是仅在某一“关键迭代”起作用；这与“持久记忆”的设计意图一致。
- **干预实验**：跨序列边界替换状态（并做通道级均值/方差校准以排除分布偏移的解释）会导致性能下降，说明状态中编码了超出局部 token 统计的、与序列上下文相关的信息；直接冻结状态（停止更新）同样造成性能损失，进一步说明“持续写入”与“持续读取”二者缺一不可。
- **总体判断**：论文的结论可概括为——在循环 Transformer 中，把“计算流”和“记忆流”解耦、并为后者提供独立且门控的持久状态，是一种**参数开销小、随迭代深度可扩展、且与现有循环基线兼容**的改进；其收益在 1.4B 规模上已可测量（PPL 与下游平均准确率同向改善），但幅度属于“稳定小幅”而非“量级跃迁”。

## 7. 贡献与启示

- **概念层面**：把 SSM 式的“选择性状态更新”从序列轴迁移到**循环轴**（沿迭代维度的逐 token 递归），为循环架构提供了一个轻量、可解释的记忆机制；这一“轴替换”思路可推广到其他复用结构的模型（如多步推理、扩散式语言模型）。
- **设计层面**：明确提出并实验验证了“并联而非替代”的原则——保留 Vanilla Looped 的直接主干反馈，同时叠加状态分支，避免了 state-only 设计中的信息瓶颈。
- **工程层面**：状态更新与混合器模块化（恒等 / 注意力 / Mamba-2 可插拔），并给出等参配置，便于在既有循环模型代码库中低成本集成。
- **分析层面**：用 Shapley 值量化“每一次状态读取”的边际贡献，并配合替换/冻结两类因果式干预，为“状态确实被使用”提供了比单纯消融更有说服力的证据。
