## 摘要
循环 Transformer 通过重复应用共享骨干网络来增加每个 token 的计算量，从而在固定骨干参数量的情况下提供一种提升语言建模与下游任务性能的方法。然而，每个循环都依赖于前一个循环，因此增加循环深度也会增加解码延迟。现有方法包括并行循环 Transformer（Parallel Loop Transformers），其通过在不同 token 位置上重叠循环计算来降低延迟，但在更大深度下边际准确率增益迅速递减。为应对这一挑战，我们提出 LoopFold，它将同一 token 前缀在多个循环深度上的计算折叠为并行批次。一个轻量级预测器估计后续循环的输入，使其能够在较早循环完成之前开始。随后，一个校正器利用较早循环新获得的结果来精炼这些后续循环的输出。所有组件仅使用最终的下一 token 预测损失进行联合训练。在 1.4B 模型实验中，更深的 LoopFold 配置在八项任务上取得逐步更高的平均零样本准确率，从 53.41% 提升至 56.38%。原始循环模型和 PLT 在相同深度范围内仅表现出有限增益。与九循环原始模型相比，LoopFold 使用五个顺序阶段和额外并行计算，将解码延迟降低 46%。

## Abstract
Looped Transformers increase computation per token by repeatedly applying a shared backbone, offering a way to improve language modeling and downstream task performance at a fixed backbone parameter count. However, each loop depends on the preceding loop, so increasing recurrent depth also increases decoding latency. Existing approaches include Parallel Loop Transformers, which reduce latency by overlapping loop computation across token positions, but yield rapidly diminishing marginal accuracy gains at larger depths. To address this challenge, we introduce LoopFold, which folds computation at multiple recurrent depths into parallel batches for the same token prefix. A lightweight predictor estimates inputs to later loops so they can start before earlier loops finish. A corrector then refines the outputs of these later loops using newly available results from earlier loops. All components are trained jointly using only the final next-token prediction loss. In experiments with 1.4B models, deeper LoopFold configurations achieve progressively higher average zero-shot accuracy across eight tasks, rising from 53.41% to 56.38%. Vanilla looped models and PLT show limited gains over the same depth range. Compared with a nine-loop vanilla model, LoopFold uses five sequential stages and additional parallel computation to reduce decoding latency by 46%.

# LoopFold 论文结构化总结

## 1. 核心问题与研究动机

- **背景**：循环 Transformer（Looped Transformer，如 Universal Transformer）通过重复应用共享骨干网络，在骨干参数量固定时增加每个 token 的计算量（即“循环深度”），可提升语言建模与下游任务性能。
- **核心矛盾**：每次循环依赖上一次循环的输出，导致循环深度增加会同步增加顺序骨干阶段数与逐 token 解码延迟。
- **现有方案及其不足**：
  - **PLT（Parallel Loop Transformers）**：跨 token 位置错位重叠循环计算以降低延迟，但每个循环都存在位置错配，深度增大时边际准确率增益迅速衰减。
  - **循环深度并行采样器**：并行精炼多个 token 草稿，但减少精炼步数是以牺牲精度换取速度。
- **核心挑战**：如何在后续循环的输入尚未就绪时提前启动它们，同时仍能纳入前面循环的结果。

## 2. 方法论

### 核心思想
将同一 token 前缀在多个循环深度上的计算**折叠为并行批次**：用轻量预测器估计后续循环的输入使其提前运行，再用校正器把新得到的早期循环结果注入并修正并行输出。所有组件仅用最终下一 token 预测损失联合训练。

### 关键技术细节

- **调度表示**：调度 `1 + n + ⋯ + n`，即 1 次初始骨干评估 + `S−1` 个阶段、每阶段 `n` 个并行评估；目标深度索引 `D = n + S − 1`。例如 `1+3+3` 用 3 个阶段、宽度 3 达到 `D=5`，共 7 次骨干评估。
- **输入预测（Predictor）**：先用 `H₁ = F(H₀)` 计算状态变化 `V₁ = H₁ − H₀` 作为循环深度的初始增量；共享的逐 token 线性映射 `J_pred`（写作 `I + ΔJ`，`ΔJ` 零初始化）反复作用于该增量，初始化更深状态：
  `Z^(1)_{1+ℓ} = H₁ + Σ_{m=1}^{ℓ} J_pred^m V₁`。恒等初始化下退化为线性外推 `H₁ + ℓV₁`。预测只执行一次。
- **并行评估与校正**：
  - 每阶段把 1 个顺序状态与 `n−1` 个临时状态沿 batch 维拼接，一起送入共享骨干并行计算，再拆分回各通道（各通道 token 位置与因果掩码相同，注意力在通道内独立计算）。
  - 骨干输出 `Y^(s)_j+1` 因基于旧输入估计而“陈旧”，用共享线性映射 `J_corr` 按输入变化量修正：`Z^(s)_{j+1} = Y^(s)_{j+1} + J_corr(Z^(s)_j − Z^(s−1)_j)`，按深度顺序传播，使新信息在并行输出间顺序流动。
- **训练目标**：仅用最深层状态 `Ĥ_D` 计算下一 token 的交叉熵损失，所有组件端到端联合训练；预测器与校正器参数独立、跨深度/位置共享（校正器还跨阶段共享）。
- **计算成本**：每 token 共 `1 + n(S−1)` 次骨干评估、`S` 个顺序阶段；额外参数仅 `2d²`（1.4B 模型约 8.39M），外加 `S(n−1)` 次逐 token 线性映射。

## 6. 主要结论与发现

- **质量随深度提升**：1.4B 模型上，LoopFold 在 D=5→9 时 Avg-8 从 **53.41% 升至 56.38%**，而原始循环模型（53.69→54.18）与 PLT（52.41→52.10）在相同深度范围内变化很小。
- **延迟显著降低**：D=9 时 LoopFold 只需 **5 个顺序阶段**（而非 9 个），解码延迟降低 **46%**（121.68 ms vs 122.88 ms 的对比语境下，相对九循环原始模型），同时 Avg-8 提升 **2.20 个百分点**，PPL 更低，代价是额外并行骨干计算。
- **匹配训练计算量**：在 1.68 与 2.16 ZFLOPs 下 LoopFold 的 PPL 与 Avg-8 优于原始循环模型；1.20 ZFLOPs 下原始模型仍领先。
- **吞吐量**：B=1 时 LoopFold（1+3+3，D=5）吞吐为五循环原始模型的 **1.65×**，且随 batch 增大近似线性扩展，速度比稳定在 1.61–1.65×。
- **组件贡献**：去掉校正的损失（ΔPPL +0.34）大于去掉预测（ΔPPL +0.16），说明**校正（纳入早期循环新信息）更关键**；恒等映射优于完全移除，学习映射又优于恒等。
- **状态演化**：完整模型在深度 4 的状态随阶段推进逐渐靠近其自身顺序参考轨迹，而去掉校正后对齐明显变差；但“重复 H₁ 初始化”在浅层反而更接近顺序轨迹，最终 PPL 却更差——说明**最小化与顺序轨迹的瞬时距离并非好并行精炼的必要条件**。
- **概念性结论**：循环深度与顺序解码深度**不必重合**，额外循环计算可以转移到并行维度，只要临时状态随后被校正。

## 7. 优点

- **问题切入精准**：抓住“循环深度 = 顺序延迟”这一根本瓶颈，而非仅在 token 位置维度做流水线。
- **方法简洁且轻量**：预测器/校正器均为逐 token 线性映射（`I + ΔJ`，零初始化），额外参数仅 8.39M（1.4B 模型），且与骨干端到端联合训练，无需多阶段训练或额外监督。
- **校正机制设计巧妙**：用“输入变化量”修正“陈旧输出”，并按深度顺序传播，使并行批次内仍保留信息流的因果性。
- **实验框架严谨**：明确区分“匹配训练计算量 / 可比延迟 / 匹配目标深度”三种制度，避免把不同固定量的结果混为一谈；同时报告 PPL、八任务零样本、延迟与吞吐，覆盖质量与效率两个维度。
- **消融有层次**：组件移除 → 恒等 vs 学习 → 状态相似度分析，层层递进，并诚实指出“贴近顺序轨迹≠更好质量”这一反直觉发现。
- **工程视角完整**：讨论 KV 缓存膨胀问题并给出 First-KV reuse / Hard overwrite-64 两种折中方案。

## 8. 不足与局限

- **计算成本上升**：以额外 FLOPs 换延迟，总骨干评估次数为 `1 + n(S−1)`，多于同深度原始模型；论文自己也承认这是主要代价。
- **KV 缓存内存膨胀**：默认需为每次循环评估存独立 KV（如 7×），KV 共享方案虽降至 5×，但带来 PPL 轻微上升（7.62→7.68/7.63）与延迟增加（99.89→103.21/104.94 ms）。
- **规模与数据覆盖有限**：主实验仅 1.4B 模型、Pile 30B token、英文八任务；未验证更大模型、更多数据或多语言场景的泛化性。
- **消融规模偏小**：组件分析与状态分析均在 410M/25B 上完成，未在 1.4B 上复核，结论的可迁移性存疑。
- **基线覆盖不完全**：作者主动省略了循环深度并行采样器（因需 per-loop 输入注入），也未与 PonderLM、Ouro 等自适应深度方法直接对比。
- **硬件信息缺失**：未报告 GPU 型号/数量/训练时长，影响算力成本核算与可复现性。
- **收益递减**：图 2 显示固定阶段数下增加并行宽度的边际 PPL 增益递减，方法在极宽并行时性价比会下降。
- **延迟测量条件单一**：主比较为 batch=1、关闭张量并行，未覆盖真实服务中张量并行/连续批处理等场景。
