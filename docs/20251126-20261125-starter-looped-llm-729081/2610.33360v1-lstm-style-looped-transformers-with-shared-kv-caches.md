## 摘要
循环 Transformer 通过复用权重，以更少参数完成深层计算。我们研究一种 LSTM 风格的 Transformer，它还在其循环核心中共享一个键值缓存。在宽度 1024 下，与不共享权重的对照模型相比，在几乎匹配的前向 FLOPs 下，它使用的参数少 40.4%，并将持久缓存集从十五个减少到四个。并行训练由标准注意力前向过程提供缓存条目，而续接阶段读取使用共享注意力递归产生的条目。我们在固定训练 token 预算的最后 10% 期间，通过一致性损失对齐两个训练阶段的缓存条目，以解决这种不匹配。在 FineWeb 的三个模型宽度上，这消除了相对于全缓存评估的 81--89% 的续接损失惩罚。该改进在两个训练随机种子下的不相交文档上得到复现。在四种宽度和 1.05--4.19B 训练 token 下，权重绑定的损失代价在较低 token 预算时最小，这表明在数据和模型存储受限时有机会使用循环计算。

## Abstract
Recurrent transformers reuse weights to perform deep computation with fewer parameters. We study an LSTM-style transformer that also shares one key--value cache across its recurrent core. At width 1024, it uses 40.4% fewer parameters than an untied control at nearly matched forward FLOPs, and reduces persistent cache sets from fifteen to four. Parallel training supplies cache entries from a standard-attention pass, whereas continuation reads entries produced recursively using shared attention. We address this mismatch by aligning the two training passes' cache entries with a consistency loss during the final 10% of a fixed training-token budget. Across three model widths on FineWeb, this removes 81--89% of the continuation-loss penalty relative to full-cache evaluation. The improvement replicates on disjoint documents for two training seeds. Across four widths and 1.05--4.19B training tokens, the loss cost of weight tying is smallest at lower token budgets, suggesting an opportunity to use recurrent computation when data and model storage are limited.

# 《LSTM-Style Looped Transformers with Shared KV Caches》论文总结

## 1. 核心问题与研究动机

- **背景**：循环/权重绑定 Transformer（Universal Transformer、ALBERT、Huginn 等）通过重复应用同一组 Transformer 块，将“参数数量”与“计算深度”解耦，从而以更少参数完成更深的计算。
- **被忽视的代价**：权重虽被复用，但**注意力 KV 缓存通常不被复用**——每次迭代、每个块都要为前序 token 单独存一份 K/V。因此一个循环模型在推理时仍需存储 P + K·R + E 组缓存（本文默认配置为 15 组），存储开销并未随参数一起下降。
- **核心问题**：能否在“权重绑定”的基础上，让整个循环核心**共享同一份 KV 缓存**？以及：并行训练时缓存由标准注意力产生，而推理续写时缓存由共享注意力递归产生，这种**训练-推理不一致**会带来多大损失惩罚，能否用训练目标缓解？
- **整体含义**：论文系统测量了“参数共享”和“缓存共享”两种压缩手段各自的损失与计算代价，并指出权重绑定的损失代价在**较低 token 预算**下最小，暗示在数据与存储受限场景下循环计算更有价值。

## 2. 方法论

### 2.1 架构：P1E2 + LSTM 式门控循环

- 结构为 **1 个非绑定 prologue 块 + 4 个权重各异的 core 块 + 2 个非绑定 epilogue 块**；core 重复 3 次（R=3），共 15 次块应用但只有 7 组块权重。
- 注意力窗口：prologue 与第一个 core slot、最后一个 epilogue 用 2048 长窗，其余用 1024 短窗；15 层非绑定对照在索引 0/4/7/10/14 使用长窗，保证长短窗应用次数一致。
- 其他组件：Pre-RMSNorm（带学习增益）、RoPE、GQA（2 个 query head 对应 1 个 KV head，head 维 64）、SwiGLU、无增益的 per-head QK RMS 归一化、输入输出 embedding 共享。

### 2.2 LSTM 式深度循环更新

设 $N$ 为无增益 RMSNorm、$N_g$ 为带增益的候选归一化，初始 $s=N(P(x))$，$c_0=h_0=s$，每次迭代：

$$g_r = N_g(F(h_{r-1})),\quad f_r=\sigma(W_f h_{r-1}+b_f),\quad i_r=\sigma(W_i h_{r-1}+b_i)$$
$$c_r = f_r \odot c_{r-1} + i_r \odot g_r,\qquad h_r = N(c_r)$$

- 门控按 token 与通道作用，**无 tanh、无输出门**；carry $c$ 累积信息，其归一化读出 $h$ 供下一次 core 应用、门控和 epilogue 使用。
- 门矩阵零初始化，$b_f=1$、$b_i=0$，初始门值约 0.7311 / 0.5；配合恒等初始化的块，首次更新保持方向不变（$c_1=1.2311s,\ h_1=h_0$）。

### 2.3 共享 KV 缓存策略

- **唯一 donor**：整个 core 只用一份缓存——**最后一个 core 块、最后一次迭代自己算出的 K/V**。
- 所有 core 块、所有迭代在**前序位置**读这份 donor，在**当前位置**仍用自己算的 K/V；注意力仍遵守各块的窗口与文档边界；prologue 与 epilogue 保留独立缓存。
- 结果：缓存集从 $P+KR+E=15$ 降为 $P+1+E=4$；K 在 QK 归一化与 RoPE 之后存储。

### 2.4 两遍训练目标

1. 第一遍用标准注意力，得到 CE₁，并保留 donor；
2. 从同一 prologue 种子重启循环，用保留的 donor 做共享缓存注意力，重算 epilogue 得 CE₂；
3. 最小化 $\mathcal{L}_{2p}=\tfrac12 CE_1+\tfrac12 CE_2$，donor 保留在计算图中，第二遍损失也会更新缓存生产者。

### 2.5 Donor 一致性损失（修复训练-推理不匹配）

- 令 $X_1,X_2$ 分别为两遍各自最终 donor 张量（$X\in\{K,V\}$）：

$$e_X=\frac{\text{mean}\big[(X_2-\text{stopgrad}(X_1))^2\big]}{s_X+10^{-6}},\qquad \mathcal{L}=\mathcal{L}_{2p}+\frac{\gamma}{2}(e_K+e_V),\ \gamma=0.3$$

- $s_X$ 为分支起点标定一次的参考均方（16 个 8192-token chunk），此后固定；只有辅助目标被 detach，第一遍 donor 经第二遍 CE 的梯度仍然有效。
- **施加方式**：从父模型最终 decay 起点分支，重跑最后 1600 次更新（占 4.19B token 预算的 10%），保持优化器状态、数据流与学习率日程不变。

### 2.6 变深度与停止规则

- 训练时 $R\sim U\{3,\dots,6\}$；推理时用相邻读出状态的余弦相似度 $q_{r,t}=\frac1d\langle N(h_{r,t}),N(h_{r-1,t})\rangle$，当 $q>0.98$（且 $r\ge2$）停止，上限 6 次。

## 3. 实验设计

- **数据**：FineWeb，统一由 modded-nanogpt 框架训练；全局 batch 262,144 token（32 个 8192-token chunk），注意力不跨 chunk/文档。
- **规模网格**：宽度 384/512/768/1024；训练 token 预算 1.048576B / 2.097152B / 4.194304B（对应 4000/8000/16000 次更新）。
- **四个训练变体**：15 层非绑定对照；单遍标准缓存 cell；两遍共享缓存 cell；其修复分支。
- **评测协议**：
  - **Chunk 验证**：1280 个 chunk × 8192 = 10,485,760 个目标；标准验证与并行共享缓存验证。
  - **Prompt-prefill 续写（主指标）**：1280 篇文档，2048 prompt + 512 计分目标（655,360 目标），teacher forcing，全缓存 vs 共享缓存对比同一批目标。
  - 诊断设置：512 prompt + 2048 目标；两遍 prefill 诊断；冷启动逐 token 顺序评测。
  - **留出确认**：另取 1280 篇不相交文档，在两个训练种子上验证 width-768 修复。
- **对照/消融**：
  - 参数匹配的跨宽度对比（width-1024 循环 vs width-768 非绑定）；
  - 训练算力近似匹配对比（两遍 2.097B vs 非绑定 4.194B）；
  - 更新规则 2×2 因子实验（门控 carry / 普通覆盖 × 有无输入注入）＋ Huginn 式注入基线；
  - 梯度截断（仅回传最后 8 次）与深深度（R 到 32/64）；
  - 一致性损失变体（donor-only / donor+epilogue / 加输出蒸馏、γ ∈ {0.1,0.3,1.0}、全程施加 vs 晚期施加、优化器重置 pilot）；
  - 早期缓存生产者 vs 晚期生产者；2 vs 4 次 refinement sweep；
  - 变深度训练与逐 token 停止规则；
  - 实测显存与解码时延（单卡 H100，batch 1/16/64/160）。

## 6. 主要结论与发现

1. **参数与缓存双重压缩可行**：width 1024 下参数比同宽非绑定对照少 **40.4%**，前向 FLOPs 仅多 1.5–2.4%，持久缓存集从 **15 降到 4**（等长 ring 下存储省 3.75×，按实际窗口分配省 2.86×）。
2. **权重绑定有损失代价，且随 token 预算增大而增大**：width 768 三个种子上，两遍模型共享减非绑定的差距从 1.05B 的 0.0115 增到 2.10B 的 0.0209、4.19B 的 0.0309（种子标准差 0.0009/0.0014/0.0025）；差距随宽度增大而缩小。即在**低 token 预算**下绑定的代价最小。
3. **两遍训练存在续写惩罚**：width 768 上全缓存 3.2827 vs 共享续写 3.3347，惩罚 0.0520；短 prompt/长续写设置下更大（0.0826）。
4. **晚期 donor 一致性显著修复该惩罚**：三个宽度上消除 **81–93%**（摘要口径 81–89%）的惩罚，全缓存损失仅增加 0.0011–0.0025，通过预设的 chunk 质量门槛（≤0.005）；留出文档上两个种子分别改善 0.0434/0.0298，惩罚下降 80%/75%。
5. **跨宽度参数匹配**：修复后的 width-1024 循环模型（136.2M）比 width-768 非绑定（135.98M）续写损失低 0.0441 nats，但前向 FLOPs 为 1.66×、估计训练算力为 3.22×；同宽非绑定对照（228.49M，3.1515）仍更优。
6. **门控 carry 在训练深度上有效但不鲁棒**：比普通覆盖好 0.0321；但迭代翻倍到 6 次时损失从 3.4517 升到 4.0125，而注入式/Huginn 式更耐受额外深度。梯度截断对 cell 伤害大（深度 32 时 +0.0757），对注入式反而有益（−0.0140）。
7. **停止规则不划算**：固定深度 4（3.3761，4 次）优于余弦停止（3.3816，平均 4.75 次）。
8. **显存省但时延不省**：batch 160 时填充缓存峰值显存比标准布局低 2.72–2.77×、比非绑定低 2.85–2.87×；但 width 1024/batch 160 下共享缓存解码 37.2 ms vs 标准 20.7 ms，原因未定位。

## 7. 优点

- **问题切分清晰**：把“参数共享”与“缓存共享”视为两种独立代价分别测量，避免了笼统宣称“循环模型更高效”。
- **指标设计严谨**：区分 chunk 验证、并行
