## 摘要
深度循环通过反复应用固定的计算块来提高有效模型深度。然而，共享注意力参数并不会共享在不同循环迭代中生成的键值（KV）状态，这会在自回归解码过程中导致内存随循环深度增长。我们在一个通用的深度循环框架内，研究如何通过架构和缓存共享方法来降低这一内存开销。我们首先研究一种循环混合架构，它重复一个 Transformer 层堆栈，其中循环 mLSTM 或 Gated DeltaNet 块替代大多数注意力层，并保留周期性的 Transformer 注意力锚点。然后，我们在 Parcae 风格架构中将循环限制在专用的循环工作区，并测试其稳定化适配器作为循环混合架构的包装器。最后，我们训练一种带有循环 KV 重放的循环 Transformer，其中只有选定的循环迭代写入 KV 状态，供后续迭代复用。这训练模型在推理时使用相同的共享 KV 拓扑运行。我们发现，循环混合架构需要足够频繁的注意力锚点，其性能强烈依赖于循环混合器。对于跨迭代 KV 共享，循环 KV 重放允许多个循环迭代复用相同的 KV 状态，同时保持性能接近为每次迭代使用独立 KV 缓存的完整循环 Transformer。

## Abstract
Depth recurrence increases effective model depth by repeatedly applying a fixed computation block. However, sharing attention parameters does not share the key-value (KV) states generated at different recurrence iterations, which causes memory growth with recurrence depth during autoregressive decoding. We study how to reduce this memory cost through architectural and cache-sharing approaches within a common depth-recurrent framework. We first study a looped hybrid that repeats a stack of Transformer layers, with recurrent mLSTM or Gated DeltaNet blocks replacing most attention layers and periodic Transformer attention anchors retained. We then restrict recurrence to a dedicated recurrent workspace in a Parcae-style architecture and test its stabilising adapter as a wrapper for the looped hybrid. Finally, we train a looped Transformer with recurrent KV replay, where only selected recurrence iterations write KV states that later iterations reuse. This trains the model to operate with the same shared KV topology used during inference. We find that looped hybrids require sufficiently frequent attention anchors, with performance depending strongly on the recurrent mixer. For cross-iteration KV sharing, recurrent KV replay allows multiple recurrence iterations to reuse the same KV states while retaining performance close to the full looped Transformer with separate KV caches for each iteration.

# 论文总结：深度循环语言模型的架构与 KV 重放

## 1. 核心问题与整体含义

- **背景**：深度循环（depth-recurrent / looped）语言模型将一组物理层堆栈重复应用 R 次，以 L×R 的有效深度换取远少于等效 Transformer 的参数存储与优化器状态，并支持推理时通过改变循环次数来扩展算力。
- **核心矛盾**：注意力参数跨循环共享，但**各循环迭代产生的 KV 状态无法共享**。自回归解码时，KV 缓存大小随序列长度、层数、批大小、头维度以及**循环迭代数**线性增长，形成"参数省了、显存没省"的困境。
- **研究问题**：如何在保留精确注意力（exact attention）收益的前提下，降低深度循环模型的推理内存？
- **整体含义**：论文在统一深度循环框架下，从"改架构"与"改缓存拓扑"两条路线系统比较三种降低显存的方案，为深度循环模型的实际部署提供实证参考。

## 2. 方法论

### 2.1 循环混合架构（Looped Hybrid）
- 逻辑堆栈含 L 个垂直位置，执行 R 次循环；精确注意力 Transformer 锚点集合为 A，其余位置用循环序列混合器（mLSTM 或 Gated DeltaNet）替代。
- 锚点层：`h_{r,l+1} = T_l(h_{r,l}; θ^T_l)`，Transformer 参数 θ^T_l 跨循环共享。
- 循环层：`u_{r,l} = M_{r,l}(h_{r,l}; θ^M_{r,l})`，`h_{r,l+1} = u_{r,l} + F_l(u_{r,l}; θ^F_l)`——混合器参数按循环迭代独立，MLP 参数在同一垂直位置跨循环共享。
- 引入**锚点步长 sd**：每 sd 层放一个 Transformer 锚点；sd 越小，精确 token 级交互重建越频繁，但注意力计算与 KV 产生位置也越多。

### 2.2 PARCAE 风格架构与包装器
- 遵循 Prelude / recurrent Core / Coda 分解：Prelude 产出表示 e，投影到循环工作区；每次迭代先过输入注入适配器 `ez_t = I(z_t, e)`，再过 mLSTM 核心 `z_{t+1} = C(ez_t; θ^C)`；R 次后投影回隐藏维，经 Coda 输出。
- 训练时采样前缀深度 n（仅推进状态、不建图）与后缀深度 k（保留在 autograd 图中），实现截断反传与随机循环调度。
- **稳定化适配器**：`d_t = softplus(dt_bias)`，`A = exp(A_log)`，`decay = exp(−d_t·A)`，`x_{t+1} = x_t ⊙ decay + d_t(eB^⊤)`，通过反复注入原始表示 e 抑制循环漂移。
- **包装器消融**：仅把该适配器套在循环混合架构每次循环之前（`eh_r = I(h_r, h_0)`，`h_{r+1} = H(eh_r)`），不引入 Prelude/Core/Coda 分解。

### 2.3 KV 重放与缓存压缩训练
- 核心公式：`Attn_{r,l} = softmax(Q_{r,l}K_{b_r,l}^⊤/√d_k)V_{b_r,l}`，其中 `b_r = r` 为标准注意力，`b_r ≠ r` 为 KV 重放。
- **两种范式**：
  - *仅推理压缩*：按普通注意力训练，解码时强行复用早期迭代的 KV，导致训练/推理 KV 来源不一致。
  - *缓存压缩训练（KV replay）*：训练前向即按目标共享策略执行，迭代分为**写入者**（计算并存储新 KV）与**读取者**（只算新 Q、复用最近写入者的 KV）；重放字典仅存在于单次训练前向中，不是生成长缓存。
- **三种路由策略**（以 (r,l) → 缓存组 g(r,l) → 槽位 c(r,l)=g(r,l)·L+l）：
  - *Stride-s 缓存*：`g(r,l)=⌊r/s⌋`，`w(r,l)=1[r mod s=0]`；s=R 退化为全共享，s=1 退化为逐迭代独立。
  - *选择性循环缓存*：选定循环集 U 获得独立组（偏移 +1），其余落入共享组 0；`w=1[r∈U] ∨ 1[r=0]`。
  - *选择性层缓存*：选定 Transformer 锚点层 S 获得逐循环独立缓存，其余层共享组 0。

## 3. 实验设计

- **训练数据**：Nemotron-CC-HQ 语料，m2rnn-400m 分词器，统一约 5.03B token 预算（`4096×64×4×4800`）。
- **评测基准**：PIQA、WinoGrande、ARC-Easy、HellaSwag、ARC-Challenge、SciQ（归一化准确率）、CORE / CORE-Extended（百分点，报告评估种子均值±标准差）、WikiText 困惑度；GSM8K 采用 8-shot 思维链、每题 8 次生成，报告 Majority@8 / Pass@8 及 95% bootstrap 置信区间。
- **对比方法/配置**：
  - **基线**：24 层非循环 Transformer（406.37M 参数，4096 序列长度）。
  - **循环混合**：主设置 24 层 × 4 循环 × 4096 长度，sd ∈ {2,3,4,6,8,12}；mLSTM 与 GDN 对比；另有 12 层 × 8 循环匹配设置；以及 PARCAE 适配器包装器消融（sd=4/6/8/12）。
  - **PARCAE**：12 层 × 8 循环 × 2048 长度，d_r ∈ {768,1024,1536} × 分配 {2/4/6, 4/4/4, 6/4/2}；额外训练 2/4/6、d_r=1536 的 29.6B token 版本。
  - **KV 重放**：24 物理层 × 6 循环全循环 Transformer，stride 2 与 stride 3，覆盖训练/推理拓扑匹配与不匹配组合，并与"仅推理压缩"对照。

## 6. 主要结论与发现

- **循环混合**：需要足够密集的注意力锚点；性能强烈依赖循环混合器选择。mLSTM 下更密锚点（更小 sd）总体更好，但不呈严格单调；**GDN 显著优于 mLSTM**，且在 sd=2–6 间较为稳健（如 sd=6 时 CORE 18.79、PPL 29.97，接近甚至局部超过基线）。
- **PARCAE 适配器包装器**：单独套用会**严重损害**循环混合性能（CORE 降至负值、PPL 飙升至 961–2768），说明仅靠输入重注入不足以稳定循环混合架构。
- **PARCAE 本体**：增大循环工作区维度 d_r 并不带来一致提升，效果依赖 Transformer 层在核心两侧的分配；29.6B token 扩展训练在所有指标上均优于同配置 5.03B 版本（CORE 15.10 vs 12.47，PPL 35.75 vs 45.29），接近基线。
- **KV

- **KV 重放与缓存压缩**：训练/推理拓扑是否匹配是决定 KV 重放能否生效的关键变量。若仅在推理阶段强行复用早期迭代 KV、而训练时仍按标准逐迭代注意力执行，则训练与推理的 KV 来源不一致，模型质量明显退化；反之，在训练前向中即按目标共享策略执行“写入者/读取者”路由，可让模型适应压缩后的缓存拓扑，从而在相同压缩率下取得更好的质量—显存折中。
- **压缩率与质量的权衡**：stride-s 缓存通过增大 s 提高共享程度、降低 KV 缓存规模，但压缩越强，循环迭代间可用的精确历史信息越少，性能通常越受限；s=1 等价于逐迭代独立缓存、无压缩收益，s=R 等价于全循环共享、压缩最强。选择性循环缓存与选择性层缓存提供了介于两者之间的细粒度折中：前者只让部分循环保留独立缓存，后者只让部分 Transformer 锚点层保留逐循环缓存，从而把有限的缓存预算分配给更需要的循环或层。
- **内存分析**：解析公式与实测峰值显存均表明，深度循环模型的 KV 缓存随循环迭代数线性增长，是推理内存的主要来源之一；KV 重放能够实质性降低解码峰值显存，但收益大小取决于共享粒度与路由策略。论文由此强调：深度循环模型“参数省显存”的优势不会自动转化为推理显存优势，必须同时设计缓存拓扑。
- **总体结论**：三条路线各有侧重——循环混合通过“少而精”的精确注意力锚点加高效序列混合器控制 KV 产生位置；PARCAE 类工作区架构通过循环核心与稳定化适配器改变状态承载方式，但单独包装适配器并不能稳定循环混合架构；KV 重放则在不改架构的前提下直接压缩缓存，但要求训练时即模拟推理共享拓扑。论文的核心实证信息是：深度循环语言模型的实际部署需要把**架构锚点密度、循环混合器选择、训练时缓存拓扑一致性**作为联合设计问题，而非仅追求参数共享。

## 7. 局限与需谨慎解读之处

- **资源未对齐**：基线、循环混合与 PARCAE 的参数量差异较大（约 241M–1.47B），并非等参数、等 FLOPs 的严格对照；作者亦将其定位为探索性比较。
- **训练预算偏短**：主实验约 5.03B token，明显短于相关 PARCAE 工作的 29.6B token；扩展训练结果虽显示更长训练可缩小差距，但尚未覆盖更大模型与更长上下文。
- **统计稳健性有限**：主要训练仅单一随机种子，GSM8K 绝对分数很低且仅单种子，CORE 类指标虽报告评估种子波动，但不足以全面刻画方差。
- **评测范围**：以常识推理、语言建模困惑度和 8-shot GSM8K 为主，未系统评估长上下文、指令微调、服务吞吐、批大小变化下的实际显存—延迟曲线。
- **KV 重放结论的边界**：结论主要建立在 24 层×6 循环的全循环 Transformer 与 stride 2/3 配置上；更强压缩、不同层数/循环数、与其他注意力变体结合时的行为仍需验证。

## 8. 对后续研究的启示

- 深度循环模型的“参数效率”与“推理内存效率”应分开评估；报告参数量时需同时报告随循环数增长的 KV 缓存开销。
- 若采用 KV 重放，训练阶段应显式采用目标推理拓扑，避免训练/推理不一致；选择性层缓存可能是比全局共享更可控的折中方向。
- 循环混合架构中，精确注意力锚点的密度与混合器类型存在强交互；GDN 在本文设置下优于 mLSTM，但需在等参数、等算力、多种子条件下进一步确认。
- PARCAE 类适配器的稳定化效果依赖完整 Prelude/Core/Coda 与训练调度，简单“包装器”式移植可能适得其反。
