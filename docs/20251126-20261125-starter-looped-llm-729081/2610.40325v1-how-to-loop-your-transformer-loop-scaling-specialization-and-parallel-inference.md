## 摘要
Transformer 模型中的循环通过重复应用同一个 Transformer 或其部分来复用权重，从而在不增加参数量的情况下加深模型。循环是否有用取决于哪项约束占主导：模型规模、训练算力，还是自回归推理效率。我们在从零训练的稠密仅解码器 Transformer 中联合研究这些权衡，改变模型中被循环的部分、循环次数以及循环之间的信息传递方式。我们的实验涵盖最多 10 亿参数的模型，训练数据最多 1550 亿 token，算力最高达 $1.07\times10^{21}$ FLOPs，循环次数最多 32 次。我们发现，在固定参数预算下，循环整个 Transformer 通常能获得最强的质量；而当训练 FLOPs 受限时，循环中间层块能带来更好的回报。增加循环并非总是有益：收益最终会饱和、反转或变得不稳定。这促使我们追问：强制每个循环使用相同权重是否会限制更深循环带来的收益。我们通过添加小型、特定于循环的低秩适配器来解决这一问题，这些适配器能提升质量，且随着循环次数增加，收益更大。循环 Transformer 还会出现与循环次数成正比的解码减速。Parallel Loop Transformers 通过在相邻 token 位置之间跨循环传递隐藏状态来解决这一问题，使各循环阶段能够并发运行。然而，在我们的实验中，原始形式并不能稳定保留普通循环带来的质量收益。我们发现，保留当前 token 的嵌入，并在合并之前分别对其和前一 token 的隐藏状态进行归一化，可以在不同模型规模和训练预算下恢复强劲性能。总之，这些结果表明，有效的循环需要使设计匹配资源约束和推理设置。

## Abstract
Looping in transformer models reuses weights by repeatedly applying the same transformer, or parts of it, making the model deeper without increasing its parameter count. Whether looping is useful depends on which constraint dominates: model size, training compute, or autoregressive inference efficiency. We study these trade-offs jointly in dense decoder-only transformers trained from scratch, varying which parts of the model are looped, how many loops are applied, and how information is passed between loops. Our experiments span models with up to 1B parameters, trained on up to 155B tokens with up to $1.07\times10^{21}$ FLOPs and 32 loops. We find that looping the full transformer generally gives the strongest quality at a fixed parameter budget, whereas looping a middle block of layers gives a better return when training FLOPs are constrained. Adding loops is not uniformly beneficial: gains eventually saturate, reverse, or become unstable. This motivates asking whether forcing every loop to use the same weights limits the benefit of deeper looping. We address this by adding small loop-specific low-rank adapters that improve quality, with larger gains as more loops are added. Looped transformers also suffer a decoding slowdown proportional to the number of loops. Parallel Loop Transformers address this by passing hidden states between loops across adjacent token positions, allowing loop stages to run concurrently. However, in our experiments the original formulation does not consistently retain the quality gains of ordinary looping. We find that preserving the current-token embedding and separately normalizing it and the previous-token hidden state before combining them recovers strong performance across model scales and training budgets. Together, these results show that effective looping requires matching the design to the resource constraint and inference setting.

## 2. 方法论

### 2.1 循环放置与计算顺序（七种设计）

- **Full-Stack Looping**：整个 Transformer 堆栈重复 L 次，`H^(L) = F_θ^∘L(X)`。
- **Per-Layer Looping**：每个 block 先完成 L 次循环再进入下一个 block；与 Full-Stack 参数量与总 block 评估次数相同，仅执行顺序不同。
- **Middle-Stack / Middle-Layer Looping**：保留首尾各 ⌊B/3⌋ 个 block 只跑一次，仅对中间连续区域做堆栈级或逐层循环，有效深度为 `B + (L−1)M`，训练算力更低。
- **子层循环**：Attention-Only、MLP-Only、Attention 与 MLP 独立循环（`T_ind = M^∘RM ∘ A^∘RA`）。

### 2.2 循环专属特化（Loop-Specific Specialization）

- 核心思想：共享主权重 `W`，为每个循环 ℓ 添加小型低秩修正 `W^(ℓ) = W + ΔW^(ℓ)`，兼顾参数节省与表达差异化。
- 三种实现（rank ≤ 8，unit scaling，与主权重联合从零训练）：
  - **Loop LoRA**：每个循环独立一对 `B_ℓA_ℓ`。
  - **Loop Matrix**：学习 `L×L` 混合矩阵 `M`，`ΔW^(ℓ) = Σ_j M_ℓj B_jA_j`，可组合多个低秩分量、有效秩更高。
  - **Loop Softmax**：用 `softmax(S_ℓ,:)` 约束混合系数非负且归一化。
- 参数量对比：严格共享为 `d_in·d_out`；Loop LoRA 为 `d_in·d_out + L·r(d_in+d_out)`；完全独立为 `L·d_in·d_out`。

### 2.3 并行循环与归一化重注入（对 PLT 的修正）

- **Cross-Loop Parallelism（CLP）**：第 ℓ 个循环在 token n 处接收 `b_n^(ℓ) = e_n + h_{n−1}^(ℓ−1)`，即用**前一 token** 的上一循环状态替代当前 token 状态，使各循环可在解码时批量并行。
- **原始 PLT 的配套机制**：KV sharing（后续循环复用第一循环的全局 KV cache）+ Gated Sliding-Window Attention（G-SWA，用学习到的 head-wise 门控融合共享全局 cache 与循环私有滑窗 cache），将 KV 内存从 `O(LND)` 降到 `O(ND + (L−1)wD)`。
- **论文的关键修正**：
  1. 保留当前 token 嵌入 `e_n`（消融显示去掉后性能劣于 Vanilla 甚至发散）；
  2. 对 `e_n` 与循环状态 `r_n^(ℓ)` **分别做 RMSNorm**，再用门控混合：
     `b_n^(ℓ) = g_n^(ℓ) ⊙ ē_n + (1 − g_n^(ℓ)) ⊙ r̄_n^(ℓ)`，其中 `g ∈ [0,1]^d`。
  3. 门控对比了固定 50/50、标量门、rank-8 线性门、rank-8 MLP 门，最终默认 rank-8 线性门（仅增加 <0.015% 非嵌入参数）。
- 命名：**Normalized Shifted PLT**（可并行解码）与 **Normalized Unshifted PLT**（同 token 传递、仍串行，作为质量参照）。

## 6. 主要结论与发现

1. **循环位置取决于约束类型**：
   - 固定参数预算下，**Full-Stack Looping 质量最佳**，且随模型规模与 TPP 增大优势更明显。
   - 训练 FLOPs 受限时，**Middle-Stack Looping 回报更高**（只重复中间块，算力增量小）。
2. **循环次数并非越多越好**：L ≤ 16 时普遍有增益，但边际收益递减，L 很大时会出现**饱和、反转甚至训练不稳定**；低 TPP 更早饱和；Attention/MLP 独立循环最不稳定。
3. **循环专属特化随循环加深而更有价值**：L=2 时收益微弱，L=4/8 时明显；Loop Matrix 通常最强；仅增加 1.1%–4.3% 非嵌入参数（对比物理深度 ×2 需 +51.4%）。但**同等训练 FLOPs 下，物理加深仍优于循环特化**——特化是"参数高效"而非"算力高效"。
4. **原始 PLT 会损失质量**，主因是**跨 token 位移重注入接口**（而非 KV 共享本身）：嵌入与隐藏状态尺度差异大（隐藏态 RMS 可达嵌入的 10×–600×），直接相加会被大尺度项主导。
5. **修正方案有效**：分别 RMSNorm + 门控混合 + 保留当前 token 嵌入，可使 Normalized Shifted PLT 在 L=2 时**匹配甚至超过 Full-Stack Looping**，并保持并行解码；L=4 时仍略逊于 Unshifted 版本但具竞争力。去掉当前 token 嵌入会导致性能劣于 Vanilla 甚至发散。
6. **循环可同时提升数据效率与 FLOP 效率**（在过训练区间）：1B 模型上，两循环 TPP=80 的模型达到相同 BPB 所需 FLOPs 少于 Vanilla TPP=160；但 L=4 的每 FLOP 回报更弱。
7. **下游任务**：1B 模型上循环方法在 8 任务中 6 项优于 Vanilla（ARC-Challenge、HellaSwag 提升最明显），但 MMLU/MMLU-Pro 仍接近随机水平。

## 7. 优点

- **统一受控的实验框架**：同一数据、tokenizer、训练配置下横向比较七种循环设计与多种特化方法，有效分离"设计效应"与"预算效应"。
- **三维资源视角**：同时以参数量、训练 FLOPs、推理并行性三个维度评估，揭示了单一视角下被掩盖的权衡（如 Full-Stack vs. Middle-Stack 的翻转）。
- **PLT 的组件级归因**：通过逐组件重建（shift → KV sharing → G-SWA → normalization → gate）精确定位质量损失来源，并给出轻量修正（rank-8 门仅增 <0.015% 参数）。
- **规模覆盖广**：70M–1B、TPP 10–160、L 最多 32，跨 10 个评估集，结论稳健性较好。
- **实践指导明确**：给出"参数受限选 Full-Stack、算力受限选 Middle-Stack、需并行解码选 Normalized Shifted PLT（L=2）"的可操作建议。
- **诚实报告不稳定运行**（红三星标记）与缺失配置，未做插补。
