ABSTRACT
Looped Transformers reduce parameter count by repeatedly applying shared blocks,
but parameter sharing alone does not determine how the results of repeated com-
putation are reused. We take the depth-memory view of residual connections and
analyze which representation is stored after each block application and how later
reads weight it. A full block output contains both its input and its new update,
so weighting that output also reweights the history already carried by the input.
Reading individual updates instead, with the shared stack’s input kept on a separate
path, gives separate controls over input strength, total update weight, and allocation
across updates. The Loopback Transformer implements these controls: geometric
decay sets the total update weight and supplies a recency prior, and attention learns
how to allocate that weight. On ClimbMix, Loopback reaches lower validation loss
than standard Transformer baselines with 40–75% of their Transformer parameters
(excluding token embeddings and the output head) at reference scales from 191M
to 3B, with training tokens and executed depth matched. It also has higher mean
accuracy over thirteen downstream tasks at 1.4B and 3B. At 191M, 374M, and
778M, it has the lowest validation loss and the highest thirteen-task mean among
the standard Transformer and seven looped residual designs.

INTRODUCTION
Looped Transformers reduce parameter count by repeatedly applying shared blocks to an evolving
hidden representation (Dehghani et al., 2018; Lan et al., 2019). Sharing separates computational
depth from the number of distinct blocks and supports latent reasoning and inference-time scaling
(Saunshi et al., 2025; Geiping et al., 2026). Each visit applies the same transformation to a different
hidden state and so produces a different update. Parameter sharing fixes which transformation is
reused; it leaves open how the updates from successive visits are stored, carried forward, and used.
Residual connections turn depth into a form of memory: each layer writes new computation into a
residual stream carried forward to later layers. Standard residual addition accumulates block updates
with fixed unit coefficients (He et al., 2016), whereas Attention Residuals (AttnRes) learns how to
weight these updates and the input (Team et al., 2026). Hyper-Connections (HC) and Hyperloop
introduce learned pathways across residual streams or loop visits (Zhu et al., 2025a; Zeitoun et al.,
2026).
This depth-memory view (Team et al., 2026) connects residual design to linear attention and related
recurrent models. Linear attention expresses attention over token history as writes to and reads from
a recurrent memory (Katharopoulos et al., 2020); RetNet and Mamba-2 additionally control how that
memory is retained across steps (Sun et al., 2023; Dao & Gu, 2024). We use this write–transport–read
perspective to analyze repeated computation along depth. Here, each block produces a new write
from a representation assembled from earlier writes, so the memory rule also influences subsequent
computation. We therefore examine what is stored and how memory transitions and readout determine
each update’s contribution.
Seen this way, common residual designs tie together quantities that could be controlled separately.
First, a full block output contains both its input and its new update. Weighting that output therefore
also weights the history carried by the input. Storing updates separately lets the reader assign a
coefficient directly to each update. Second, a joint softmax over the original input and stored updates
makes them compete for a fixed total weight. Ordinary addition instead fixes the input coefficient but
assigns every update weight one, so total update weight grows with the number of block applications.
We therefore want separate controls over input strength, total update weight, and allocation across
updates.
The Loopback Transformer is built around these three controls. It stores individual block updates
rather than full block outputs and keeps the shared stack’s input on a separate path with coefficient
one. Geometric decay assigns a baseline weight to each update. A softmax reader redistributes their
total weight according to update content, using the decay weights as a recency prior. This separates
total update weight from allocation without changing the shared blocks or their token-axis attention.
We compare against the standard Transformer, which uses distinct parameters at every layer (labeled
Standard in tables and figures), and against seven looped residual designs, always at the same budget
of training tokens and the same executed depth. On ClimbMix (Diao et al., 2026), Loopback reaches
lower validation loss and a higher thirteen-task mean than Standard at 191M, 374M, 778M, 1.4B,
and 3B while storing 40–75% of its Transformer parameters (Tables 2, 4 and 9 and Fig. 1). At 191M,
374M, and 778M, it also has the lowest validation loss and the highest thirteen-task mean of all nine
designs (Table 2).
We make three contributions:
• We connect residual designs with linear attention and related recurrent models by adapting their
memory-update rules from token sequences to network depth. The resulting framework describes
what each block writes and how its contribution is transported and read.
• Within this framework, we design the Loopback Transformer, which adds a weighted sum of
block updates to the original loop input. Geometric decay keeps the total update weight bounded
as visits increase at fixed stack size. Attention adjusts each update’s weight according to its
content while preserving the total.
• On ClimbMix, Loopback reaches lower validation loss and higher zero-shot task means than
matched-depth standard Transformers at five scales from 191M to 3B, with 40–75% of their
Transformer parameters.

PRELIMINARIES
2.1
LOOPED TRANSFORMER
A looped Transformer shares parameters across depth by repeatedly applying the same sequence of
Transformer blocks. Each block contains causal token attention followed by an MLP, with a residual
connection around each computation. We call this shared sequence a stack, consisting of K distinct
blocks with transformations f0, . . . , fK−1.
We adopt Huginn’s prefix–middle–coda layout (Geiping et al., 2026), with P prefix blocks, a shared
middle stack of K blocks repeated for R loop iterations, and C coda blocks. Following Zeitoun
et al. (2026), we denote this topology by [PL →KL (×R) →CL], where the suffix L denotes
layers, counting each block application as one layer of executed depth. The model stores P + K + C
distinct blocks and executes P +RK +C block applications. Let h0 be the prefix output entering the
shared stack. Within this stack, r ∈{0, . . . , R −1} indexes loop iterations, and k ∈{0, . . . , K −1}
identifies a block’s position within each iteration. The index s = rK + k ∈{0, . . . , RK −1}
counts block applications across all iterations. At application s, we apply the shared block fk, where
k = s mod K.
To describe how residual connections carry computation across depth, we distinguish a block’s full
output from the update it produces. Let hs denote the aggregated hidden representation before
application s, and let xs be the input passed to block fk. A single-stream model passes one hidden
representation between blocks, so xs = hs; a multi-stream model may form xs by mixing several
parallel hidden states. Aggregating the block’s result with stored computation produces the next
readout hs+1. The full block output is fk(xs), and the block update is
δs = fk(xs) −xs.
(1)
We suppress batch and token indices; each token’s block update is in Rd, where d is the hidden width.
The block update measures the change produced by the block itself, before residual aggregation.

RESIDUAL CONNECTIONS AS DEPTH MEMORY
Following the depth-memory view (Team et al., 2026), we describe residual connections and recurrent
memory by the same write, transport, and read operations. We first compare full block outputs with
individual block updates as the stored value, then expand the recurrence to see how the original input
and earlier block updates enter later hidden states. The expansion is what we use to compare how
existing residual designs reuse earlier computation, and it leads to the design of Loopback.

3.2
OUTPUTS VERSUS UPDATES
A full block output fk(xs) = xs + δs contains both the current block update and earlier computation
carried by its input. A read weight on this output therefore applies to both. Storing δs separately lets
the read assign a coefficient directly to that block update.
Consider two successive full block outputs under ordinary residual addition: h1 = h0 + δ0 and
h2 = h0 + δ0 + δ1. Let ρ ∈[0, 1] be the read weight on h1, with the remaining weight 1 −ρ
assigned to h2. Their weighted read is
ρh1 + (1 −ρ)h2 = h0 + δ0 + (1 −ρ)δ1.

hold for reweighted trajectories. Reading updates separately removes the cumulative-sum restriction.

LOOPBACK TRANSFORMER
Storing block updates separately allows each read weight to act directly on one update. Loopback
uses this representation to form each new hidden state from the original loop input h0 and a weighted
sum of past block updates (Fig. 3). Geometric decay bounds their total weight as loop iterations
increase, while attention adjusts their relative weights using update content. The input stays outside
this allocation with coefficient one, preserving the usual residual identity path: if all updates vanish,
the shared stack returns h0. Only the residual aggregation changes; the shared blocks are unchanged.
4.1
GEOMETRIC DECAY SETS THE PRIOR AND TOTAL WEIGHT
High representation similarity has been observed across depth in Pre-Norm Transformers and across
iterations in looped Transformers (Zhu et al., 2025a; Zeitoun et al., 2026). If successive block updates
share a common component, ordinary residual addition reinforces that component at every iteration.
Decay limits this accumulation by shrinking the weights of earlier updates. The decay-only reference
accumulates updates within each loop iteration and applies a fixed retention 0 < λ ≤1 at its end.

depth: blocks supply the values, retention defines their prior weights, and attention reads them to
form later block inputs. Its explicit history allows individual updates to be reweighted. The bank
requires O(KRd) storage, and total read work is O((KR)2d) per token beyond block computation.
5
EXPERIMENTS
We evaluate parameter efficiency, residual designs, and readers on ClimbMix (Diao et al., 2026).
Main comparisons match training tokens and executed depth within each scale. Scale names and the
20-tokens-per-parameter (TPP) budget use Standard’s total parameters; Transformer counts exclude
embeddings and the vocabulary head. Training and evaluation details are in Section D.
Baselines.
The standard Transformer uses independent blocks; Plain Loop repeats shared blocks
with ordinary addition. HC learns full stream mixing, mHC uses Sinkhorn-normalized transport,
Hyperloop uses diagonal transport, and iHC uses identity transport with learned read and write gates
(Table 1). AttnRes and MHAR are our loop-level adaptations of Attention Residuals and multi-head
attention residuals (Team et al., 2026; Luo et al., 2026b). Adapters act only inside the loop. Looped
arms share the topology and learning rate within each setting; adapter placement and memory sources
differ.

0.005 nats. At 374M with 24 layers, Loopback stores 58.3% of the standard baseline’s Transformer

5.5
LINEAR ATTENTION AND RECURRENT MEMORY IN LOOPED TRANSFORMERS
We adapt the nine recurrent cores, Mesa, and a LaCT-inspired reader in Table 1 to visit boundaries at
191M and 374M, leaving token attention unchanged. Each reader uses either cumulative visit states
or whole-visit updates; both interfaces initialize to Plain Loop (Section B.4).
The update interface gives lower validation loss in all 22 family–scale comparisons (Fig. 8 and Ta-
ble 11). Every update-based reader improves on Plain Loop, but the best readers still trail Loopback
by 0.0302 nats at 191M and 0.0285 at 374M. These results favor updates over states as the memory
value. Fixed-state recurrent cores keep one practical advantage for long loops: each new write is
absorbed without rereading the history, and the state does not grow with the visit count. We have not
tested whether optimized recurrent kernels turn this into lower memory traffic or higher throughput
in deeply looped models.
5.6
EFFICIENCY: COMPUTE, THROUGHPUT, AND MEMORY
Loopback’s residual aggregation adds only 0.04–0.08% forward FLOPs over Standard at matched
executed depth in the three measured configurations (Fig. 9 and Table 15). These extra operations nor-
malize and score stored updates, form their weighted sum, and apply decay and mixture replacement;
they introduce no Q/K/V projections or extra block evaluations. With our fused implementation,
3B training throughput is 6% below Standard’s on the same eight H100 GPUs with the same batch
layout. Detailed runtime and memory measurements are reported in Section I.

Parameter sharing and residual reuse. Models with shared depth use weight tying (Dehghani et al.,

(Saunshi et al., 2025; Geiping et al., 2026), and adaptive recursion (Bae et al., 2026). Hyperloop
learns connections between loop visits (Zeitoun et al., 2026). Residual pathways use gating, addition,
and concatenation (Srivastava et al., 2015; He et al., 2016; Huang et al., 2018), scaling (Bachlechner
et al., 2021; Wang et al., 2024), depth mixtures (Bapna et al., 2018), multi-stream mixing (Zhu et al.,
2025a; Xie et al., 2025), and attention-based aggregation (Team et al., 2026; Luo et al., 2026a;b).
Storing updates is not new; what we add is the split of update coefficients into input strength, total
weight, and allocation, and an account of how each design constrains them.
Attention and recurrent memory. Sequence memory includes attention and additive fast weights
(Vaswani et al., 2017; Katharopoulos et al., 2020; Schlag et al., 2021), retention and gating (Sun
et al., 2023; Yang et al., 2023; Qin et al., 2024), structured state-space dynamics (Gu et al., 2021; Gu
& Dao, 2023; Dao & Gu, 2024), delta-rule corrections (Yang et al., 2024; 2025; Team et al., 2025;
Peng et al., 2025), and optimization-based memory (Von Oswald et al., 2023; Zhang et al., 2026). We
adapt these operations along depth, retaining each block’s token attention; results concern residual
interfaces, not the original architectures’ efficiency.

CONCLUSION
We present Loopback, a residual design for parameter-efficient looped Transformers. We connect
residual computation with linear attention and recurrent memory by treating successive block appli-
cations as memory steps along depth: each application writes new computation, which later blocks
access through the residual connection. Loopback stores each block’s update separately and reads
this history with attention. The read starts from geometrically decayed weights and redistributes them
according to content without changing their sum; the weighted updates are then added to the original
loop input. Across the 191M, 374M, 778M, 1.4B, and 3B scales, Loopback improves aggregate
quality over matched-depth standard Transformer baselines while using 40–75% of their Transformer
parameters, excluding token embeddings and the output head. In looped models, how the results of
shared computation are retained and reused matters as much as which blocks are shared.
8
LIMITATIONS AND FUTURE WORK
Our evidence is limited to ClimbMix pretraining at the tested scales and budgets, with single-run
large-scale comparisons. The input coefficient is fixed at one; we have not tried learned or layer-
specific input injection. Explicit history adds memory traffic and activations, so parameter savings
need not reduce latency or peak memory. Extra visits have not improved validation loss. Next steps
are other pretraining corpora, controlled comparisons of the reader interfaces, compact memories,
and training with a variable visit count.
ETHICS STATEMENT
This work studies the architecture of language models. All models have at most 3B parameters and
are trained on ClimbMix, a public pretraining corpus, with evaluation on public benchmarks; no new
data were collected and no human subjects were involved. The models are research artifacts that
inherit the biases of their training corpus and are not intended for deployment. The method reduces
stored parameters at matched executed depth and does not alter the risks associated with language
models in general.

D.2
RESIDUAL RULES AND EVALUATION
Trunk weights are shared across visits; connections and queries are untied where required. The mHC,
Hyper-Connections, and Hyperloop adapters act at visit boundaries with four streams; mHC uses 20
Sinkhorn iterations and Hyperloop uses zero residual bias. iHC wraps each middle block with four
streams, reading the block input through gates before it and writing the block update back through
gates after it; it uses magnitude 2, gate offset 10−6, and a learned final readout. MHAR reads loop
states at visit boundaries with eight heads and an outer blend. AttnRes reads the loop input and block
states before token attention and before the MLP in each loop block, and once at loop exit, using
Block AttnRes with N = 8. Loopback reads block updates after each middle block with one head
and λ = 1/4. The queries and gates of MHAR, AttnRes, and Loopback start at zero.
Held-out language modeling.
Validation uses disjoint ClimbMix shard 3583. As in training,
documents are tokenized with beginning-of-sequence markers, concatenated, and packed into 4,096-
token sequences. All models use the first 1,024 sequences and their final checkpoints, evaluated in
BF16. Loss averages next-token cross-entropy over 4,095 predicted positions per sequence after
shifting labels. It is reported in nats; perplexity is its exponential.

COMPUTE AND EFFICIENCY MEASUREMENTS
FLOP accounting.
Table 15 covers three scales. PyTorch’s operator counter measures forward
FLOPs on one 4,096-token bf16 sequence, including the vocabulary head. Scaled-dot-product
attention substitutes for the uncounted flash kernel; uncounted elementwise work is added analytically.
For a read at destination s over s + 1 stored updates, the score and weighted-sum matmuls contribute
4(s + 1)d FLOPs per token, excluding normalization, softmax, and mixture replacement. Anchored
decay costs 3d per token at each visit end; AttnRes reads before token attention and before the MLP
in each loop block, and once at loop exit, over the loop input and up to eight loop states; the stream
rules cost O(n2d) per connection for n = 4 streams.
Training measurements.
Measurements use one eight-H100 node, FSDP, bf16 compute, and each
scale’s micro-batch. Loopback uses fused reads measured in 160-step timing runs; other entries come
from the training logs, including AttnRes in Fig. 9, which trains with its fused read. For these three
scales, throughput uses median step time, and memory is the trainer’s reported peak. Activations
dominate sharded model state here, so fewer stored weights need not lower peak memory. At 3B, the
mean logged training throughputs are 24.7k tokens/s/GPU for Standard and 23.3k for Loopback, a
6% gap after rounding. Both runs use the same eight-H100 node, four 4,096-token sequences per
GPU, and 60 gradient accumulation steps. These means cover the logged intervals of the final 20-TPP
training stage.

The fused read.
Each read uses one Triton kernel, streaming updates once per token tile while
accumulating the scored and prior softmaxes together. Backward saves one score per token and update
rather than normalized keys, then reloads each update and writes its gradient once. Tests compare
the kernel with a direct PyTorch implementation of Eq. (16). In FP32, the output, the installed
coefficients, and every gradient (query, updates through the value and key paths, proposal, input, and
previous coefficients) agree to within 10−6 relative error, measured as the largest absolute difference
over the largest reference magnitude, across widths 768–3,072, 2–20 stored updates, ragged token
counts, and boundary and in-visit reads. With bf16 inputs, both implementations are compared with
an FP64 evaluation of the same rounded inputs, and the fused error is no larger than the reference’s.
At zero queries the output and coefficients match the decay-only reference, which reduces to Plain
Loop only at λ = 1. An end-to-end comparison of the two implementations on a small model gives
bitwise-identical results at initialization and agreement within 10−6 after perturbing the queries,
forward and backward. Most remaining step-time overhead is in backward, as each update receives
gradients from later reads. The kernel and tests will be released with the code.
