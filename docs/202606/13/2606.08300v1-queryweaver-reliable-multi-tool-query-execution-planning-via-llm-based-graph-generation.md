## 摘要
许多针对个人数据的现实查询跨越多个应用程序，需要结构化规划，因为单个工具只能暴露部分信息。虽然LLM表现出强大的推理和工具使用能力，但可靠地执行多步骤、跨工具的查询仍然具有挑战性。我们引入了一个系统，它将自然语言查询转换为结构化图，并通过确定性规划器执行。我们的方法使用深度优先搜索来解析依赖关系并跨工具合并结果，提高了可靠性，并实现了超越传统基于关键词搜索的查询。即使使用较小的或本地托管的LLM，我们也展示了高准确性。

## Abstract
Many real-world queries over personal data span multiple applications and require structured planning, as individual tools expose only partial information. While LLMs show strong reasoning and tool use, reliably executing multi-step, cross-tool queries remains challenging. We introduce a system that converts natural language queries into structured graphs and executes them via a deterministic planner. Our approach uses depth-first search to resolve dependencies and combine results across tools, improving reliability and enabling queries beyond traditional keyword-based search. We demonstrate high accuracy even with smaller or locally hosted LLMs.

- **整体含义**：本文提出QueryWeaver，将自然语言查询转换为结构化依赖图，并通过确定性规划器（深度优先搜索）执行，旨在提升跨工具多步查询的可靠性，并降低对大型专有LLM的依赖。

## 2. 方法论：核心思想、关键技术细节、算法流程

- **核心思想**：将自然语言查询解析为表示实体（节点）与关系（边）的图，外加过滤器约束。然后使用深度优先搜索（DFS）从返回变量出发，按依赖顺序解析每个节点，通过双向工具调用传播候选集，最终合并结果。

- **关键技术细节**：

  - **图表示**：
    - 节点类型：Email、Person、Self、File、Folder、Event、Date、Place、Webpage（共9种）。
    - 边关系：预定义双向边集合（例如 Email `from` Person、Event `occurred_on` Date、File `parent` Folder等），视为无向以便DFS遍历。
    - 过滤器：按节点类型定义允许的字段和操作符（如Email支持 `subject contains`、Date支持 `value =/ > / <`）。
    - LLM将被提示输出符合JSON schema的图结构，包含action（find/count）、return_var、vars、constraints（边和过滤器）。

  - **DFS执行规划（Algorithm 1: ExecutePlan）**：
    1. 从return_var开始递归DFS。
    2. 对某节点，若所有邻居已访问（即“边界节点”），则通过本地过滤器直接解析候选集（如日期归一化、Self固定）。
    3. 否则，先递归处理每个邻居，然后对每个邻居调用对应双向工具（工具名由节点类型和边类型确定），得到当前候选集，再与之前结果取交集。
    4. 最终对当前节点应用过滤器，保存候选集。
    5. 回溯到父节点，继续。
    6. 最终根据action（find/count）和return_mode（one/all）输出结果。

  - **日期归一化**：使用单独的LLM prompt将相对日期（“last month”、“in February”）转换为具体范围（MM/DD/YYYY或MM/YYYY），作为Date过滤器的值。

- **算法流程（文字说明）**：
