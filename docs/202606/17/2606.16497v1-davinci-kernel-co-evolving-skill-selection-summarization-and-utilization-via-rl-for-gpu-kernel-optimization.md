## 摘要
GPU内核优化代表了一种范式，其中功能正确性被假定，执行效率是目标。我们提出了daVinci-kernel，一个强化学习框架，通过动态演化的技能库将技能发现与技能利用相结合。daVinci-kernel联合训练三个共享一个LLM主干网络的智能体：技能选择智能体通过BM25和LLM重排序检索相关技术；策略智能体根据所选技能生成多轮CUDA/Triton内核；技能总结智能体将成功的过程提炼为可重用技能。候选技能仅在执行验证确认可复现加速后才被添加。所有三个智能体共享一个LLM主干网络，通过在多样性过滤数据上的结构化SFT冷启动初始化，然后使用多轮REINFORCE和每个智能体的优势估计进行端到端联合优化。在KernelBench上，daVinci-kernel-14B在Fast_1阈值下，在Level 1、Level 2和Level 3上分别达到37.2%、70.6%和32.2%，优于之前最强的RL训练模型Dr.Kernel-14B。

## Abstract
GPU kernel optimization represents a paradigm where functional correctness is assumed and execution efficiency is the objective. We present daVinci-kernel, a reinforcement learning framework that couples skill discovery with skill exploitation through a dynamically evolving skill library. daVinci-kernel jointly trains three agents sharing one LLM backbone: a Skill Selection Agent that retrieves relevant techniques via BM25 and LLM reranking, a Policy Agent that generates multi-turn CUDA/Triton kernels conditioned on selected skills, and a Skill Summary Agent that distills successful rollouts into reusable skills. Candidate skills are added only after execution-based verification confirms reproducible speedups. All three agents share a single LLM backbone, are initialized via a structured SFT cold start on diversity-filtered data, and are then jointly optimized end-to-end with multi-turn REINFORCE and per-agent advantage estimation. On KernelBench, daVinci-kernel-14B achieves 37.2%, 70.6%, and 32.2% on Level 1, Level 2, and Level 3 under the Fast$_1$ threshold, outperforming the strongest prior RL-trained model, Dr.Kernel-14B.

## 1. 论文的核心问题与整体含义（研究动机和背景）

GPU内核优化与传统的代码生成任务不同：它通常从一个已正确实现但不高效的代码开始，目标是通过一系列变换提升执行效率，而非确保功能正确性。性能提升是渐进、累积、可组合的，这使强化学习（RL）成为自然范式。然而，随着策略不断改进，性能进一步提升的来源会发生变化：早期主要通过宽泛的变换修正明显低效，后期则需要更加精细、紧密耦合的优化决策。因此，早期获得的知识在后期可能不再适用。现有多数方法专注于加强当前任务的生成器或搜索过程，却缺乏对优化知识进行持续维护和使用的能力。本文提出 **daVinci-kernel**，旨在通过技能发现与技能利用的闭环动态演化，使可重用优化知识与策略当前的性能前沿保持对齐。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 核心思想
- **技能-策略协同进化**：将技能选择、技能利用、技能总结整合到一个统一的强化学习循环中。共享一个LLM主干网络的三个智能体联合训练，技能库动态增长并接受执行验证，确保只有可靠的知识进入库中。

### 关键技术细节

#### 三个智能体及共享骨干
- **技能选择智能体 (Selection Agent)**：给定任务描述，通过两阶段检索（BM25预过滤 + LLM重排序）从技能库中选出至多3条技能。
  - 第一阶段：BM25索引，抓取top-20候选。
  - 第二阶段：LLM基于任务描述和技能名称/描述进行相关性判断，调用 `select_skills` 工具输出至多3个技能。
- **策略智能体 (Policy Agent)**：接收任务和可选的技能上下文，通过多轮对话与代码执行环境交互，生成优化的CUDA/Triton内核。技能内容注入到提示中。
- **技能总结智能体 (Summary Agent)**：当策略智能体产生强过程时（满足速度提升阈值条件：`R* > α·r₁` 且 `R* > β`，其中α=1.2, β=1.2），对成功轨迹进行分析并提取可重用技能。候选技能需通过执行验证（重新运行任务确认加速），才最终加入技能库。

#### 奖励与优势估计
- 策略奖励：`R_{i,t} = C(y_{i,t}) · (1 + speedup_{i,t} + PR_{i,t})`，其中 `PR` 是生成内核覆盖端到端运行时的比例。
- 优势估计采用多轮TRLOO（Turn-level REINFORCE Leave-One-Out），将所有方案（k+1种技能方案 + 空方案）的n个过程合并到一个LOO组中。
- 选择优势：每个技能方案的平均回报与同任务其他方案的平均回报之差。
- 总结优势：验证速度提升高的技能获取奖励，并在同任务的多个总结调用间进行LOO。

#### SFT冷启动
- 使用GPT-5.4收集种子轨迹，经过多样性过滤（Qwen3-Embedding-8B聚类+HDBSCAN，每个聚类最多保留2个实例）后，分别生成选择、策略、总结的监督微调数据。三个数据集合并用于初始化共用LLM骨干。

#### 联合RL训练
- 每个训练batch中，每个任务展开为k+1个并行方案（k=3个独立选择+1个空方案），每个方案生成n=4条过程。
- 联合损失：`Loss = Loss_policy + w_select * Loss_select + w_summary * Loss_summary`。

## 6. 论文的主要结论与发现

- **daVinci-kernel-14B在KernelBench上全面超越Dr.Kernel-14B**：Level 3 Fast 1达32.2%（相较22.1%提升46%），Level 2 Fast 1达70.6%（相较58.5%提升12个百分点）。优势在更难的任务上更显著。
- **技能注入是性能关键**：消融1（推理时移除技能）导致大幅下降，尤其在困难任务上，表明技能为策略提供不可或缺的引导。
- **SFT数据多样性过滤防止技能模式坍缩**：无过滤时模型过度学习通用模式，导致后期性能停滞。
- **联合多智能体RL对高精度优化至关重要**：仅训练策略智能体时，优秀阈值（Fast 2）下的性能严重退化，技能库与策略能力前沿不匹配。
- **LLM重排序优于纯BM25**：BM25在Fast 1下表现尚可，但在严格阈值下崩溃；LLM重排序能够识别深层瓶颈。
- **纯RL可获得宽度但无法保证深度**：无技能条件下RL在Fast 1表现优秀，但高阈值下远逊于技能辅助版本。

## 7. 优点：方法或实验设计上的亮点

- **创新性的闭环技能演化框架**：首次将技能选择、利用、总结在同一RL循环中端到端训练，确保技能库随策略进步而动态更新。
- **执行验证驱动的技能质量控制**：只有经过可复现加速验证的技能才入库，避免无效技能污染。
- **多智能体联合优势估计**：通过将不同技能方案的过程分组计算策略优势，降低方差；选择优势和总结优势的设计合理。
- **冷启动阶段的多样性过滤**：通过聚类下采样减少通用模式，增强技能多样性。
- **全面的消融实验**：5种消融设置覆盖了框架各重要组件，结论有说服力。
- **训练动态可视化**：展示了不同方法在验证集上的变化趋势，验证了技能共演化带来的稳定性。
