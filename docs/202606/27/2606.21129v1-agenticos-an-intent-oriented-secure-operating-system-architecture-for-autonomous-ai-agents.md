## 摘要
传统基于“资源暴露加权限检查”的操作系统安全模型，在LLM驱动的自主智能体获得规划、工具使用、网络访问和代码执行能力时面临结构性挑战。一旦智能体运行时因提示注入或恶意工具输出而受损，攻击者可将POSIX风格的资源原语组合成远超用户任务授权的行为。为此，我们提出AgenticOS，一种意图导向的安全操作系统架构，将可委托、可审计的软件能力整合为操作系统原生能力，而非替换所有应用程序。其核心见解是将操作系统从“资源管理器”重构为“意图过滤器”：智能体不直接请求低级资源，而是提交结构化意图声明，系统据此合成一个最小权限环境，并施加强制中介、审计和信息流约束。在实现层面，我们引入四层架构——幽灵内核、逻辑快门、智能体胶囊和语义边界网关，以及意图ABI、仅清单运行时、基于编织器的能力生成和AgenticOS原生技能的准入模型。

## Abstract
Traditional OS security models based on "resource exposure plus permission checks" face structural challenges as LLM-driven autonomous agents acquire capabilities for planning, tool use, network access, and code execution. Once an agent runtime is compromised through prompt injection or malicious tool outputs, an attacker can compose POSIX-style resource primitives into behaviors far beyond the user's task authorization. To address this, we propose AgenticOS, an intent-oriented secure OS architecture that consolidates delegable, auditable software capabilities into OS-native ones rather than replacing all applications. The core insight is to reframe the OS from a "resource manager" into an "intent filter": instead of requesting low-level resources directly, agents submit structured intent declarations, from which the system synthesizes a least-privilege environment with mandatory mediation, auditing, and information-flow constraints. At the implementation level, we introduce a four-layer architecture -- Ghost Kernel, Logic Shutter, Agent Capsule, and Semantic Boundary Gateway -- together with the Intent ABI, Manifest-Only Runtime, Weaver-based capability generation, and an admission model for AgenticOS-native Skills.

# AgenticOS 论文总结

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：LLM驱动的自主智能体具备规划、工具调用、网络访问、代码执行和跨应用协作能力，传统OS安全模型基于“资源暴露+权限检查”（如POSIX系统调用）已无法应对新型威胁。
- **核心问题**：用户授权的是“任务意图”，而OS暴露的是“资源原语”。一旦智能体被提示注入、供应链投毒或恶意工具输出攻击，攻击者可以组合资源原语（文件、网络、进程、内存映射、动态执行）执行远超原始任务授权的行为，如横向移动、数据泄露、持久化或隐蔽通信。
- **整体含义**：需要将OS从“资源管理器”重构为“意图过滤器”，让智能体不直接请求低级资源，而是提交结构化意图声明，系统据此生成最小权限环境并强制审计约束，从而在操作系统层面为自主AI智能体提供原生安全支持。

## 2. 方法论

### 核心思想
- **意图优先**：系统基于任务意图和外部效果授权，而非基于原始文件、端口或进程。
- **最小权限**：智能体启动前必须提交Manifest（清单），系统只生成完成声明任务所需的最小能力集。
- **无原始字节流**：智能体胶囊不直接访问套接字、管道、设备文件或任意协议字节流。
- **无任意执行**：胶囊不暴露exec、fork、dlopen、mmap等可泛化为任意执行环境的接口。
- **可审计**：所有外部效果记录为结构化事件，绑定到Manifest、能力令牌和调用链。
- **可证明隔离**：底层隔离、度量、能力生成链应可形式化建模，TCB最小化。

### 关键技术细节
1. **四层架构**：
   - **Ghost Kernel（幽灵内核）**：最高特权级，仅提供加密内存分配、确定性时间片调度、度量和认证根；不暴露通用系统调用接口。
   - **Logic Shutter（逻辑快门）**：语义翻译层和策略执行点，负责意图解析与验证、能力令牌管理、审计日志生成、信息流标签；运行在胶囊之下、幽灵内核之上。
   - **Agent Capsule（智能体胶囊）**：实际的智能体代码运行时环境，遵循“仅清单运行时”原则；所有能力来自Manifest，动态生成专用接口表，禁止通用资源操作接口。
   - **Semantic Boundary Gateway（语义边界网关）**：外界唯一受控边界，代理复杂协议、托管凭证、实现语义通道（结构化消息而非原始字节流）、输出审计与规范化。

2. **Intent ABI（意图ABI）**：面向任务意图的应用二进制接口，提供六类结构化语义操作：身份与会话、文档与数据、网络能力、工具链、模型推理、环境观察。禁止传统POSIX接口（open、read、write、socket、execve等）。

3. **Weaver动态能力生成**：根据Manifest、智能体代码和标准语义库生成胶囊运行时环境，需验证Manifest与代码引用一致性、标准库签名有效性、禁止接口不可达、信息流路径可分析、构建可复现。

4. **Skill生成与准入**：新能力在开发态生成，需经过能力声明、静态分析、测试与证明、签名注册后才能成为系统能力，运行时不可自扩容。

### 流程（文字说明）
- 智能体提交Manifest → Weaver动态生成专用ABI Stub并注入胶囊 → 胶囊通过Intent ABI调用 → Logic Shutter进行意图解析、能力验证、信息流标签检查 → 授权后由Semantic Boundary Gateway执行具体外部效果（协议代理、凭证托管等），所有事件记录到审计日志。
