## 摘要
计算机使用智能体在桌面自动化领域取得了快速进展，越来越多的用户将 OpenClaw 等智能体部署在 Mac Mini 上以实现持续自动化。然而，现有基准测试（包括针对 macOS 的）在没有框架增强的情况下评估智能体，并依赖二元评估结果。因此，它们既无法捕捉现代智能体所利用的框架能力，也无法反映长周期、多应用任务中的部分进展。我们提出 MacAgentBench，这是一个全面的 macOS 智能体基准测试，涵盖 25 个应用中的 676 个任务，其中近 60% 涉及 GUI 和 CLI 交互。该基准测试采用确定性规则评估，并引入细粒度的多检查点评分，为多应用任务提供能力注释。在三个框架和 16 个模型上的实验表明，最佳配置（Claude Opus 4.6 在 OpenClaw 上）达到了 73.7% 的 Pass@1，而这一优势主要来自技能库而非框架设计。细粒度指标进一步揭示了具有相似 Pass@1 的模型在子目标完成度上可能差异显著。我们的代码和数据已在 https://github.com/JetAstra/MacAgentBench 公开。

## Abstract
Computer use agents (CUAs) have advanced rapidly in desktop automation, and a growing number of users deploy CUAs such as OpenClaw on Mac Mini for always-on automation. However, existing benchmarks, including those for macOS, evaluate agents without framework augmentation and rely on binary evaluation. As a result, they fail to capture both the framework capabilities leveraged by modern CUAs and the partial progress on long-horizon, multi-application tasks. We present MacAgentBench, a comprehensive macOS agent benchmark comprising 676 tasks across 25 applications, with nearly 60% involving both GUI and CLI interaction. The benchmark adopts deterministic rule-based evaluation and introduces fine-grained multi-checkpoint scoring with capability annotations for multi-application tasks. Experiments across three frameworks and 16 models show that the best configuration, Claude Opus 4.6 on OpenClaw, attains 73.7% Pass@1, while this advantage is primarily driven by the skill library rather than by framework design. Fine-grained metrics further reveal that models with similar Pass@1 can differ substantially in sub-goal completion. Our code and data are publicly available at https://github.com/JetAstra/MacAgentBench.

  1. 将 CUA 评估简化为固定的截图–GUI–动作循环，但现代 CUA 实际上是**框架与模型协同工作**，框架提供超越 GUI 的能力（如命令行访问、脚本执行、预建技能库）。
  2. 依赖**二元通过/失败**判断，对于长周期、多应用任务，无法揭示智能体实际取得了多少**部分进展**，掩盖了子目标完成度的差异。
- **核心问题**：缺乏一个能够公平比较不同 CUA 范式（纯GUI智能体、混合框架、智能体工具集）、并支持细粒度进度跟踪的 macOS 桌面智能体基准。
- **论文目标**：提出 MacAgentBench，填补该空白，推动桌面智能体评估的标准化。

### 2. 论文提出的方法论

- **核心思想**：构建一个**环境开放**的 macOS 桌面基准，不限制智能体框架与环境交互的方式，从而允许在同一组任务上比较纯GUI智能体、混合框架和智能体工具集（agent harness）。
- **关键技术细节**：
  - **基础设施**：基于 Docker–QEMU 堆栈实现 macOS 虚拟化，利用 QEMU 的写时复制（copy-on-write）机制，使容器启动时间降至 **30 秒**，每实例磁盘开销仅 **1 GB**，支持在一台服务器上并行运行多个评估实例。
  - **任务构建**：共 **676 个任务**，覆盖 **25 个应用**，其中 **59.8% 涉及 GUI 和 CLI 混合交互**。种子任务来自 macOSArena（63个）和新设计（110个），经交叉验证后保留 169 个种子，再通过**参数替换 + 指令改写**扩展为 4 个变体。
  - **评估协议**：采用**完全确定性的规则评估**，避免 LLM-as-judge 的可复现性问题。共 **156 个 getter 函数**，分为三类：Shell 命令、AppleScript、Python 脚本。
  - **细粒度多检查点评分**：针对 **140 个多应用任务**引入检查点，每个检查点对应一个关键子目标，最终分数为通过检查点比例（0~1），任务仅当全部检查点通过才记为 Pass。每个检查点还标注了五类能力维度：**Research、App State、Content、File Ops、Sys Config**，便于分析模型能力不平衡。
  - **评估流水线**：环境启动（30s）→ 任务初始化 → 智能体执行（最多50步）→ 评估 → 容器销毁（完全隔离）。

### 6. 论文的主要结论与发现

- **框架设计大幅影响性能**：同一模型（Claude Opus 4.6）在无框架支持下 Pass@1 仅 39.2%，而在 OpenClaw 上达 73.7%，AgentS3 上 66.9%。
- **优势主要来自技能库，而非框架设计**：在有技能覆盖的任务上 OpenClaw 大幅领先（Claude 达 89.4%），但在无技能覆盖的任务上，5/8 的模型在 OpenClaw 上反而低于基线，表明 OpenClaw 的整体优势由技能驱动。AgentS3（无技能库）则在两类任务上均稳定提升。
- **细粒度评估揭示隐藏差异**：Pass@1 相同的模型（如 UI-TARS-72B-DPO 和 UI-TARS-1.5-7B 均为 1.4%），Score 却不同（12.9% vs 8.9%），说明二元指标无法反映部分进展。能力维度上，File Ops 最容易，Research 最难。
- **鲁棒性是独立维度**：Pass@1 与 Pass 4 之间差距巨大（如 Claude on OpenClaw Pass@1=73.7%，Pass 4=58.6%），表明单次成功率不能代表一致性。
- **Claude 从框架增强中获益最大**：基线中 GPT-5.4 领先 Claude（58.4% vs 39.2%），但在框架支持下 Claude 反超，显示其与框架的协同更好。

### 7. 优点

- **环境开放性**：首次允许公平比较纯 GUI 智能体、混合框架和智能体工具集等不同 CUA 范式在同一 macOS 桌面任务集上的表现。
- **大规模高质量任务**：676 个任务，覆盖 25 应用，近 60% 混合 GUI+CLI，反映真实复杂工作流。
- **确定性规则评估**：完全避免 LLM-as-judge 的可重复性问题，评估结果一致且可复现。
- **细粒度多检查点评分**：对多应用任务提供部分进度信号，揭示二元指标掩盖的能力不平衡；能力维度标注有助于定位模型弱点。
- **基础设施高效**：Docker-QEMU + 写时复制，30s 启动，1GB 磁盘开销，支持并行评估，显著降低实验成本。
- **全面实验覆盖**：跨框架、跨模型、技能影响、鲁棒性、细粒度、每类别、失败模式等多角度分析。

### 8. 不足与局限

- **硬件差异**：macOS 在 QEMU 虚拟机中运行，缺乏 Apple 硬件 GPU 支持，可能存在渲染效果差异（如圆角、视图过渡）。论文已排除因差异导致任务行为不同的情况，但像素级差异未被完全排除。
- **版本绑定**：基准绑定到 macOS Tahoe 26。应用行为、AppleScript 接口、UI 布局可能随版本变化，迁移到新版本需重新审阅和更新脚本。
- **任务覆盖**：当前 676 个任务虽为最大 macOS 基准，但仍可扩展至更多应用和场景（如专业设计软件、更多系统工具）。
- **潜在滥用风险**：CUA 具备 GUI+CLI 能力，可能被用于未经授权操作。论文通过**隔离容器 + 去标识化 + 研究许可**缓解风险，但部署到生产系统仍需额外安全措施。
- **原生 GUI 模型评估受限**：由于输出格式不兼容，原生 GUI 模型（UI-TARS、ScaleCUA 等）无法在 AgentS3 和 OpenClaw 上评估，限制了跨框架对比的覆盖面。
- **技能库依赖**：OpenClaw 的优势主要来自预定义技能，但技能本身是特定于当前版本和应用的；对无技能覆盖任务表现不佳，表明框架的通用设计仍需改进。
