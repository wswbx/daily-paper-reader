## 摘要
LLM智能体的技能自我进化方法旨在将执行轨迹转化为可复用的技能文档，但当前流程通常从每个任务中学习一条轨迹，在检查之前合并候选技能补丁，并在推理前加载完整技能语料库。我们提出SkillCAT，一个无需训练的框架，将该过程分为三个阶段。对比因果提取（CCE）为每个任务采样多条轨迹，并比较同任务的成功/失败对，以识别解释结果差异的证据。评估增强进化（AAE）在源任务克隆上回放每个候选补丁，并在分层技能补丁合并前只保留改善或保持任务结果的补丁。拓扑感知任务执行（TTE）将进化后的技能编译为可路由的子技能拓扑，因此推理仅加载与任务相关的能力节点。我们在常见智能体基准上评估SkillCAT，包括SpreadsheetBench、WikiTableQuestions和DocVQA，并进一步测试跨模型和分布外泛化。在这些设置中，SkillCAT将平均得分相比基线提升高达40.40%，展示了无需模型训练的可靠技能进化。

## Abstract
Skill self-evolution methods for LLM agents aim to turn execution trajectories into reusable skill documents, but current pipelines typically learn from one trajectory per task, merge candidate skill patches before checking them, and load the full skill corpus before inference. We propose SkillCAT, a training-free framework that separates this process into three stages. Contrastive Causal Extraction (CCE) samples multiple trajectories for each task and compares same-task success/failure pairs to identify evidence that explains outcome differences. Assessment-Augmented Evolution (AAE) replays each candidate patch on source-task clones and keeps only patches that improve or preserve task outcomes before hierarchical skill patch merging. Topology-Aware Task Execution (TTE) compiles the evolved skills into a routable sub-skill topology, so inference loads only the capability nodes relevant to the task. We evaluate SkillCAT on common agent benchmarks, including SpreadsheetBench, WikiTableQuestions, and DocVQA, and further test cross-model and out-of-distribution generalization. Across these settings, SkillCAT raises the average score over baselines by up to 40.40%, demonstrating reliable skill evolution without model training.

## 1. 核心问题与整体含义（研究动机和背景）
- **问题**：LLM智能体的技能自我演化方法（如Trace2Skill）存在三个关键缺陷：
  1. **单轨迹偏差**：从单个轨迹提取证据不可靠，成功可能是偶然策略，失败难以定位根因。
  2. **未验证合并**：候选技能补丁在合并前不经过独立验证，低质量或有害补丁可能污染技能库。
  3. **推理解下文过载**：合并后的技能持续增长，推理时加载全部内容增加提示长度、分散注意力。
- **动机**：现有方法离线批处理（如Trace2Skill）虽比顺序更新高效，但仍面临上述问题。需要一种无需模型训练的框架，能可靠地从经验中提取技能、验证质量并控制上下文。
- **整体含义**：SkillCAT通过分离技能生命周期为三个可观测阶段（对比因果提取、评估增强进化、拓扑感知任务执行），在不进行模型微调的情况下，显著提升技能演化的可靠性和泛化能力，为LLM智能体可复用技能的自动化构建提供了新范式。

## 2. 方法论
### 核心思想
将技能自我演化分解为三个阶段，分别解决单轨迹偏差、未验证合并和上下文过载。

### 关键技术细节
#### 2.1 对比因果提取（CCE）
- **多种子采样**：对每个任务使用K个随机种子（默认5个）运行智能体，收集多条轨迹及其二元结果（成功/失败）。
- **对比对构建**：从同任务的成功和失败轨迹中各选一条组成对比对（τ⁺, τ⁻），确保任务难度和输入相同，隔离执行差异。
- **因果分水岭识别**：定位成功与失败轨迹中动作序列首次出现差异的时间步 `w_i`。
- **证据提取**：围绕分水岭提取局部证据、推断失败原因、生成可编辑的技能教训，形成候选经验记录 `r_i`。
- **回退机制**：若某任务所有轨迹同成功或同失败，则使用单轨迹提取器（回退）或跳过该任务。

#### 2.2 评估增强进化（AAE）
- **源任务回放**：对每个候选补丁 `p_j`，在其源任务克隆集上隔离应用该补丁，记录基线结果 `y_j` 和回放结果 `ŷ_j`。
- **评分规则（四种结果转换）**：
  - (0→1): 失败→成功 → 3.0（最强证据）
  - (1→1): 成功→成功 → 2.0（保持行为）
  - (0→0): 失败→失败 → 1.0（低价值）
  - (1→0): 成功→失败 → 0.0（拒绝）
- **阈值选择**：仅保留得分 ≥ θ（默认2.0）的补丁，即能修复失败或保持成功的补丁。
- **分层合并**：按得分从低到高分梯队合并，得分高的补丁在后续阶段享有更高优先级，最终形成进化技能 `S*`。

#### 2.3 拓扑感知任务执行（TTE）
- **拓扑构建**：离线解析进化技能 `S*` 的Markdown层次结构，1级内容为核心技能 `S°`，2级节段构成可路由节点集 `V`，并提取元数据（标题、关键词、摘要、依赖）。
- **LLM路由**：给定任务描述和预算k，LLM路由器从拓扑摘要中选择最多k个相关主节点。
- **确定性扩展**：验证节点ID，添加确定性召回和任务意图锚点，扩展依赖边，包含基础节点，得到最终节点集 `V_c`。
- **技能组装**：将核心技能与所选节点体拼接，形成路由技能 `S_c`，推理时仅加载此精简上下文。

### 算法流程（文字说明）
1. **输入**：进化任务集X、种子集Z、基础技能S0、得分阈值θ、路由预算k。
2. **CCE**：对每个任务运行多种子，若结果混合则构造对比对并提取记录；否则按回退策略处理。
3. **AAE**：将记录转为候选补丁，回放评分，阈值过滤，按得分分层合并得到S*。
4. **TTE**：编译S*为拓扑（S°, V）。在线推理时，LLM路由选择和扩展，组装路由技能Sc执行。

1. **SkillCAT在SpreadsheetBench上显著优于所有基线**：在Skill Deepening + Qwen3.5-35B-A3B下Vrf达55.50%，比Trace2Skill高25.83个百分点；平均得分提升40.40%。

3. **AAE回放评估有效过滤有害补丁**：在DocVQA上，Trace2Skill +Error导致性能下降，而SkillCAT保持提升。

## 7. 优点
1. **无需模型训练**：完全基于推理和回放，易于部署于任意LLM。
2. **对比因果提取增强证据可靠性**：通过同任务成败对比对，有效避免偶然性错误归因。
3. **回放验证机制**：在合并前对每个补丁在源任务上测试，防止有害补丁污染技能库。
4. **拓扑感知上下文控制**：将技能编译为可路由拓扑，推理时仅加载相关节点，降低提示长度和分心。
5. **广泛的泛化验证**：跨模型、跨模态（多模态DocVQA）、OOD（WikiTQ）均表现良好，且在弱初始技能下也能显著提升。
6. **可解释性**：每种评分转换对应明确语义，便于分析演进效果。

## 8. 不足与局限
1. **领域偏倚**：实验主要基于电子表格操作，其他常见智能体领域（如代码执行、网页导航、对话）未验证，通用性待考。
2. **CCE采样成本随种子数线性增长**：虽然5种子最优，但128个并行worker仍需要一定计算资源；9种子时采样时间过长（>4小时），效率下降。
3. **依赖基础技能质量**：SkillCAT在Skill Deepening（从高质量Human-Written初始化）和Skill Creation（从弱Parametric初始化）上效果不同，基础技能过差可能影响最终表现。
4. **跨模型泛化不均衡**：gpt-5.4-mini用户提升幅度远小于gemma-4-31B-it，可能因模型架构或能力限制，方法对不同模型的适应性未充分分析。
5. **回放需要源任务克隆集**：若源任务不可复制（如涉及外部API状态），回放可能不可行。
6. **未讨论技能库规模上限**：随任务增加，拓扑结构和路由复杂度如何变化未探讨。
7. **实验未包含纯强化学习方法**：对比基线均为基于推理的方法，未与需要训练的RL方法（如EvoSkill）比较（虽声称训练免费是优势，但缺乏绝对性能对比）。
