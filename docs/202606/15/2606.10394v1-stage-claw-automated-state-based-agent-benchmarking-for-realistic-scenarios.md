## 摘要
大型语言模型越来越多地被用于驱动日常应用中的个人智能体，但评估这些智能体仍然是一个挑战。现有的基准测试仍然依赖于沙盒化的人工制品、静态任务设计和粗粒度评分，这阻碍了可扩展性，并限制了向可靠个人智能体评估的进展。本文介绍了STAGE-Claw，一个用于在基于状态的个人计算环境中构建和评估现实个人智能体场景的自动化框架。给定一个任务提示，STAGE-Claw会自动创建并验证一个真实的基准测试任务，包括其环境、任务提示、真实结果和相关的验证程序。随后，智能体在真实操作环境中进行评估，其性能通过最终系统状态的正确性来衡量，而不仅仅是文本响应。使用STAGE-Claw，本文创建了一个包含40个具有挑战性的现实场景智能体任务的基准测试，评估了11个前沿模型，并分析了它们的任务得分、成本、工具调用可靠性以及常见失败模式。总体而言，STAGE-Claw提供了一种可扩展的、基于状态的方法来评估现实用户场景中的智能体。

## Abstract
Large language models are increasingly used to power personal agents for everyday applications, but evaluating these agents remains a challenge. Existing benchmarks still rely on sandboxed artifacts, static task design, and coarse scoring, which hinder scalability and limit progress toward reliable personal-agent evaluation. This paper introduces STAGE-Claw, an automated framework for building and evaluating realistic personal-agent scenarios in state-based personal-computing environments. Given a task hint, STAGE-Claw automatically creates and validates a realistic benchmark task with its environment, task prompts, ground truth, and related verification programs. Agents are then evaluated in realistic operating environments, where performance is measured by the correctness of the final system state rather than only the textual response. Using STAGE-Claw, this paper creates a benchmark with 40 challenging real scenario agent tasks, evaluates 11 frontier models, and analyzes their task scores, costs, tool-call reliability, and common failure patterns. Overall, STAGE-Claw offers a scalable, state-based way to evaluate agents in realistic user scenarios.

1.  **性能与效率存在权衡**：顶级模型（如 Claude-Opus-4.7）性能最佳（得分77.1，一次通过率80%），但代价是高计算开销（、运行时间长、API费用高）。而 GPT-5.4 则提供了最好的效率，同时保持了竞争力。

5.  **基于状态的评估更可靠**：与模拟文本输出的“虚拟状态”评估相比，“基于状态”的评估能暴露出更多由于“执行失败”或“真实状态更新失败”导致的问题，提供了更忠实的评估。
6.  **记忆干扰具有显著影响**：将关键信息注入智能体的“持久记忆”后，即使有误导性或矛盾信息，性能也会下降，这表明记忆质量对下游状态更新至关重要。

### 7. 优点

-   **自动化、可扩展**：STAGE-Claw 的自动化生成和验证流程，显著降低了构建高质量、真实场景基准测试的人力成本，为解决基准测试规模化问题提供了可行路径。
-   **基于系统状态的真实评估**：评估不再依赖文本输出，而是检查**真实工具（日历、文件、笔记等）的系统状态是否被正确修改**，这更贴近最终用户对智能体的真实期望（“把事情做好”），且评估结果更客观、可审计。
-   **细粒度的失败分析**：通过对工具调用、失败原因的详细分析，能够精确定位智能体在复杂工作流中的薄弱环节（如“Shell命令错误”、“文件路径缺失”、“状态更新错误”），为模型和Agent框架的改进提供了具体指导。
-   **开源**：代码已公开，便于社区复现和使用。

### 8. 不足与局限

1.  **任务规模有限**：当前基准测试仅包含40个任务，论文也承认其定位是“高质量试点基准（pilot benchmark）”，在统计上不算非常全面。
2.  **评估协议非统计完备**：主要结果基于“单次有效运行”，内在的随机性考虑不足。虽然随后进行了有限的三次重复运行诊断，但未能覆盖所有模型，无法全面评估可靠性。
3.  **构建成本依然很高**：尽管实现了自动化流水线，但每个任务仍需约$35-40的API成本和1-2小时时间，对于需要海量任务的超大规模基准测试来说，其成本和质量保障依然是瓶颈。
4.  **平台相关性**：评估依赖于真实的个人计算环境（macOS、特定工具链），这意味着评估结果可能不仅反映模型能力，也受限于操作系统配置、权限、工具封装集成（OpenClaw框架）和软件运行时的稳定性，平台的通用性有待验证。
5.  **缺乏任务家族间性能差异分析**：虽然报告了任务分布（5个组），但并未深入分析模型在不同任务类型（如时间冲突解决 vs. 信息提取）上的具体表现差异，未能展现模型的细粒度能力画像。
