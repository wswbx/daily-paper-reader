## 摘要
紧凑型语言模型（LMs）降低了工具代理的成本、延迟和部署风险。然而，MCP风格的工具使用不仅仅是孤立的函数调用：代理必须从实时目录中发现工具，满足模式，跨中间输出维护依赖关系，并在执行证据中落地最终响应。小型规划器通常生成看似合理的工作流图，但在工具解析、参数验证、依赖跟踪或执行中失败。我们认为，小语料蒸馏难以很好地处理这种失败模式。数百个教师轨迹可以教授工作流格式，但很少涵盖修复失败计划所需的恢复行为，以应对变化的工具目录。我们引入Evoflux，一种推理时演化搜索方法，将紧凑工具使用视为可执行工具工作流的修复。它通过结构化编辑、执行反馈、自适应强度、元引导重新设计和多样性剪枝来演化类型化工作流图。在横跨实时MCP服务器和250个工具的留出MCP-Bench任务上，Evoflux将小型规划器的执行可行性从大约3%提高到17-24%。相比之下，在相同搜索挖掘数据上的SFT和SFT+DPO要么匹配、要么表现不佳，甚至低于零样本性能；ReAct达到更高峰值，但方差和令牌成本更高。这些结果表明，在稀缺的教师轨迹预算下，基于执行的搜索更可靠。

## Abstract
Compact language models (LMs) reduce cost, latency, and deployment risk for tool agents. Yet MCP-style tool use requires more than isolated function calling: an agent must discover tools from live catalogs, satisfy schemas, preserve dependencies across intermediate outputs, and ground final responses in executed evidence. Small planners often generate plausible workflow graphs that fail under tool resolution, parameter validation, dependency tracking, or execution. We argue that this failure mode is poorly handled by small-corpus distillation. A few hundred teacher traces can teach workflow format, but rarely cover the recovery behavior needed to repair failed plans over changing tool catalogs. We introduce Evoflux, an inference-time evolutionary search method that treats compact tool use as the repair of executable tool workflows. It evolves typed workflow graphs through structured edits, execution feedback, adaptive intensity, meta-guided redesign, and diversity pruning. On held-out MCP-Bench tasks spanning live MCP servers and 250 tools, Evoflux raises execution feasibility from roughly 3% to 17-24% across small planners. In contrast, SFT and SFT+DPO on the same search-mined data match, underperform, or collapse below zero-shot performance; ReAct reaches higher peaks, but with higher variance and token cost. These results show that execution-grounded search is more reliable under scarce teacher-trace budgets.

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：Evoflux是一个**自适应推理时演化搜索过程**。它将紧凑型小模型作为提议算子，在有限的执行-修复循环内生成、评估和修正工作流候选。工作流表示为**类型化的有向无环图（DAG）**，具有工具节点、依赖边、验证节点和最终输出节点。搜索通过一系列结构化编辑、执行反馈、自适应强度控制、元引导重新设计和动作哈希多样性剪枝来演化候选工作流。
- **关键技术细节**：
  - **候选表示与构建**：每个候选包含符号动作图、编译后工作流、可行性元数据、执行日志和裁判分数。构建过程包括解析、工具解析、模式验证、依赖检查，并通过有限重试循环获得第一个可行工作流。
  - **执行评分**：使用MCP-Bench提供的LLMJUDGE评估器，对每个可行候选在6个子维度（任务完成、接地性、工具适当性、参数准确性、依赖感知、并行性与效率）上打分（1–10分），每个维度执行5次后取平均，最终分数为6维平均值。
  - **类型化编辑语言**：包括工具交换、参数编辑、工具插入/删除、步骤重排序、验证器插入。编辑基于节点级失败证据（编译消息、静态检查、执行日志、裁判反馈），采用两种模式：利用模式（编译上下文后由规划器提出编辑）和探索模式（随机堆叠编辑）。
  - **自适应强度与元引导**：通过**增长统计量G**追踪近期进步，G的指数移动平均用于计算强度I（I∈[Imin,Imax]）。强度控制父代选择和变异模式。当G过低且冷却计数器为零时，触发元引导步骤，由规划器接收当前最佳和最差候选后提出全局重新设计。
  - **多样性剪枝**：使用动作哈希分桶（16个桶），按桶轮转保留最多K个候选，避免种群坍缩。
  - **训练基线**：从搜索过程中收集正例（最佳候选）构建SFT数据集（177个样本），再收集偏好对（624对）构建DPO数据集。使用LoRA进行微调。

## 3. 实验设计：数据集、基准、对比方法

- **数据集与基准**：
  - **MCP-Bench**：包含28个实时MCP服务器和250个工具，覆盖金融、旅行、科学计算、学术搜索等领域。任务分为搜索集D_search（用于开发和超参数调优）和留出评估集D_eval（用于最终比较）。评估指标为执行可行性（feasibility）和基于LLMJUDGE的6维平均分数。
- **对比方法**：
  - **零样本直接解码（Zero-shot）**：不经过任何训练或搜索，直接生成工作流。
  - **SFT**：在177个教师轨迹上进行监督微调。
  - **SFT+DPO**：先SFT再在624对偏好数据上进行直接偏好优化。
  - **ReAct**：使用思维-行动-观察循环进行顺序工具调用，最大15轮。
  - **Evoflux**：推理时演化搜索（不更新模型权重）。
- **评估配置**：使用4个小模型（Llama-3.2-3B、Qwen3.5-4B、SmolLM3-3B、DeepSeek-R1-Qwen-1.5B）和2个大模型（Sonnet-4-5、Llama3-70B）作为规划器。实验在两个分图（搜索分图和验证分图）上进行。

## 6. 论文的主要结论与发现

- Evoflux在留出任务上将小模型的执行可行性从约3%提升至17–24%，而SFT和SFT+DPO要么匹配零样本，要么低于零样本（如Qwen3.5-4B完全崩溃）。

## 7. 优点

- **方法设计亮点**：
  - **类型化编辑语言**：将编辑约束为可编译、可执行的操作，避免无限制图重写，缩小搜索空间。
  - **自适应强度与元引导**：动态平衡探索与利用，并在局部停滞时触发全局重设计，提升搜索效率。
  - **基于执行的评分**：不只看格式有效性，而是依赖真实执行结果和细粒度裁判打分，确保优化目标与任务成功对齐。
  - **多样性剪枝**：通过动作哈希分桶防止种群收敛到近重复候选，保持探索覆盖。
  - **公平比较框架**：严格分离搜索分图和验证分图，并让训练基线使用与搜索相同的轨迹预算，结论可信度高。
- **实验亮点**：
  - 同时比较多种方法（SFT、DPO、ReAct、零样本、Evoflux）在同一预算下，清晰揭示了训练与搜索的权衡。
  - 提供子技能分析、工作流深度/宽度分析、可视化案例等丰富结果，增强了可解释性。

## 8. 不足与局限

- **实验覆盖有限**：仅在MCP-Bench一个基准上评估，未在更多工具调用数据集或真实应用中验证泛化性。
- **训练预算固定较小**：论文不否认更大蒸馏数据集可能改变结论，但未探索超过数百条轨迹的情况。
- **自回归模型依赖**：搜索流程仍然依赖基础小模型作为提议器和编译器，若基础模型太弱（如DeepSeek-R1-1.5B），Evoflux也无法完全挽回。
- **成本考量不够全面**：仅报告令牌计数，缺乏实际时间、API调用次数、美元成本等指标。推理时搜索的多次执行可能带来更高的延迟。

- **未考虑在已训练模型上使用Evoflux**：未来的混合策略（训练+搜索）可能进一步提高性能。
- **伦理注意事项**：搜索过程可能产生多个候选并多次调用外部工具，增加了数据隐私和访问控制风险，论文仅在讨论中提及，未在实验中量化。
