## 摘要
计算机使用智能体（CUA）在桌面自动化方面取得了快速进展，越来越多的用户将OpenClaw等CUA部署在Mac Mini上以实现持续自动化。然而，现有的基准（包括macOS的基准）在评估智能体时没有考虑框架增强，并且依赖于二元评估。因此，它们未能捕捉现代CUA所利用的框架能力，以及在长期多应用任务中的部分进展。我们提出了MacAgentBench，一个全面的macOS智能体基准，包含25个应用程序中的676个任务，其中近60%涉及GUI和CLI交互。该基准采用确定性基于规则的评估，并引入了针对多应用任务的细粒度多检查点评分与能力标注。在三个框架和16个模型上的实验表明，最佳配置（OpenClaw上的Claude Opus 4.6）达到了73.7%的Pass@1，而这一优势主要源于技能库而非框架设计。细粒度指标进一步揭示，具有相似Pass@1的模型在子目标完成度上可能存在显著差异。我们的代码和数据公开于https://github.com/JetAstra/MacAgentBench。

## Abstract
Computer use agents (CUAs) have advanced rapidly in desktop automation, and a growing number of users deploy CUAs such as OpenClaw on Mac Mini for always-on automation. However, existing benchmarks, including those for macOS, evaluate agents without framework augmentation and rely on binary evaluation. As a result, they fail to capture both the framework capabilities leveraged by modern CUAs and the partial progress on long-horizon, multi-application tasks. We present MacAgentBench, a comprehensive macOS agent benchmark comprising 676 tasks across 25 applications, with nearly 60% involving both GUI and CLI interaction. The benchmark adopts deterministic rule-based evaluation and introduces fine-grained multi-checkpoint scoring with capability annotations for multi-application tasks. Experiments across three frameworks and 16 models show that the best configuration, Claude Opus 4.6 on OpenClaw, attains 73.7% Pass@1, while this advantage is primarily driven by the skill library rather than by framework design. Fine-grained metrics further reveal that models with similar Pass@1 can differ substantially in sub-goal completion. Our code and data are publicly available at https://github.com/JetAstra/MacAgentBench.

# MacAgentBench：在真实macOS桌面环境中对AI智能体的基准测试

## 1. 论文的核心问题与整体含义（研究动机和背景）
- **背景**：计算机使用智能体（CUA）在桌面自动化领域快速发展，越来越多的用户将CUA（如OpenClaw）部署在Mac Mini上实现持续自动化。已有基准（如OSWorld、WindowsAgentArena等）主要针对Linux和Windows，macOS上的基准很少且功能有限。
- **核心问题**：现有CUA基准存在两个根本性局限：
  1. **评估视角局限**：仅将CUA评估简化为固定的截图- GUI-动作循环，忽略了现代CUA系统由**框架+模型**协同工作的事实。框架提供了命令行访问、脚本执行、预定义技能等超越纯GUI的能力。
  2. **评估粒度粗糙**：依赖二元通过/失败判断，对于复杂的多应用长程任务，无法揭示智能体实际完成了多少子目标（部分进展）。
- **研究动机**：亟需一个能全面、公平评估不同CUA范式（从纯GUI智能体到混合框架再到智能体工具箱）的macOS基准，并能捕捉智能体的部分进展和能力分布。

## 2. 论文提出的方法论：核心思想、关键技术细节
- **核心思想**：构建一个**环境开放**的macOS智能体基准——不对智能体框架如何与环境交互施加任何限制，允许公平比较不同CUA范式在相同任务集上的表现。同时引入**细粒度多检查点评分**和**能力标注**，揭示二进制评估无法发现的能力不平衡。
- **关键技术细节**：
  - **基础设施**：基于Docker-QEMU虚拟化macOS环境。利用QEMU的写时复制（copy-on-write）机制，所有容器共享一个基础镜像，每个实例只记录运行时写入的轻量差异层。容器启动时间约30秒，每实例磁盘开销约1GB，支持在单台服务器上并行评估多个实例。
  - **智能体-环境交互**：不限制交互方式。支持两种部署模式：容器内部署（如OpenClaw作为原生macOS应用预装在容器内，内部编排AI循环）和外部部署（框架在容器外运行，通过SSH/VNC远程交互）。
  - **任务构建**：
    - 种子任务来源：63个改编自macOSArena（重写评估脚本以适应新版macOS）+ 110个新设计（涵盖iWork套件和常见桌面操作）。经交叉验证排除4个不可靠任务，最终169个种子任务。
    - 每个种子任务通过**参数替换**（改变具体数值值）+ **指令改写**（LLM重述语义等价的指令）扩展为4个变体，共676个任务。
  - **任务统计**：覆盖25个应用，6大类别（生产力224、系统44、互联网108、开发44、多媒体116、多应用140）。59.8%的任务同时涉及GUI和CLI交互。
  - **评估协议**：
    - 完全确定性、基于规则的评估，避免LLM-as-judge的复现性问题。
    - 每个评估器由getter函数（提取相关状态）+ metric函数（比较并返回通过/失败）组成。
    - 156个unique getter函数：Shell命令(88)、AppleScript(48)、Python脚本(20)。
    - 对于140个多应用任务，定义细粒度检查点（平均每个任务4.1个检查点，范围2-7），最终分数为通过的检查点比例。
    - 每个检查点还标注一个**能力维度**：Research（外部知识查询）、App State（应用状态验证）、Content（内容正确性）、File Ops（文件系统操作）、Sys Config（系统设置修改）。
  - **评估流水线**：环境启动（30s内）→ 任务初始化（运行设置脚本）→ 智能体执行（最多50步）→ 确定性评估 → 重置（销毁COW层，任务间完全隔离。

## 3. 实验设计：数据集/场景、Benchmark、对比方法
- **Benchmark**：MacAgentBench本身，共676个任务。
- **评估框架**：三种框架：
  - **/（基线）**：纯GUI智能体，仅使用截图和鼠标/键盘动作。
  - **AgentS3**：多智能体协作架构（规划器、反射器、编码器、定位器）。
  - **OpenClaw**：容器内智能体工具箱，可访问Shell、AppleScript、内置技能库（53个技能）、内存、Web搜索等。
- **评估模型**：16个模型，分为：
  - **通用视觉语言模型（VLM）**：Claude Opus 4.6、GPT-5.4、Gemini 3.1 Pro、Qwen3VL系列(235B/32B/8B)、InternVL3.5系列(14B/8B) —— 在三个框架上都评估。
  - **原生GUI智能体模型**：UI-TARS(72B/7B)、ScaleCUA(32B/7B)、GUI-Owl-1.5(32B/8B)、OpenCUA(32B/7B) —— 仅在基线框架上评估（因无法可靠产生AgentS3和OpenClaw所需动作格式）。
- **评估指标**：
  - Pass@1（单次尝试通过率）、Pass@4（四次尝试中至少一次通过）、Pass4（四次全部通过）、Score（多应用任务检查点通过比例）、Avg. Steps、Tokens（In/Out）、Avg. Cost。

## 4. 资源与算力
- **基础设施**：Docker-QEMU堆栈，使用sickcodes/Docker-OSX镜像（QEMU 10.0.0，macOS Tahoe 26）。QEMU参数：4 CPU核、4GB RAM，qcow2磁盘格式。
- **开源模型推理**：在NVIDIA H200 GPU集群上自托管推理（模型参数量从7B到235B不等）。具体GPU数量未明确说明，但从并行容器数量（最多7个）可推断约需8-16个H200 GPU运行1-2周。
- **闭源模型**：通过官方API访问，成本在论文中按任务平均报告（如Claude Opus 4.6 on OpenClaw平均每任务成本$1.35）。
- **算力消耗**：未提供精确的GPU小时数，但提到评估所有开源模型在三个框架上完整676任务需要约8-16个H200 GPU运行1-2周。

## 5. 实验数量与充分性
- **任务规模**：676个任务（含4个变体），覆盖25个应用，是迄今为止最大的macOS智能体基准。
- **模型与框架组合**：3框架×16模型（其中8个通用VLM在三个框架上都有评估，8个原生GUI模型仅在基线上评估），共生成约(8×3 + 8×1) = 32个框架-模型组合。
- **评价维度**：Pass@1、Pass@4、Pass4、Score、Avg. Steps、Tokens、Cost，以及按类别和能力维度的分解。
- **消融/分析实验**：
  - **技能驱动分析**：将任务分为“有技能覆盖”和“无技能覆盖”子集，分别比较OpenClaw、AgentS3和基线的Pass@1，揭示OpenClaw优势主要来自技能库而非框架设计。
  - **鲁棒性分析**：通过Pass@1、Pass@4、Pass4的差距衡量一致性。
  - **细粒度多检查点分析**：针对140个多应用任务，按五个能力维度分解Score。
- **充分性评价**：实验设计较为全面：覆盖了主流闭源和开源模型、多个代理范式、多种指标。技能分析设计精巧。但缺少对OpenClaw技能库中单个技能贡献的消融，也缺少对更多框架（如其他Grounded Agent框架）的对比。另外，由于开源模型在AgentS3/OpenClaw上表现差，部分框架-模型组合无意义（如InternVL在OpenClaw上全部失败）。整体而言，实验充分且公平，但存在一定局限性（下一节详述）。

## 6. 论文的主要结论与发现
1. **框架设计对性能有显著影响**：最佳配置（Claude Opus 4.6 on OpenClaw）达73.7% Pass@1，而同一模型在基线上仅39.2%（提升34.5个百分点）。AgentS3也带来一致提升（Claude Opus 4.6达66.9%）。
2. **OpenClaw的优势主要来自技能库**：在有技能覆盖的任务上，OpenClaw大幅领先（Claude Opus 4.6达89.4%）；但在无技能覆盖的任务上，OpenClaw对多数模型甚至低于基线（5/8模型出现下降）。相反，AgentS3（不使用技能）在无技能任务上稳定优于基线。
3. **鲁棒性差异显著**：Claude和GPT-5.4 on OpenClaw的Pass@4接近（85.2% vs 82.8%），但Pass@1相差13.0点，Pass4相差20.1点，说明模型能达到相似的能力上限，但一致性差异很大。
4. **细粒度评估暴露能力不平衡**：Score始终高于Pass@1，说明智能体常完成部分子目标。不同模型在同一Pass@1下Score可能不同。File Ops分数最高，Research分数最低。GPT-5.4在基线上表现出高度不均衡（File Ops 97.7%, Research仅55.0%），而Claude on OpenClaw更均衡。
5. **通用VLM优于开源模型**，但Claude受益于框架增强更多。

## 7. 优点
- **环境开放设计**：允许不同CUA范式公平比较，区别于固定截图-动作循环的现有基准。
- **规模大且多样**：676个任务，25个应用，近60%混合GUI+CLI，覆盖常见macOS工作流。
- **细粒度多检查点评价**：突破二元评估局限，提供部分进展信号，并带能力维度标注，便于诊断瓶颈。
- **确定性规则评估**：完全可复现，避免LLM-as-judge的不确定性。
- **轻量级基础设施**：30秒启动、1GB磁盘开销、并行支持，相比macOSWorld（15分钟/次）和macOSArena（5分钟/次）大幅降低评估成本。
- **技能影响分析**：巧妙分离框架设计和技能库对性能的影响，提供重要见解。
- **鲁棒性分析**：通过Pass@1、Pass@4、Pass4揭示一致性维度，提出新的评价方向。

## 8. 不足与局限
- **硬件加速缺失**：macOS运行在QEMU虚拟机上，无Apple硬件GPU支持，导致渲染效果差异（如圆角、视图过渡）。虽经人工验证排除功能性偏离的任务，但GPU加速缺失可能影响某些UI元素的识别难度。
- **macOS版本绑定**：基准基于macOS Tahoe 26，应用行为、AppleScript接口、UI布局可能随版本变化，迁移到新版本需重新验证。
- **覆盖范围限制**：676个任务虽是最大，但仍有大量应用和场景未覆盖（如Xcode、Final Cut Pro等专业软件）。
- **技能库分析局限性**：仅区分有无技能覆盖，未深入分析单个技能贡献；OpenClaw的失败模式（如InternVL完全失效）未充分归因。
- **基线框架缺陷**：纯GUI基线使用pyautogui，存在已知bug（如macOS上rightClick不工作），可能低估纯GUI能力。
- **模型选择偏差**：原生GUI模型仅在基线上评估，未验证它们在AgentS3/OpenClaw上的潜在表现（作者声称它们无法可靠产生所需格式，但缺乏实证支持）。
- **评估成本**：尽管基础设施高效，但API费用对闭源模型仍不菲（Claude Opus 4.6 on OpenClaw平均每任务$1.35）。
- **开放性问题**：未讨论技能泛化能力（在未见过任务上的表现）、技能定义对结果的影响、以及更复杂的用户意图理解等挑战。
