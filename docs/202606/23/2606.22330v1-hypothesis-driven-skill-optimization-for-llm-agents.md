## 摘要
外部技能可以在不改变模型权重的情况下改进面向动作的LLM智能体，但若从稀疏或带噪声的轨迹中提炼技能，持续更新技能存在风险。一个看似合理的反思可能编码了有用流程、虚假捷径或目标执行器无法可靠遵循的规则。我们提出基于假设驱动的技能优化（HDSO），这是一个免训练框架，其中技能管理者和智能体执行器均为冻结推理端点。管理者观察执行器轨迹，提出带有明确验证方案的可证伪假设，将该假设实例化为候选技能包，通过配对控制/处理执行验证，审查行为差异，仅将得到支持的候选技能合并到经批准的存储库中。执行器通过渐进式披露使用经批准的技能，未选择技能时保留仅执行器路径。在ALFWorld上，HDSO将Qwen3-8B的仅执行器基线平均成功率提升+6.9个百分点，Qwen3.6-27B提升+4.0个百分点。在技能发现和验证过程中，20%随机翻转成功/失败反馈的情况下，HDSO为Qwen3-8B保持+7.1个百分点的增益。迁移和异构对诊断进一步表明，经验证的存储库可超出发起运行的有用范围，但跨模型管理仅在管理者诊断、执行器能力和验证证据一致时才能成功。HDSO为冻结动作智能体提供了可审计的技能生命周期，而非无约束的记忆累积过程。

## Abstract
External skills can improve action-oriented LLM agents without changing model weights, but persistent skill updates are risky when they are distilled from sparse or noisy trajectories. A plausible reflection may encode a useful procedure, a spurious shortcut, or a rule that the target executor cannot reliably follow. We propose Hypothesis-Driven Skill Optimization (HDSO), a train-free framework in which both the skill curator and the agent executor are frozen inference endpoints. The curator observes executor traces, proposes a falsifiable hypothesis with an explicit validation plan, instantiates the hypothesis as a candidate skill package, validates the package through paired control/treatment executions, reviews behavior differences, and consolidates only supported candidates into an approved repository. The executor consumes approved skills through progressive disclosure, preserving the executor-only path when no skill is selected. On ALFWorld, HDSO improves executor-only baselines by +6.9 Avg. SR points for Qwen3-8B and +4.0 points for Qwen3.6-27B. Under 20% randomly flipped success/failure feedback during skill discovery and validation, HDSO preserves a +7.1-point gain for Qwen3-8B. Transfer and heterogeneous-pair diagnostics further show that validated repositories can be useful beyond the run that produced them, but cross-model curation succeeds only when curator diagnosis, executor capability, and validation evidence align. HDSO provides an auditable skill lifecycle for frozen action agents rather than an unconstrained memory accumulation procedure.

# 基于假设驱动的LLM智能体技能优化（HDSO）论文总结

## 一、核心问题与研究动机

- **背景**：面向动作的LLM智能体（如ReAct）可通过外部技能（可复用的过程、调用规则等）在不改变模型权重的情况下提升性能。但在实际部署中，从稀疏或带噪声的轨迹中提炼技能存在显著风险：一个看似合理的反思可能是有用的流程、虚假的捷径，或是执行器无法可靠遵循的规则。如果每个反思都直接追加到提示中，技能库会累积过度泛化甚至矛盾的规则。
- **核心问题**：如何决定一个技能是否应该成为持久的智能体知识？需要一个系统的方法来分离“真正的程序改进”与“噪声/过拟合”，并避免无约束的记忆累积。
- **整体含义**：本文提出将技能更新视为**假设检验过程**，通过提出可证伪的假设、前瞻性配对验证、行为差异审查和审计记录，仅批准有明确证据支持的技能。从而为冻结推理智能体提供可审计、可控的技能生命周期。

## 二、方法论：核心思想与技术细节

### 2.1 核心思想

- **HDSO框架**：由两个冻结的推理端点组成——技能管理者（Curator）和执行器（Executor），两者参数均固定。
- **假设生命周期**：观察轨迹 → 提出可证伪假设 + 验证计划 → 实例化为候选技能包 → 配对控制/处理执行 → 审查行为差异 → 批准或拒绝；拒绝的假设保留在假设账本中，用于后续避免重复发现或缩小方向。
- **关键约束**：不改变模型权重，不进行微调或奖励模型训练；只更新外部技能库S。

### 2.2 关键技术细节

- **Executor设计**（Algorithm 1）：标准ReAct风格的环境策略，附加可选技能接口。运行时最多检索3个紧凑技能卡片；执行器可以选择请求完整技能内容。当无技能可用或未选择时，退化为无技能ReAct基线。技能使用被记录为轨迹中的“采用事件”。
- **Curator优化循环**（Algorithm 2）：维护三个状态对象：批准库S、假设库H、证据账本L。
  - **发现轨迹收集**：从当前执行器+技能库获取轨迹。
  - **假设提出**：Curator根据紧凑证据（任务指令、观察、动作、结果等）输出结构化假设，包含行为声明、证据、适用范围、期望指标变化、风险、回滚条件、技能包（含调用规则、可选代码载荷等）。
  - **配对验证**：控制臂使用当前S，处理臂使用S∪{候选技能}，在相同任务索引上执行。统计处理唯一胜、控制唯一胜、净胜、ΔSR、步长变化、无效动作变化、护栏杆回归等。核心统计量：net(S;V)=b-c，ΔSR=(1/|V|)Σ(y(τ1)-y(τ0))。使用单侧McNemar/binomial检验p值作为诊断。
  - **分阶段验证**：先筛选-小规模（4目标+2护栏杆任务），筛选-中规模（8+4），确认（32+12）。通过条件包括净胜≥1、ΔSR≥0.05、护栏杆回归数为0（小规模）或≤1（中、确认）。p值记录但不作为硬阈值。
  - **审查与合并**：Curator审查配对行为差异，将候选分类为“已验证方向”、“有希望需修订”、“错误方向”或“证据不足”。仅接受“已验证方向”合并到S。

## 七、优点

1. **方法论创新**：首次将技能更新系统化为“假设-验证-审查”生命周期，从概念上区别于直接追加反思或训练curator的方案。
2. **免训练部署友好**：curator和executor均为冻结推理端点，适合私有部署或模型不可更改的场景；优化可通过离线日志异步进行。
3. **配对验证机制**：通过控制/处理配对执行实现前瞻性效果评估，避免仅凭事后反思决定技能有效性。
4. **渐进式披露**：轻量级的技能接口，防止完整技能库污染上下文，同时保持无技能基线的行为。
5. **可审计性**：技能库包含假设记录、证据、验证结果、拒绝原因，便于回滚和调试。
6. **噪声鲁棒性**：在优化信号污染下仍能产生有效技能，增加了实际应用的可靠性。
