## 摘要
LLM智能体越来越依赖外部技能（可复用的工具规范），但现实世界的任务往往需要组合多种技能，而不仅仅是选择一个。我们将此形式化为组合技能路由问题：给定一个复杂的用户查询和一个大型技能库，将查询分解为原子子任务，为每个子任务检索适当的技能，并组合成一个可执行计划。我们提出了SkillWeaver，一个分解-检索-组合框架，结合了LLM任务分解器、带FAISS索引的双编码器技能检索器以及依赖感知的DAG规划器。为支持评估，我们引入了CompSkillBench，这是一个包含300个组合查询的基准测试，涵盖来自公共MCP生态系统的2,209个真实MCP服务器技能，横跨24个功能类别。我们的实验表明，任务分解质量是主要瓶颈：标准LLM分解在步骤级别仅达到34.2%的类别召回率。为解决此问题，我们提出了迭代技能感知分解（SAD），一种检索增强的反馈循环，迭代地将分解与可用技能对齐。SAD在一次迭代中将分解准确率从51.0%提升到67.7%（+32.7%，Wilcoxon p < 10^-6）；DA条件分析证实，正确的粒度是有效检索的前提（当DA=1时，CatR@1从34%上升到41%）。SkillWeaver将上下文窗口消耗减少了99%以上，迁移实验证实了泛化能力（即使目标类别不在检索池中，相对DA增益也达到+35.6%）。

## Abstract
LLM agents increasingly rely on external skills -- reusable tool specifications -- but real-world tasks often require composing multiple skills, not just selecting one. We formalize this as the Compositional Skill Routing problem: given a complex user query and a large skill library, decompose the query into atomic sub-tasks, retrieve the appropriate skill for each sub-task, and compose an executable plan. We present SkillWeaver, a decompose-retrieve-compose framework combining an LLM task decomposer, a bi-encoder skill retriever with FAISS indexing, and a dependency-aware DAG planner. To support evaluation, we introduce CompSkillBench, a benchmark of 300 compositional queries over 2,209 real MCP server skills spanning 24 functional categories, sourced from the public MCP ecosystem. Our experiments reveal that task decomposition quality is the primary bottleneck: standard LLM decomposition reaches only 34.2% category recall at the step level. To address this, we propose Iterative Skill-Aware Decomposition (SAD), a retrieval-augmented feedback loop that iteratively aligns decomposition with available skills. SAD improves decomposition accuracy from 51.0% to 67.7% (+32.7%, Wilcoxon p < 10^-6) in a single iteration; DA-conditioned analysis confirms that correct granularity is the prerequisite for effective retrieval (CatR@1 rises from 34% to 41% when DA=1). SkillWeaver reduces context window consumption by over 99%, and transfer experiments confirm generalization (+35.6% relative DA gain even when target categories are absent from the retrieval pool).

## 1. 核心问题与整体含义（研究动机和背景）

- **研究动机**：LLM 智能体越来越多地依赖外部技能（可复用的工具规范）来完成复杂任务。然而，现实中的用户查询往往需要组合多个技能，而非仅仅选择一个。现有工作（如 SkillRouter）主要处理单技能选择，缺乏对组合规划的建模。
- **核心问题**：形式化定义了 **组合技能路由（Compositional Skill Routing）**：给定一个复杂查询和一个大型技能库，需要将查询分解为原子子任务，为每个子任务检索合适的技能，并组合成一个可执行的计划。
- **整体意义**：提出了一种系统性的分解-检索-组合框架，并识别出**任务分解质量是主要瓶颈**，通过迭代反馈改善分解，显著提升路由性能，且具有跨领域泛化能力。

## 2. 方法论：核心思想、关键技术细节、算法流程

### 2.1 框架总体架构：SkillWeaver（三步级联）

1. **分解（Decompose）**：使用指令微调的 LLM（Qwen2.5-7B-Instruct）将用户查询分解为原子子任务列表 `[t1, ..., tK]`，每个子任务恰好需要一个技能。
2. **检索（Retrieve）**：对每个子任务，使用双编码器（all-MiniLM-L6-v2，384维）和 FAISS 索引（IndexFlatIP），从 2,209 个技能库中检索 top-k 候选技能。采用两种表示：仅元数据（名称+描述）或包含技能正文（前2000字符）。
3. **组合（Compose）**：利用兼容性感知的规划器（式4）选择最终技能分配，结合检索相关性和技能间兼容性（I/O类型、类别Jaccard、关键词共现），并构建依赖DAG以实现并行执行。

### 2.2 关键方法：迭代技能感知分解（SAD）

- **核心思想**：LLM 分解器生成的子任务描述通用，与技能元数据对齐差。SAD 通过检索增强反馈循环，使分解与技能词汇对齐。
- **算法流程**（Algorithm 1）：
  1. 初始分解 D^(0)（无技能提示）。
  2. 对每个子任务检索 top-H 候选技能，汇总成提示集 H^(i)。
  3. 使用新提示重新分解：D^(i+1) = LLM(psys, p_SAD(q, H^(i)))。
  4. 若提示集 Jaccard 收敛（>0.6），停止；否则继续迭代。
- **默认设置**：H=15，单次迭代即可获得主要收益，T=1 为默认，T=2 可选以进一步提升检索精度。

## 3. 实验设计

- **分解准确率 DA**：预测步骤数等于 ground-truth 步骤数的比例；放松版 DA±1。
- **基线方法**：
  - **Vanilla**：标准分解（无技能提示）
  - **+SAD**：单次迭代 SAD
  - **Iterative SAD**：多轮迭代
  - **LLM-Direct**（上限估计）：将 100 个技能名直接放入提示（qwen-max）
  - **ReAct-style**（qwen-max）：迭代式思维-行动-观察

## 5. 主要结论与发现

1. **分解是主要瓶颈**：Vanilla 分解在 2,209 个技能库上 CatR@1 仅 34.2%，DA 仅 51.0%。**DA 条件分析**表明，正确步骤数是检索有效的先决条件（DA=1 时 CatR@1 升至 41.2%）。
2. **SAD 显著改善分解**：一次迭代后 DA 从 51.0% 提升至 67.7%（+32.7%，p<1e-6），DA±1 从 71.3% 提升至 84.3%。
3. **元数据已足够检索**：仅元数据编码即可达到 CatR@10 = 69.0%，说明简洁的技能元数据携带强判别信号。
4. **SAD 泛化到未见技能**：在类别剔除和技能剔除实验中，SAD 仍保持相对 DA 增益（+35.6% 和 +23.2%），表明学习的是词汇级结构而非具体技能映射。
5. **重排序是有效杠杆**：LLM 列表重排序试点将 CatR@1 从 37.1% 提升至 40.9%（+10.3%，p<0.01），关闭了约 11% 的 @10-to-@1 差距。
6. **上下文消耗减少 99% 以上**：从 884K token（全技能）降至平均约 1,160 token/查询。
