## 摘要
现实世界中的计算机使用任务通常跨越多个应用和设备，要求Agent在动态运行时故障下协调异构环境。现有的多设备Agent系统支持任务分解和跨设备分配，但恢复机制在很大程度上仍是粗粒度的：当执行失败时，它们通常重试相同的策略、重新分配子任务或修改全局计划，而并未系统性地建模设备本地的策略空间。这限制了它们区分可在当前设备内修复的故障与需要跨设备重规划的故障的能力。我们提出H-RePlan，一个面向多设备Agent的分层重规划框架，支持统一的API-CLI-GUI执行。H-RePlan为每个设备配备可互换的执行策略，并通过紧凑的跨层故障抽象将设备本地策略恢复与编排器级全局重规划分离。为评估该能力，我们引入HeraBench，一个故障注入基准，在Linux和Android设备上构建跨设备工作流，并注入策略级和设备级故障。实验表明，H-RePlan显著优于单策略和粗粒度多设备基线，实现了更高的完成率、指令遵循率和完美通过率，同时降低了可靠端到端成功所需的令牌成本。这些结果表明，范围感知的分层恢复对于鲁棒的多设备Agent执行至关重要。

## Abstract
Real-world computer-use tasks often span multiple applications and devices, requiring agents to coordinate heterogeneous environments under dynamic runtime failures. Existing multi-device agent systems support task decomposition and cross-device assignment, but recovery remains largely coarse-grained: when execution fails, they typically retry the same strategy, reassign the subtask, or revise the global plan, without systematically modeling the device-local strategy space. This limits their ability to distinguish failures that can be repaired within the current device from those that require cross-device replanning. We propose \textbf{H-RePlan}, a hierarchical replanning framework for multi-device agents with unified API--CLI--GUI execution. H-RePlan equips each device with interchangeable execution strategies and separates device-local strategy recovery from orchestrator-level global replanning through a compact cross-layer failure abstraction. To evaluate this capability, we introduce \textbf{HeraBench}, a fault-injected benchmark that constructs cross-device workflows over Linux and Android devices and injects strategy- and device-level failures. Experiments show that H-RePlan substantially outperforms single-strategy and coarse-grained multi-device baselines, achieving higher completion, instruction adherence, and perfect-pass rates while reducing the token cost required for reliable end-to-end success. These results demonstrate that scope-aware hierarchical recovery is essential for robust multi-device agent execution.

- **研究动机**：现实世界中许多计算机使用任务（如报销申请）需要跨多个应用和设备（手机、笔记本电脑）协同完成。现有的大语言模型Agent系统虽已支持任务分解和跨设备分配，但其故障恢复机制存在严重缺陷：
  - 恢复方式粗放：当执行失败时，通常只会重试相同策略、重新分配子任务或修改全局计划。
  - 缺乏对设备本地策略空间的系统性建模：无法区分哪些故障可以在当前设备内通过切换执行策略修复，哪些必须重新进行跨设备全局规划。
  - 现有多设备系统（如CRAB、UFO 3）通常只为每个设备暴露单一执行策略（如仅GUI或仅CLI），限制了运行时恢复的灵活性。
- **整体含义**：要构建鲁棒的跨设备Agent系统，必须显式建模每个设备的策略空间，并实现范围感知的**分层恢复**——在设备内部解决策略级故障，在编排器层面解决设备级故障。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：提出**H-RePlan**，一个分层重规划框架，将恢复过程分离为**设备层策略恢复**和**系统层全局重规划**，通过紧凑的跨层故障抽象连接两者。
- **技术细节**：
  - **问题形式化**：将跨设备协作建模为自然语言指令I通过一系列设备接地步骤S执行；每个设备具有动态能力配置文件Φ(d) = (OS_d, App_d, Cap_d, Π_d)，其中Π_d是可用的执行策略集（API、CLI、GUI）。
  - **分层架构**：
    - **编排器（Orchestrator）**：系统级规划器，维护全局子任务链P = ⟨q1, q2, ..., qk⟩。支持三种模式：
      - **任务创建**（O_create）：根据用户指令和设备配置文件生成顺序子任务链。
      - **信息追加**（O_append）：子任务成功后，将结果抽取并追加到后续依赖子任务。
      - **全局重规划**（O_replan）：子任务失败时，接收结构化故障证据（Cross-Layer Failure Event），重写剩余子任务链（重试、重新路由、插入恢复子任务等）。
    - **策略规划器（Strategy Planner）**：设备级规划器，为每个设备上的子任务选择执行策略并处理策略级故障。三种决策状态：EXECUTE(π, x)（选择策略并生成指令）、DONE(y)（完成）、ESCALATE(c)（升级到编排器）。支持策略切换（API、CLI、GUI）进行本地恢复。
    - **跨层故障事件（Cross-Layer Failure Event, CLFE）**：紧凑的规划导向故障抽象，包含五个关键元素：失败子任务标识、源设备、失败类型分类、本地策略尝试总结、升级理由。作为本地执行和全局重规划之间的证据接口。
    - **策略执行Agent**：三种互补Agent——API Agent（结构化服务访问）、CLI Agent（本地计算和文件操作）、GUI Agent（界面交互）。
- **算法流程**（文字说明）：
  1. 编排器根据用户指令和设备配置文件创建有序子任务链，依次派发。
  2. 设备策略规划器接收子任务，分解策略步骤，选择初始执行策略，生成策略特定指令发送给对应执行Agent。
  3. 执行Agent返回结果到策略规划器：成功则继续执行下一个步骤或标记子任务完成；失败则进入重规划状态，尝试切换策略（如API失败换GUI）。
  4. 若所有本地策略均失败，策略规划器构造CLFE并升级到编排器。
  5. 编排器根据CLFE决定：同一设备重试、跨设备重新分配、插入恢复子任务或宣告全局失败。
  6. 重复直至指令完成或无法恢复。

## 6. 论文的主要结论与发现

- H-RePlan在任务完成率（75.84%）、指令遵循率（77.72%）和完美通过率（36.78%）上显著优于所有基线。

- 消融实验证明四个关键组件（全局重规划、策略规划器、CLFE、API策略）均不可或缺，缺少任何一个都会显著降低性能。
