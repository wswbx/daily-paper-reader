## 摘要
定制化AI智能体是驻留在自身应用程序内部、访问自身数据与工具、实施安全边界并拥有独立品牌与审计轨迹的智能体。它们与通用型智能体的区别在于适用性而非能力：每个智能体都针对单一任务构建，由负责维护的工程师完成。目前尚无公开实践指南阐述如何端到端构建此类智能体。相关组件（函数调用API、模型上下文协议、代码协作智能体）虽随处可见，但串联它们的实践方法却散见于播客、博客和泄露的系统提示中。本文将这些实践整理成一套方法论——“层层渗透的智能体”：首先建立并保持两个前提条件，然后在智能体生命周期中重复三项实践。前提条件包括：（P1）基础层——将LLM作为软件组件，以工具、系统、消息及提示缓存框架呈现；（P2）构建模块——函数调用、MCP、CLI编排、liteshell模式、智能体循环、技能、角色、钩子与脚手架。三项实践为：（P3）使用通用型智能体进行原型开发；（P4）收割、整合并交付最终CLI产品（Turtle模式）；（P5）智能体测试智能体——通过行为场景驱动测试，作为传统测试的补充而非替代。工作循环为P3→P4→P5→回溯，并自然得出推论：多智能体编排即CLI组合。该方法论在构造上无框架依赖，源自AAC——为开源LAMB平台构建的定制化智能体，由一名开发者借助AI结对程序员在约十天内开发并投入生产。我们将其作为可迁移实践呈现，独立于任何语言或框架。

## Abstract
Custom AI agents areagents that live inside their own   application, talk to their own data and tools, enforce their own security boundaries,   and carry their own brand and audit trail. What separates them from the general-purpose   tier is fit, not capability: each is built for one job, by the   engineer who will maintain it. No published practice sets out how to build one end to   end. The pieces are everywhere (function-calling APIs, the Model Context Protocol, code   agents to pair with), but the practice that chains them lives in podcasts, blogs, and   leaked system prompts. This paper writes that practice down as a methodology, Agents All   the Way Down: two preconditions crossed once and kept, then three practices repeated   for the agent's life. The preconditions are (P1) Substrate, the LLM as a software   component, framed as tools, then system, then messages under prompt-caching; and (P2)   Building blocks: function calling, MCP, CLI orchestration, the liteshell pattern, the   agent loop, skills, characters, hooks, and scaffolding. The practices are (P3) prototype   with a general-purpose agent; (P4) harvest, fold, and ship the result as a CLI, the   Turtle pattern; and (P5) agent-tests-agent, in which a general-purpose agent drives it   through behavioural scenarios, a complement to classical testing, not a replacement. The   working loop is P3 to P4 to P5 and back, and one corollary falls out for free:   multi-agent orchestration is just CLI composition. The methodology is framework-free by   construction. It was distilled from the AAC, a custom agent for the open-source LAMB   platform, built in about ten days by one developer with an AI pair-programmer and in   production . We present it as a transferable practice, independent of any language or framework.

- **研究动机**：相关组件（函数调用 API、MCP 协议、通用代码智能体）早已存在，但串联这些组件的实践方法碎片化地散落在博客、播客、泄露的系统提示中，没有形成书面、完整、可重复的工程流程。本文旨在填补这一空白，提供一套框架无关、可迁移的构建实践。
- **整体含义**：作者提出了“Agents All the Way Down”方法论，强调将LLM视为软件组件，通过两个前提条件（P1 基底层、P2 构建块）和三个循环实践（P3 原型化、P4 封装为CLI、P5 智能体测试智能体）构建和维护定制化智能体。该方法论源自作者团队构建AAC代理的实践经验，并已在多个子项目中验证。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

- **核心思想**：将LLM作为软件组件，以“工具 → 系统提示 → 消息”的结构化方式进行编排；利用提示缓存（prompt caching）机制降低迭代成本；将定制化智能体最终交付为CLI工具（Turtle模式），从而天然支持多智能体编排（CLI组合）。
- **五个阶段（P1-P5）**：
  - **P1 基底层（Substrate）**：工程师必须内化LLM作为软件组件的本质，包括：next-token预测原理、tokenizer对成本和行为的影响、固定上下文窗口的资源竞争、对齐栈的作用，以及四个实际约束（成本、幻觉、上下文、时间）。特别强调提示缓存的KV缓存纪律：工具声明 → 系统提示 → 消息，稳定性从高到低排列，缓存命中可大幅降低成本。
  - **P2 构建块（Building blocks）**：熟悉函数调用、MCP协议、CLI编排、liteshell模式、智能体循环（agent loop）、技能（skills）、角色（characters）、钩子（hooks）和脚手架（scaffolding）。其中liteshell模式是一个创新命名：将应用程序操作封装为类CLI的接口，让LLM通过单个dispatch工具调用，利用其预训练中对shell知识的掌握，降低token开销。
  - **P3 使用通用智能体进行原型化（Prototype with a general-purpose agent）**：利用Claude Code、OpenCode等通用代码智能体作为结对编程伙伴，快速探索平台、发现缺失的API、构建首个工作原型。强调“先构建再设计”，架构通过构建自然涌现。
  - **P4 收割、整合并交付为CLI（Harvest, fold, ship as CLI）—— Turtle模式**：将从P3中发现的工具、安全脚手架、技能、角色等整理为版本化文件；嵌入一个小的智能体循环（带预处理钩子的安全门）；最终交付为CLI工具，具有无状态调用、会话ID续接、结构化输出、`--help` 等特性。Turtle命名的三层含义：乌龟层层堆叠的宇宙论、Papert的Logo Turtle、CLI可被另一智能体驱动。
  - **P5 智能体测试智能体（Agent-tests-agent）**：用通用CLI智能体驱动定制化智能体，通过自然语言场景和评估规则，生成结构化评估（通过/失败+证据）。这是一种行为回归测试方法，补充而非替代传统确定性测试（单元测试、集成测试、端到端测试）。P5可暴露行为缺陷（如确认循环、术语泄露等）。
- **循环结构**：P3→P4→P5→回溯循环，是工程师维护智能体的核心工作流。前提条件P1、P2只需内化一次，后续不断迭代P3-P5。迭代成本因缓存纪律而降低：前缀稳定，每次增量小。
- **多智能体编排推论（Turtle推论）**：在P4中交付的CLI可被另一个CLI调用，因此多智能体编排就是CLI组合。作者以此展示了“忍者神龟”角色模型（Splinter/Leo/Don/Mike/Raph），并指出Ralph循环等模式可直接用shell脚本实现。

- **主要结论**：定制化AI智能体的构建可以通过一套系统化的五阶段方法论实现，该方法是框架无关的，可迁移至任何LLM提供商、编程语言和应用领域。核心价值在于将LLM视为组件、利用缓存纪律降低迭代成本、通过Turtle模式实现低开销编排、以及用智能体测试智能体弥补传统测试的不足。

## 7. 优点

1. **系统性与完整性**：首次提出端到端的方法论，覆盖从底层认知到生产测试的完整链路，并为每一步设立了验收标准和反例清单。

3. **经济性设计**：P1的缓存纪律和P4的Turtle模式（低token开销CLI替代高开销MCP）使得迭代成本可控，工程师可以频繁循环。
4. **P5的创新实践**：将智能体测试智能体作为行为质量保证手段，是对传统确定性测试的有力补充。论文提供了具体案例（七个bugs），展示了该方法的实用性。
5. **多智能体编排的自然派生**：通过Turtle推论，避免了引入专门的多智能体框架，简化了架构。
6. **命名与概念贡献**：为liteshell模式、Turtle模式、P5等新概念命名，便于社区交流与复用。
