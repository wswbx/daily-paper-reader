## 摘要
现实世界的计算机任务往往跨越多个应用和设备，要求智能体在动态运行时故障下协调异构环境。现有的多设备智能体系统支持任务分解和跨设备分配，但恢复机制大体上是粗粒度的：当执行失败时，它们通常重试相同的策略、重新分配子任务或修订全局计划，而没有系统地对设备本地策略空间进行建模。这限制了它们区分可在当前设备内修复的故障与需要跨设备重规划的故障的能力。我们提出 H-RePlan，一种面向多设备智能体的分层重规划框架，支持统一 API-CLI-GUI 执行。H-RePlan 为每个设备配备可互换的执行策略，并通过紧凑的跨层故障抽象将设备本地策略恢复与编排器级别的全局重规划分离。为评估该能力，我们引入 HeraBench，一个注入故障的基准测试，在 Linux 和 Android 设备上构建跨设备工作流，并注入策略级和设备级故障。实验表明，H-RePlan 显著优于单策略和粗粒度多设备基线，实现了更高的完成率、指令遵循率和完美通过率，同时降低了实现可靠端到端成功所需的令牌成本。这些结果表明，范围感知的分层恢复对于鲁棒的多设备智能体执行至关重要。

## Abstract
Real-world computer-use tasks often span multiple applications and devices, requiring agents to coordinate heterogeneous environments under dynamic runtime failures. Existing multi-device agent systems support task decomposition and cross-device assignment, but recovery remains largely coarse-grained: when execution fails, they typically retry the same strategy, reassign the subtask, or revise the global plan, without systematically modeling the device-local strategy space. This limits their ability to distinguish failures that can be repaired within the current device from those that require cross-device replanning. We propose \textbf{H-RePlan}, a hierarchical replanning framework for multi-device agents with unified API--CLI--GUI execution. H-RePlan equips each device with interchangeable execution strategies and separates device-local strategy recovery from orchestrator-level global replanning through a compact cross-layer failure abstraction. To evaluate this capability, we introduce \textbf{HeraBench}, a fault-injected benchmark that constructs cross-device workflows over Linux and Android devices and injects strategy- and device-level failures. Experiments show that H-RePlan substantially outperforms single-strategy and coarse-grained multi-device baselines, achieving higher completion, instruction adherence, and perfect-pass rates while reducing the token cost required for reliable end-to-end success. These results demonstrate that scope-aware hierarchical recovery is essential for robust multi-device agent execution.

## 1. 核心问题与整体含义（研究动机和背景）

- **研究背景**：大语言模型（LLM）智能体在计算机操作任务中展现出强大能力，但现实任务往往跨越多个应用程序和设备（如手机到笔记本电脑的文件传输、报销流程等）。现有单设备智能体已支持 API、CLI、GUI 等多种执行策略，但这些策略各有优劣，需要灵活组合。
- **核心问题**：现有的多设备智能体系统（如 CRAB、UFO 3）虽然支持任务分解与跨设备分配，但其故障恢复机制粗粒度——当执行失败时，通常只是重试同一策略、重新分配子任务或修订全局计划，**没有系统建模设备本地的策略空间**。这导致无法区分“可在当前设备内修复的故障”与“需要跨设备重规划的故障”，造成不必要的全局重规划或策略失效。
- **研究动机**：为了提升多设备智能体在动态故障场景下的鲁棒性和效率，需要一种**范围感知的分层恢复框架**，将设备级策略恢复与系统级跨设备重规划分离。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：H-RePlan 提出**分层重规划**框架，包含两个主要层面：
  - **全局编排器（Orchestrator）**：维护跨设备的任务计划，负责任务创建、信息追加（将成功子任务结果传递给后续子任务）和全局重规划。
  - **设备级策略规划器（Strategy Planner）**：在单个设备内，根据子任务和本地历史，选择可用的执行策略（API、CLI、GUI）并执行；当本地策略失败时，尝试在同一设备内切换策略（本地恢复），若无法修复则向上层编排器上报并传递**跨层故障事件（CLFE）**。

- **关键设计**：
  - **统一的策略控制抽象**：每个设备支持其平台可用的 API、CLI、GUI 策略子集，作为可互换的“执行策略”，平台无关。
  - **跨层故障事件（CLFE）**：作为设备级执行与系统级规划之间的紧凑故障抽象，包含：失败子任务标识、源设备、故障类型分类、已尝试的本地策略摘要、升级原因推理。CLFE 帮助编排器判断是否可在同一设备重试、换设备或插入恢复子任务，避免传递过多低级日志。
  - **执行流程**：编排器将用户指令分解为有序子任务链 → 分派给指定设备 → 设备策略规划器选择策略并执行 → 结果返回；若失败，设备端尝试本地恢复（最多两次策略切换），否则上报 CLFE → 编排器更新计划（重试、换设备、插入恢复步骤或宣布失败）。

- **算法流程（文字说明）**：
  - 编排器 `Ocreate`：输入用户指令和所有设备能力，输出有序子任务链。
  - 子任务执行成功后，编排器 `Oappend`：将结果仅追加到依赖的后继子任务中。
  - 子任务失败后，编排器 `Oreplan`：结合当前指令、失败子任务、历史、CLFE 和设备能力，重写剩余子任务链。
  - 策略规划器 `Sd`：输入子任务、本地历史、剩余预算、设备能力，输出三个决策之一：`EXECUTE(策略, 指令)`、`DONE(结果)`、`ESCALATE(CLFE)`。

## 3. 实验设计：数据集/场景、基准（HeraBench）、对比方法

- **基准（HeraBench）**：作者构建了**故障注入的多设备基准**，包含 23 个种子任务，扩展为 174 个评估变体。每个变体在**四个设备环境**（两台 Linux + 两台 Android）上运行，使用真实服务与本地文件。
- **故障注入类型**：
  - **无故障**：基线场景。
  - **本地故障**：禁用某设备上的特定策略（如 API、CLI），但同一设备其他策略仍可用。
  - **全局故障**：禁用某设备上所有本地恢复路径（如服务完全不可达），需跨设备（相同类型设备）重新分配。
  - **混合故障**：同时包含本地和全局故障。
- **对比方法**：
  - **CRAB**（GUI 和 API 变体）
  - **UFO 3**（GUI 和 API 变体）
  - **H-RePlan**（混合策略，即使用 API、CLI、GUI 三种策略）
- **评价指标**：
  - **任务完成率**：最终环境状态满足所需外部状态条件的百分比。
  - **指令遵循率**：成功的黄金步骤占所有黄金步骤的比例（允许的设备约束根据故障类型调整：本地故障必须用原设备，全局故障允许用同类型其他设备）。
  - **完美通过率**：完成率 100% 且指令遵循率 100% 的剧集比例。
  - **效率指标**：每集平均 token 消耗（Tok./Ep.）、完美通过的期望 token 成本（Tok./PP = Tok./Ep. / 完美通过率）。

## 6. 主要结论与发现

- **主要结论**：范围感知的分层恢复（H-RePlan）显著优于单策略和粗粒度多设备基线。
- **定量结果**：
  - H-RePlan 在 HeraBench 上达到 75.84% 完成率、77.72% 指令遵循率、36.78% 完美通过率。
  - 相比最强基线 UFO 3-GUI（完美通过率 13.79%），H-RePlan 的完美通过率提升 2.7 倍；相比 UFO 3-API（完美通过率为 0），H-RePlan 实现可靠端到端成功。

- **范围级分析**：H-RePlan 在所有故障范围下的完成率和指令遵循率均优于 UFO 3 两种变体；在混合故障下收益最大（完成率提升+19.9%~+35.4%）。
- **消融实验**：移除全局重规划导致性能下降最大；移除策略规划器导致指令遵循率下降更明显；移除 CLFE 后编排器响应更盲目（同等概率重试/换设备/中止），降低恢复效果；移除 API 策略后性能下降但仍优于 UFO 3-GUI，说明分层恢复结构本身的价值。
- **行为分析**：本地故障下，策略规划器大多能在两次策略尝试内本地恢复（不升级），升级后的编排器倾向于让同一设备重试（91.7% 完成率）；全局/混合故障下则倾向跨设备分配。

## 8. 不足与局限

- **实验覆盖局限**：
  - 仅包含 Linux 和 Android 设备，未覆盖 Windows、macOS、iOS 等主流平台，可能限制通用性。

- **潜在偏差**：故障注入可能偏向于容易恢复的场景（如 API 故障后使用 GUI 可替代），对于完全依赖某策略的硬故障可能仍无法恢复。此外，H-RePlan 需要更复杂的提示设计和设备能力描述，可能增加系统部署难度。
- **动态性**：未评估环境中实时状态变化（如用户中途干预、网络突然恢复）对恢复的影响。
