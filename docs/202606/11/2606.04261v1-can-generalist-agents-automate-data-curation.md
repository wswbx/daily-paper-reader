## 摘要
策展训练数据是现代人工智能开发中最重要但劳动密集的部分之一：从业者根据嘈杂的基准反馈迭代地提出、实施、评估和修订数据策略。我们研究通用编码智能体是否能够自动化这个数据策展循环。我们引入了*Curation-Bench*，一个以智能体为中心的基准，它固定了模型、训练配方和评估套件，同时赋予智能体命令行权限以检查数据、实施策略、将策略提交到固定的训练/评估管线并进行修订。在视觉-语言指令微调实例化中，开箱即用的智能体在十次迭代内达到了已发表的强数据选择基线。然而，轨迹分析揭示了一个持续的*执行-研究差距*：即使提供了策略指南和论文参考文献，智能体主要调整局部策略变体，而不是探索新的策略家族。要求每次迭代引用、实例化和改编先前方法的脚手架将智能体转向了方法引导的探索。该脚手架智能体自主组合——无需人工设计输入——一个数据选择策略，该策略以十分之一的数据预算超越了已发表的强基线。总体而言，当前智能体能够运行策展循环，但可靠的数据研究需要脚手架方法适应，而不是仅仅开放式的提示。代码和基准已开源。

## Abstract
Curating training data is among the most consequential yet labor-intensive parts of modern AI development: practitioners iteratively propose, implement, evaluate, and revise data policies against noisy benchmark feedback. We ask whether generalist coding agents can automate this data-curation loop. We introduce *Curation-Bench*, an agent-centric benchmark that fixes the model, training recipe, and evaluation suite while giving agents command-line access to inspect data, implement policies, submit them to a fixed training/evaluation pipeline, and revise. In a vision-language instruction-tuning instantiation, out-of-the-box agents reach strong published data-selection baselines within ten iterations. However, trajectory analysis reveals a persistent *execution-research gap*: agents mainly tune local policy variants rather than explore new policy families, even when given strategy guides and paper references. Scaffolds requiring each iteration to cite, instantiate, and adapt a prior method shift agents toward method-guided exploration. The scaffolded agent autonomously composes -- without human design input -- a data-selection policy that outperforms strong published baselines at one-tenth their data budget. Overall, current agents can run the curation loop, but reliable data research requires scaffolded method adaptation, not open-ended prompting alone. Code and benchmark are open-sourced.

## 1. 论文的核心问题与整体含义

- **研究动机**：数据策展（data curation）是现代AI开发中最关键但也最劳动密集的环节。从业者需要反复提出、实施、评估和修订数据策略（如筛选、混合、重写等），而这一迭代搜索过程消耗大量人力。
- **核心问题**：通用编码智能体（generalist coding agents）能否自动化这一数据策策循环？即智能体能否像人类从业者一样，通过观察数据、实现策略、提交训练评估、根据反馈迭代改进，来发现高质量的训练数据子集？
- **整体含义**：若智能体能自动化数据策展，将大幅降低模型微调的人力成本，使资源有限的团队也能从数据优化中获益。但论文发现，当前智能体虽能“运行循环”，却难以进行真正的数据研究探索，需要结构化引导（scaffold）才能突破。

## 2. 研究方法论

- **核心思想**：构建一个以智能体为中心的基准Curation-Bench，该基准固定模型架构、训练配方和评估套件，仅允许智能体通过命令行操作数据策展策略（选择、过滤、重写等），并记录完整的策略轨迹。
- **关键技术细节**：
  - **基准契约**：包含四条原则：数据隔离（只改变数据）、终端现实（智能体通过标准终端交互）、污染控制（自动审计训练集与评估集的重叠）、轨迹可读性（每次迭代持久化脚本、清单、训练输出、评估分数等）。
  - **环境接口**：智能体在Docker容器中工作，拥有任务说明、只读候选池、随机选择起始脚本、日志目录，以及用于验证、审计、训练、评估的CLI命令。
  - **评估维度**：除了下游模型性能（平均分数、恢复全数据增益的百分比），还引入轨迹诊断标签：新策略家族（是否切换到不同类型的数据策略）、有依据（是否由具体证据支撑）、有效（是否提升指标）、浅层（是否为反应性的局部调整）。
  - **支架设计**：四种支架（从轻到重）：
    - **开箱（open-prompt）**：仅提供标准循环指令。
    - **轻量I（Data Strategies）**：提供可能的策略家族列表（如源平衡、质量过滤、多样性采样等）。
    - **轻量II（Research Papers）**：提供从论文编译的技能卡片，建议智能体参考。
    - **重量I（Self-Research）**：要求每次非基线迭代必须写观察、假设、预期效果和最小变更，且必须基于具体证据。
    - **重量II（Adapt Papers）**：要求每次非基线迭代必须引用具体先前方法，解释为何适用，改编实现并验证清单。
- **算法流程**（文字描述）：
  1. 智能体读取任务和约束，检查候选池。
  2. 提出数据策略（选择、混合、过滤、评分或重写）。
  3. 实现策略，生成训练数据集并保存清单。
  4. 使用固定训练配方微调模型。
  5. 在固定基准套件上评估。
  6. 写入运行笔记（假设、证据、下一步行动）。
  7. 循环迭代，根据反馈修订策略。

## 6. 论文的主要结论与发现

1. **发现1：通用智能体是有效的数据策展执行者**。在开箱提示下，Claude Code等智能体在10次迭代内达到或超过强基线（ICONS, ARDS），恢复约59%的全数据微调增益，仅用1.5%的数据池。
2. **发现2：存在执行-研究差距**。智能体主要进行局部策略变体调整（源比例、长度阈值、种子等），很少探索新策略家族；其理由往往基于模糊的“提高质量”而非具体证据。
3. **发现3：轻量支架拓宽考虑但不改善最佳结果**。轻量I和II增加了新策略家族的尝试率和依据性，但最终分数未超过开箱最大值（34.0）。智能体词汇变了但实现仍然简单。
4. **发现4：重量级支架促成更大突破**。重量I（Self-Research）将依据迭代从57%提升至91%，但分数略降。重量II（Adapt Papers）消除浅层操作，新策略家族率升至67%，最佳分数34.9（超过100k ARDS/ICONS基线），且自主组合了EL2N损失选择+助手损失噪声过滤的混合策略。
5. **发现5：更多迭代持续改善**。从10次到50次迭代，平均分数持续上升（开箱逐渐，重量II方差减少）。说明搜索计算本身是一种有意义的策展资源。
6. **重写任务可行**：使用适当MLLM工具，智能体通过重写恢复71%全数据增益，优于模板重写基线。

## 7. 优点

- **新颖基准**：填补了数据策展自动化和智能体评估之间的空白，继承DataComp的数据隔离原则但引入迭代搜索和轨迹跟踪。
- **轨迹诊断**：不仅报告最终分数，还量化智能体的搜索行为（新家族率、依据率、浅层率），使过程可审计。
- **系统支架设计**：从轻到重逐步增加约束，揭示了智能体从“执行者”变为“研究者”所需的关键干预（强制方法适应）。
- **实验丰富**：多智能体、多模型、多数据集、多预算、多迭代、重写扩展，结果稳健。
- **开源**：代码和基准公开，促进可重复性和后续研究。
- **实际价值**：证明智能体可用较少数据（1.5%池）达到高增益，降低微调门槛。

## 8. 不足与局限

- **领域覆盖有限**：主要限于视觉语言指令微调，仅一个CLIP预训练实例和一个重写扩展。结论可能不适用于纯文本预训练、代码、数学或特定领域指令微调。
- **支架比较非全因子**：重量级支架组合了方法依据、结构化日志、类别旋转等多种成分，未隔离单一因果因素。
- **轨迹标签依赖LLM注释**：使用Claude Opus 4.7自动标注，存在判断偏差，尽管提供了准则和示例。
- **计算成本未量化**：未报告总GPU小时数或API调用成本，影响实用性评估。
