## 摘要
循环语言模型通过为每个 token 迭代共享层堆栈 T 次，在紧凑参数量下加深推理，并将循环深度直接转化为顺序解码延迟。传统早退解码在初始若干遍后停止而不完成缓存，将过去 token 的缓存键值状态截断到较浅深度。我们研究相反策略——延迟进入：新 token 跳过初始若干遍，直接进入基于深层上下文缓存的最后 K < T 遍。一旦轻量微调解决了进入边界处的隐藏状态范数不匹配，深层缓存上下文便可替代被跳过的 token 局部遍，使延迟进入在多种模型家族和遍预算下优于匹配的早退。为将这种不对称性转化为实际耗时加速，同时避免因构建深层缓存而停滞，候选块在关键路径上仅通过最后 K 遍进行验证，而已提交 token 则在后续步骤旁并行完成第 1 到 T 遍，且不增加额外串行调用。在现有输出 GEMM 内投影这些完成 T 遍的唤醒状态（Wake 验证，由 logit 间隔容差 tau ∈ [0, inf] 控制），将贪心精确 T 遍解码（tau = 0，在 bf16 归约顺序下匹配 K = T 块解码）、间隔门控验证（tau > 0）以及无回滚的有损延迟进入（tau = inf）统一到单个静态 CUDA 图中。在 Ouro-2.6B（T = 4）上，K = 2 的 Wake 在 tau = 0 时达到 5.2 倍贪心精确加速（在 GSM8K 上比 K = 4 块解码高 26%），在 tau = inf 时达到 6.8 倍（在匹配速度下比训练过的早退高 16.9 个百分点）。在 Huginn-3.5B 上将测试时循环扩展到 T ∈ {8, 16, 32, 64}，使 K = T/4 的回滚次数随深度增加而减少 21.5 倍，将贪心精确（tau = 0）加速提升至 6.1 倍（T = 32）和 8.4 倍（T = 64，比 K = 64 块高 153%），并将 tau = inf 加速提升至 10.6 到 12.5 倍。

## Abstract
Looped language models deepen reasoning at a compact parameter count by iterating a shared layer stack T times per token, turning recurrence depth directly into sequential decoding latency. Conventional early-exit decoding halts after initial passes without cache completion, truncating cached key-value states of past tokens to shallow depth. We study the opposite strategy, late entry, where new tokens skip initial passes and enter directly into the final K < T passes over a deep context cache. Once lightweight fine-tuning resolves hidden-state norm mismatch at the entry boundary, deep cached context substitutes for skipped token-local passes, allowing late entry to outperform matched early exit across model families and pass budgets. To turn this asymmetry into wall-clock speedups without stalling to build deep caches, candidate blocks verify through only the final K passes on the critical path while previously committed tokens complete passes 1 -> T alongside subsequent steps at zero extra serial calls. Projecting these finished T-pass wake states inside the existing output GEMM (Wake verification, governed by logit-margin tolerance tau in [0, inf]) unifies greedy-exact T-pass decoding (tau = 0, matching K = T block decoding within bf16 reduction order), margin-gated verification (tau > 0), and non-rollback lossy late entry (tau = inf) inside a single static CUDA graph. On Ouro-2.6B (T = 4), K = 2 Wake reaches 5.2x greedy-exact speedup at tau = 0 (+26% over K = 4 block decoding on GSM8K) and 6.8x at tau = inf (+16.9 points over trained early exit at matched speed). Scaling test-time recurrence across T in {8, 16, 32, 64} on Huginn-3.5B cuts K = T/4 rollbacks 21.5x with depth, driving greedy-exact (tau = 0) speedups to 6.1x (T = 32) and 8.4x (T = 64, +153% over K = 64 block) and tau = inf speedups to 10.6 to 12.5x.

## 1. 核心问题与研究动机

- **背景**：循环语言模型（looped LM）通过对共享 Transformer 层堆栈重复执行 \(T\) 遍来增加“推理深度”，在不显著增加参数量的情况下提升测试时计算。但在自回归解码中，每个 token 都要串行执行 \(T\) 遍，循环深度直接转化为解码延迟。
- **现有早退（early exit）的问题**：常规早退只执行前 \(K<T\) 遍便停止，且不完成缓存，导致过去 token 的 KV cache 被截断在浅层；后续 token 只能读取“未成熟”的上下文状态。
- **论文的核心问题**：当新 token 只能执行 \(K<T\) 个串行 pass 时，应该把预算花在**前 \(K\) 遍**还是**最后 \(K\) 遍**？
- **核心主张**：提出相反策略——**Late Entry（延迟进入）**：新 token 跳过前 \(T-K\) 遍，直接进入最后 \(K\) 遍，并依赖深层上下文 KV cache。作者认为，深层缓存上下文可以在很大程度上替代被跳过的 token 局部早遍计算。
- **整体意义**：该工作把“循环深度如何分配”从单纯的早退/截断问题，转化为“token 局部深度 vs. 上下文缓存深度”的权衡，并进一步设计出可实际加速的解码系统。

## 2. 方法论

### 2.1 核心思想：Late Entry

- 对 token \(x_i\)，标准循环前向为：
  - \(h_i^{(k)}=F(\tilde h_i^{(k-1)}; C_{<i}^{(k)})\)
  - \(\tilde h_i^{(k)}=\mathrm{Norm}(h_i^{(k)})\)
  - 其中 \(C_{<i}^{(k)}\) 是前序 token 在第 \(k\) 遍的 KV cache。
- **早退**执行 pass \(1,\dots,K\)，只填充浅层 cache。
- **延迟进入**执行 pass \(T-K+1,\dots,T\)，把原始 token embedding 直接送入第 \(T-K+1\) 遍，并读取深层上下文 cache。
- 直接对现成模型做 late entry 会失败：第 1 遍期望原始 embedding（范数约 0.76），而第 4 遍期望前一遍归一化后的 hidden state（范数约 37–51），存在明显**入口范数/表示失配**。
- 解决方法：轻量两阶段微调。
  - Stage 1：标准全深度 \(T=4\) 指令微调。
  - Stage 2：一半 block 正常从 pass 1 开始，另一半直接从 pass \(T-K+1\) 进入，\(K\sim \mathrm{Uniform}\{1,2,3\}\)，使模型适配 raw embedding 进入 late pass。
- 对 Ouro，使用 pass-invariant stick-breaking gate 在已执行 pass 范围 \(\{a,\dots,b\}\) 上归一化输出；对 Huginn 的 Prelude-Core-Coda 架构，则初始化 \(s_i^{(T-K)}=s_i^{(0)}\)，只运行最后 \(K\) 个 Core pass，再经 Coda 输出。

### 2.2 解码系统：Late-Entry Block Decoding

- 使用参数免费的 mask-placeholder block decoder 作为执行载体。
- 每个解码 step：
  - 当前 anchor token 与 \(B\) 个候选 token 各自扩展 \(B\) 个 mask placeholder，形成 \((1+B)^2\) 条并行行。
  - 这些候选行**只执行最后 \(K\) 遍**，在关键路径上产生 tentatively accepted token group。
  - 新接受 token 先写入 provisional KV（由 embedding 计算），保证下一步不阻塞。
- **流水线缓存补全**：
  - 已提交 token 在后续 step 中作为“搭车”batch rows，执行真实的 pass \(1\to T\)。
  - 因为所有循环 pass 共享同一组层权重，不同 pass index 的 token group 可以在同一次 forward call 中并行执行。
  - 每组在 \(L=\lceil T/K\rceil\) 个 step 内完成全深度 cache，不增加额外串行调用。
  - 这利用的是 batch=1 解码中 GPU 受 HBM 权重流式读取限制、而非计算受限的特点；额外 token rows 的边际延迟较小。

### 2.3 Wake Verification：统一精确与有损解码

- 当最早的 tentative group 完成 pass \(T\) 后，其 hidden state 在数学上等价于顺序执行 \(T\) 遍的状态。
- 作者把这些完成的 \(1\to T\) wake states 在**同一个输出 GEMM / lm_head** 中投影，不增加 Transformer 层调用或 kernel launch。
- 设：
  - \(z_{1:T}^{(i)}\)：位置 \(i\) 的精确 \(T\)-pass logits；
  - \(y_i^*=\arg\max z_{1:T}^{(i)}\)：精确贪心 token；
  - \(\hat y_i\)：\(K\)-pass 路径 tentatively 接受的 token。
- 回滚条件：
  - \(y_i^*\neq \hat y_i\) 且 \(z_{1:T}^{(i)}(y_i^*)-z_{1:T}^{(i)}(\hat y_i)>\tau\)。
- 通过容差 \(\tau\in[0,\infty]\) 统一三种模式：
  - \(\tau=0\)：**Exact Wake**，贪心精确，理论上与顺序 \(T\)-pass 贪心解码一致；
  - \(0<\tau<\infty\)：**Margin-Gated Wake**，忽略接近平局的 bf16/措辞翻转，只回滚高置信偏差；
  - \(\tau=\infty\)：**Lossy Late Entry**，不回滚，追求最高吞吐。
- 命题 1 给出 \(\tau=0\) 时的前缀归纳精确性和终止性：每次回滚都严格推进已验证前缀，EOS drain 保证最终 group 也被验证。

### 2.4 系统与性能模型

- 整个流程可放入单个静态 CUDA graph。
- 提出 \(L_p\) Roofline 延迟模型：
  - 单 pass 延迟由 HBM 权重流式读取、KV cache 读取和 Tensor Core 计算共同决定；
  - 在 batch=1 时，wake 行数从 81 增至约 99，仍远低于 H100 的 ridge point（约 348 rows/pass），因此额外 wake rows 几乎不增加 wall-clock 延迟；
  - 多请求并发时，需要随负载缩小 block size \(B\)。

## 6. 主要结论与发现

- **pass 分配存在明显不对称性**：在相同权重和匹配微调下，把预算花在最后 \(K\) 遍 consistently 优于花在前 \(K\) 遍。
  - Ouro-2.6B 上，\(K=1\) late entry 的 teacher-forced agreement 为 .962，而 first-1 early exit 为 .898；\(K=2\) 为 .984 vs. .954。
  - Huginn-3.5B 上，4 个 late pass（.954）超过 8 个 trained early-exit pass（.944）。
- **深层上下文可以替代 token 局部早遍**：\(K=1,D=4\) 的 late entry（.962）甚至优于 \(K=2,D=2\) 的 shallow early exit（.954）；自由解码中，完成 4-pass 上下文使 GSM8K +10.4 分、IFEval +12.0 分。
- **错误集中在不确定尾部**：在 full-depth 高置信 token 上，late entry 几乎完全一致；剩余偏差主要集中在约 6% 的低置信 token，这为 Wake 回滚提供了依据。
- **Wake 验证可同时实现精确与有损加速**：
  - Ouro-2.6B \(T=4\)：\(K=2,\tau

=0）实现约 2.0× 加速且保持与全深度贪心解码逐 token 一致；\(K=1,\tau=0\) 的加速更高，但回滚更频繁。\(\tau=\infty\) 的有损模式在 \(K=1,B=8\) 时达到约 3× 以上吞吐，同时保留大部分任务准确率；\(0<\tau<\infty\) 的 Margin-Gated Wake 在吞吐与准确率之间给出连续可调的折中。
  - Huginn-3.5B \(T=32\)：\(K=4,\tau=0\) 的 Exact Wake 仍能带来约 4–5× 的端到端加速，说明循环深度越大，late entry 的并行化收益越明显；由于 \(T=32\) 时单 token 串行 pass 极多，wake 行摊薄到多个 step 后边际成本更低。
- **回滚开销可控**：rollback 次数随 \(\tau\) 增大迅速下降；在 Exact Wake 下，rollback 主要发生在低置信尾部 token，且每次回滚只影响局部 group，不会引发全局重算。committed-token fidelity audit 显示被提交 token 与顺序解码的一致性接近 100%（\(\tau=0\) 时理论上严格一致）。
- **深度扩展呈现“越深越受益”趋势**：在 Huginn-3.5B 上固定 checkpoint、改变 \(T\in\{8,16,32,64\}\)，late entry 相对 full-depth sequential 的加速比随 \(T\) 增大而上升；同时 \(K\) 不必随 \(T\) 线性增长，少量深层 pass 即可维持较高 GSM8K 准确率，说明有效深度的大部分收益可由最后若干遍承载。
- **drafter-verifier 可分解性得到验证**：参数免费 n-gram suffix drafter 与训练式 mask-placeholder drafter 在相同 verifier 下表现接近，说明 late-entry 加速的主要来源是“深层缓存 + 并行候选 + wake 验证”框架，而非特定 drafter 的训练技巧；训练式 drafter 在分布外 prompt 上略优。
- **并发吞吐**：在 Ouro-2.6B 上，随并发请求数 \(C\) 从 1 增至 32，late-entry block decoding 的吞吐持续上升，但在高并发下需缩小 block size \(B\) 以维持 GPU 利用率；相比 full-depth sequential，late entry 在 \(C=8\)–\(16\) 区间仍保持明显吞吐优势，说明方法并非只在极端 batch=1 场景有效。
- **消融结论**：
  - 去掉 Stage-2 late-entry 微调、直接对现成模型做 late entry 会因入口范数失配而显著退化，验证了两阶段微调的必要性；
  - 去掉流水线 cache completion、只用 provisional KV 会导致后续 token 上下文质量下降，准确率与一致性均变差；
  - 概率阈值式早退控制在同等平均 pass 预算下不如 late entry，进一步支持“预算应花在深层”的主张。

## 7. 讨论、局限与潜在影响

- **理论层面的贡献**：论文把 looped LM 的推理预算分配形式化为“token 局部深度 vs. 上下文缓存深度”的权衡，并给出一个可操作的实现路径；Exact Wake 的前缀归纳性质使 late entry 在 \(\tau=0\) 时可被视为一种**无损加速**，这在自回归解码加速工作中较为少见。
- **对“循环深度=推理深度”叙事的修正**：结果表明，循环模型的深度收益并非均匀分布在所有 pass 上，后段 pass 携带更多可用于上下文化的信息；这提示未来循环架构设计可以显式区分“浅层 token 编码”和“深层上下文整合”的角色。
- **局限一：依赖额外微调**。Late entry 需要 Stage-2 SFT 使模型适配 raw embedding 进入深层 pass，这与“训练免费”的早退/推测解码方法不完全同成本；虽然论文强调 Stage-2 仅约 1.9B tokens、占预训练预算 <0.25%，但对无法微调的大模型仍构成门槛。
- **局限二：验证范围偏窄**。主要实验集中在单张 H100、batch=1、贪心解码；多请求并发只在 Ouro-2.6B 上较系统评估，且未覆盖采样解码、beam search、长上下文场景。Wake 的精确性证明针对贪心解码，采样情形下的等价性需要额外讨论。
- **局限三：baseline 复现问题**。LoopAhead 官方代码不可用，作者自行复现三个训练 arm 并取最快，虽已尽量公平，但仍可能与原方法最优配置存在差距。
- **局限四：系统层面耦合**。整个流程依赖静态 CUDA graph、特定 mask-placeholder block decoder 和 batch 内 pass-index 并行，工程实现复杂度较高；在非 H100 硬件、不同 batch 形状或动态序列长度下，Roofline 模型中的 ridge point 会变化，收益可能需要重新标定。
- **潜在影响**：若后续工作能将 late entry 与训练免费适配（如轻量 LoRA 或入口重参数化）结合，并扩展到采样解码与长上下文，则有望成为循环语言模型部署的默认解码策略；同时，它也为“非均匀深度分配”在标准 Transformer 上的应用提供了概念先导。

## 8. 启发与可迁移点

- **“后段优先”的预算分配直觉**可迁移到其他迭代式推理结构，如扩散语言模型的去噪步数分配、多步检索增强生成的迭代轮次分配、以及层间循环/权重共享模型的推理调度。
- **缓存补全的流水线思想**：把“当前 token 的快速路径”和“历史 token 的慢速补全”解耦，并利用 batch 内并行隐藏慢路径延迟，是一种通用的“延迟满足”式系统设计，可借鉴到 speculative decoding 的 verifier 调度、MoE 的专家预取等场景。
- **Wake 验证的容差统一框架**：用单一 \(\tau\) 在精确、近似、有损三档之间连续切换，提供了“按业务容忍度调节加速”的工程范式，适合需要 SLA 分级的部署环境。
- **诊断先于设计**：论文先通过入口范数测量、teacher-forced agreement、低置信 token 分布等诊断定位问题，再设计微调与系统方案，这种“先量化失配、再针对性修复”的研究路径值得在类似加速工作中复用。
