# Looped Models are Fast Multi-Token Predictors 

Ayhan Suleymanzade 1, Sean McLeish 1,2 , Sehoon Kim 3, Jinwoo Kim 3, Antoine Bosselut 1

> 1

EPFL 2University of Maryland 3KAIST 

Abstract. Looped language models can adapt computation for predicting a token without a proportional rescaling in unique model parameters by adjusting the number of loops. This property has been used for self-speculative decoding, taking shallow loops as fast drafters and deep loops as verifiers, which is effective since drafting still uses full parameters. In this paper, we show that shallow loops can be also predictive of several future tokens and leverage this to drastically accelerate the inference of looped language models. To that end, we present Floodgates , a simple self-speculative decoding method that appends a block of mask tokens as a suffix and learns via low-rank adaptation to draft these tokens in parallel. Across seven models, five benchmarks, a range of batch sizes, and both greedy and sampled decoding, Floodgates is the fastest lossless decoding method in most cases, attaining up to 7.5 × acceleration. Through analysis, we show that this speedup is enabled by all-depth training of looped models, with the shallow drafter’s ability to leverage full-depth computation by conditioning on deep prefix cache evaluated during verification.

Autoregressive (AR) transformer language models pro-duce text one token after another. In each layer, the hidden state of the new token is updated by attending to the hidden states of all earlier tokens by the preceding layer. A token can therefore be generated only after all of the tokens before it, leading to a serialized bottleneck in speed (Santilli et al., 2023; Suleymanzade et al., 2026a). Due to local regularities in natural language (Church and Hanks, 1990), many upcoming tokens can be easy to predict, and speculative decoding uses this to accelerate generation (Leviathan et al., 2023; Chen et al., 2023). A fast drafter proposes several tokens, and the model verifies all of them in one forward pass. Yet, the drafter is usually a small separate network (Li et al., 2024a; Chen et al., 2026a) or a subset of the layers (Zhang et al., 2024; Elhoushi et al., 2024; Liu et al., 2024), computed with only a fraction of the parameters of the model. Thus, the drafters are usually prevented from using the full knowledge encoded in all layers of the model, leading to a limited verification rate of their drafts. Looped language models naturally avoid this limitation. They process each token through a group of layers repeatedly (Dehghani et al., 2019; Geiping et al., 2025; Zhu et al., 2025), so they can reduce their computation for faster generation by shallowing their loop without a proportional decrease in their parameters. This allows for an effective self-speculative decoding scheme that uses the deep loop to verify each token drafted by a shallow loop, in which the drafter now has access to the full knowledge within the model since every loop runs the same block. Yet, existing methods either draft a single token per loop (Cho et al., 2026; Ha and Kim, 2026) or attain good acceptance rate only when the model runs many loops (Li et al., 2026). Moreover, they often rely on 

pipelining for parallelism, starting the next token before the current one has finished its loops. As tokens at different loops are batched together, the methods need to maintain separate, per-depth prefix cache across all batched loops, diminishing their utility when serving many requests at once where memory becomes a bottleneck.

In this paper, we show that a single loop of a looped language model can be adapted to draft several future tokens in parallel while attending to the final-loop prefix cache computed during verification, drastically accelerating inference. Our first intuition is that looped training can make shallow loops predictive of several future tokens, as it supervises every depth and hence pressures each future token to be predicted as early as possible, encouraging shallow hidden states of past tokens to be already helpful (Section 4.2). The second is that the shallow drafter can make use of full-depth computation through the prefix cache, which holds the keys and values of earlier tokens at the final loop. The model computes this cache during verification, so the drafter can attend to it “for free”. We present Floodgates , a simple self-speculative decoding method that appends a block of mask tokens as a suffix and learns to read the final-loop prefix cache to draft these tokens in parallel using a single loop iteration. We use low-rank adapters (Hu et al., 2022) that are active only while drafting, so the verifier parameters do not change and thus decoding remains lossless. On models that run many loops, where a single loop costs only a small fraction of a decoding step, Floodgates further refines this draft with additional passes of the pretrained loop ( elastic drafting ) to balance drafting cost and acceptance without extra training. Across seven looped models and five math, coding, and reasoning benchmarks, Floodgates decodes faster than all prior lossless methods under greedy decoding and in most cases under sampling (Figure 1). An illustration is given in Figure 2. In summary, we make the following contributions: (1) We introduce Floodgates, a simple self-speculative decoding method that adapts a single loop via low-rank adapters to draft several tokens in parallel from mask tokens while reading the deep prefix cache from verification, and refines the draft with elastic passes of the pretrained loop on deep models (Section 3). It overcomes the limitations of existing methods by effective multi-token prediction and its access to the deep prefix cache. (2) We evaluate Floodgates on seven looped models and five math, coding and reasoning benchmarks. Floodgates is the fastest lossless decoding method on every model and every task under greedy decoding and in most cases under sampling (Section 4.1). It decodes up to 5 .1× faster than plain decoding on average with a single loop on 4-loop models and up to 7 .5× faster with elastic drafting on 32-loop models, and on some models, it is nearly twice as fast as the best prior method. At the largest batch size that fits in memory, it reaches up to 1 .9× the throughput of the strongest baseline method (Section 4.4). 2(3) Through controlled comparisons, we show that self-speculative drafting with a single loop iteration gives larger speedups than drafting with a separate smaller network (EAGLE, DFlash) or with the first layers of a non-looped model (Llama 3.2, LayerSkip), supporting the utility of drafting with all of the parameters of the model (Section 4.2). We also show that deep prefix cache accelerates decoding up to 1 .3× (Section 4.2), and that elastic drafting maximizes acceleration by optimizing the cost-acceptance tradeoff across verifiers of varying depths (Section 4.3). 

# 2 Background 

Let V denote a token vocabulary, and let ∆ |V |− 1 be the probability simplex over V , whose vectors p ∈ ∆|V |− 1 we index by p(v) ∈ R. An autoregressive language model generates text x = ( x1, x2, . . . ) with xt ∈ V sequentially, predicting each next token from a conditional distribution p(· | x≤t) ∈ ∆|V |− 1. We write the cross-entropy between a predicted distribution p ∈ ∆|V |− 1 and a target token v ∈ V as CE (p, v ) := − log p(v).

Speculative decoding. Speculative decoding (Leviathan et al., 2023; Chen et al., 2023) accelerates a target model p using a faster draft model q that proposes upcoming tokens. Given a prefix x≤t, the drafter proposes 

k draft tokens d = ( d1, . . . , dk) ∈ V k, and the target model evaluates all of them in a single decoding step to obtain its own predictions. Under greedy decoding, this is done as: 

yj = argmax (pj ), pj := p(· | x≤t, d<j ), j = 1 , . . . , k + 1 , (3) and the drafts are accepted up to the first mismatch dj̸ = yj , where the target model substitutes its own prediction yj . Each step thus produces at least one and at most k + 1 tokens while keeping the output identical to greedy decoding with p. Under sampling, each draft dj is drawn from a draft distribution qj and accepted with probability min {1, pj (dj )/qj (dj )}. Upon the first rejection, a replacement token is sampled from the normalization of max {0, pj − qj }, which leaves the output distribution of p unchanged (Leviathan et al., 2023). Because verifying k + 1 tokens in parallel at small batch sizes takes nearly the same time as a single-token decoding step, the speedup grows with the number of accepted tokens τ generated per step and decreases with the relative cost of drafting.

These passes do not use the adapters ϕ and therefore require no extra training. While this update resembles Jacobi decoding (Santilli et al., 2023; Fu et al., 2024) and DAS-Wave (Li et al., 2026), which refine uninitialized or repeated tokens from scratch, elastic drafting starts from the trained multi-token draft of (4) and therefore requires far fewer passes. Iterating (6) creates a direct tradeoff between drafting cost and acceptance, since running more passes E improves the draft at the cost of one additional loop per pass. Because each pass updates all W draft tokens in parallel, running E passes costs only E/W effective loops per position, which is much cheaper than the R loops of tokenwise generation and yields higher speedup when E and W are chosen adaptively to the verifier depth R.On shallow models with, e.g., R = 4, where a single loop already costs a quarter of a decoding step, single-pass drafting with E = 0 is fastest, whereas on deep models with, e.g., R = 32, where each loop is a small fraction of a step, additional passes E > 0 pay off. We treat E as a hyperparameter and select the value that maximizes speedup on held-out problems for each model (Appendix B.1), following standard practice for choosing the draft block size in speculative decoding (Leviathan et al., 2023; Chen et al., 2024). 

Concurrent serving. Because an untrained shallow loop only predicts the immediate next token, prior self-speculative methods for looped models (Cho et al., 2026; Ha and Kim, 2026) rely on depth pipelining ,starting the next token at the first loop before earlier tokens have finished their R loops. While pipelining parallelizes drafting and verification, it batches together tokens at different loop depths, say B ⊆ [R] (e.g., one every four loops), and therefore must store and read the prefix cache c<t r of all such loops r ∈ B. When serving many concurrent requests, maintaining and reading B separate caches per request saturates runtime memory bandwidth, causing diminishing return in throughput. By drafting a block of future tokens in parallel from a single loop, Floodgates avoids pipelining altogether. All drafted slots of a sequence attend only to the deep prefix cache c<t R , reading the keys and values of past tokens once per step for the entire draft block. At batch size one, decoding is memory-bound, so verifying all k draft tokens in parallel takes nearly the same time as verifying a single token. As the batch size B grows, verification becomes compute-bound and its runtime increases with the total number of verified drafts, so checking all kB candidates across the batch wastes compute on low-confidence tokens at later positions (Sahoo et al., 2026). To keep throughput high across batch sizes, we use single-pass drafting ( E = 0) and verify only the most promising drafts in the batch. Specifically, let αb,j

## 4.3 Elastic drafting across verifier depths (Q3) 

A key advantage of looped models is that their compute can be scaled at test time by varying the number of loops R without retraining (Geiping et al., 2025; Suleymanzade et al., 2026b). We now test how the optimal budget E changes with verifier depth and how Floodgates compares with prior methods across test-time depths.

# 5 Related work 

Speculative decoding and drafter capacity. Speculative decoding accelerates generation without changing the target distribution by using a fast draft model to propose candidate tokens and verifying them in a single forward pass of the target model (Leviathan et al., 2023; Chen et al., 2023). To achieve a large speedup, the drafter must be both much cheaper to run than the target model and accurate enough that most of its proposals 11 are accepted (Leviathan et al., 2023; Zhou et al., 2024). In dense models, where every layer is applied once per token, these two requirements conflict. Fast drafters are therefore either small separate networks trained on target features (Li et al., 2024a,b, 2025; Chen et al., 2026a; Hui et al., 2026; Cheng et al., 2026; Huang et al., 2026; Chen et al., 2026b), or self-speculative methods that skip or exit early from layers of the target model (Zhang et al., 2024; Elhoushi et al., 2024; Liu et al., 2024; Xia et al., 2025; Lin et al., 2026). In both cases, the drafter uses only a fraction of the parameters of the target model, which limits its verification rate. On looped models, Cho et al. (2026) even found a separate drafter slower than training-free self-speculation. Floodgates avoids this tradeoff by using a shallow loop of the model’s own shared block as the drafter, reducing computation while keeping all parameters of the model. 

Multi-token prediction and mask-token drafting. To propose multiple tokens without running the drafter sequentially, a model can be trained to predict several future tokens in parallel. One line of work adds auxiliary output heads that predict future tokens from the final hidden state (Cai et al., 2024; Ankner et al., 2024; Gloeckle et al., 2024; DeepSeek-AI, 2024), or pretrains a looped model so that later loops predict later tokens (Shomali et al., 2026). A second line of work, which is closest to our drafting pass, appends placeholder or mask tokens as a suffix and adapts the model with a small number of trained parameters to fill them in at once (Monea et al., 2023; Bhendawade et al., 2024; Samragh et al., 2025; Sahoo et al., 2026). On a dense model, however, the mask tokens pass through all layers, so a separate drafting pass costs about as much as verification, which can cancel the speedup (Javat and Kazakov, 2026). In a looped model, a drafting pass can be as cheap as a single loop iteration, so Floodgates drafts from the accepted tokens at a small fraction of a decoding step. 

Looped language models and their decoding. Looped language models apply a shared block of layers repeatedly to every token (Dehghani et al., 2019; Geiping et al., 2025; Zhu et al., 2025; McLeish et al., 2025; Bae et al., 2025), and the number of loops can be chosen at inference time (Yu et al., 2026; Schwethelm et al., 2026). Prior methods for fast decoding of looped models use the loop without training. LoopSpec and WaveFront take the prediction after an early loop as the draft for the next token (Cho et al., 2026; Ha and Kim, 2026), building on pipelined speculative execution (Hooper et al., 2023). Because the model has only been trained to predict the immediate next token, this yields at most one draft token per loop, and because later tokens start their loops before earlier tokens finish, it requires storing a separate key-value cache for every loop depth. DAS and DAS-Wave instead let shallow passes attend to the final-loop prefix cache (Li et al., 2026), but because the loop is not trained to look ahead, DAS drafts one token at a time and DAS-Wave refines a window of drafts over many shallow passes, which pays off only on models with many loops. Similarly, the parallel sampler of Geiping et al. (2026) decodes multiple tokens in parallel without a verification step, which changes the outputs of the model and thus is not lossless. Floodgates shares with DAS-Wave the deep prefix cache and the use of the model’s own loops for elastic passes, but starts from a trained multi-token draft, so that a single loop iteration already yields several tokens and elastic passes are used only when a single loop is cheap. 

# 6 Conclusion 

We presented Floodgates, a simple self-speculative decoding method that adapts a shallow loop of a looped language model to draft several upcoming tokens in parallel over suffix mask tokens. Across seven looped models and five benchmarks, Floodgates outperforms prior lossless decoding methods at batch size one, and its speedups carry over to high-throughput batched serving. Our analysis shows that a shallow loop makes an effective drafter because all-depth training already encourages early states to carry information about future tokens, and because conditioning on the deep prefix cache lets a single loop build on full-depth context computation. These findings suggest that looped models are naturally suited for fast multi-token generation once their shallow loops are trained to look ahead.

18 A.2 Training details 

Data. We train each drafter on greedy generations from its target model. For the five base models, we generate continuations on 7,473 GSM8K training problems, 7,500 MATH training problems (Hendrycks et al., 2021), 3,000 Python function signatures and docstrings from CodeSearchNet (Husain et al., 2019), and 256-token prefixes from 4,000 FineWeb-Edu documents (Penedo et al., 2024). GSM8K and MATH prompts follow the 3-shot and 4-shot evaluation formats, and CodeSearchNet prompts follow the HumanEval+/MBPP+ format. For the reasoning models, we generate continuations on the 7,473 GSM8K training problems and 2,032 MATH training problems using their chat template with thinking enabled and a limit of 4,096 new tokens. 

Adapters and loss. We apply rank-64 LoRA adapters (Hu et al., 2022) to all attention and feed-forward projections. On Recurrent Llama 3.2, Recurrent TinyLlama, and Huginn 3.5B, adapters are placed on the prelude, core, and coda layers, as well as the input projection that combines the token embedding with the recurrent state. Adapters and the mask embedding m are initialized to zero. In the training loss (5), we set slot weights wj ∝ e−(j−1) /4 normalized to sum to one. On the Ouro models, each mask slot predicts the token at its own position, producing k drafts from k mask tokens. On the other three models, each position predicts the next token, so the slot of the last verified token xt also produces a draft, and k mask tokens yield k + 1 drafts. 

Optimization. We train with AdamW (Loshchilov and Hutter, 2019) using decay rates ( β1, β 2) = (0 .9, 0.95) for the first and second moments, zero weight decay, a peak learning rate of 4 × 10 −4 with 100 warmup steps and linear decay to 4 × 10 −5, gradient clipping at 1 .0, and a batch size of 8 sequences. For each training sequence, we sample 64 positions uniformly from the generated continuation and append a block of k mask slots after each position. A single forward pass of the frozen target model computes the deep prefix cache c<t R for all sampled positions in a sequence. Attention masks prevent slots placed at different sampled positions from attending to one another. The frozen model runs in bfloat16 and the adapters in float32. ## A.3 Implementation details 

We implement our decoding engine in PyTorch with static key-value buffers for each loop depth, CUDA graphs, and Triton kernels. The training-free baselines in Table 1 (except LoopSpec and WaveFront, which use the authors’ code) run in this engine and share the same verification step. Plain decoding in our engine is 32% faster on Ouro 1.4B than in SGLang, ensuring that our speedups are measured against a strong baseline. All inference experiments are run on a single NVIDIA A100-80GB GPU in bfloat16. 

## A.4 Baseline settings 

LoopSpec and WaveFront. We use the official implementations from the authors. LoopSpec serves one request at a time in SGLang (Zheng et al., 2024) and is benchmarked against SGLang’s plain decoding. Following the authors’ settings, we use proposal depths d1 = 1 for one proposal (LoopSpec ∗) and ( d1, d 2) = (1 , 2) for the full method on the Ouro models, and d1 = 2 and (2 , 8) on the 32-loop models. WaveFront is evaluated in its lossless setting on the models it supports, drafting a token after every loop on the Ouro models and after every 

Td loops on Huginn 3.5B, where we report the better of Td = 4 and Td = 8. 19 DAS and DAS-Wave. Since neither method has public code, we reimplemented both following Li et al. (2026) in our engine with the same verification step as Floodgates. DAS drafts eight tokens sequentially, where each draft position runs r loops conditioned on the deep prefix cache ( r = 2 on Recurrent Llama 3.2 and Recurrent TinyLlama, and r = 4 on Huginn 3.5B). On the Ouro models, where an untrained first loop cannot read the final-loop cache (Figure 4), DAS runs one loop per draft conditioned on the first-loop cache, which gives its best results. DAS-Wave updates a window of up to γ positions in parallel over J refinement rounds. Each round runs k loops over the window conditioned on the deep prefix cache, where each position takes as input the token predicted at the preceding position in the previous round and the window grows by one position per round. On the 32-loop models, we use the paper’s settings ( γ = 32 and J = 24, with k = 1 on Recurrent Llama 3.2 and Recurrent TinyLlama and k = 2 on Huginn 3.5B). On the 4-loop Ouro models, where each round costs 1 /4 of a decoding step, we use J = 12 rounds over γ = 16 positions on the base models and J = 8 rounds over γ = 32 positions on the reasoning models, which performed best among the settings we tested. 

Jacobi decoding and prompt lookup decoding. Jacobi decoding iteratively refines a window of candidate tokens over multiple passes of the full model (Santilli et al., 2023; Fu et al., 2024). We use a window of 32 positions with two model passes conditioned on the deep prefix cache on the 32-loop models, and report the best of one, two, or four passes on the Ouro models. Prompt lookup decoding searches the prefix for the most recent match of the last n tokens and proposes the γ tokens that followed it (Saxena, 2023). We report the better of (n, γ ) = (2 , 8) and (3 , 12). 

Trained baselines. The separate drafters in Section 4.2 are trained for Ouro 1.4B on the same four-domain data and for the same 32K steps as Floodgates (Appendix A.2). The 1-layer and 4-layer separate drafters follow EAGLE (Li et al., 2024a), where each position combines its token embedding with the final hidden state of Ouro 1.4B, passes through the drafter layers, and is read out by the frozen head of Ouro 1.4B over k = 12 mask tokens using the loss in (5). The DFlash drafter (Chen et al., 2026a), following LoopSpec (Cho et al., 2026), uses five layers at the width of Ouro 1.4B that attend to hidden states from five layers of Ouro 1.4B and drafts a block of 16 tokens from mask tokens, trained with the optimizer settings and loss weights of DFlash. On Llama 3.2 1B and LayerSkip Llama 3.2 1B (Elhoushi et al., 2024), we replace the loop with the first Ld layers of the dense model and train LoRA adapters on those layers over k = 12 mask tokens using each model’s own generations (Appendix A.2). For LayerSkip’s native self-speculative decoding, we draft one token at a time from the exit after layer Ld, verify with the remaining layers, and report the speedup at its best Ld.

## B.4 Comparison with the parallel sampler 

The parallel sampler of Geiping et al. (2026) initializes a window of tokens and updates their hidden states in parallel across multiple recurrent steps, emitting each token once its hidden state changes by less than a threshold. Because the released code does not support the retrofitted models, we reimplemented it in PyTorch with four loops per step and a convergence threshold of 0 .03, and measure its speedup relative to plain decoding in the same implementation. Because the parallel sampler does not verify its predictions, it is not lossless (Table 11). Under greedy decoding, its accuracy stays within 3 points of plain decoding on Recurrent Llama 3.2 and Recurrent TinyLlama, but drops on all five tasks on Huginn 3.5B, including by 4 points on GSM8K (23 .0% vs. 27 .0%) and 9 points on MATH-500 (16 .0% vs. 25 .0%), where a third of the tokens reach 32 loops before converging. Under sampling, accuracy drops further, by 13 points on GSM8K and 12 points on MBPP+ for Huginn 3.5B, and by 6–8 points on MATH-500 and MBPP+ for Recurrent Llama 3.2. Table 12 compares its speedups with those of Floodgates. Linear readers. Following Future Lens (Pal et al., 2023), we train a separate linear reader for each layer and each lookahead offset j ∈ { 1, 2, 3}. The reader applies a learned linear map to the hidden state of token xt

Data. Because the two models share a tokenizer, we train and evaluate both on the same text. ## B.8 Serving with a single shared cache across loops 

A looped model stores the keys and values of every loop, which limits how many requests fit in memory. Prairie et al. (2026) show that some looped models can instead keep only the final-loop key-value cache and reuse it at every loop without further training. Unlike the deep prefix cache in the main text, which only the drafting pass reads, this setting reuses the final-loop cache across all R verification loops as well. Because LoopSpec and WaveFront start the next token before the current token finishes its loops, they require the cache of every loop and cannot use a single cache.
