# Abstract 

Standard autoregressive large language models attend to the growing history of generated tokens, making the key–value (KV) cache a central memory and through-put bottleneck in long-chain reasoning and multi-branch sampling. Yet an im-portant class of reasoning problems is naturally first-order Markovian: the next step depends on a sufficient representation of the current state, rather than on the raw sequence of all earlier steps. We develop a unified design paradigm for 

Markovian-reasoning specialized large language models . At the cache level, the Markovian state interface transforms history-dependent KV storage into constant-size state transfer with respect to the number of reasoning steps. At the learning level, we reformulate long-chain prediction as independently trainable one-step transition objectives, with explicit state bottlenecks, distillation, invariance, and drift-consistency losses. At the architectural level, we introduce a dual-loop Trans-former: an outer loop advances the reasoning state, while an inner recurrent-depth loop allocates adaptive computation to each transition through shared weights and explicit memory tokens or recurrent matrix states. We connect this architecture to a three-region cache, step-relative positions, truncated backpropagation, branch-aware checkpoints, and a transition-centric evaluation protocol. The organizing principle is simple: the optimal reasoning system need not remember everything; it must carry forward exactly what the future needs . This principle opens a path toward specialized reasoning engines whose memory footprint is decoupled from reasoning-chain length. 

# 1 Introduction 

1.1 Background and motivation 

Autoregressive language models usually approach multistep reasoning through explicit or implicit long-context modeling. When decoding token t, conventional causal attention may revisit the keys and values of all earlier tokens. The resulting KV cache grows linearly with context length, becoming a dominant constraint in long reasoning chains, branched search, and large-batch inference. For example, a 70-billion-parameter model at a 128K context can require KV memory on the order of tens of gigabytes, depending on its attention layout and numerical format. 

> Preprint. arXiv:2611.28285v1 [cs.AI] 20 Nov 2026

Sliding-window attention, attention sinks, attention-score eviction, compressed-cache transport, recurrent memory, and state-space models have made remarkable progress in controlling this cost [3–7, 12, 30, 31]. These methods primarily operate at the level of attention patterns, cache budgets, or computational representations. A stronger opportunity arises when the task itself imposes a dependency structure: a broad family of reasoning trajectories has a state-transition description in which the next step is conditionally independent of the earlier trajectory given a sufficient current state. Examples include staged mathematical derivations, execution traces, instruction-level program transformation, state-machine agents, theorem-proving tactic states, and industrial process validation. Markov Chain of Thought (MCoT) makes this perspective concrete through a derive-then-reduce 

operation: after solving a subproblem, the reasoner rewrites the remaining task as a new, self-contained problem [28]. The complete trajectory is no longer the indispensable interface. The new problem state is. We advocate a fundamental change in the design philosophy of reasoning models: from maximizing retained history to enforcing the transmission of sufficient state . Markovian reasoning is a distinct computational paradigm, not merely a cache-management trick. Its structural prior makes it possible to redesign architecture, data, training objectives, and serving systems around the transition itself. This opens a direct route to long-horizon inference with bounded memory, reusable computation, and scalable state branching. 

1.2 Contributions 

Our contributions form one integrated research program: 1. A formal state-transition foundation. We define Markovian reasoning, state sufficiency, history invariance, and compression error as properties that determine when exact history removal is justified. 2. Structural KV-cache pruning. We develop three realization paths—training-free approx-imation, training-aligned block-causal attention, and recurrent-state architecture—and a concrete three-region cache with step-wise rotation, fixed state slots, positional consistency, rollback, and inference-engine integration. 3. Transition-centric pretraining. We replace long-chain joint supervision with state–action– next-state triplets, independent transition losses, bottleneck regularization, counterfactual dependence probes, teacher distillation, and step-parallel data scheduling. 4. A dual-loop Transformer. We combine an outer Markovian step loop with an inner shared-weight depth loop, using memory tokens or recurrent matrix states as the explicit cross-step interface and adaptive halting as a compute allocator. 5. An evaluation framework aligned with the task. We measure transition fidelity, state sufficiency, chain-level success, long-horizon extrapolation, counterfactual robustness, and the dependence of cache size and latency on the number of reasoning steps.

2.3 Markovian reasoning versus conventional chain of thought 

Conventional chain-of-thought (CoT) prompting retains every intermediate derivation in a growing transcript [35]. Markovian CoT adds a decisive operation at every step: reduce the completed reasoning into the next self-contained problem . This semantic reduction is what separates a structured state interface from an arbitrary sliding context window. It is also what makes the reasoning horizon independent of the raw context window, provided the state remains sufficient. 

# 3 Structural KV-Cache Compression 

3.1 From heuristic eviction to task-structured removal 

Full caching stores the complete token history. Sliding windows and StreamingLLM maintain bounded windows and attention sinks; H2O and SnapKV select a bounded set of apparently important past tokens; CacheGen compresses cache transfer; and recurrent architectures update a fixed hidden state [3–5, 12, 31]. Our approach establishes the retention rule from the task dependency graph: 

retain the sufficient state; remove earlier semantic steps . This changes the rationale for pruning from an empirical estimate of token importance to a structural property of the state transition. 

3.2 Decoupling semantic history from attention support 

Attention has two distinct responsibilities: retrieving semantically relevant past information and providing nonsemantic support positions such as attention sinks. 3.3 Three realization paths 

We organize implementation into three mutually reinforcing paths: 

A: Training-free approximation. Retain sinks, static Q, and the latest reduced state while dropping earlier step KV from an existing model. Use KL or Jensen–Shannon probes and fall back to recomputation when output distributions drift. 

B: Training-aligned exact structure. Train with block-causal masks, explicit step-final state tokens, and step-relative positions. At inference, use exactly the same dependency graph and position convention. This is the direct route to structural pruning. 

C: Recurrent-state architecture. Replace raw cross-step KV with an SSM, linear-attention state, or learned matrix recurrence. The cross-step interface is fixed in size and updated in place. Path A discovers useful task families; Path B enforces their dependency structure in training; Path C realizes the strongest memory-efficient inference engine.

Before structural pruning, probe whether a task is genuinely Markovian: inject distant-prefix per-turbations, measure changes in the next-token distribution, inspect remote attention mass, and test whether counterfactual updates to the current state alter the successor correctly. A mixed policy can preserve small local windows or selected global heads when needed. In-place state replacement is irreversible unless checkpoints are retained. The critical operation is to cut each reasoning chain at semantically independent boundaries , not at arbitrary token positions. From a trajectory (q1, s 1: T , a ), construct (qt, s t, q t+1 ) samples; use a capable generator to produce reduced successor problems; then conduct a zero-history verification test: can a solver continue from qt+1 without the earlier transcript? # 5 Dual-Loop Transformer Architecture 

5.1 Outer transition loop and inner depth loop 

Two families of recurrent Transformers supply complementary building blocks. Recurrent Memory Transformers pass memory tokens between segments [8]; Universal and looped Transformers reuse a computational stack at increasing effective depth [9, 11, 24, 25, 32]. We integrate them into a dual-loop design: • Outer step loop ( t = 1 , . . . , T ): consumes current state qt and memory Mt, generates action st and successor state qt+1 , and discards step-local KV. • Inner depth loop ( r = 1 , . . . , R t): repeatedly applies a shared Transformer stack to the current step’s hidden representation, allowing hard transitions to receive more computation without adding parameters. The architecture uses a single shared transition core, as visualized in Figure 2. Depth is a reusable computational resource; the state is the sole cross-step semantic interface. 

5.2 Explicit memory tokens and recurrent matrix states 

An interface of m memory tokens provides a learned sufficient statistic for the next step. Read-memory tokens precede each segment; write-memory tokens at its end are carried into the next segment. A small range such as m = 4 –16 is a useful design starting point, with capacity determined by the dimension of the task state. Prefix-token injection permits a nonintrusive wrapper around a pretrained Transformer, while read/write separation creates a direct differentiable path through the state interface. 6Figure 2: Dual-loop Transformer architecture with transition-centric pretraining. 5.3 Adaptive computation and termination 

Simple state transitions may require one depth iteration, while difficult steps merit several. Options include fixed depth, a learned router assigning Rt from a small set, and fixed-point halting based on 

ρr = ∥h(r+1) − h(r)∥2

∥h(r)∥2 + δ . (10) We favor fixed-point criteria with a hard Rmax and a training distribution that samples recurrent depth. This makes computation an adjustable inference-time resource without changing parameter count. Step-level stopping uses a terminal predicate or learned pstop and an explicit maximum number of outer steps. 

# 6 Training, Runtime, and Complexity 

6.1 Three-stage training curriculum 

The training sequence is deliberately progressive. Stage I: transition warm-up learns the basic state-action map and step boundary format from short, supervised transitions. Stage II: Markovian invariance consolidation introduces prefix perturbations, state pairing, bottleneck penalties, distilla-tion, and drift losses until the model’s behavior depends on the state rather than incidental history. 

Stage III: long-chain self-rollout mixes teacher-forced and model-generated states, applies scheduled sampling, and trains the model to remain stable over many successive transitions. Each observed transition can be trained independently, removing the need to backpropagate through the full chain length. Where differentiable memory crosses several steps, truncated backpropagation 7through time (BPTT) keeps a bounded gradient window while transmitting detached memory between segments. Within the depth loop, gradients still propagate across the recurrent applications; activation checkpointing and carefully scheduled recurrence depth control memory. 

6.2 Training stability as a dynamical-system problem 

Repeatedly applying one stack can amplify unstable hidden-state directions. A simplified recurrence 

h(r+1) = αh (r) + βe + Fθ (h(r)) (11) suggests the importance of Jacobian spectral control, residual scaling, pre-normalization, gradient clipping, step-wise input reinjection, smaller learning rates for recurrent parameters, and curricula that gradually increase loop depth. These controls prevent hidden-state collapse, spurious early fixed points, and the failure mode in which additional iterations cease improving the answer. 

6.3 Inference engine 

The serving stack contains a step scheduler, input constructor, recurrent core, sampler, state manager, KV block manager, and Markovian validity monitor. Three practical cache policies are available: clear and rebuild step-local KV at each boundary; store a fixed state register that survives across steps; or project an explicit dense state into a few virtual memory tokens. A hybrid implementation can compare compact and full-context paths on sampled steps and invoke a fallback when their distributions diverge. For branch search, memory tensors can be replicated and advanced in batches rather than copying unbounded historical KV. The runtime can schedule multiple branches, score successor states, retain the best candidates, and checkpoint the small state at selected steps.

7.2 Controlled state-only inference probe 

To quantify the immediate benefit of a sufficient-state interface, we conducted a controlled inference probe on three pretrained backbones. For each model, deterministic addition and modulo-10 transition tasks were evaluated at history lengths k ∈ { 1, 8, 32 , 128 }. A full-history prompt and a current-state-only prompt received identical current states and next operations. We measured actual KV tensor sizes 

in a PyTorch forward pass and recorded greedy generation outcomes. This prompt-level experiment directly demonstrates the memory advantage of state transmission before architecture-specific training. Across all three backbones, state-only KV size stays essentially constant as the history grows, while the full-history baseline grows with the transcript. On Qwen2.5-Coder-14B-Instruct, the 128-step state interface reduced measured cache size by approximately 96 .9% on addition while maintaining perfect correctness in all 12 cases. The cross-backbone results establish a compelling direction: turn an already powerful state-compression interface into a native model capability through transition-centric training and Markovian invariance. # 8 Discussion and Vision 

The proposed specialization makes a decisive architectural choice: long-horizon reasoning should be built around state evolution , not the mechanical accumulation of its entire textual trace. A well-designed state carries every constraint needed by the next transition, while the serving engine avoids allocating memory to redundant completed steps. In more complex workflows, the same principle naturally extends to richer state carriers and hybrid state interfaces, preserving the model’s state-first organization. State-space models compress through recurrence; our formulation adds a task-level criterion for what the recurrence must preserve. The two ideas are complementary. A promising endpoint is a hybrid in which an SSM serves the outer Markovian loop and a Transformer serves the inner depth loop. An equally compelling system-level arrangement delegates global planning and open-domain interaction to a general-purpose language model, while a specialized recurrent kernel executes long sequences of structured transitions and returns the terminal state. Neuro-symbolic verification strengthens this state-centered vision. LogicSAGE couples an 8B neural reasoner with Socratic-guided symbolic correction, demonstrating the power of specialized reasoning and explicit feedback [38]. The probabilistic soft-logic verifier ProbVeri extends this principle to 9uncertainty-bearing reasoning steps through contrastive energy-based inference [39]. Both directions complement our execution architecture: a compact successor state can be inspected by symbolic or probabilistic verification modules, and their feedback can shape the next transition without requiring an ever-growing textual history. This division of labor extends beyond mathematical CoT. It invites compact reasoning machines for symbolic computation, tool-mediated agents, theorem provers, industrial workflows, automated verification, and any domain where a well-defined state and a repeatable transition operator exist. The next research frontier is to learn adaptive sufficient-state capacity : not one fixed memory size for every problem, but a state interface that grows only when the true dimensionality of the task demands it. 

# 9 Conclusion 

We present a unified design for Markovian-reasoning specialized language models, connecting formal state sufficiency, structural KV-cache pruning, transition-centric pretraining, and a dual-loop recurrent Transformer. The core consequence of a fixed sufficient-state interface is decisive: cache size becomes independent of the number of completed reasoning steps, while shared recurrent weights allow computation depth to be assigned where each transition needs it. The training objective makes this behavior native; the inference engine turns it into practical step-wise state management; and the evaluation protocol measures the qualities that matter for this task family. 

The guiding vision is a shift from remembering as much as possible to transmitting only what is necessary. Specialized reasoning can be long-horizon without being long-context. Sufficient-state transmission, step-parallel training, and parameter-shared recurrent computation together define a powerful alternative to the ever-growing reasoning transcript. We envision a family of specialized large language models whose reasoning horizon grows through repeated state transitions while memory remains bounded, computation remains adaptable, and every step is organized around an explicit state of the problem.

# A Detailed Cache Design and Engineering Realization 

A.1 Why a standard decoder retains historical KV 

In a conventional causal Transformer, the query of token t may attend to the key/value vectors of every earlier token, so the cache grows unboundedly as decoding proceeds. In a Markovian task, the two roles played by attention can be separated. The first is semantic aggregation : recovering useful information from earlier steps. The second is nonsemantic attention support : retaining stable positions that accumulate attention mass, including attention sinks. Once all task-relevant history is captured in zi, the semantic role no longer requires raw earlier-step tokens, while a fixed number of sink tokens can supply the second role. The static condition Q must be distinguished from historical steps. It may include the system directive, the original problem, and persistent rules. It remains present throughout the chain, can be prefix-cached across requests when identical, and is never removed merely because an earlier reasoning segment has been completed. The cache contract is 

Ci = KV( Q) ⊕ KV(sink) ⊕ KV( zi) ⊕ KV(current step) .

The cost of the fixed prompt is not a cost that grows with the number of reasoning transitions. 

A.2 Training-free, training-aligned, and recurrent alternatives 

Route A is a fast way to assess whether a pretrained model behaves as though the task were approximately Markovian. Route B is the direct means of making the retention rule part of the model definition. Route C is the native end-state architecture. A practical research sequence uses A to audit the assumption, B to establish aligned transitions, and C to distill the computation into a recurrent kernel. Conditional independence in the data-generating process is not automatically the attention graph of a conventional pretrained Transformer. Dropping earlier KV only at inference can change attention normalization and RoPE geometry. The training-aligned route establishes a block-causal mask and position convention common to training and decoding. 12 Table 5: Implementation routes for Markovian cache pruning.

The static region stores the system/problem prefix and a small attention-sink set. The dynamic state region stores m memory tokens or a fixed matrix recurrence. The within-step region stores causal KV for the tokens currently being generated. A state-slot rotation occurs at every semantic step boundary: 1. A.4 Position, attention sinks, and serving blocks 

The logical positions of tokens must not be confused with their physical cache slots. Under RoPE, an overwritten slot cannot simply inherit the slot index as its token position; such a change alters relative-position behavior. We recommend local position indices beginning at zero for each step, fixed virtual positions for the state interface, and an explicit boundary-reset rule. When using global absolute positions in an existing checkpoint, the original logical positions must instead be preserved. Attention sinks, commonly a small fixed set of four to eight tokens, can remain pinned in a ring buffer. With PagedAttention [6], the state register can be mapped to reserved physical blocks and updated at fixed offsets. The allocator then maintains a stable block budget rather than continuously appending historical step blocks. Step-local blocks are released at the semantic boundary. Block-sparse or variable-length IO-aware kernels [19] implement the attention mask while keeping computation efficient. 

A.5 Checking dependency range before pruning 

Four complementary probes establish the state interface: 1. Distant-prefix intervention. Inject information at an earlier step j < i − 1 and measure whether the next-step output distribution changes when the final state is fixed. KL or Jensen–Shannon distance provides a direct numerical signal. 13 2. Layer/head attention inspection. Estimate the fraction of attention mass outside a local window of width d. A per-head or per-layer analysis guides hybrid local/global configura-tions. 3. Counterfactual state intervention. Perturb si or zi and check whether the successor changes according to the transition rule. The model must use the state rather than recite a memorized trajectory. 4. Mixed-depth fallbacks. Keep a few global bypass heads or a bounded local window when a task has weak residual long-distance dependencies. This creates a smooth transition between exact and approximate state sufficiency. 

A.6 Checkpoints, rollback, and branching 

In-place overwrite removes raw preceding states. A search procedure that explores branches therefore maintains explicit checkpoints. Every N steps, serialize the state register and logical position metadata to CPU memory or NVMe. Restoring a branch loads the nearest checkpoint and replays the required transitions. State hashes and token/position identifiers detect branch misalignment. The footprint of one checkpoint depends on the fixed memory interface, not the full generated transcript. 

A.7 Strategy selection 

When a task is proven or strongly verified to be Markovian, the structural state-slot route gives the strongest memory bound. For approximately Markovian problems with uncertain distant dependen-cies, a small window combined with recurrent attention is a natural fallback. For open-domain tasks dominated by arbitrary historical retrieval, attention-score eviction and transfer compression remain valuable tools. The objective is to select a model architecture matched to the dependency structure of the workload. 

# B Complete Transition-Centric Learning Recipe 

B.1 How specialized pretraining differs from general language modeling 

General-purpose LLM pretraining rewards prediction under arbitrary long-range token dependencies. In the specialized setting, each example teaches a conditional transition from qt to (st, q t+1 ). A short local context, often on the order of hundreds to a few thousand tokens depending on task-state complexity, replaces a long chain as the elementary sample. The objective need not require extrapolation of global positional embeddings across the entire reasoning horizon. The transition-centric model consequently places less emphasis on long-context extension techniques and more emphasis on a dedicated state compression head, state sufficiency, and robust step bound-aries. A recurrent or sliding-window backbone is appropriate when its training and inference windows agree. Mamba-style selective state models provide a natural fixed-size carrier, but being a state-space model alone does not force its hidden state to forget irrelevant history; the transition and bottleneck objectives are what impose that specific inductive bias. 

B.2 Constructing state–action–next-state triplets 

The data pipeline follows seven operations: 1. Split the reasoning trajectory. Map (q1, s 1: T , a ) into T independent triplets (qt, s t, q t+1 ).2. Generate reduced problems. A strong teacher produces qt+1 as a new problem whose continuation can be solved without the earlier derivation. 3. Verify independence. A separate solver receives only qt+1 and attempts the remaining task. Reject or regenerate failures. This is a substantive sufficiency check, not a string-length check. 4. Remove long-range shortcut signals. For task-focused pretraining, favor self-contained segments over arbitrary long-document concatenations that encourage the model to exploit unavailable history. 14 5. Pack samples with block-diagonal masks. Independent short samples can be packed into efficient hardware sequences, but cross-example attention must remain disabled. 6. Augment counterfactually. Perturb states and generate their correct successors, explicitly breaking spurious historical correlations. 7. Cut at natural boundaries only. Token-length truncation is not semantic reduction. Bound-aries should coincide with a new mathematical subproblem, tool-call round, tactic state, or verified state-machine transition. Program execution traces, finite automata, theorem-proving tactic states, game records, symbolic algebra, and tool usage provide procedurally generated transitions with exact labels. Small high-quality sets can be used to adapt pretrained models before scaling the specialized corpus. 

B.3 Detailed objective components Transition NLL. Minimize negative log-likelihood of (st, q t+1 ) conditioned on (Q, q t). Within the step, the causal mask prevents leakage from the target reduced state into the generated action. 

State bottleneck. Constrain the length or entropy of qt+1 and penalize copies of irrelevant historical text. A contrastive term can distinguish minimally sufficient states from longer, redundant alternatives. An auxiliary adversary can attempt to reconstruct older history from the state, with its success penalized subject to preservation of next-step predictive information. 

Independence consistency. Train a discriminator or verifier to judge whether a proposed successor state is sufficient for solving the rest of the task. Correct and incorrect successor pairs can also support preference optimization. 

Full-context teacher distillation. Match the teacher’s next-action logits using a student that receives only zi. This transfers predictive information through the bottleneck. 

Drift consistency. Compare S1 → S2 → S3 with a direct one-step transition initialized from the same S2. A KL term encourages the same operator regardless of the path used to obtain the state. 

Loop consistency. Compare a fixed state processed for R and R + 1 inner iterations; prevent extra computation from becoming uncontrolled stochastic resampling. 

Boundary recognition. Train step-end markers, transition markers, and chain-end markers so the outer loop operates on the correct semantic units. The multi-objective construction in Eq. (8) coordinates these terms. The goal is neither an empty state nor a copied transcript: it is a representation carrying precisely the information necessary for the successor transition. 

B.4 Three stages of pretraining and adaptation 

The first stage retains a reduced general-language foundation, sufficient to parse natural-language descriptions of states. It uses shorter sequence lengths and does not invest in long-context extension merely to support an eventual unbounded reasoning transcript. The second stage is state-transition pretraining: synthetic Markovian tasks train the model to compress intermediate reasoning into a self-contained successor problem and predict the next transition. The third stage is supervised task adaptation using MCoT-like triplets, followed by self-distillation and longer generated trajectories. Because independent state-transition pairs can be shuffled freely, data parallelism is especially effective. Model and pipeline parallelism remain available when parameter size demands them, but context parallelism no longer carries the burden of processing one extremely long chain. The desired engineering effect is higher sample throughput and a shorter gradient path for the same number of supervised transitions. 15 Table 6: Two complementary recurrent Transformer traditions.

# C Detailed Dual-Loop Realization 

C.1 Comparing recurrent design lines 

Our recommended realization uses recurrent depth as the computational backbone and memory tokens as the explicit state interface. The outer loop advances the Markovian trajectory; the inner loop supplies the depth required to compute a difficult transition. The same shared transition operator is reused because each step represents another application of the same conditional rule. 

C.2 Algorithmic skeleton                       

> Algorithm: Dual-loop Transformer with adaptive depth
> Initialize state q1, memory M1, and shared stack Fθ.
> For t= 1 , . . . , T max :Set h(0) ←Embed([BOS] , q t, M t).
> For r= 1 , . . . , R max :Update h(r)←Fθ(h(r−1) , e r).
> Break on fixed-point convergence. Decode (st, q t+1 , M t+1 )from the final hidden state. Reset step-local KV; break if Term( qt+1 ).

The inner loop can use learned loop embeddings or another explicit recurrence-depth coordinate. Its hidden-state updates and shared weights determine effective depth; the step loop determines the number of state transitions. Consequently, increasing reasoning horizon does not increase the number of learned parameters or retained historical KV vectors. 

C.3 Memory token quantity, read/write routing, and injection 

The number m of memory tokens is an explicit information bottleneck. A practical starting range is 4–8 for compact numerical states and 8–16 for structured automata, increasing to 16 –32 when sufficiency probes reveal lost constraints. Read tokens appear at segment input and write tokens at segment output. The preceding write slots become the subsequent read slots, retaining a differentiable path through a small interface. Prefix-token injection is the simplest wrapper around pretrained Transformers. At each inner iteration, reinject the original step embedding as a stabilizing signal. Two particularly important recurrent failure modes are hidden-state collapse , in which token representations become nearly identical, and 

loop collapse , in which the model learns to ignore recurrence and gives the same output after one or many iterations. Sandwich normalization, careful output-projection initialization, residual scaling, lower learning rates, and intermediate supervision counter these failures. 

C.4 Matrix-state alternative and numerical stability 

The delta-rule recurrence in Eq. (9) corrects an existing state prediction rather than blindly accumu-lating repeated writes. To maintain numerical stability over long chains, normalize keys, control the update magnitude (for example, keep β∥k∥2 within a stable range), accumulate sensitive state statistics in FP32, and periodically rescale blocks. Memory-token and matrix-state variants offer complementary implementation paths: the former is accessible through pretrained Transformer wrappers, while the latter gives a compact inference-oriented recurrent kernel. 16 C.5 Adaptive loop depth 

Three depth-control mechanisms are natural: 1. Fixed R. Choose a constant such as R = 2 or R = 4 for predictable latency and memory. 2. Fixed-point / adaptive computation time. Stop when normalized hidden-state change falls below a threshold, up to Rmax [10]. 3. Learned routing. A step-level router selects a depth from a small set (for example 

{1, 2, 4, 8}), and token-level routing may stop easy tokens earlier [25]. Randomized depth sampling during training prevents one fixed iteration count from becoming hardwired into the parameters. Heavy-tailed sampling allocates most training updates to short recurrences while occasionally exposing the model to deeper computation. Training and inference must share the relevant recurrence-depth support; inference should not silently exceed the depth range that the training dynamics have learned. 

# D Progressive Training and Recurrent Stability 

D.1 Three training stages in detail Stage I: transition-operator warm-up. This stage establishes reliable local mapping before imposing the full Markovian bias. Use abundant single-step transition pairs and short trajectory fragments. Train with transition cross-entropy and boundary-recognition losses; keep invariance and bottleneck penalties at zero or a very small weight. Monitor single-step perplexity, exact transition success, and correct recognition of the step-end marker. The objective is to make the recurrent unit competent at the fundamental state-to-successor computation. 

Stage II: consolidation of Markovian invariance. This is the central transformation from a general sequence model into a state-transition model. Introduce paired transitions whose current state is identical but whose distant history differs, randomized irrelevant prefixes, and positional perturbations. Increase history-invariance, state-alignment, information-bottleneck, and drift-consistency penalties progressively. Track the Markovian invariance rate : the fraction of matched-state pairs whose successor answers or distributions agree within tolerance. Also measure state fidelity, past-history predictability from encoded states, correct forgetting after state updates, and boundary accuracy. A practical target is invariance and fidelity above a threshold such as 95% , provided one-step transition success remains intact. A model that merely loops is not yet a Markovian reasoner; the intended inductive bias is that its future depends on explicit sufficient state rather than incidental prior text. 

Stage III: long-horizon autonomous rollout. Mix ground-truth and model-generated states through scheduled sampling. Preserve transition, bottleneck, invariance, distillation, and boundary objectives while emphasizing rollout consistency. Pure teacher forcing is insufficient because the model never learns to recover from its own small transition errors. Long-horizon training must expose the operator to the states it generates in deployment. 

D.2 Truncated BPTT and gradient accounting 

The factorization in Eq. (2) permits independently observed transitions to be shuffled and trained in batches. Full T -step backpropagation is unnecessary for supervised one-step prediction. For differentiable state transfer over multiple outer steps, divide a trajectory into length-B windows and detach memory at each boundary; the memory transports information, while the backward graph remains bounded by B. Within each step, retain gradients through the selected R shared-weight depth applications, using activation checkpointing to control retained activations. During reinforcement-learning post-training, reconstruct memory and hidden states with the current policy parameters rather than reusing stale rollout-time tensors, maintaining consistency of the differentiated action distribution. 17 D.3 The repeated core as a dynamical system

A locally linearized update with spectral radius greater than one can multiply perturbations exponentially with depth. Pre-normalization, residual scaling, constraints on injection projections, gradient clipping, smaller recurrent-core learning rates, and a depth curriculum such as 2 → 4 → 8 stabilize the iteration. Intermediate supervision counters hidden-state collapse and makes additional iterations meaningful. Test explicitly for insufficient memory capacity, false convergence or loop collapse, accidental accumulation of step KV, inconsistent positional indices, and inference depth outside the training support. 

# E Inference-Engine Realization 

E.1 Prefill, recurrent execution, and adaptive termination 

The runtime contains a loop scheduler, input constructor, shared recurrent core, sampler, state manager, KV-block manager, and Markovian validity checker. Following prompt prefill, only the fixed static condition, selected attention sinks, and current state interface survive. Static Q tokens may be reused by prefix caching. Each outer step builds input from static condition, state memory, and a bounded local workspace; executes Rt recurrent-depth updates; samples the local segment and successor; and replaces the state slot at the boundary. Termination follows the task predicate, learned stopping probability, fixed-point condition, or configured Tmax . Since parameter count is independent of recurrent depth, a serving scheduler may shift computation toward difficult steps without loading different model weights. 

E.2 Three cache policies Clear-and-rebuild. At each step, reconstruct a fresh local KV allocation and release it after extracting the successor state. This provides a simple semantically transparent implementation but repeats encoding. 

Fixed recurrent register. Preserve a fixed-size register containing static prefix KV and the latest state KV; reset or overwrite transient blocks. The bounded register is a practical deployment default compatible with fixed-size GPU memory pools. 

Virtual-state cache. Carry a dense latent state and project it into a handful of virtual tokens before each transition. Its storage approaches a fixed constant and its effectiveness depends on trained state fidelity. A hybrid policy compares state-only and recent-segment paths on selected steps, falling back to longer context when output distributions diverge. 

E.3 Parallel branching with explicit states 

The current state is a small tensor, so a batch of B candidate trajectories requires a memory bank of shape [B, m, d ], not B copies of the entire old transcript. Advance candidates together, score successors, select the top K branches, and release all local KV. Checkpoints at chosen boundaries save a fixed state and positional metadata, enabling replay after a failed continuation.

# G Experimental Program and Measurement Protocol 

G.1 Evaluation criteria 

Evaluation should measure (1) transition fidelity and KL against a full-context teacher; (2) sufficiency of the reduced state; (3) final chain-level success; (4) length extrapolation when trained on short chains and tested at k = 100 or greater; (5) correct reaction to counterfactual state changes with invariance to irrelevant prefixes; (6) self-correction after injected intermediate-state errors; (7) KV payload, peak GPU memory, and time per output token versus horizon; and (8) accuracy as a function of actual inner-loop depth. Conventional long-document retrieval benchmarks assess a different design objective. 

G.2 Baselines, datasets, and ablations 

Include four baseline families: full-KV general LLMs; cache-eviction and cache-compression methods such as H2O, SnapKV, and StreamingLLM; sliding-window attention, Mamba/SSM, and linear-attention state kernels; and specialized fixed-depth Transformers without the inner recurrent loop. Match backbone and evaluation conditions wherever a controlled architectural comparison is possible. Build verifiable datasets from synthetic arithmetic and symbolic rewriting, deterministic automata, pro-gram traces, and rule-based state transitions. Add reduced-state triplets derived from GSM8K/MATH-style problems, theorem-proving tactic states, industrial process checks, structured compliance tasks, and domain-specific stepwise deduction. Controlled finite-state tasks are especially valuable be-cause the true state dimension and transition kernel are known. Jointly ablate Markovian penalty weights, counterfactual-prefix perturbations, stopping policy, depth R, state size ds, hard or soft 19 masks, sink and memory-token counts, local segment length, and truncated-BPTT window. A joint state-capacity/depth sweep reveals the essential compression–computation tradeoff. # I Further Implications and Research Vision 

The explicit Markovian structure is a purposeful specialization. Numbering conventions, long-range references, proof branches, and global visited sets need to be included in the current state whenever they are task-relevant; otherwise they cannot be recovered after history is discarded. State-plus-bounded-summary hybrids, occasional full-context anchors, and selected global bypass heads extend coverage where strict compactness is not the right abstraction. 20 SSMs place compression in a recurrent architecture; our proposal additionally locates its justification in the task dependency graph and the measurable sufficiency of a reduced state. This suggests a tightly integrated outer SSM state evolution and inner Transformer depth recurrence. A general-purpose model can plan, retrieve, and recognize Markovian subproblems; a specialized state kernel can execute repeated structured transitions; the general model can then integrate the result. Such cooperation preserves generality at the system level while specializing the high-frequency execution path. Future research priorities include adaptive memory-token capacity, native recurrent GPU kernels, process-reward and reinforcement-learning post-training, minimax and information-theoretic bounds under state-sufficiency assumptions, multi-task transition kernels with task-conditioned memory initialization, higher-order and partially observable Markov extensions, and verified interfaces with external calculators, solvers, and simulators. The larger aim is to make long-horizon reasoning a sequence of state transitions and reusable computation , rather than an ever-growing transcript.
