## 摘要
基于LLM的用户模拟器正越来越多地用于评估对话助手。然而，这些模拟器可能偏离其既定目标，或无法穷尽探索所有指定选项，从而导致评估错误被错误归因于助手。已有工作考察了单任务设定下的目标对齐，但许多实际场景要求模拟器执行具有顺序任务、回退逻辑和跨任务依赖的多步骤工作流，而模拟器保真度在此类场景中尚未得到测量。为填补这一空白，我们引入一个包含500个工作流的基准，这些工作流使用分层任务网络（HTN）抽象表示。我们的实验表明，模拟器的保真度会随工作流复杂度急剧下降，且目标漂移占失败的大多数。保真度还取决于助手的回复风格，同一模拟器在不同风格下的得分会显著更好或更差。为此，我们提出ReUST（Reasoning + User State Tracking，推理+用户状态跟踪），一种简单的提示策略，用于在对话轮次间维护状态信息。ReUST将中型和大型模型的目标成功率提高超过12个百分点，并降低模拟器对助手回复风格的敏感性。

## Abstract
LLM-based user simulators are increasingly used to evaluate conversational assistants. Yet, these simulators can drift from their assigned goals or fail to exhaustively explore all specified options, causing evaluation errors incorrectly attributed to the assistant. Prior work has examined goal alignment in single-task settings, but many practical scenarios require simulators to execute multi-step workflows with sequential tasks, fallback logic, and cross-task dependencies, where simulator fidelity has not been measured. To close this gap, we introduce a benchmark of 500 workflows represented using the Hierarchical Task Network (HTN) abstraction. Our experiments reveal that the simulator's fidelity degrades sharply with workflow complexity, and that goal drift accounts for the majority of failures. Fidelity also depends on the assistant's response style, with the same simulator scoring substantially better or worse across styles. To address this, we propose ReUST (Reasoning + User State Tracking), a simple prompting strategy to maintain state information across dialogue turns. ReUST improves goal success rate by more than 12 points for mid-sized and large models, and reduces simulator sensitivity to the assistant's response style.

## 1. 核心问题与整体含义

- **研究动机**：基于 LLM 的用户模拟器被广泛用于规模化评估对话助手，但其有效性建立在一个关键假设上：模拟器会忠实执行被分配的目标。实际中，模拟器可能偏离目标、跳过步骤、过早回退、遗漏选项或虚构约束，这些错误会被误判为助手错误，并降低评测覆盖度。
- **背景缺口**：已有工作主要关注单任务场景下的目标对齐，而现实应用常要求模拟器执行**多步骤工作流**：顺序任务、回退逻辑、重试行为、跨任务依赖。此类场景下模拟器保真度尚未被系统测量。
- **整体含义**：论文将评测对象从“助手能力”转向“用户模拟器本身的可靠性”，提出多步工作流基准，并指出模拟器保真度并非模拟器固有属性，而会受到助手回复风格的显著影响。

## 2. 方法论

### 2.1 基于 HTN 的工作流建模

- 使用**分层任务网络（HTN）**表示工作流，固定三层结构：
  - **Task（任务）**：如酒店预订、交通预订，必须按顺序完成。
  - **Method（方法）**：完成任务的不同方式，如火车或出租车，按顺序尝试，当前方法耗尽后回退。
  - **Step（步骤）**：带具体参数值的单次动作，如“预订 7 AM 火车”，按顺序重试直到成功。
- 工作流复杂度由两个维度控制：
  - **路径长度**：从开始到成功完成所需尝试的总步骤数。
  - **回退深度**：主方法完全失败、被迫切换备选方法的任务数量。
- 跨任务依赖包括三类：
  - **直接传播**：复用已完成任务的值。
  - **计算推导**：基于先前结果计算新值。
  - **条件分支**：根据早期任务如何解决决定后续参数。
- 工作流被规则化、确定性地序列化为自然语言目标；模拟器只能看到目标文本，看不到底层 HTN 或采样执行路径。

### 2.2 受控对话评测框架

- 对话循环由三方组成：
  - **用户模拟器**：根据自然语言工作流目标生成用户请求。
  - **对话助手**：解析请求并调用工具。
  - **脚本化工具环境**：根据隐藏的采样执行路径返回成功/失败。
- 由于环境完全决定哪些步骤成功，偏离真实路径主要来自模拟器，包括错误参数、错误任务选择、错误顺序或过早回退。
- 助手固定为 Nova Pro，以减少助手侧差异。

### 2.3 评价指标

- **Goal Success Rate, GSR（主指标）**：工作流是否被完全按规定执行；要求调用数量等于期望数量，且每一步工具和参数均匹配，二值判定。
- **Tool Accuracy**：正确工具选择比例；分母使用 `max(M,N)`，对额外调用进行惩罚。
- **Argument Accuracy**：所有参数均匹配的步骤比例。
- **Survival Rate**：首次错误前完成的步骤比例，用于区分早期崩溃与接近成功。

### 2.4 ReUST 提示策略

- **核心思想**：要求模拟器在每轮维护结构化内部状态，并基于状态进行推理，而不是从对话历史中重新推断进度。
- 每轮输入包括：工作流目标、对话历史、上一轮状态；输出一个 JSON 形式的 Thought 块，包含：
  - `current_task`
  - `previous_turn_summary`
  - `fixed_params`
  - `variable_options`
  - `tried`
  - `remaining`
  - `next_action`
- 模拟器从该状态块生成单行用户回复。提示指令与具体任务无关，具有任务泛化性。
- 与 DST 和 ReAct 的关系：ReUST 跟踪的是模拟器自身在工作流中的进度，而非助手信念状态；通过外化工作记忆降低长对话中的状态重建负担。

## 3. 实验设计

- **数据集/基准**：
  - 构建 **500 个工作流**的分层评测集，回退深度 0–3 各 125 个。
  - 路径长度约 **11–38 步**，目标文本平均约 **929 词**。
  - 领域基于 MultiWOZ：酒店、火车、出租车、餐厅、景点，均属于单一旅行场景。
- **模拟器模型**：
  - Small：Qwen3 32B。
  - Medium：Llama 3.3 70B、Qwen3 235B。
  - Large：DeepSeek V3.1 671B。
  - 均为开源权重模型，温度设为 0。
- **助手人格/回复风格**：
  - Terse：仅返回成功/失败。
  - Tool-only：仅说明哪个任务成功/失败。
  - Echo：复述当前尝试的参数。
  - History：列出该工具已尝试的所有值。
  - Suggestive：类似 Echo，但失败后主动提供目标外的替代选项。
- **对比方法**：
  - Baseline：仅给目标，无状态跟踪或推理支持。
  - Goal Reminder：每轮重复完整目标。
  - Summary：维护自由文本摘要、当前任务、下一动作。
  - State Tracking Only：维护结构化 JSON 状态，但不进行推理。
  - ReUST：结构化状态 + 推理。
- **主要实验组**：
  - Baseline vs ReUST 在四个模型/三个规模层上的比较。
  - Qwen3 235B 上的五种提示策略消融。
