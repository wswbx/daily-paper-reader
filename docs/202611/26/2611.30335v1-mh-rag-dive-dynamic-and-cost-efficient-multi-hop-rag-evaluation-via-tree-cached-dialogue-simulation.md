## 摘要
质量评估对于判断对检索增强生成（RAG）系统的更改是提升还是维持其性能至关重要。然而，现有评估方法往往依赖单轮或单跳交互，因此无法捕捉多跳、多轮对话的复杂性。我们提出 MH-RAG-DIVE，一个动态交互式用户模拟框架，旨在在更复杂的多跳和多轮设置中评估 RAG 系统。该框架通过引入上下文发现器（Context Discoverer）扩展 RAG-DIVE，该组件识别可在持续对话中组合以生成多跳问题的文档。为应对动态用户模拟的高计算成本，我们进一步引入对话缓存器（Conversation Cacher），它在保持评估动态特性的同时复用先前评估运行中的轮次。我们在六种不同的 RAG 配置上评估该框架，并将其结果与原始 RAG-DIVE 评估以及静态、人工创建的 CLAPNQ 数据集进行比较。实验表明，各评估方法呈现出较为一致的性能趋势，而更复杂的多跳和多轮设置则暴露出 RAG 系统面临的额外挑战。此外，对话缓存器大幅降低了 token 消耗，表明其有望使动态评估更具成本效率。最后，我们将 MH-RAG-DIVE 应用于具有领域特定数据的工业 RAG 系统，证明其适用于真实世界的评估场景。总体而言，结果表明所提方法为评估 RAG 系统提供了一个更复杂且成本更高效的框架。所有代码和实验数据均在我们的 GitHub 仓库（https://github.com/Daniel-Innsbruck/MH-RAG-DIVE）中公开可用。

## Abstract
Quality assessment is essential for determining whether changes to a Retrieval-Augmented Generation system improve or maintain its performance. However, existing evaluation approaches often rely on single-turn or single-hop interactions and therefore do not capture the complexity of multi-hop, multi-turn conversations. We introduce MH-RAG-DIVE, a dynamic interactive user simulation framework designed to evaluate RAG systems in more complex multi-hop and multi-turn settings. The framework extends RAG-DIVE with a Context Discoverer, which identifies documents that can be combined to generate multi-hop questions within an ongoing conversation. To address the high computational cost of dynamic user simulation, we further introduce a Conversation Cacher, which reuses turns from previous evaluation runs while preserving the dynamic nature of the evaluation. We evaluate the framework across six distinct RAG configurations and compare its results with the original RAG-DIVE evaluation and the static, human-created CLAPNQ dataset. Our experiments show consistent performance trends across the evaluation approaches, while the more complex multi-hop and multi-turn setting exposes additional challenges for RAG systems. Furthermore, the Conversation Cacher substantially reduces token consumption, demonstrating its potential to make dynamic evaluation more cost-efficient. Finally, we apply MH-RAG-DIVE to an industrial RAG system with domain-specific data, demonstrating its applicability to real-world evaluation scenarios. Overall, our results show that the proposed approach provides a more complex and cost-efficient framework for evaluating RAG systems. All code and experimental data are publicly available in our GitHub repository (https://github.com/Daniel-Innsbruck/MH-RAG-DIVE).

## 2. 方法论

### 2.1 核心思想

- 在 RAG-DIVE 基础上扩展两个关键组件：
  1. **Context Discoverer（CD，上下文发现器）**：自动发现可组合成多跳问题的跨文档上下文块；
  2. **Conversation Cacher（CC，对话缓存器）**：以树结构缓存历史对话轮次，仅在必要时重新生成，降低动态模拟成本。
- 整体框架包含五个组件：
  - Context Discoverer；
  - Conversation Generator（CG，对话生成器）；
  - Conversation Validator（CV，对话验证器）；
  - Conversation Cacher；
  - Conversation Evaluator（CE，对话评估器）。

### 2.2 关键技术细节

- **评估向量库 \(V_{eval}\)**：
  - 将原始文档递归切分为带重叠的块；
  - 每块附带文档头、创建日期、父文档 ID \(P(d_i)\)、块在文档中的位置 \(Idx(d_i)\)、文档总块数 \(N(d_i)\)；
  - 所有块嵌入后存入 \(V_{eval}\)，与下游 RAG 检索架构解耦。
- **两阶段多跳上下文发现**：
  1. 从 \(V_{eval}\) 随机采样起始块 \(d_A\)，用带过滤的语义 kNN 检索候选块，强制 \(P(d_j) \neq P(d_A)\)，保证跨文档；
  2. 从候选邻域采样第二块 \(d_B\)，由 LLM 判断其与 \(d_A\) 的主题关系，输出桥接主题集合 \(T_{bridge}\) 和二元置信度；
     - 置信度为 0 则拒绝并继续采样；
     - 若所有 k 个邻居均不满足，则丢弃 \(d_A\) 并重新开始；
  3. 找到有效块对后形成源集合 \(S_1=\{d_A,d_B\}\)，连同 \(T_{bridge}\) 交给 CG 生成首轮多跳问题。
- **确定性上下文扩展**：
  - 用触发参数 \(\alpha,\beta\) 指定在哪些对话轮次扩展 \(d_A\)、\(d_B\) 的相邻块；
  - 扩展方向 \(dir \in \{above, below\}\)，到达文档边界时自动反向；
  - 扩展后 \(S_t = S_{t-1} \cup \{d_{adj}\}\)，后续问题基于扩展上下文生成，但不再引入新文档。
- **Conversation Generator**：
  - 首轮被提示生成需要整合两个块信息的多跳问题；
  - 查询类型沿用 MultiHop-RAG 的三类：**inference、comparison、temporal**；
  - 输出 bundle \(G_1\)，包括 RAG 输入、独立问题、查询类型、标准答案、二值 Multi-Hop Flag、合成桥接主题；
  - 后续轮次多跳推理为可选，只有首轮被可靠标记为多跳问题。
- **Conversation Validator**：
  - 沿用 RAG-DIVE 的通过/失败校验；
  - 首轮额外校验：
    - **Query Type Alignment**：问题是否符合声明的查询类型；
    - **Multi-Hop Integrity**：两个块是否都是回答所必需的，单块可答则拒绝。
- **Conversation Cacher（树缓存）**：
  - 根节点存储 \(S_1\) 和 \(G_1\)；
  - 每个节点存储目标系统响应 \(y_t\)、缓存输出 bundle \(G_{t+1}\)、子节点引用；
  - \(\alpha,\beta,dir\) 随节点持久化，保证上下文扩展与缓存轨迹一致；
  - 当 RAG 返回新响应 \(y_t\)，计算其与当前节点所有缓存响应键 \(\tilde{Y}_t\) 的语义相似度，从最相似分支继续；
  - 缓存 bundle \(\tilde{G}_{t+1}\) 再由 CV 结合当前对话历史验证：通过则复用该轮，否则重新生成并作为新分支加入；
  - 缓存树随不同 RAG 输出动态增长。
- **Conversation Evaluator**：
  - 沿用 RAG-DIVE 的四个单轮指标：context recall、context precision、faithfulness、correctness；
  - 两个多轮指标：forgetfulness、context retention；
  - 按 Multi-Hop Flag 过滤单轮指标，分别报告单跳与多跳问题的表现。

## 6. 主要结论与发现

- **问题质量较高**：
  - 人工评估中，correctness、answerability、plausibility、diversity、coherence 多数超过 90%；
  - **95%** 的首轮多跳问题通过 multi-hop integrity 检查，确实需要两个块共同作答。
- **缓存显著降低成本**：
  - 首轮缓存命中率 100%，随后逐轮下降：71.4%、50%、35%、23.7%；
  - CG token 减少约 **45%**；
  - CV token 增加约 **11%**；
  - 总 token 减少约 **28%**；
  - RAG-DIVE 的 token 消耗是 MH-RAG-DIVE 的两倍以上。
- **结果一致性较好**：
  - 单轮指标标准差最大约 0.02；
  - 多轮指标方差略高：context retention 0.04，forgetfulness 0.05；
  - 多跳首轮指标方差最大约 0.02。
- **多跳多轮评估更具挑战性**：
  - RAG 系统在 MH-RAG-DIVE 上通常得分低于 RAG-DIVE 和 CLAPNQ；
  - 多跳问题得分普遍更低，尤其在 1-chunk 和 BGE-small 配置下更明显；
  - MH-RAG-DIVE 放大了不同 RAG 配置之间的性能差异，更容易暴露检索配置的强弱。
- **性能趋势总体一致**：
  - 三种评估方法在六种配置上的趋势大体相似；
  - Agentic 和 8-chunk 配置通常 correctness 较高，1-chunk 最低；
  - CLAPNQ 上系统整体表现最好，说明人工静态问题相对容易。
- **工业场景可迁移**：
  - 工业 RAG 系统在 MH-RAG-DIVE 上得分最低，在原有 QA 集上最高；
  - 说明更复杂、更动态的多跳多轮评估能暴露系统在原评估集中未体现的弱点。
