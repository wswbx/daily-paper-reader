## 摘要
最近的LLM代理得益于处理复杂任务的技能。技能封装了模块化的过程性知识和执行专业任务的指令，例如设置沙盒环境、运行测试套件或跨多个文件重构函数。随着技能库的增长并跨任务和领域变得可复用，选择合适的技能组合已成为核心瓶颈。现有方法分为两类：一类将代理的推理暴露给整个技能集合；另一类通过嵌入或基于LLM的重排序器进行技能检索。两者均提供了有用的见解，但忽略了技能组合的结构性本质——这是一个关于哪些技能、多少技能以及何种顺序的联合决策，这三个维度无法解耦。我们将其形式化为结构化技能组合：给定任务和技能库，预测一个可执行的技能计划，该计划联合指定激活的子集、数量和执行顺序。我们提出SkillComposer，它将结构化技能组合实例化为任务条件下的技能序列预测。SkillComposer在技能标识符上使用受约束的自回归解码器，因此子集、数量和顺序在单次解码过程中联合出现，并且连续技能之间的依赖关系被自然捕获。我们从真实的人工策划的技能库构建任务-组合对的训练集。然后沿着两个轴评估SkillComposer：在保留测试集上的组合质量，以及在两个生产级编码代理上对SkillsBench的下游任务成功率。在GPT-5.2-Codex和Gemini-3-Pro-Preview上，SkillComposer相对于无技能基线将通过率提高了+23.1和+18.2个百分点，超越了前三名检索，并以更低的提示令牌成本匹配了黄金技能检索的上限。

## Abstract
Recent LLM agents benefit from skills for solving complex tasks. Skills encapsulate modular packages of procedural knowledge and instructions for performing specialized tasks, such as setting up a sandboxed environment, running a test suite, or refactoring a function across multiple files. As skill libraries grow and become reusable across tasks and domains, selecting an appropriate skill composition has emerged as a central bottleneck. Existing approaches fall into two categories. One exposes the agent's reasoning to the entire skill collection; the other performs skill retrieval via embeddings or LLM-based rerankers. Both provide useful insights; however, they miss the structural nature of skill composition, which is a joint decision over which skills, how many, and in what order -- three dimensions that cannot be decoupled. We formalize this as structured skill composition: given a task and a skill library, predict an executable skill plan that jointly specifies the activated subset, count, and execution order. We propose SkillComposer, which instantiates structured skill composition as task-conditioned skill sequence prediction. SkillComposer uses a constrained autoregressive decoder over skill identifiers, so subset, count, and order emerge jointly from a single decoding pass, and dependencies between successive skills are captured naturally. We build a training set of task-composition pairs from a real, human-curated skill library. We then evaluate SkillComposer along two axes: composition quality on a held-out test set, and downstream task success on SkillsBench across two production-grade coding agents. On GPT-5.2-Codex, Gemini-3-Pro-Preview, SkillComposer raises the pass rate by +23.1, +18.2pp over the no-skill baseline, surpassing top-3 retrieval and matching the gold-skill retrieval upper bound at lower prompt-token cost.

## 2. 方法论：核心思想、关键技术细节、公式/算法流程

- **核心思想**：将每个技能库中的技能索引视为一个闭集词汇表中的输出 token，使用一个任务条件约束自回归解码器，生成一个以 STOP token 结尾的变长技能索引序列，同时解决子集选择、计数预测和顺序确定。
- **关键组件**：
  - **任务编码器**：冻结的预训练文本编码器（Qwen3-Embedding-0.6B）将序列化提示映射为任务向量 h（投影到 256 维）。
  - **自回归解码器**：一个 3 层、256 维的 Transformer（4 个注意力头），逐 token 预测技能索引，条件为任务向量和之前生成的 token。
  - **辅助头**：
    - **计数头**：线性分类器从任务向量直接预测技能数量（1~8）。
    - **集合头**：MLP 为每个技能输出一个与任务相关的相关性分数（二分类，判断该技能是否在黄金技能集合中）。

- **算法流程**（文字说明）：
  1. 输入任务描述 x、环境上下文 c、技能库 S（K=196 个技能，每个技能提供名称和一行描述）。
  2. 编码器将输入序列化为提示并输出任务向量 h。
  3. 解码器从 START token 开始，逐 step 预测技能索引，每步融合检索先验和集合信号，直至输出 STOP。

## 6. 主要结论与发现

- 在合成测试集和真实任务保持集上，SkillComposer 均以极少的可训练参数（~3.9M）超越了 SFT（600M）和 LLM 裁判，特别是在真实分布偏移下，SkillComposer 仅下降 11 pp，而 SFT 下降 27.5 pp。

- TF‑IDF 作为解码先验效果最好（优于 BM25 和密集嵌入），因为技能名称短且词汇特异性强。
- 每个组件都是必要的：去除检索先验或集合信号会显著降低 Set F1。
- 案例研究发现：SkillComposer 能比黄金技能集选出更精炼的技能组合，但在处理长链任务（≥3 个技能）时易少输出技能，表明训练数据中长序列记录不足是主要改进空间。

## 7. 优点

- **创新性**：首次将技能组合形式化为结构化预测问题，显式联合建模子集、数量和顺序，而非两个独立步骤。
- **高效性**：仅用 3.9M 可训练参数（154× 少于 SFT）达到或超越 SFT 性能，推理延迟与 SFT 相当（约 10⁶ ms？图中示约 100 ms 量级），远快于 API 裁判（约 10⁶ ms？实际图 5c 中 Gemini 约 5×10⁵ ms）。
- **稳健性**：在分布偏移（从合成到真实任务）下表现更可靠，模型未过度记忆模板。
- **可解释性**：计划可检查，每个输出对应可执行技能，解码日志可追溯。
- **实验设计**：多维评估（组合质量 + 下游成功率 + 消融 + 案例），并进行了公平的 token 成本对比。

## 8. 不足与局限

- **实验覆盖**：仅使用文本任务描述和代码导向的技能库；未涵盖多模态任务、交互式场景或实时更新的技能库。
- **领域限制**：主要针对软件工程和数据分析类任务，在科学工作流、机器人、具身智能等领域的泛化性未验证。
- **长链问题**：对需要 3 个以上技能的任务，SkillComposer 倾向于漏输出，原因是训练数据中长序列样本偏少（合成 corpus 强调 ≤3 skill 组合）。
- **资源报告不足**：未明确训练所需的 GPU 小时数或具体硬件配置，不利于可重复性。
- **依赖外部检索**：解码时依赖 TF‑IDF 先验（虽然可预计算），若技能库更新则需要重新构建索引。
- **风险**：作为通用框架，不涉及敏感领域评估，但任何技能组合系统若误选技能可能导致计划失败；未讨论安全审计或错误传播分析。
