## 摘要
诸如 autoresearch 之类的长时间运行编码智能体能够持续发现开放式问题的优化方案。然而，它们往往收敛到单一的高级方法，然后进行低级编辑，同时错过其他更优的解决方法。我们假设两种框架层级的设计选择导致了这一行为：在单个长时间运行的智能体中积累上下文，以及只暴露单一程序状态进行编辑。我们引入了 SwarmResearch，一种编排器-子智能体框架，其中 Shepherd 智能体利用全局上下文来引导一组 Search 智能体，每个智能体在其各自的 git 分支中基于局部上下文进行操作。在开放式优化任务中，SwarmResearch 在 13/15 的任务上发现了优于或可媲美最先进的 LLM 引导进化与多智能体技术的解决方案，这得益于更高层次的探索。与串行和并行智能体的固定扩展相比，SwarmResearch 的编排器引导扩展通过在不同搜索深度上自适应并行度，发现了性能更优的解决方案。

## Abstract
Long-running coding agents such as autoresearch can persistently discover optimizations for open-ended problems. However, they tend to converge onto a single high-level approach, then proceed with low-level edits while missing other superior approaches to the problem. We hypothesize two harness-level design choices contribute to this behavior: accumulating context in a single long-running agent and only exposing a single program state to edit. We introduce SwarmResearch, an orchestrator-subagent harness in which a Shepherd Agent uses global context to steer a population of Search Agents, each operating with local context in their respective git branch. On open-ended optimization tasks, SwarmResearch discovers better or comparable solutions to state-of-the-art LLM-guided evolution and multi-agent techniques on 13/15 tasks, driven by higher-level exploration. Compared with fixed scaling of serial and parallel agents, SwarmResearch's orchestrator-guided scaling discovers better-performing solutions by adapting parallelism at different search depths.

# SwarmResearch：编排编码智能体以进行开放式发现

## 1. 核心问题与整体含义（研究动机与背景）

论文指出，当前长时间运行的编码智能体（如 autoresearch）在执行开放式优化任务（如设计快速的 LLM 推断算法、数学优化、启发式算法工程）时，容易陷入 **“过早收敛陷阱”**：智能体在找到一种看起来不错的高级方法后，会不断在该方法周围进行低层次、增量式的代码微调，从而错过其他可能更优的全新方法。

产生这种行为的根本原因被归为**框架（harness）级别的两个设计缺陷**：

- **上下文积累偏置**：单个智能体的对话历史不断增长，强化了当前方法，使得“大幅转向”变得极不可能。
- **单一程序状态**：所有改进被提交到同一个可编辑的程序上，没有保留并发展并行竞争方案，本质上变成了贪婪局部搜索。

作者从“系统工程”角度出发，主张通过改进**上下文管理**和**程序版本管理**来释放编码智能体的探索潜力，从而在更广阔的解空间中实现高质量发现。

## 2. 方法论

### 核心思想

提出**编排器-子智能体（Orchestrator-Subagent）架构**，名为 **SwarmResearch**。整体结构由一个 **Shepherd Agent（牧羊人智能体）** 和多个 **Search Agents（搜索智能体）** 组成。

- **Shepherd Agent**：保持全局上下文，负责策略性地生成和引导 Search Agents，包括选择父解、指定子智能体类型（探索者/优化者）、提供精炼的非指令性提示。
- **Search Agents**：在各自独立的 git 分支上工作，拥有**局部上下文**。分为两类：
  - **Explorer（探索者）**：使用全新的上下文窗口，不受之前工作影响，适合尝试大的、高层次的改动。
  - **Optimizer（优化者）**：继承父智能体的对话历史，适合在已有方法上做序列化精细改进。

### 关键技术细节

- **父解选择**：Shepherd 可从主基线（全新探索）或已完成智能体的提交（迭代改进）创建新分支。
- **分支与版本管理**：每个 Search Agent 分配独立 git 分支，保存完整演化记录，避免贪婪丢弃竞争方案。
- **上下文隔离**：Search Agents 只看到自己分支的文件和（对于 Optimizer）直接父代的对话历史；Shepherd 通过提示选择性传递全局信息，防止所有智能体都聚焦于当前最优解。
- **Shepherd 行为模式**：初始阶段启动多波探索者（~4-8个），后期对最有前途的方案启动优化者。借助精心编写的提示（如“避免已探索的想法”或“指出当前方法的弱点”）引导而不直接指派具体想法。

### 算法流程文字说明

1. Shepherd 接收任务（含基线代码和评估器）。
2. Shepherd 创建新分支，选择父解，确定子智能体类型，可选附带提示。
3. 被启动的 Search Agent：
   - 进入工作区，读取 `prompt.md` 和已有 `findings.md`。
   - 探索者：设想一个全新思路，实现、评估，只尝试一个主要想法，完成后提交并更新 `findings.md`。
   - 优化者：在最多 5 次迭代中逐步改进，每次评估后保留改进、回退退化，提交。
4. Search Agent 返回摘要给 Shepherd。
5. Shepherd 根据所有返回信息决定下一步要启动新的搜索智能体（继续探索、序列化或组合），直至预算用尽。

## 3. 实验设计

### 基准与任务

使用 **15 个开放式优化任务**，来自三个领域：

- **数学优化（5 个）**：Circle-Packing, Signal Processing, Erdos Min Overlap, MMD-14-3, 3rd-Autocorrelation。这些任务要求编写程序来构建新的数学证明/构造。
- **系统优化（5 个）**：来自 ADRS 基准，包括 EPLB, LLM-SQL, Txn Scheduling, Cloudcast, PRISM。基于真实世界系统研究问题。
- **启发式算法（5 个）**：来自 ALE-Bench-Lite（AtCoder Heuristics Contest），包括 Territory (AHC008), Halloween Candy (AHC015), Graphorean (AHC016), Balancing by Balance (AHC025), Stack of Boxes (AHC026)。这些是竞赛问题，分数反映竞争者的 Elo 评级。

每个任务均提供一个可以运行的最简基线代码。

### 对比方法

- **EvoX**：最先进的 LLM 引导进化算法，使用 Opus 4.6 模型，运行 100 代，每任务平均成本 $23.50。
- **CORAL**：多智能体协作系统，4 个智能体共享基于文件系统的记忆，使用 Claude Code，每任务 $50 预算。
- **固定缩放基线**：在 Pi 框架下用 Minimax-M2.5 模型，运行不同 (并行数, 串行迭代) 组合（5×12, 10×6, 15×4, 20×3, 30×2），总计 60 次迭代，取最优配置与 SwarmResearch 协调器引导缩放比较。

### 特殊案例研究

- **近似推测解码（Approximate Speculative Decoding）**：目标模型 gemma-4-26B-A4B-it，草稿模型为其 MTP 头。使用 30 个推理密集型任务（来自 LiveCodeBench v6, AIME 2026, GPQA Diamond, HLE-MCQ）。SwarmResearch 运行约 11 小时，对比 vanilla autoresearch 和 CORAL 各约 12 小时，评估 5 个种子的平均值。

## 4. 资源与算力

- 实验中使用的模型：**Opus 4.6**（Claude Code）和 **Minimax-M2.5**（部分固定缩放实验）；Shepherd 使用 Claude Sonnet-4.6。
- **推测解码案例**：在 **8 块 A6000 GPU** 上运行和评估。
- **成本**：每任务 $50 预算（CORAL 和 SwarmResearch），EvoX 平均 $23.50/任务。15 个任务的总预估 API 成本约 **$1700**（包括所有方法）。
- **运行时间**：SwarmResearch 约 11 小时，autoresearch 和 CORAL 约 12 小时。
- **未涉及模型训练**，全部为测试时使用 LLM API，没有自定义模型的预训练成本。

## 5. 实验数量与充分性

- **主要对比实验**：每个方法在 15 个任务上各执行 **一次**（单次运行）。作者坦言单次运行受随机性影响大，但由于成本限制以及 LLM 驱动探索的固有高方差，他们推荐在现实预算下使用单次长时间运行以获得代表性结果。对所有方法一视同仁，因此具有一定公平性。
- **固定缩放消融**：5 个任务，每个配置运行 3 次取平均，寻找最优 (n,k) 组合，再与 SwarmResearch 协调器引导缩放（同样 3 次平均）比较。
- **案例研究**：5 个种子平均，作者报告了加速比和准确率，并与基线的单一结果比较。
- **代码变更粒度分析**：对 SwarmResearch 和 CORAL 的每个提交计算变更行数，与 EvoX 中改进父代的提交比较。
- **总体评价**：实验覆盖多领域（数学、系统、启发式），且包含内部消融（引导缩放 vs 固定缩放）。但由于单次运行主导，结果的统计稳定性较弱。作者在附录 B 中讨论了运行间方差问题，承认这是一个挑战，并建议研究者根据任务特性调整多次运行预算。实验设计在可接受范围内，但**充分性上可进一步加强**（如对更多种子进行主实验）。

## 6. 主要结论与发现

- SwarmResearch 在 **13/15** 个开放式优化任务上**超过或达到** SOTA 进化（EvoX）和多智能体（CORAL）方法的性能。
- 代码变更粒度分析显示，SwarmResearch 的每次尝试平均变更 **3.2 倍** 于 CORAL、**1.7 倍** 于 EvoX 的代码行数，证实其更倾向于高层方法探索。
- 在固定缩放对比中，协调器引导的缩放（动态调整宽度和深度）在 **4/5** 个任务上优于最优固定缩放配置，且无需手动选择超参数。
- 在推测解码案例中，SwarmResearch 达到 **4.58 倍** 于朴素解码的吞吐量（均值 tok/s），准确率 60.6%（基线 65.8%），远超 autoresearch（1.80×）和 CORAL（2.26×）。最佳方案包含批处理、持久化线程池、自适应 MoE 专家数等系统级优化，以及一些新颖但效果有限的采样策略。

## 7. 优点

1. **简单而有效的设计**：不依赖复杂超参数（无需要手动配置并行/串行度），Shepherd 自适应调整搜索策略。
2. **上下文管理创新**：通过新鲜窗口 + 继承历史的分层设计，有效平衡探索与利用，避免所有智能体聚焦同一点。
3. **版本管理自然支持多样性**：git 分支机制允许多条竞争演化线并存，不丢弃弱势但具潜力的方案。
4. **与现有工具兼容**：实现为三个技能文件（shepherd, explorer, optimizer），可直接在 Claude Code 等流行编码智能体上使用。
5. **广泛的任务覆盖**：数学、系统、启发式三领域验证方法的通用性。
6. **详尽的消融分析**：通过与固定缩放对比，证明协调器智能体带来的增益。
7. **案例研究深入**：提供了解决方案树的可视化（图1），展示了探索路径的多样性。

## 8. 不足与局限

1. **不增强 LLM 的底层创造力**：SwarmResearch 不改变 LLM 生成新想法的能力，探索出的方案仍倾向于已知方法变体。
2. **Shepherd 行为高度依赖提示工程**：复杂的战略规划（如识别瓶颈并设计针对性实验）对当前模型难以实现，限制了架构潜力的充分发挥。
3. **单次运行方差风险**：由于成本限制，主实验仅单次运行，可能因随机性导致结果偏差。作者承认此问题但未提供多次运行稳定性测量。
4. **执行成本较高**：每任务 $50 预算对大规模研究不经济。案例研究中使用的是较新的 Opus 4.8，成本更高。
5. **对比基线的可能偏差**：EvoX 在 GPT-5 模型下表现更好，但文中仅使用了 Opus 4.6，可能低估了进化方法的性能。CORAL 的复现结果差于原论文，虽做了说明但仍影响公平性。
6. **启发式任务上仍落后人类专家**：在 AHC 竞赛中，SwarmResearch 的最佳分数（~2000-2500）远低于人类 SOTA（~3500），表明在需要深度领域知识和密集优化的任务上仍有代差。
7. **不完整的评估**：未对所有任务进行多次种子平均，未对失败案例进行系统性分析。案例研究中的新方法（如 comonotone sampling）虽然被 LLM 提出来且声称有效，但实际复现显示其效果不可靠，这是高风险点。
