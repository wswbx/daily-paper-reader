## 摘要
自主发现系统将回答查询的资源（模拟器、仪器或分析模型）与选择下一步要查询的内容的算法相结合。大多数针对这一循环的软件框架继承了数值优化的控制结构：实验以固定次数运行，查询成本不出现在编程接口中，决策制定被视为免费。在实践中，查询的成本可能相差几个数量级，而基于大型语言模型或昂贵代理的规划器也会消耗自身资源。在此，我们提出CADAQUES，一个基于一个架构原则的开源Python框架：成本是发现循环的一等原语。CADAQUES将循环分为两个结构协议：回答查询的Oracle和提出查询的Driver，并针对共同的向量值预算（涵盖挂钟时间、CPU小时、货币成本和语言模型令牌）对评估和决策进行收费。一个仅追加的账本记录每次交易的执行前声明的成本和执行后结算的成本，使它们的差异成为实验的一个可观察属性。我们通过从带有噪声的有限尺寸估计中定位二维伊辛模型的临界温度，并与精确的热力学极限参考进行比较来评估该架构。在这个噪声环境中，集中在最佳观测结果周围的策略可能被噪声引起的峰值误导，而一个探索使用廉价低保真度查询并用更高保真度进行精化的方案，在所研究的预算规模下，比全程高保真度产生更低且更少变化的误差。计量每迭代增加几十微秒，比最便宜的Oracle查询低三个数量级。该框架采用MIT许可证，并归档于Zenodo（doi:10.5281/zenodo.21293589）。

## Abstract
Autonomous discovery systems couple a resource that answers queries (a simulator, instrument, or analytic model) to an algorithm that selects what to query next. Most software frameworks for this loop inherit the control structure of numerical optimization: campaigns run for a fixed number of iterations, query costs are absent from the programming interface, and decision-making is treated as free. In practice, queries may differ in cost by orders of magnitude, and planners built on large language models or expensive surrogates consume resources of their own. Here we present CADAQUES, an open-source Python framework built on one architectural principle: cost is a first-class primitive of the discovery loop. CADAQUES separates the loop into two structural protocols, an Oracle that answers queries and a Driver that proposes them, and charges both evaluations and decisions against a common vector-valued budget spanning wall time, CPU hours, monetary cost, and language model tokens. An append-only ledger records, for each transaction, the cost declared before execution and the cost settled afterwards, making their discrepancy an observable property of the campaign. We evaluate the architecture by locating the critical temperature of the two-dimensional Ising model from noisy finite-size estimates against the exact thermodynamic-limit reference. In this noisy setting, strategies that concentrate around the best observed result can be misled by noise-induced peaks, whereas a schedule that explores with cheap low-fidelity queries and refines with higher-fidelity ones yields lower and less variable errors than high fidelity throughout, at the studied budget scale. Metering adds tens of microseconds per iteration, three orders of magnitude below the cheapest oracle query. The framework is MIT-licensed and archived at Zenodo (doi:10.5281/zenodo.21293589).

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：现有自主发现系统（如自驱动实验室、贝叶斯优化、LLM Agent）的软件框架通常继承数值优化的控制结构，存在三大假设：①实验以固定迭代次数运行，假设每次查询成本相同（实际差异可达数量级）；②查询成本未显式暴露在编程接口中，使得多保真度策略难以直接表达；③决策过程（如模型拟合、LLM调用）被视为免费，但实际可能消耗大量资源（时间、Token、费用）。这些假设导致：基于迭代次数的性能比较不可靠；预算自适应策略实现困难；决策成本被系统性地忽略。
- **整体含义**：需要在发现循环的架构层面将成本作为一等原语，实现统一的资源记账、预算控制和事务级溯源，从而支持公平的资源归一化比较和经济有效的实验规划。

### 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：CADAQUES 将发现循环解耦为两个结构协议——**Oracle**（回答查询）和 **Driver**（提出查询），所有操作（评估和决策）均消耗共同的多资源向量预算（挂钟时间、CPU小时、货币成本、LLM Token），并通过仅追加账本记录每次交易的**声明成本**（执行前估计）和**结算成本**（实际产生），使两者差异成为可观测属性。
- **关键技术细节**：
  - **数据模型**：`Cost` 是冻结数据类，包含 `seconds`, `cpu_hours`, `euros`, `tokens` 四个分量，支持分量级加法和支配关系；`Query` 包含设计变量 `params` 和保真度 `fidelity`；`Result` 包含被回答的 Query、标量值 `value`、自由元信息 `info` 以及结算成本。
  - **Oracle 接口**：`price(query) -> Cost` 返回声明成本；`evaluate(query) -> Result` 执行查询并返回含结算成本的 Result。
  - **Driver 接口**：`propose(history, budget_view) -> Query` 基于历史结果和只读预算视图提出下一个查询；`observe(result) -> None` 接收每次结算后的反馈。只读预算视图暴露 `total`, `spent`, `remaining`, `fraction_used`，Driver 可据此自适应调整策略。
  - **运行循环（Campaign）**：每次迭代分决策阶段（测量 Driver 提案时间并记账）和查询阶段（检查声明成本是否可承受，若不可承受则终止；执行后无条件结算）。预算用尽、Driver 主动停止或达到最大查询次数时终止。终止时返回完整的账本和追溯分析结果。
  - **账本（Ledger）**：仅追加的 Transaction 记录，包含角色（oracle/driver）、标签、声明与结算成本、时间戳、元信息。支持导出 JSON Lines，可直接重构资源归一化的最佳值曲线。

### 3. 实验设计：数据集/场景、benchmark、对比方法

- **任务场景**：通过最大化二维伊辛模型（J=kB=1）有限尺寸、有限采样的磁化率估计 $\chi(T)$ 来定位临界温度 $T_c \approx 2.269$（精确热力学极限值）。查询空间 $T \in [1.5, 3.5]$，Oracle 返回带有噪声和有限尺寸偏差的估计值。
- **Benchmark**：精确的 $T_c$ 作为外部参考，评价指标为估计的最佳温度 $T^*$ 与 $T_c$ 的绝对误差 $|T^*-T_c|$。
- **对比方法**：
  - **RQ2**（固定保真度，名义10秒挂钟预算）：对比 RandomDriver（均匀随机采样）、AnnealedLocalDriver（预算自适应局部搜索，扰动尺度随 `fraction_used` 从 0.5 线性衰减至 0.02）、GP-EI（固定超参数 RBF 核 + 期望改进，8个初始随机点，512候选网格）。Ising 模拟固定保真度 L=24, 400测量扫, 200平衡扫。
  - **RQ3**（保真度经济性，相同10秒预算）：对比固定低保真度（L=16, 150测量）、固定高保真度（L=32, 800测量）、两阶段调度（前半预算全区域低保真均匀采样，后半在最佳低保真温度 $\pm 0.25$ 内高保真均匀采样）。所有方法为基础随机采样（不含自适应）。
- **种子**：10个伪随机种子（0-9），决定蒙特卡洛流和 Driver 随机选择。

### 4. 资源与算力

- **文中明确指出**：运行在单核 CPU（虚拟化 Intel Xeon 2.80 GHz，Ubuntu 24.04，CPython 3.12.3，NumPy 2.4.4）。每次实验名义预算为 10 秒挂钟时间。未使用 GPU。未提及多节点或分布式资源。绝对计时依赖具体环境。
- **框架开销测量**：使用廉价分析 Oracle 进行 5000 次查询，纯 Python 循环 4.0 μs/次，完整 CADAQUES 循环 28.8 μs/次，额外开销约 25 μs/次，远低于 Ising Oracle 中位结算成本（约 65 ms）。

### 5. 实验数量与充分性

- **实验数量**：RQ2 和 RQ3 各使用 10 个种子，每个种子运行一次完整实验。总计 RQ2 3 种策略 × 10 = 30 个运行，RQ3 3 种策略 × 10 = 30 个运行。另外有框架开销微基准（3 次重复 5000 查询）。
- **充分性分析**：
  - **积极方面**：声明了种子和可复现的随机流；报告了中位数、四分位距、最大误差、失败次数（误差>0.3）；提供了统计检验（Mann–Whitney U，但明确指出因样本小和多重比较仅作探索性使用）。
  - **局限**：10 个种子仅能支持粗糙的统计结论；任务仅一维且为模拟，缺乏真实仪器、高维空间、并行执行、多资源类型（如 Token、货币）的验证；GP-EI 实现固定超参数且无噪声鲁棒策略；所有实验在同一台机器上运行，未展示环境可迁移性。

### 6. 论文的主要结论与发现

1. **预算表达性的构造性证明**：`AnnealedLocalDriver` 直接使用 `BudgetView.fraction_used` 调整扰动规模，证明预算状态可通过只读视图暴露给 Driver 实现自适应调度，而迭代计数框架无法原生支持。
2. **集中策略易受噪声诱导的“最优值陷阱”**：在固定保真度下，AnnealedLocalDriver 和 GP-EI 均出现多次因噪声尖峰导致的巨大误差（>0.6），而随机搜索的中位误差最小（0.069）且失败率最低（1/10）。GP-EI 的决策成本占结算成本的 3.2%。
3. **保真度经济性重要**：两阶段调度（低保真探索+高保真精化）在所有 10 个种子中误差均低于 0.1，优于固定高保真（中位误差 0.116，4/10 失败）、优于固定低保真（中位 0.068，但最大误差略高 0.130 vs 0.098）。在此预算下，覆盖率比每步精度更重要。
4. **框架开销可忽略**：每次迭代约 25 μs，比最便宜的 Oracle 查询低三个数量级。
5. **声明/结算差异成为可定量观测属性**：账本暴露了声明成本模型的巨大误差（中位超支 652%），支持事后校准和归因。

### 7. 优点：方法或实验设计上的亮点

- **架构创新**：将成本作为一等原语集成到发现循环的最核心接口中，而非事后附加；使用向量预算避免强加单一交换率；分辨声明与结算成本，使成本模型误差成为可测数据。
- **低耦合设计**：基于 `typing.Protocol` 的结构类型，允许外部代码无需继承即可参与，促进了与现有优化库（如 BoTorch）、实验室平台（如 ChemOS）的互操作。
- **交易级溯源**：仅追加账本包含完整的决策与查询记录，可直接重建资源归一化性能曲线，支持事后灵活分析，符合 FAIR 数据原则。
- **实验设计**：使用具已知精确解的物理模型（伊辛模型）作为目标，使噪声效果和策略失败可被客观评估；故意使用未校准的成本模型来验证账本的诊断能力。
- **透明报告**：不仅报告平均表现，还报道了失败案例（如 AnnealedLocal 和 GP-EI 的大误差），暴露了过拟合峰的脆弱性。

### 8. 不足与局限

- **实验覆盖有限**：仅使用一维、模拟任务；未在真实仪器、多目标、向量输出、并行执行、分布式环境下测试。
- **统计能力弱**：仅有 10 个种子，结论多为趋势而非严格显著性；对 GP-EI 的比较不公平（固定超参数，噪声不鲁棒）。
- **声明成本模型故意未校准**：虽然暴露了问题，但可能导致决策过程中错误拒真查询（在真实应用中可能浪费资源）。框架未提供不确定性裕度或概率性可承受性检查。
- **异步与故障处理缺失**：当前仅支持顺序执行；无批次提议、无并发结算、无失败查询重试支持。
- **多资源集成不完整**：除了挂钟时间，其他资源依赖自愿报告（如 `last_proposal_cost`），缺乏自动计量集成（如 API 客户端自动记录 Token、调度系统记录 GPU 小时）。
- **应用限制**：未涉及 LLM Agent 端到端集成，也未提供标准贝叶斯优化 Driver。结果泛化性存疑。
- **偏差风险**：两阶段策略的简单性使其对低保真阶段结果敏感，若低保真阶段被误导（如边界噪声），第二阶段可能仍然不佳（尽管本实验中未出现）。
