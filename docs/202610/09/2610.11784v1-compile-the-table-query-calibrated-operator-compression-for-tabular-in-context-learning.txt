## Abstract 

Tabular in-context learning (ICL) has emerged as a training-free and accurate paradigm for tabular prediction, but current approaches to compressing its in-context examples face an accuracy– throughput tradeoff: fixed subsets can sacrifice accuracy, while query-specific retrieval limits cache reuse and batching across queries, reducing throughput. We propose QCOC (Query-Calibrated Operator Compression ), which exploits the exchangeability and repeated use of in-context examples by compiling their full KV cache once into compact memory shared across subsequent queries. Instead of retaining raw examples, QCOC clusters their states into joint-KV prototypes, preserves per-cluster multiplicities and the original example count, and calibrates prototype values against attention query vectors produced by the in-context examples through an anchored closed-form solution. Prototype compression drives the speedup, while value fitting helps preserve accuracy. On 64 held-out OpenML-CC18 datasets, QCOC achieves the highest mean accuracy among the compared compression and retrieval methods at both retained counts. Across 12 configurations on seven long tables, it ranks first among compressed methods in ten and averages 0.23 percentage points below full context. Compressing 8,192 in-context examples to 512 memory slots yields a 10.5 × cache compression ratio; excluding one-time compilation, in a single-core CPU online-serving comparison over 1,000 queries, QCOC is up to 508 × faster than dynamic retrieval baselines and 1.98 × faster than full-context inference. These results show that QCOC enables compact-memory reuse and efficient inference across queries while retaining accuracy close to full context.

## 1 Introduction 

Tabular in-context models predict new rows from a labeled in-context example set [12, 13, 26]. Larger contexts expose more in-context information, but increase cache memory and repeated-query inference cost [8, 27]. To resolve this tradeoff, we propose Query-Calibrated Operator Compression (QCOC ), which shifts the object of compression from in-context examples to the query–output mapping defined by the in-context example set. For a fixed in-context example set D, each attention head defines a mapping from a query state q to an attention output AD(q); we refer to this mapping as the in-context-example-conditioned attention operator .Once the in-context example set is fixed, the full KV cache determines this mapping: subsequent queries share the same cache while producing query-dependent outputs. We study tabular compression through 

reusable operator compilation : approximate the full-cache operator once with a compact memory and apply the compiled operator to subsequent queries. Section 3 gives the formal definition. Concretely, QCOC compiles the operator induced by an in-context example set into a compact, reusable KV memory. Because the labeled in-context examples are exchangeable, their individual identities and input order need not be retained: at every layer and head, joint-KV clustering groups their states into prototypes, while exact cluster counts restore the total attention contribution of the examples represented by each prototype. Any length-dependent query transformation is evaluated using the original number of in-context examples N

rather than the number of compressed slots M . Attention query vectors produced by the in-context examples are passed through the full cache to obtain target outputs. With the compressed keys and cluster counts fixed, one regularized least-squares solve fits the compressed value vectors to reproduce these outputs. The compiled KV memory is reused by every future query while still producing a query-specific attention output. Our contributions are: • We propose Query-Calibrated Operator Compression ( QCOC ), a post-hoc KV-compression method for tabular ICL. It uses the exchangeability and repeated reuse of labeled in-context examples to aggregate their states into joint-KV prototypes with exact cluster counts, then fits the prototype values using attention query vectors produced by the examples, producing compressed KV memory reusable across queries without extra data or model updates. • We derive a prototype approximation bound that relates attention-output error to key and value approx-2imation errors, and show that the closed-form value fit cannot increase the residual on its calibration queries. Additional analysis characterizes how approximation error may propagate or change across query distributions. • Through the primary benchmark, long-context evaluation, transfer-model experiments, and multi-query serving experiments, we show that QCOC retains predictive performance close to full context after KV-cache compression and reduces online inference cost when the cache is reused across queries. Component analysis further clarifies the roles of cluster counts, the original example count N , and value fitting, while failure-case analysis identifies the method’s limitations. 

## 2 Related Work 

Tabular ICL and long-context scaling. Prior-data fitted networks learn to perform supervised prediction in context [12, 24]. TabPFN v2 strengthens small-data prediction, while TabICL scales model capacity through a column-then-row architecture [13, 26]. Several works address the remaining in-context example count bottleneck at the input or execution level. Scaling TabPFN studies row sketching and feature selection, BAPS constructs class-balanced prototypes, and Chunked TabPFN preserves exact full-context computation through tiled-block attention [8, 15, 27]. TuneTables and in-context data distillation optimize synthetic contexts or model parameters for a target table [9, 22]. TACO instead trains a dedicated compressor and predictor end to end, mapping the training table into a reusable latent context [33]. QCOC differs by post-hoc compiling the internal in-context-example KV states of an existing pretrained tabular ICL model, without updating model parameters or replacing its predictor. 

Global and dynamic row selection. Global methods select one context that is reused across queries. They include random or clustering-based subsets, LUCoS K-Medoids in a learned tabular representation, and more general coresets or distilled datasets [6, 14, 29]. Their one-time selection supports efficient serving, but a single subset cannot preserve all query-relevant regions. Dynamic methods instead adapt the selected rows to each query: KATE performs nearest-neighbor retrieval, MICP routes queries among contexts, CRUMB constructs distribution-matched query batches, and ARASH adapts retrieval and context size [11, 16, 20, 32]. Dynamic selection improves local relevance but limits context reuse and batching across queries. QCOC mitigates this tradeoff by compiling one reusable layer-wise KV memory whose attention output remains query-dependent. 

Reusable context representations. Language-model work has learned to replace long prompts with reusable hidden representations. Gist tokens and ICAE train compact memory tokens, Activation Beacon compresses layer activations directly, and recent evidence shows that even pooling is a strong baseline when evaluated carefully [7, 10, 23, 34]. Cartridges and latent context compilation further study reusable memories for later queries [5, 19]. 

KV-cache compression. Efficient-attention methods replace quadratic attention with low-rank features or landmarks [4, 31]. KV-cache compression has been introduced for autoregressive language models through token eviction [18, 21, 35], state merging [2, 30], and layerwise budget allocation [3]. Recent language-model studies have also explored optimizing or reconstructing compressed KV states beyond token eviction and state merging [17, 25, 28, 36].

## 4 Experiments 

We evaluate QCOC in terms of predictive accuracy, long-context scalability, component effects, and multi-query serving efficiency. We first compare it with compression and retrieval methods at the same retained counts, and then use long-table, component, and serving experiments to examine its accuracy retention, the role of each design choice, and the efficiency gains from reuse across queries. 

4.1 Experimental Protocol 

Primary and long-context benchmarks. The primary benchmark contains 64 held-out OpenML-CC18 datasets [1], uses up to 512 in-context examples, and evaluates retained counts M ∈ { 32 , 64 }; ten dis-joint validation datasets determine all hyperparameters. Long-context experiments cover seven CC18 datasets together with SUSY, HIGGS, and Covertype under varying in-context example counts and compression ratios. Appendix C gives further protocol and data-split details. 

Baselines. We compare full-context inference, fixed row selection, dynamic retrieval, and direct KV compres-sion. Fixed row selection includes class-balanced random selection, input-space K-means, and LUCoS [14]; dynamic retrieval includes MICP [32], CRUMB [11], KATE [20], standardized raw-space KNN, and an ARASH-style reproduction [16]. The primary direct-KV baseline is weighted joint-KV; key centroids and ToMe/KVMerger-style variants are compared in Appendix Table 6. All methods use the same prediction model; Appendix D gives exact definitions. 

Metrics and uncertainty. We use accuracy averaged equally across datasets to measure predictive performance; prediction agreement, probability mean absolute error (MAE), and attention-output mean squared error (MSE) measure deviation from full-context inference. We also report cache memory and serving time. Confidence intervals use paired bootstrap over datasets; Appendix C defines the metrics and Appendix H gives the timing protocol.

4.5 Long-Context Accuracy and Serving Cost 

The long-table results compare accuracy, cache footprint, and online serving cost. At N = 8 ,192 and M = 512 ,

QCOC is the strongest compressed method on CC18-Long, SUSY, and HIGGS, whereas KATE remains substantially better on Covertype. Relative to Full, its cache is 10.53 × smaller on CC18-Long; Appendix Table 11 gives the corresponding results for the three external datasets. Increasing the retained count narrows but does not close the Covertype gap to Full (Appendix Tables 15 and 16). This failure case matters: one shared memory is effective when the full-cache behavior can be represented globally, but query-local retrieval can be preferable on heterogeneous tables. After compilation, the shared memory reduces single-core serving time from 3.79 to 1.91 ms per query relative to Full and avoids KATE’s per-query cache construction (Figure 3). In panel C, QCOC time changes little as 

N grows at a fixed compression ratio, while Full and query-specific retrieval become costlier. The advantage comes from reusing a bounded cache, not an inherent speed difference between KV-compression constructions. These measurements exclude one-time cache construction and compilation; Appendix Table 14 reports the latter separately. Hence, practical gains require enough queries to amortize compilation. The positive residual–accuracy-loss association in Appendix Figure 7 motivates reconstruction residual as a candidate diagnostic. 

## 5 Conclusion 

This work treats compression for tabular in-context learning as compilation of the attention operator induced by a fixed example set, rather than selection of a smaller set of rows. QCOC approximates that operator with a compact, reusable KV memory and calibrates its values to preserve query-dependent attention outputs. On held-out CC18 datasets, it achieves the highest mean accuracy among the compared compression and retrieval methods at both retained counts; on long tables, it remains close to Full in aggregate while reducing 9online serving cost across repeated queries. These gains depend on reusing the same compiled memory across enough queries to justify full-cache construction and one-time compilation. A single shared memory can also miss query-local structure, as the Covertype result shows. Reducing compilation cost and selecting among multiple reusable memories are therefore natural next steps.

## C Additional Experimental Details 

Data and splits. For the primary study, we retain 64 OpenML-CC18 tasks with at most ten classes after excluding the flattened-image tables. A stratified 20% test partition is held out, and up to 512 in-context examples are selected from the remainder. Ten disjoint validation datasets determine all hyperparameters. Cache compression receives no test query, label, prediction, or test-query hidden state. We use a single-estimator TabICL v2 classifier with column and class shuffling disabled. The seven CC18 long-table datasets use N ∈ { 512 , 2048 , 4096 , 8192 }, M ∈ { N/ 32 , N/ 16 , N/ 8}, and 1,000 test queries per setting. We use chronology-respecting holdouts for electricity and bank-marketing and stratified holdouts otherwise. External experiments use official Covertype, SUSY, and HIGGS data with 

N = 8192 , M = 512 , 1,000 disjoint test rows, and three splits. Dataset identifiers are listed below. 

Baseline execution. MICP routes queries among cluster-specific contexts; CRUMB constructs an MMD-matched context for each query group; KATE performs per-query retrieval in TabClustPFN embedding space; and standardized raw-space KNN retrieves directly from standardized inputs. Every baseline uses TabICL for prediction rather than label voting, and all methods share the same model and in-context example pool. 

Statistical unit. The dataset is the unit for paired bootstrap intervals. For repeated-split diagnostics, scores are first averaged within each dataset before datasets are resampled, so repeated splits do not count as independent evidence.

Joint-KV and key-only prototypes then have indistinguishable accuracy, but joint-KV lowers probability and attention errors on 55 and 63 of 64 datasets. To test whether the layerwise closed-form attention-output match can be improved through the final prediction objective, we evaluate an iterative end-to-end extension. Starting from the M = 32 QCOC memory, we keep the model parameters, compressed keys, and cluster-count weights unchanged and update only the compressed values. Using 128 independent unlabeled calibration rows, we take centered logits from the full cache as teacher targets and minimize centered-logit MSE together with an anchor penalty to the closed-form solution. The learning rate, number of steps, and anchor weight are selected on three validation datasets and then fixed to 3 × 10 −4, 30, and 10 −4, respectively. Across ten validation datasets, iterative refinement increases mean accuracy from 88.60% to 89.20%, with a 2/8/0 win/tie/loss record; probability MAE decreases from 0.0201 to 0.0153, and centered-logit MSE from 0.3227 to 0.0442. The fidelity improvement does not consistently translate into higher long-context accuracy. On electricity , at N = 8 ,192 , probability MAE decreases from 0.1543 to 0.1076 while accuracy drops from 0.80 to 0.78; at N = 32 ,768 , probability MAE decreases from 0.2485 to 0.2029 and accuracy rises from 0.80 to 0.82, still leaving a gap to full context. The extension also introduces extra unlabeled data, backpropagation, and iterative hyperparameters. We therefore retain it as a fidelity diagnostic and optional extension, while the main paper uses the closed-form method that requires neither an additional calibration set nor gradient-based optimization.
