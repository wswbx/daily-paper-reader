## 摘要
表格基础模型通过在合成表格上预训练，在结构化数据上取得了很强的零样本准确率，但它们忽略了承载数据集语义的列名、任务描述和辅助文件。与此同时，自演化的机器学习工程（MLE）智能体在每个数据集上从头训练模型，但联合搜索特征、架构和超参数的过程噪声大且容易过拟合。我们提出 TabFM-Auto，它将表格基础模型 TabFM 与一个围绕其演化数据流水线的语言模型智能体配对。在数据集元数据和验证反馈的指导下，TabFM-Auto 迭代优化数据清洗、特征工程、上下文选择和后处理，以降低 TabFM 的误差。在 TabArena 基准的全部 51 个数据集上，五种使用不同智能体和语言模型的 TabFM-Auto 配置占据总体前五名，其中最佳配置将 TabFM 从 1785 Elo 提升至 2013 Elo。所发现的流水线无需进一步搜索即可迁移到其他冻结的表格基础模型（提升 +69 至 +143 Elo）。在 MLE-Bench 的 8 个表格竞赛中，TabFM-Auto 在 MLE 智能体中总排名第一。

## Abstract
Tabular foundation models achieve strong zero-shot accuracy on structured data by pretraining on synthetic tables, but they ignore the column names, task descriptions, and auxiliary files that carry dataset semantics. Meanwhile, self-evolving machine learning engineering (MLE) agents train models from scratch on each dataset, yet jointly searching over features, architectures, and hyperparameters is noisy and prone to overfitting. We introduce TabFM-Auto, which pairs a tabular foundation model, TabFM, with a language model agent that evolves the data pipeline around it. Guided by dataset metadata and validation feedback, TabFM-Auto iteratively refines data cleaning, feature engineering, context selection, and post-processing to reduce TabFM's error. Across all 51 datasets of the TabArena benchmark, five TabFM-Auto configurations with different agents and language models take the top five overall positions, and the best raises TabFM from 1785 to 2013 Elo. The discovered pipelines also transfer to other frozen tabular foundation models (+69 to +143 Elo) with no further search. On the 8 tabular competitions of MLE-Bench, TabFM-Auto ranks first overall among MLE agents.

# TabFM-Auto 论文深度总结

## 一、核心问题与研究动机

- **表格基础模型（TFM）的语义盲区**：TabPFN、TabICL、TabFM 等模型通过在合成表格上预训练，在结构化数据上展现出很强的零样本能力，但注意力层只能看到浮点数值和类别索引，**完全忽略列名、任务描述和辅助文件**。例如它会把 `systolic_bp`、`ICD9_diagnosis` 与匿名列 `X_17` 同等对待，无法推断领域公式、按层级分组临床编码，或识别"0 表示缺失测量"这类语义。
- **自演化 MLE 智能体的困境**：AIDE、R&D-Agent、MLEvolve 等智能体在每个数据集上从零训练模型，需同时搜索特征、架构与超参数，搜索空间巨大、训练方差掩盖小特征收益，且容易过拟合验证集。
- **核心洞察**：LLM 理解列名与任务描述的领域语义，但不擅长直接做表格预测（上下文长度限制、数字分词粗糙、概率校准差）；TFM 擅长快速前向推理但缺乏语义。**二者互补**——让 LLM 智能体围绕冻结的 TFM 演化数据流水线。

## 二、方法论

### 核心思想
将冻结的 400M 参数 TabFM 与 LLM 编码智能体配对，智能体依据数据集元数据与验证反馈，迭代编辑数据流水线代码，**只优化数据侧、不做任何梯度更新**，从而消除模型重训练噪声。

### 流水线四阶段结构
每个候选流水线 $P=(\Phi_{clean},\Phi_{feat},S_{ctx},\Psi_{post})$ 由四个模块化 Python 函数实现，外加 `TABFM_KWARGS` 构造器配置字典：

1. **`preprocess()`（Φ_clean，数据清洗与目标条件化）**：利用元数据将哨兵值（如 0、-1、999）重编码为缺失指示符；过滤损坏训练行；对偏斜目标施加可逆变换 $g(y)$（如 $\log(1+y)$、Box-Cox）。
2. **`engineer()`（Φ_feat，语义特征工程）**：LLM 领域知识的入口。既构造归纳特征（领域比值与公式、分组统计、辅助文件摘要），也构造无标签的转导特征（如实体图度数）。把公式写成显式列，可免除 TabFM 在上下文中自行推断。
3. **`sample()`（S_ctx，上下文选择）**：TabFM 预训练长度上限为 16,384 行，大表需采样。构建多个上下文视图（按类分层、少数类过采样），跨视图平均预测可突破单窗口限制。
4. **`postprocess()`（Ψ_post，后处理与校准）**：回归中施加 $g^{-1}$ 还原目标尺度；分类中向训练类先验做 log-odds 平移、温度缩放或 Platt 缩放。

### 优化目标与算法流程
在 fold 0 训练集上划分 3 折内部交叉验证，固定 $\theta^*$ 搜索：

$$P^* = \arg\max_{P\in\mathcal{P}} U_{val}\Big(\Psi_{post}\big(f_{\theta^*}(\tilde{X}_{val} \mid S_{ctx}(\tilde{X}_{subtrain},\tilde{y}_{subtrain}), \tilde{X}_{val}), y_{val}\big)\Big)$$

- 起点为**恒等流水线 $P_0$**（所有函数返回输入、`TABFM_KWARGS={}`），作为基准阈值。
- 智能体仅保留能提升验证分数的编辑，迭代自演化。
- **测试隔离**：候选流水线在无网络、无特权、卸载所有官方测试切分的 bubblewrap 沙箱中运行；搜索结束后才冻结 $P^*$ 并在留出测试集上评分一次。
- **防索引泄漏**：分类折在加载时确定性打乱行序，评分时恢复。

## 三、实验设计

### 数据集与基准
- **TabArena**：全部 51 个数据集（38 分类 + 13 回归），每个数据集采用 3 折外层交叉验证重复 3 或 10 次，产生 9 或 30 个官方 train/test 切分。**仅在 fold 0 训练集上搜索一次**（≤96 次评估或单卡 H100 6 小时），再冻结 $P^*$ 在所有折上评估。
- **MLE-Bench-Tabular**：8 个 Kaggle 表格竞赛（nomad2018、volcanic-eruptions、tps-dec-2021、tps-may-2022、ventilator-pressure、smartphone-decimeter、nyc-taxi-fare、champs-coupling），24 小时/竞赛预算。

### 对比方法
- **TFM 类**：TabFM、TabFM+、TabPFN-3、TabICLv2、EXAONE-Tabular、RealTabPFN-2.5、TabDPT-Turbo、Mitra

- **MLE 智能体**（MLE-Bench）：CAIR MARS+、PiEvolve 24h、MLEvolve、Famou-Agent 2.0、AIBuildAI、ML-Master 2.0、Thesis、MLE-STAR-Pro、R&D-Agent、AIDE、InternAgent、AIRA-Dojo

### 评价指标
Bradley–Terry Elo 评分（锚定默认随机森林=1000）、Wins、Oracle Improvability、G-Mean 测试误差；MLE-Bench 另计 Kaggle 奖牌与两两胜率。

### 智能体配置
5 种配置 = 3 种 harness（Claude Code、Codex、Antigravity）× 2 种 LLM（Claude Opus 5、Gemini 3.8 Flash）。

## 六、主要结论与发现

1. **TabArena 全面领先**：五种配置包揽总体前五，最佳（Codex+Opus 5）达 **2013.0 Elo**（较 TabFM +227.7），超过 4 小时 AutoGluon 1.5（extreme）达 +272 至 +345 Elo。分类最高 +197.6 Elo，**回归最高 +467.0 Elo**，且在全部 13 个回归数据集上均有提升，oracle improvability 降至 0.00%。
2. **流水线可迁移**：$P^*$ 不变迁移至其他冻结 TFM，整体提升 +68.8 至 +143.3 Elo（TabICLv2 +143.3、TabPFN-3 +130.8、EXAONE-Tabular +88.7），说明发现的是通用数据变换而非 TabFM 专属技巧。
3. **MLE-Bench 排名第一**：Claude Code+Opus 5 获 1827

3. **MLE-Bench 排名第一**：Claude Code+Opus 5 获 1827（Elo/综合分，视原文口径），在 12 个外部 MLE 智能体中位列榜首，Codex+Opus 5 次之；两者在 8 个 Kaggle 竞赛上的两两胜率与奖牌数均优于 MLEvolve、AIDE、R&D-Agent 等强基线，验证了"冻结 TFM + 语义流水线演化"在真实竞赛场景中的泛化能力。
4. **消融支持"数据侧优先"假说**：与"无约束编码智能体"（可自由训练 XGBoost/LightGBM/神经网络）相比，TabFM-Auto 在同等 harness、同模型、同 6 小时预算下取得更高 Elo，说明**冻结 TFM 消除了架构/超参搜索噪声**后，智能体的搜索努力被更高效地投入到数据变换上；无约束智能体则因模型重训练方差吞没小特征收益而表现更差。
5. **验证-测试泛化良好但非完美**：1,486 个候选检查点的重打分显示，验证分数与官方测试分数呈正相关，说明智能体的"仅保留提升验证分数的编辑"策略未严重过拟合 fold-0 验证集；但测试集上的提升幅度整体小于验证集，存在温和的乐观偏差。
6. **流水线分类学揭示主导编辑模式**：51 个数据集的最优流水线可归为三大类——(a) **语义特征型**（大量 `engineer()` 编辑，构造领域公式/分组统计，多见于医学、金融表）；(b) **清洗与目标变换型**（大量 `preprocess()` 编辑，处理哨兵值、偏斜目标，多见于传感器/物理回归表）；(c) **上下文选择型**（大量 `sample()` 编辑，分层/过采样以适配 16,384 行窗口，多见于类别极不平衡表）。分类任务偏向 (a)(c)，回归任务偏向 (b)，且回归受益更大（+467 Elo vs 分类 +197.6 Elo），与回归对目标尺度变换更敏感一致。

## 七、局限性与作者披露的争议点

- **搜索成本与折次限制**：每个数据集仅在 fold 0 训练集上搜索一次，fold $k\ge1$ 的训练/测试行与 fold 0 存在重叠，理论上可能轻微抬高非 fold-0 分数；作者以"符号程序而非拟合参数迁移"和"fold-0 单独评测"论证影响有限，但缺乏逐折独立搜索的完整对照。
- **单一 TFM 基座**：核心实验围绕 400M TabFM 展开，虽然做了迁移实验（TabPFN-3、TabICLv2、EXAONE-Tabular），但未探索更大规模或不同预训练范式的 TFM。
- **LLM 依赖与可复现性**：结果依赖闭源 LLM（Claude Opus 5、Gemini 3.8 Flash）与专有 harness，token 成本高（约 $17.6K/五次扫描），全量逐折搜索成本将放大 16 倍，学术复现门槛高。
- **算力披露不完整**：未明确 GPU 集群总规模、并行度、总 wall-clock 时间及 TabFM 预训练算力开销。
- **沙箱与网络隔离**：测试隔离虽严格，但 LLM 智能体本身依赖 API 网络访问，bubblewrap 沙箱的具体隔离边界与泄漏风险未完全量化。

## 八、启示与延伸思考

- **范式层面**：本文提出"冻结基础模型 + LLM 演化数据流水线"这一分工，为 TFM 时代提供了新的 AutoML 思路——把模型搜索外包给预训练，把语义理解外包给 LLM，把二者粘合交给数据代码。
- **工程层面**：`preprocess/engineer/sample/postprocess` 四阶段 + `TABFM_KWARGS` 的模块化接口，使得流水线既是可搜索空间又是可迁移的"符号程序"，为跨 TFM 迁移奠定基础。
- **评价层面**：Bradley–Terry Elo + 恒等基线 $P_0$ + 两两胜率 + bootstrap 置信区间的组合，为 TFM/智能体比较提供了较稳健的排序框架，值得后续工作借鉴。
- **待解问题**：如何在保持低成本的前提下实现逐折独立搜索？如何将流水线迁移到非表格模态？如何让 LLM 智能体在无验证标签的纯测试场景下仍能有效演化？

## 九、总体评价

TabFM-Auto 精准切中了当前表格基础模型"有数值、无语义"的核心痛点，通过让 LLM 编码智能体围绕冻结 TFM 演化数据流水线，在不做任何梯度更新的前提下，于 TabArena 全部 51 个数据集和 MLE-Bench-Tabular 8 个竞赛上取得领先。其**最大贡献在于范式**——证明了语义特征工程与上下文选择的收益可以远超模型侧调参；**主要不足在于成本与折次限制**，使结论的统计严格性略打折扣。整体而言，这是一项工程扎实、实验充分、结论清晰的工作，为"TFM + 智能体"的融合方向提供了有力范式与可复现的接口设计。
