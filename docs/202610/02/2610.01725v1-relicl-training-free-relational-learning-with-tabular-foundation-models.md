## 摘要
表格基础模型无需任何训练即可在单表任务上达到最先进的性能。近期研究表明，它们也很适合通过深度特征合成（DFS）进行关系学习，DFS 通过将其他表的列的聚合值作为特征加入，将关系模式展平为单张表。这种方法很有吸引力，因为它直接受益于底层表格基础模型的改进或定制化。在本文中，我们指出了 DFS 的两个关键问题：特征爆炸和交互盲区。第一个问题源于：随着模式变得更加复杂，DFS 特征的数量会迅速增长，从而限制了可扩展性和性能。第二个问题源于按列聚合没有考虑特征交互，从而限制了性能。我们提出并探索了一种称为 RelICL 的替代方法，它保留了 DFS 的优点，但缓解了这两个问题。其核心是，RelICL 沿模式图逐步传播并融合信息，且用于完成该过程的正是最终用于预测的同一表格基础模型。在我们使用 RelBench 任务进行的实验研究中，RelICL 与基于深度特征合成的最强方法表现相当。

## Abstract
Tabular foundation models achieve state-of-the-art performance on single-table tasks without any training. Recent work suggests that they are also well-suited for relational learning via deep feature synthesis (DFS), which flattens a relational schema into a single table by adding aggregates of the other tables' columns as features. This approach is appealing because it directly benefits from improvements to or customization of the underlying tabular foundation model. In this paper, we identify two key problems with DFS: feature explosion and interaction blindness. The first problem arises because the number of DFS features grows quickly as the schema becomes more complex, limiting scalability and performance. The second problem arises because column-wise aggregates do not account for feature interactions, limiting performance. We propose and explore an alternative method termed RelICL, which keeps the benefits of DFS but alleviates these two problems. At its heart, RelICL propagates and fuses information step by step through the schema graph, using the same tabular foundation model that is eventually used for prediction to do so. In our experimental study using RelBench tasks, RelICL was on par with the strongest approach based on deep feature synthesis.

## 1. 核心问题与整体含义

- **研究背景**：表格基础模型（TFM，如 TabPFN、TabICL、TabFM）在单表任务上无需训练即可达到 SOTA。近期工作尝试用深度特征合成（DFS）将 TFM 用于关系学习：沿元路径聚合上下文表列，把关系模式展平为单张扩展任务表，再交给 TFM 预测。
- **核心问题**：DFS 虽简单有效，但有两个固有缺陷：
  - **特征爆炸**：DFS 特征数约为 \(O(\#\text{meta-paths} \times \#\text{attributes} \times \#\text{aggregates})\)，随 schema 复杂度快速增长；实践中常需限制元路径深度或剪枝，例如默认深度为 2。
  - **交互盲区**：每个 DFS 特征只聚合单列，无法建模上下文表列间交互。
- **论文含义**：作者证明，对某些任务，有界深度 DFS 或不含交互的 DFS 预测器无法优于随机猜测。因此，论文提出 **RelICL**，目标是在保留“免训练、可用任意 TFM”优点的同时，缓解特征爆炸与交互盲区。

## 2. 方法论

- **核心思想**：不再沿元路径逐列聚合，而是沿 schema 图逐步传播、池化并融合**行嵌入**；并且用于特征提取、特征融合和最终预测的是同一个 TFM。
- **关键假设**：Assumption 1：行嵌入是良好特征，即 \(T(T_{\text{enc}}(R))\) 的性能与 \(T(R)\) 相当。多数近期 TFM 都包含编码器与预测头。
- **推断 DAG**：以任务表为根做 BFS，得到表的部分顺序；边 \(R \to S\) 表示表 \(R\) 的信息应融合进表 \(S\)。
- **三阶段流程**：
  1. **外向遍历**：按反向拓扑顺序，从任务表传播相关键，剪除不被任务表间接引用的上下文行，降低注意力成本。
  2. **内向遍历**：按拓扑顺序处理表。对表 \(R\)，融合其子表 \(C\) 的信息得到 \(R^+\)；对子表行嵌入做池化，如 sum/mean/max，并加入引用行数 count 特征；再用 \(T_{\text{enc}}\) 提取 \(R^+\) 的行嵌入。
  3. **预测**：处理完任务表得到扩展任务表 \(T^+\)，运行完整 TFM \(T(T^+)\) 得到预测。
- **如何避免两个缺陷**：
  - **避免特征爆炸**：新增特征数只取决于直接子表/局部邻域，不随全库表数增长；无需深度界。
  - **避免交互盲区**：传播的是整行嵌入，每个嵌入元素依赖整行信息，可捕获特征交互。
- **实现技巧**：schema rewrite（内联叶子表、消除 junction table）、降维（如 Gaussian random projection，默认降到 32 维）、大表子采样、合并 many-to-one 关系、时间过滤与时间池化。
- **超参数与集成**：共 11 个超参数；默认配置通过 12 个任务上的随机搜索选择；回归任务集成 2 个成员，分类任务集成 4 个成员；默认 backbone 为 TabICL v2，也测试 TabPFN v3。
