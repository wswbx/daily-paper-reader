## 摘要
真实世界的表格往往是异构的，兼具数值特征与自由形式的字符串列。表格基础模型（TFM）在数值表格上表现优异，但要求将字符串编码为数值；而大语言模型（LLM）虽具备语义知识，却并非为表格预测而设计。现有的大多数桥接方案将 LLM 用作单元格字符串的即插即用编码器，但如何为表格学习有效提取表示仍缺乏充分探索。我们表明，LLM 与表格之间的接口与 LLM 本身同样重要。按单元格逐一应用时，更大的 LLM 并不能给出更好的特征；而采用我们的接口，相同的 LLM 会随规模增大而稳定提升。TILE（Table-Interfaced LLM Embeddings，表格接口化 LLM 嵌入）融合了四个要素：行序列化以提供跨列上下文，中间层提取以避开专门用于下一词元预测的层，按列池化以消除平均池化的长度偏差，以及旁路特征以将数值和类别绕过 LLM 直接传递。与 TFM 配合使用时，TILE 在含字符串的表格上树立了新的最优水平。在 100 个数据集上，它在 89% 的划分中优于最强基线，在 7 个 LLM 和 10 种表格学习器上均取得提升，并在包含 108 个数据集的 STRABLE 基准上排名第一。

## Abstract
Real-world tables are often heterogeneous, combining numerical features with free-form string columns. Table foundation models (TFMs) excel on numerical tables but require strings to be encoded numerically, while large language models (LLMs) hold semantic knowledge but are not designed for tabular predictions. Most existing bridges use LLMs as plug-in encoders for cell strings, yet how to extract representations effectively for tabular learning remains underexplored. We show that the interface between LLMs and tables matter as much as the LLM itself. Applied cell-wise, larger LLMs do not give better features. With our interface, the same LLMs improve steadily with size. TILE (Table-Interfaced LLM Embeddings) combines four ingredients: row serialization to provide cross-column context, intermediate-layer extraction to avoid layers specialized for next-token prediction, columnar pooling to remove mean pooling's length bias, and by-pass features to route numbers and categories past the LLM. Paired with TFMs, TILE sets a new state of the art for tables with strings. Across 100 datasets, it beats the strongest baseline on 89% of splits, with gains across 7 LLMs and 10 tabular learners, and ranks first on the 108-dataset STRABLE benchmark.

# TILE 论文结构化总结

## 1. 核心问题与整体含义

- **背景**：真实世界的表格是异构的——数值列（表示量）与字符串列（承载语义与世界知识）并存，而这两类模态历史上由不同算法处理。
- **现状**：
  - 表格基础模型（TFM，尤其是 PFN 类，如 TabPFN-2.5/3/3.5、TabICLv2、EXAONE-Tabular、Causilo）已在数值表格上超越 GBDT 等工业标准方法，但它们**为数值而生**，字符串必须先被编码为数值（如 TF-IDF、字符 n-gram），这会丢弃字符串的世界知识与关系上下文（列名、相邻条目）。
  - LLM 内化了大量关于字符串实体的知识，但不擅长数值推理，且需要压平表格结构，端到端 LLM 甚至被字符 n-gram 击败。
- **核心洞察**：现有桥接方案在“上下文”与“结构”之间被迫二选一——行/表序列化方法提供上下文但压平结构且只输出文字答案；逐单元格方法保留列结构但输入过短、缺乏上下文。
- **关键发现**：**LLM 与表格之间的接口，其重要性不亚于 LLM 本身**。逐单元格应用时，更大的 LLM 并不能带来更好特征（Llama 系列几乎不提升，Qwen3 中 0.6B 甚至优于 8B）；而采用 TILE 接口后，相同 LLM 随规模稳步提升（优势从 Qwen3-0.6B 的 4.2 分增至 Qwen3-8B 的 16.7 分）。

## 2. 方法论：TILE 的核心思想与关键技术

- **整体定位**：让 LLM 理解并上下文化表格，让 TFM 从中学习。最终预测由 TFM 在一次前向传播中完成（in-context learning），而非由 LLM 生成答案。
- **两个出发点**：
  - 列是异构的，一条路径无法服务所有列（名字需要世界知识，类别需要精确身份与目标关联，数字需要精确取值）。
  - 结构按列重复，表示也必须按列重复（列 j 在第 1 行与第 1000 行含义相同）。

### 四大核心组件

1. **行序列化（Row Serialization）**：将每行拼成“The \<column name\> is \<cell value\>.”的序列，利用 LLM 注意力让每个单元格在列名与整行语境中消歧（如“E.T.”在“Spielberg”旁才明确指向 1982 年电影）。数值列也被序列化以帮助上下文化字符串，但**不从其跨度读取嵌入**。

2. **中间层提取（Intermediate-Layer Extraction）**：不读最后一层（专为下一词预测优化），而读中间层，因其承载更具迁移性的语义。每个 LLM 只选一层（Llama-3.1-8B 取第 14/32 层），且只需加载到该层，节省显存。

3. **按列池化（Columnar Pooling）**：取代全局平均池化。设行序列化为 L 个 token，提取层嵌入为 H，对字符串列 j 的 token 索引集合 I_j：
   - 单元格嵌入 c_j = (1/|I_j|) Σ_{i∈I_j} h_i
   - 每个维度在训练行上标准化得到 c̃_j，避免尺度主导 PCA。
   - 全局平均池化会被长文本列偏置、稀释短而信息量大的列。

4. **按列 PCA**：每列在训练行上单独拟合一个 PCA，得到 u = [P_j(c̃_j)]_{j∈S} ∈ R^{k·|S|}，保留列对齐。k 默认 30，并按学习器的“特征容量窗口”自适应调整：
   - k = max(1, min(⌊b/|S|⌋, max(30, ⌈a/|S|⌉)))
   - 窗口示例：TabPFN-2.5 为 [100,300]，TabICLv2 为 [50,300]，TabPFN-3 为 [50,250]。

5. **旁路特征（By-pass Features）**：最终特征 x̃ = [u; x_num; x_cat; x_te]：
   - **数值旁路**：保留 TFM 对数字的精确访问，LLM 仅贡献受数字辅助的字符串理解。
   - **类别旁路**：基数低于 50 的字符串列作为原生类别特征。
   - **目标编码旁路**：对重复度足够的字符串列做**折外（out-of-fold，5 折）目标编码**，避免高基数类别泄露标签；测试时未见类别回退到先验。

### 完整流程（6 步）
1. 序列化 → 2. LLM 前向（截断到第 ℓ 层）→ 3. 按列池化 + 标准化 → 4. 按列 PCA 投影 → 5. 拼接旁路特征 → 6. TFM 在训练+查询行上一次前向预测。所有统计量（标准化、PCA、目标编码）仅在训练行上拟合。

## 3. 实验设计

- **数据集**：100 个含字符串的表格，来自 TextTabBench（17）、CARTE（51）、WikiDBs（32）；65 个回归 + 35 个分类任务；每个数据集 5 个随机种子，训练规模 1,024 / 10k / 50k，测试 1,024 样本。
- **指标**：回归用 R²（截断为 0），分类用 ROC-AUC；聚合用按数据集-种子的 min-max 归一化分数、Elo 评分（Bradley–Terry 最大似然，303,345 场对战）、以及“improvability”指标。
- **对比基线（约 30 个）**：
  - 表格基础模型：TabPFN-2.5、TabPFN-3、TabPFN-3.5、TabICLv2、EXAONE-Tabular、Causilo。
  - 传统学习器：调优 XGBoost、CatBoost、调优 RealMLP、Ridge，分别搭配 TF-IDF（字符 n-gram + SVD）或 LLM 编码器（Llama-3.1-8B 逐单元格 + 均值池化 + PCA）。
  - 内建字符串处理：CatBoost、ContextTab、TabSTAR、TabLLM、CASE。
- **外部验证**：STRABLE 基准（108 个表格、445 条流水线、51 个基线），与自建基准仅 15 个表共享来源，且预处理不同。
- **消融/分析实验**：
  - 7 个 LLM 主干（Llama-3.2-1B/3B、Llama-3.1-8B/70B、Qwen3-0.6B/4B/8B）的规模曲线。
  - 层探测（27 个数据集上逐层打分）。
  - 池化策略对比（均值 / 末 token / 按列）。
  - 组件消融（表 2）：去数值旁路、去跨列注意力、用最后一层、去序列化中的数字、去特征容量窗口、去目标编码、去标准化、去类别旁路，以及提示词变体（加目标名、重复序列化、镜像列序、无信息列名）。
  - 特征容量窗口扫描（6 个学习器）、基数阈值扫描（5–100）。
  - 跨 10 种表格学习器的泛化性。

## 4. 资源与算力

- **总算力**：约 **15,200 GPU 小时**，其中约 6,500 小时用于方法开发、消融与探索性研究，约 8,700 小时用于基线评估与超参调优。
- **硬件**：TILE 通常可在**单张 NVIDIA V100（32GB VRAM）+ 15 个 CPU 核**上运行；LLM 编码器与 TILE 跑在 V100 上，CASE 因显存限制跑在 A100/H100 上（其运行时间较低部分源于更快硬件）。
- **显存**：TILE 峰值 8.7 GB，对比逐单元格 LLM 编码器的 16.0 GB（截断到提取层使 LLM 阶段显存近乎减半）；TF-IDF + TabPFN-2.5 仅 2.0 GB，TabLLM 需 17.1 GB，CASE 峰值 24.6 GB。
- **时间**：TILE 每数据集中位数 26–45 秒（1,024 样本）。

## 5. 实验数量与充分性

- **规模**：100 个数据集 × 5 种子 × 3 训练规模；Elo 基于 36 个方法、303,345 场对战；STRABLE 另含 108 个表格、51 个基线的独立验证；消融覆盖全部 4 个核心组件及多种变体；另有 7 个 LLM、10 个学习器的交叉验证。
- **充分性**：非常充分。既有主基准，又有外部独立基准；既有规模扫描，又有层/池化/阈值/窗口的多维度敏感性分析。
- **客观与公平性**：
  - 所有基线看到**完全相同的切分、种子、训练/测试行与指标代码**。
  - 归一化池固定为 17 个基线 + 3 个默认 TILE 变体，Elo 与原始分数不依赖该池。
  - TILE 的少数超参（提取层、特征容量窗口、基数阈值）**一次性设定后固定**，且位于宽平台区。
  - 注意点：层选择在 27 个探测数据集上完成，可能与被评测集存在轻微重叠；CASE 因未公开表格调优主干而使用回退主干 Gemma-3-4B，属于不完全对等；LLM 编码器做了“唯一单元格只嵌入一次”的优化，而 skrub 未实现，作者已声明该优化反而对基线有利。

## 6. 主要结论与发现

- **TILE 树立了含字符串表格的新 SOTA**：在 100 个数据集上于 6 个评估列（3 训练规模 × 2 任务）中全部排名第一；在 1,024 样本时回归 91.6 / 分类 90.4（归一化），远超最强基线 LLM enc. + Causilo 的 77.8 / 81.0；Elo 领先最强基线 **333 分**，在 **89% 的切分**上获胜。
- **STRABLE 上排名第一**：四个 TILE 变体占据前四，TILE + Causilo（1.024）甚至超过“每数据集选最优基线”的 oracle。
- **接口决定 LLM 贡献**：逐单元格时规模无益甚至有害；TILE 使性能随 LLM 规模稳步提升。
- **消融结论**：
  - **数值旁路**影响最大（回归约 −14 分），跨列注意力次之（回归 −6.5 ~ −9.1 分）。
  - 最后一层 vs 中间层：分类 −0.5、回归 −3.6 分。
  - 标准化、特征容量窗口、目标编码旁路各贡献不到 1 分。
  - 更丰富的提示词（加目标名、重复序列化）反而有害。
  - 列名与列序都重要（因果掩码使单元格只关注前序列）。
- **通用性**：TILE 在 7 个 LLM 主干、10 个表格学习器上均优于 LLM 编码器（10–22 分），且与最新一代 TFM 的增益叠加。
- **LLM 单独不够**：TF-IDF 大致匹配逐单元格的 Llama-3.1-8B，并击败端到端 TabLLM、ContextTab、TabSTAR。

## 7. 优点

- **问题切中要害**：将“接口设计”从隐含默认提升为显式设计空间，并用规模曲线给出强证据。
- **方法简洁、可解释**：四个组件各自对应一个明确缺陷（上下文缺失、层选择不当、池化偏置、数值/身份丢失），消融清晰归因。
- **工程高效**：截断到中间层使显存近乎减半；按列 PCA 自适应窗口兼顾精度与宽表可扩展性；旁路特征避免让 LLM 做它不擅长的事。
- **评估严谨**：外部基准（STRABLE）与自建基准来源重叠仅约 14–18%，验证充分；Elo 用 Bradley–Terry 最大似然而非在线更新，并给出按数据集重采样的 95% bootstrap 区间。
- **泛化性强**：不绑定特定 LLM 或特定表格学习器，与 TFM 代际进步正交叠加。
- **诚实报告**：明确列出消融中不奏效的变体（提示词增强、数值单元格嵌入、镜像列序等），并说明 CASE 的硬件不对等与主干替代问题。

## 8. 不足与局限

- **适用范围受限**：仅针对字符串携带预测信号的表格；纯数值表格用独立 TFM 即可，无需 TILE。
- **依赖 GPU**：LLM 嵌入阶段需要 GPU（截断虽近乎减半显存，仍为瓶颈）；LLM 阶段而非表格学习器是硬件约束的主要来源。
- **上下文窗口限制**：行序列化受 LLM 上下文长度约束（本基准最长行 3,425 token，远低于 128k，但极宽且长文本的表格需要分块）。
- **列序依赖**：解码器 LLM 的因果掩码使表示依赖列顺序（镜像列序会掉分），双向编码器是自然的下一步。
- **伦理风险**：LLM 预训练数据中的社会偏见可能被内化并传播，在招聘、信贷、司法等敏感场景需部署前审计。
- **实验层面的潜在偏差**：
  - 提取层在 27 个探测数据集上选定，与被评测数据可能不完全独立。
  - CASE 使用回退主干、运行在更快 GPU 上，与其比较并非完全对等。
  - 两个基准虽声称独立，但共享公共表格来源的稀缺性使部分重叠不可避免，作者已提醒共享来源上的增益不应视为跨基准的独立确认。
  - 部分训练规模（50k 仅 7 个回归 / 2 个分类数据集）样本量小，跨列比较需谨慎。
