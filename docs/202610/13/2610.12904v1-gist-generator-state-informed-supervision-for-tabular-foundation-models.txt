# GIST: GENERATOR -STATE -I NFORMED SUPERVISION FOR TABULAR FOUNDATION MODELS 

Zhangyang Peng 1 Jingze Shi 1 Tongyi Zhang 1 Yuyu Luo 1

## ABSTRACT 

Tabular foundation models (TFMs) based on prior-data fitted networks typically use sampled hard query labels, leaving avoidable sampling variability in pre-training. A key observation is that intermediate generator states can reveal label uncertainty beyond a sampled outcome. We propose Generator-state-Informed Supervision for TFMs (GIST), which uses these states to average query losses over conditional label distributions. GIST jointly designs task generation and query su-pervision, using entropy-calibrated encodings to obtain tractable, input-consistent targets on supported label-dependent branches. We show that this averaging pre-serves the population objective and yields no larger gradient covariance at fixed parameters within each generating distribution. Under matched pretraining sched-ules, GIST improves mean rank across three architectures on both TabArena and TALENT without changing architecture or inference. Across these benchmarks and architectures, GIST wins 62.1% of paired dataset-level comparisons against the corresponding hard-label controls. 

## 1 INTRODUCTION 

Tabular prediction estimates a categorical or numerical target from a row of features, supporting ap-plications such as credit assessment and clinical risk prediction. Tabular foundation models (TFMs) such as TabPFN and TabICL predict targets for query rows through in-context learning, using la-beled rows as context (Hollmann et al., 2025; Qu et al., 2025). Many follow the prior-data fitted network (PFN) approach: a generator samples a data-generating mechanism from a prior, produces a synthetic table, and supplies context and query rows for pretraining (M¨ uller et al., 2022). Synthetic priors determine the feature-label relationships encountered during pretraining. Priors based on Bayesian neural networks (BNNs) and structural causal models (SCMs) provide synthetic tasks for TabPFN (Hollmann et al., 2023), while mixtures of neural and tree-based SCMs supply tasks for TabICL (Qu et al., 2025). Randomized graph-based SCMs in TabICLv2 (Qu et al., 2026) and mixtures of complementary priors in Mitra (Zhang et al., 2025) further diversify the generated tasks. Standard PFN pretraining evaluates query predictions against sampled hard labels, yielding an un-biased Monte Carlo estimate of the population loss and its gradient (M¨ uller et al., 2022; Nagler, 2023). Although synthetic tasks can be generated continually, the model processes only a finite number within its computational budget. For a fixed input, a sampled label selects one class’s loss even when the generator can provide conditional probabilities for all classes. This raises our central research question: Can we use information retained during synthetic task generation to reduce the variability introduced by query-label sampling during pretraining? 

We propose Generator-state-Informed Supervision for TFMs (GIST), a framework that couples synthetic task generation with conditional query supervision . Its statistical basis is Rao-Blackwellization (RB) (Casella & Robert, 1996): replacing the sampled hard-label query loss with its conditional expectation given the model input and selected generator information. This condi-tioning fixes the prediction, allowing GIST to average over the remaining query-label uncertainty whenever the conditional probabilities are tractable. The target construction depends on how the sampled label enters input generation. For a query-label draw that does not affect the model input or task acceptance, the sampling probabilities give the target directly. For supported label-dependent branches, GIST represents the sampled class by a category code perturbed with Gaussian noise and routes all label-dependent fea-ture computations through this encoding. We separately examine where and when conditional supervision reduces clipped-gradient variance , using fixed-checkpoint diagnostics under a shared calibrated prior across train-ing stages, table lengths, and model components. Finally, a TabSwift budget sweep assesses how sensitive predictive performance is to the entropy budget . for conditional supervision with hard-label fallback under a fixed generating distribution. • Experiments on over 200 tabular datasets from TabArena and TALENT show that GIST improves predictive performance across three representative TFM architectures, winning 62.1% of paired dataset-level comparisons against the corresponding hard-label controls.

## 4 EXPERIMENTS 

We evaluate GIST as a joint design of synthetic task generation and query supervision. Our exper-iments address three complementary questions: (i) does the complete design improve downstream prediction across TFM architectures under matched pretraining schedules, in both IID and OOD evaluation? (ii) under a shared calibrated prior, where and when does conditional supervision re-duce clipped-gradient variability? (iii) how sensitive is downstream performance to the entropy budget controlling the encoding channel? 4.1 EXPERIMENTAL SETUP 

Datasets. IID evaluation covers 38 TabArena classification datasets and 188 TALENT datasets shared by all methods (Erickson et al., 2025; Liu et al., 2025). OOD evaluation uses BeyondArena’s temporal and grouped splits (Purucker et al., 2026), with each architecture’s complete feasible task set: 21 datasets for TabICLv2, 18 for TabSwift, and 12 for TabPFN-2.5. IID and OOD refer to the real-data train/test split regimes. 

Baselines. We evaluate Hard and GIST on three representative TFM architectures: TabICLv2 with column-then-row encoding (Qu et al., 2026), TabSwift with efficient row-wise attention (Liu & Ye, 2026), and TabPFN-2.5 with cell-based alternating row/column attention (Grinsztajn et al., 2025). Within TabICLv2’s GraphSCM generator family, Hard uses the original generator and hard query labels; GIST uses our joint generator–supervision design. We also include tuned CatBoost, Light-GBM, XGBoost, RealMLP, and TabM baselines (Prokhorenkova et al., 2018; Ke et al., 2017; Chen & Guestrin, 2016; Holzm¨ uller et al., 2024; Gorishniy et al., 2025). 

Metrics. We report ROC-AUC for binary tasks and log loss for multiclass tasks, averaging within datasets before weighting datasets equally. For cross-task aggregation, error is e = 1 − AUC or log loss, respectively. On each split, we compute Improvability (Erickson et al., 2025) as Im =1 − min j ej /e m, with Im = 0 when em = 0 ; mean rank uses average ranks for ties. Both are lower-is-better and follow the same dataset weighting. Paired win rates compare dataset-level mean scores within each architecture, retaining ties in the denominator. 

Training and evaluation protocols. Within each architecture, Hard and GIST use matched effec-tive global batch sizes, training schedules, and inference settings. Stage 1 (short-context pretraining) trains for 30,000 updates on synthetic tasks of fixed length 1,024 rows. Stage 2 (long-context con-tinuation) trains for 6,000 additional updates from the corresponding Stage 1 checkpoint, with task lengths sampled logarithmically between 400 and 10,240 rows. Task length counts both support and query rows. Unless stated otherwise, Hard and GIST use the final checkpoints of this two-stage, 36K-update schedule. By default, GIST uses β = 0 .15 , the all-row binary-cap budget, and no ex-ternal noise cap. TabArena evaluation uses 594 official outer splits with the benchmark’s internal validation and refitting procedures; TALENT uses five stratified folds per dataset. BeyondArena fol-lows the official outer splits without inner cross-validation for TFMs. Appendix D specifies tuning, inference, and dataset coverage. 

Environment. Our TFM runs use PPU-ZW810E servers with 16 accelerators per node (95.6 GiB each), running Ubuntu 24.04.2 LTS, PPU SDK 2.1.0, and driver 1.3.2. 4.2 PREDICTIVE PERFORMANCE 

We evaluate TabICLv2, TabSwift, and TabPFN-2.5 trained with GIST against their Hard counter-parts, which use the original GraphSCM generator and sampled hard labels. We also include five representative baselines: three gradient-boosted tree methods (CatBoost, LightGBM, and XGBoost) and two neural models (RealMLP and TabM). Evaluation covers the IID splits of TabArena and TALENT and the OOD splits of BeyondArena. Table 1 summarizes IID performance across all methods, while Table 2 reports GIST’s paired win rates against Hard within each architecture across the three benchmarks. 

IID prediction. Across the six combinations of architecture and benchmark, GIST improves mean rank and mean binary ROC-AUC in all six, and mean multiclass log loss and Improvability in four (Table 1). It also wins on a majority of datasets in every combination (Table 2). TabSwift improves all four reported metrics on both IID benchmarks, with paired win rates of 65.8% on TabArena and 67.0% on TALENT. TabPFN-2.5 achieves the largest decrease in Improvability on TabArena, from 8.61% to 4.57%, with 27/38 paired wins. 

OOD prediction. On the architecture-specific BeyondArena task sets, GIST wins on 15/18 datasets for TabSwift, 11/21 for TabICLv2, and 7/12 for TabPFN-2.5 (Table 2). Each comparison includes every task with all official splits completed for both conditions. On the 12 datasets shared by all methods, GIST lowers mean multiclass log loss for all three architectures; mean binary AUC im-proves for TabICLv2 and TabSwift but decreases for TabPFN-2.5. Appendix D.3 gives the full met-rics and comparisons with external baselines. ## 5 RELATED WORK 

Tabular Prediction Tasks. Tabular prediction comprises classification and regression from struc-tured records containing numerical and categorical features. A table can mix continuous mea-surements, categorical identifiers, and text fields, and column meanings can differ across datasets. This heterogeneity affects how models represent features and share information across tasks. Most approaches fit a separate predictor to each dataset. Gradient-boosted trees, including XGBoost, LightGBM, and CatBoost, are widely used in this setting (Chen & Guestrin, 2016; Ke et al., 2017; Prokhorenkova et al., 2018). Neural methods learn feature representations and interactions, with transformer and retrieval-based models providing alternatives (Gorishniy et al., 2021; 2024). AutoML systems combine model selection and ensembling to adapt these learners to individual datasets (Erickson et al., 2020). OpenML-CC18, TabZilla, TALENT, and TabArena support com-parisons across datasets with different sample sizes, feature types, and target distributions (Bischl et al., 2021; McElfresh et al., 2023; Ye et al., 2024; Liu et al., 2025; Erickson et al., 2025). 

Tabular Foundation Models. TFMs learn across tables during pretraining and use that experi-ence to predict on new datasets. PFNs implement this idea through synthetic tasks sampled from a prior, whose posterior predictive distribution defines the population target (M¨ uller et al., 2022; Na-gler, 2023). The generator defines the task distribution, while the supervision rule determines how sampled tasks contribute to pretraining. TabPFN, TabICL, and Mitra develop this approach through synthetic-prior construction and model design (Hollmann et al., 2023; 2025; Qu et al., 2025; Zhang et al., 2025). TabICLv2, TabFlex, and TabSwift further address context scaling and architectural efficiency (Qu et al., 2026; Zeng et al., 2025; Liu & Ye, 2026). TabDPT pretrains on real tables (Ma et al., 2025), while Real-TabPFN and Real-TabPFN-2.5 continue pretraining synthetic-data models on real datasets (Garg et al., 2025; Grinsztajn et al., 2025). Semantic models exploit column names and cell text as transferable information (Kim et al., 2024; Spinaci et al., 2025; Arazi et al., 2025). 

Generator-Informed Learning. PIQL augments TFMs with dataset statistics and generator-program representations, using a student module to reconstruct the latter from visible context at inference (Ding & Akoglu, 2026). GIST uses generator information to construct query targets while retaining the predictor and inference procedure. ALICE replaces sampled labels with conditional class probabilities derived from joint likelihood ratios for simulator-based likelihood-ratio estima-tion (Stoye et al., 2018). GIST shares this conditional-averaging principle and jointly designs task generation and supervision to obtain tractable posterior targets through an entropy-calibrated local channel in supported label-dependent branches. 

## 6 CONCLUSION 

Synthetic generators can support pretraining through the conditional label information they retain. GIST makes this information usable by jointly designing task generation and query supervision, en-abling conditional loss averaging that preserves the population objective within each fixed generating distribution. Improvements across three TFM architectures on TabArena and TALENT support the practical value of this design without changes to model architecture or inference. These results mo-tivate considering the supervision a synthetic generator can provide alongside the tasks it produces, with transfer under distribution shift remaining an open direction. 9AI USE STATEMENT

We apply the preceding rules to the categorical converters of the TabICLv2 generator (Qu et al., 2026). In the softmax converters, a continuous node state determines class probabilities, from which a discrete class is sampled. A scalar code receives one noise draw per row before broadcasting, and class permutations are applied to both labels and probability columns. D.1 PRETRAINING AND CHECKPOINTS 

All six TFM conditions are pretrained for this study; Hard uses the original GraphSCM generator and hard query labels. The implementations have 27.55M parameters for TabICLv2, 8.20M for TabSwift, and 10.72M for TabPFN-2.5. The TabPFN-2.5 implementation uses 24 layers, a hid-den dimension of 192, and three attention heads. Within each architecture, Hard and GIST use the same effective global batch sizes and learning-rate schedule. Training follows the two-stage pro-tocol in Section 4.1. Stage 2 starts from the corresponding condition’s own Stage 1 model, so the downstream comparisons measure accumulated training effects. Checkpoint selection is fixed across datasets. GIST uses a task-level entropy fraction of 0.15, all-row averaging, the binary-cap policy of Ap-pendix C.4, selective conditional targets, and no external Gaussian-scale cap. D.6 BUDGET -SENSITIVITY PROTOCOL 

The TabSwift sensitivity runs use fixed task-level budgets β ∈ { 0.05 , 0.15 , 0.30 } throughout both stages, following the training protocol in Section 4.1. Each Stage 2 run starts from its own budget’s Stage 1 checkpoint. Model and data seeds are fixed across budgets. All runs use all-row averaging, the binary cap, selective fallback, and no external noise cap. The β = 0 .15 results reuse the main run. All budgets use the same 594 TabArena outer splits, default preprocessing, internal validation, and ensemble size 16. Stage 2 TALENT results use the same 188 datasets as Table 1, comprising 120 binary and 68 multiclass tasks, with five stratified folds and ensemble size eight. All 940 folds per condition are observed; checkpoint selection is fixed across datasets. Binary AUC and multiclass log loss are averaged separately after computing each dataset’s fold mean.
